## §1 直升机三轴姿态 PID 自动驾驶仪

- 来源：steam id **3242277101** · <https://steamcommunity.com/sharedfiles/filedetails/?id=3242277101> · **载具**（PYOs Tactical data link 3.6）
- 更新时间：**2025-04-11**
- 用到：物理传感器、GPS 传感器、陀螺仪、旋翼、属性滑块（PitP/PitI/PitD…）
- 亮点：**把「世界坐标差」直接解成罗盘方位与仰角**；`rps` 软启动握手防止落地时积分爆掉；攻击/巡航/返航多模式状态机。

### 1.1 核心：世界坐标差 → 航向与仰角（圈）

```lua
pi2 = math.pi*2

-- 世界坐标差 -> (罗盘方位[圈], 仰角[圈])
-- 负号是因为游戏罗盘「东为负」：0=北, -0.25=东, ±0.5=南, +0.25=西
function G2CpsPit(g)
  return -math.atan(g[1],g[2])/pi2,                      -- atan(y=东, x=北)
          math.atan(g[3], math.sqrt(g[1]^2+g[2]^2))/pi2
end
```

### 1.2 主循环（节选）

```lua
function onTick()
  rps  = GN(24)
  dalt = (GN(2)-alt)*60                    -- 垂直速度 m/s（60 tick = 1 秒）
  alt  = GN(2)
  mapx,mapy = GN(1),GN(3)
  p,r,c = GN(15),GN(16),GN(17)             -- 俯仰 / 横滚 / 罗盘，单位「圈」
  APtgtx,APtgty,APtgtalt = GN(30),GN(31),GN(32)         -- 0 = 无航路点

  if APtgtx~=0 then APx,APy,APalt = APtgtx,APtgty,APtgtalt end

  if APx~=0 then
    local cps   = G2CpsPit({APx-mapx, APy-mapy, 0})
    local dst   = math.sqrt((APx-mapx)^2+(APy-mapy)^2)
    if dst>25 then APdir = cps end                       -- 近处冻结航向，防打转
    local dlt   = CD(c, cps)                             -- 航向误差（圈），见 04 §1.2
    local dx    = math.sin(dlt*pi2)*dst                  -- 侧向偏移 m
    local dz    = math.cos(dlt*pi2)*dst                  -- 沿航向偏移 m
    -- 远/中/近三段增益叠加，再按距离衰减
    APspdx = cl(cl(dx/200,-1,1)*12 + cl(dx/10,-1,1)*1 + cl(dx/50,-1,1)*2, -20,20)
    APspdz = cl(cl(dz/300,-1,1)*25 + cl(dz/10,-1,1)*1 + cl(dz/50,-1,1)*4, -30,30)
  end

  if rps>8 then                                          -- 软启动握手
    if not inited then
      APdir,APx,APy,APalt = c,mapx,mapy,alt; inited=true
    end
    Pit = -pid(1, p, pitT, PN('PitP'),PN('PitI'),PN('PitD'),PN('PitPM'),PN('PitIM'),0.4)
    Rol = -pid(3, r, rolT, PN('RolP'),PN('RolI'),PN('RolD'),PN('RolPM'),PN('RolIM'),0.4)
    Yaw = -pid(2, CD(c,APdir), 0, PN('YawP'),PN('YawI'),PN('YawD'),PN('YawPM'),PN('YawIM'),0.4)
    Col = 0.2 + cl(pid(4, dalt, cl(APalt-alt,-10,10),
                       PN('ColP'),PN('ColI'),PN('ColD'),PN('ColPM'),PN('ColIM'),0.5), -0.7,0.7)
  else
    Pit,Rol,Yaw,Col = 0,0,0,0
  end
  if rps<5 then inited=false end                         -- 停车即复位

  local krps = cl((rps-5)/5, 0, 1)                       -- 0@5rps -> 1@10rps
  SN(1, Pit*krps)
  SN(2, Rol*krps)
  SN(4, (Col+Yaw)*krps)                                  -- 差动输出 = 共轴 / 双旋翼偏航
  SN(5, (Col-Yaw)*krps)
end
```

**要点**
- **软启动握手**（`rps>8` 才初始化、`rps<5` 复位）：引擎没起来时清零输出，避免地面误动作与积分饱和。
- **近距离冻结航向**（`dst>25`）：目标点很近时方位角会剧烈变化，冻结可防原地打转。
- **三段增益叠加**（`/200`、`/10`、`/50`）：远处大增益快速接近，近处小增益精细修正。
- `Col=0.2+...` 的 `0.2` 是**悬停前馈**（抵消重力所需的桨距基准），纯 PID 到不了这个位置。
- `krps` 随转速渐入，避免启动瞬间满舵。
- 攻击/巡航/返航多模式用 `mode` 整数做状态机，切换时重置等待计时（状态机写法见 `02` §4）。

> ⚠ **该脚本中的 `E2R / tM / Mv / G2L`（欧拉角→旋转矩阵系列）定义后并未被调用**，属残留死代码；
> 且其 `E2R` 直接用 `input.getNumber(4/6/5)` 入 `cos/sin`，而物理传感器欧拉角单位是**圈**，须先 ×2π。
> **要写矩阵变换请用 `03_传感器与雷达解算.md` §1 的可用版本。**

## §2 汽车自适应巡航 ACC

- 来源：steam id **3687286349** · <https://steamcommunity.com/sharedfiles/filedetails/?id=3687286349> · **微控制器**（Elias Adaptive Cruise Control）
- 更新时间：**2026-06-13**（本批采集中最新的作品）
- 用到：7 路雷达（每路 4 通道：距离/方位/仰角/接近速度）、属性滑块（Time Gap / Lane Width / Speed Limiter）
- 亮点：**用车道宽度构造「接受锥」**过滤旁车道目标；目标切换带**滞后 + 锁定计时**防抖；时距分段增益；走停状态机。
- 原脚本为 **Minify 压缩态**，本例为反压缩并按语义重命名后的可读版（流程见 `01` §4）。

### 2.1 接受锥：只认本车道的目标

```lua
-- 接受锥半角（圈）：远目标锥角小、近目标锥角大
function gct(d)
  if d<=0 then return 0.01 end
  return cl(math.atan(lw*0.5/d)/(2*math.pi), 0.001, 0.01)    -- lw = 车道宽(m)
end

-- 雷达通道 h -> (距离, 方位, 仰角, 接近速度)；第 8 路无仰角/速度
function rt(h)
  local b = (h-1)*4+1
  local d,a = GN(b), GN(b+1)
  local e,rv = 0,0
  if h~=8 then e,rv = GN(b+2), GN(b+3) end
  return d,a,e,rv
end

-- 逐通道的接近速度：由距离历史差分求，再 EMA 平滑
function gcl(h,d)
  local p = pdistT[h]
  local c = (p>0 and d>0) and (p-d)*60 or 0                -- 60 tick/s
  local r = relT[h] + (c-relT[h])*ra                       -- ra = EMA 系数
  relT[h]=r pdistT[h]=d
  return r
end

-- 判定：距离有效 + 在锥内 + 确实在前方
function ok(d,a,e,ch,v,cg)
  if d<=0 or d>=800 then return false,false end
  if math.abs(a)>ch or math.abs(e)>ch then return false,false end
  if cg <= v+5.0 then return true,false end                -- 不在超车 -> 普通目标
  local q = gct(d)
  if math.abs(a)<=q and math.abs(e)<=q then return true,true end
  return false,false
end
```

### 2.2 目标选择的滞后与锁定

```lua
-- bi = 最优目标下标，bs = 最优分数（越小越紧急）
local score = d + math.abs(a)*aW + math.abs(e)*eW + math.abs(cg)*tW
if t then score = score + 200 end                    -- 对头车：硬优先级

if tlk<=0 or not curOk then
  if curOk then
    if score < bs-sw-swn then bs=score bi=h curOnc=t end   -- 抢走已锁定目标需更大余量
  else
    if score < bs-sw      then bs=score bi=h curOnc=t end
  end
end

-- 目标连续稳定 mst tick 后才认定
if ti==tls then tsn=tsn+1 else tsn=0 tls=ti end
tsb = tsn >= mst
```

**要点**
- 🔑 **接受锥 `gct()`** 比「固定方位阈值」稳得多：远目标自动收窄、近目标自动放宽，天然过滤邻车道与护栏。
- **滞后切换**：已锁定目标要被抢走需超出 `sw+swn`，未锁定时只需 `sw`；再加 `tlk` 锁定计时（tick），彻底杜绝两目标来回跳。
- **走停状态机** `sl`：低速且目标近 → 进入停车；目标远离到 `so` → 释放；`bm` 缓升控制刹车力度。
- 所有阈值集中在顶部常量区 + 属性滑块，便于调参。
- 多人下 `pdistT/relT/Is` 都是脚本变量会分叉（`01` §5）。

## §3 HSI 水平状态指示器（旋转罗盘玫瑰 + 航路点指针 + 地速矢量）

- 来源：steam id **2836937357** · <https://steamcommunity.com/sharedfiles/filedetails/?id=2836937357> · **载具**（ENDAIR A321-200）
- 更新时间：**2022-07-19**
- 用到：指南针、GPS 传感器、航路点输入、显示器
- 亮点：罗盘玫瑰与航路点指针**共用一套极坐标画法**；量程随距离**自动分档**。

```lua
function onTick()
  Compass = GN(10)                                  -- 罗盘传感器，单位「圈」
  HDG  = (((360+Compass)%1)*360)                    -- 圈 -> 度（+360 使负数也安全）
  gpsx,gpsy = GN(11),GN(12)
  navx,navy = GN(13),GN(14)                         -- 航路点
  local sf,sr = GN(15),GN(16)                       -- 前向/侧向速度
  speedT = math.sqrt(sf^2+sr^2)
  speedA = ((math.atan(sf,sr)*180/math.pi-180)+360)%360

  dtt = math.sqrt((gpsx-navx)^2+(gpsy-navy)^2)/1850     -- m -> NM（作者用 1850，标准为 1852）
  htt = ((math.atan(gpsx-navx, gpsy-navy)*180/math.pi-180)+360)%360

  navLine = not (navx==0 or navy==0)                    -- (0,0) = 未设航路点
  if dtt>9 then range=1.5 elseif dtt<3 then range=15 else range=5 end
end
```

```lua
function onDraw()
  local mx,my = 64,64
  -- 罗盘玫瑰：-90° 偏移使 0°（北）落在正上方
  screen.drawText(mx/2-2+39*math.cos(math.rad(HDG-90)),
                  my   +39*math.sin(math.rad(HDG-90)), "N")
  -- NE/E/SE/S/SW/W/NW 同法：角度 -90/-45/0/+45/+90/+135/-180/-135

  if navLine then
    local wx = mx/2-2+(dtt*range)*math.cos(math.rad(HDG+htt-90))
    local wy = my   +(dtt*range)*math.sin(math.rad(HDG+htt-90))
    screen.drawLine(mx/2,my,wx,wy)
    screen.drawCircle(wx,wy,5)
  end
  -- 地速矢量
  local ss = (speedT/100)*45
  screen.drawLine(mx/2,my, mx/2-2+ss*math.cos(math.rad(speedA)),
                            my   +ss*math.sin(math.rad(speedA)))
end
```

**要点**
- `((360+Compass)%1)*360`：加 360（整数）不影响取余，但**对负输入更稳**；`%1` 是把圈归一到 0–1 的惯用写法。
- 屏幕 **Y 向下**，`-90°` 偏移让北在正上方；`math.cos/sin` 吃**弧度**，先用 `math.rad()` 转角度。
- 量程自动分档（1.5 / 5 / 15）对应刻度 10-20-30 / 3-6-9 / 1-2-3 NM，是小型 HSI 的通用做法。
- 航路点指针角度 = **自身航向 `HDG` + 目标方位 `htt`**，这是 HSI 与固定罗盘的核心差别。

- 完整脚本：`../../../AI相关/_提取暂存/2836937357_vehicle_11.lua`

## §4 航路点管理器 + 地图交互（增删选 / 缩放分级 / 平滑镜头）

- 来源：steam id **3793369421** · <https://steamcommunity.com/sharedfiles/filedetails/?id=3793369421> · **载具**
- 用到：GPS 传感器、触控屏、`map.screenToMap` / `map.mapToScreen`、显示器
- 亮点：**一屏三区**的触控布局（缩放滑条 / 航路点标签栏 / 地图区）；缩放与**网格间距、图标大小联动分级**；
  镜头用 **EMA 平滑**跟随；`screenToMap` 把触控点反解成世界坐标。

### 4.1 状态与辅助函数

```lua
S=screen; I=input; O=output
MS=map.mapToScreen; SM=map.screenToMap          -- 双向坐标换算
tU=table.unpack; F=string.format

zoom = 1
zooms = {0.3, 2, 5, 10, 30, 50}                 -- 缩放档位
grids = {10, 100, 500, 1000, 2500, 5000}        -- 对应网格间距(m)
sis   = {5, 4, 3, 2, 1, 1}                      -- 对应图标大小
grid, SZ = 100, 4
wp  = {}                                        -- 航路点列表 {{x=,y=}, ...}
sel = 0                                         -- 当前选中的下标
wx, wy, Fz = 0, 0, 1                            -- 镜头中心(当前/目标) 与 目标缩放

-- 批量读：getN(1,2,3) -> 返回多个值
function getN(...) local a={} for b,c in ipairs({...}) do a[b]=I.getNumber(c) end return tU(a) end
-- 批量写：outN(起始通道, v1, v2, ...)
function outN(o, ...) for i,v in ipairs({...}) do O.setNumber(o+i-1,v) end end
function clamp(a,b,c) return math.min(math.max(a,b),c) end

-- 画箭头形航路点标记（两个三角拼成）
function dPoi(xx,yy,s,r,...)
  local a,x,y = ...,0,0
  a=(a or 30)*math.pi/360
  x=xx+s/2*math.sin(r); y=yy-s/2*math.cos(r)
  xx=xx-s/4*math.sin(r); yy=yy+s/4*math.cos(r)
  screen.drawTriangleF(xx,yy, x,y, x-s*math.sin(r+a), y+s*math.cos(r+a))
  screen.drawTriangleF(xx,yy, x,y, x-s*math.sin(r-a), y+s*math.cos(r-a))
end
```

### 4.2 触控三分区（onTick）

```lua
function onTick()
  touch = I.getBool(1)
  W,H,tx,ty,gx,gy,gz,dir,swp = getN(1,2,3,4,11,12,13,14,15)
  if gx == nil then return true end
  if wx == nil then                                  -- 首次：以本机位置初始化镜头
    if gx==0 then return true end
    wx,wy,Fx,Fy,Fz = gx,gy,gx,gy,zoom
  end
  if swp>0 and swp<=#wp then sel=swp end             -- 外部通道也可选中

  if touch and not t then                            -- 按下沿（t 为闩锁）
    if tx < 10 then                                  -- ① 左边缘：缩放滑条
      tz = ty
      Fz = math.sin((tz/H)^2*math.pi/2)*50           -- sin 映射：低倍率区更精细
      i = 1
      while Fz>zooms[i] do i=i+1 end
      grid, SZ = grids[i], sis[i]                    -- 网格与图标随缩放联动
    elseif ty < 13 then                              -- ② 顶部：航路点标签栏（每 13px 一个）
      ttx = math.ceil((tx-11)/13)
      if ttx>0 and ttx<=#wp then
        if sel == ttx then                           -- 再点一次 = 删除
          table.remove(wp,sel); sel=0; ttx=0
        else
          sel=ttx; Fx,Fy = wp[sel].x, wp[sel].y      -- 选中并跳转镜头
        end
      end
      if ttx == #wp+1 then                           -- 点空位 = 新增
        sel=#wp+1
        wp[sel] = {x=wx, y=wy}
      end
    else                                             -- ③ 地图区：反解世界坐标
      Fx,Fy = SM(wx,wy,zoom,W,H,tx,ty)
    end
  end

  -- EMA 平滑镜头（0.1 = 每 tick 走 10%，无过冲、无抖动）
  wx = wx+(Fx-wx)*0.1
  wy = wy+(Fy-wy)*0.1
  zoom = zoom+(Fz-zoom)*0.1
  t = touch

  outN(1, gx,gy, wx,wy, gx,gy,gz, sel, #wp)
  if sel>0 then outN(1, wp[sel].x, wp[sel].y) end
end
```

### 4.3 只画可见范围的网格（onDraw）

```lua
function onDraw()
  if wx==nil then return true end
  local w,h = S.getWidth(), S.getHeight()
  -- 多屏适配：主屏(W)跟随镜头，副屏固定跟随本机
  local mx,my,zo
  if w==W then mx,my,zo = wx,wy,zoom else mx,my,zo = gx,gy,1 end

  S.setMapColorOcean(10,10,15)                       -- 配色须在 drawMap 之前
  S.setMapColorLand(60,60,60)
  S.setMapColorGrass(40,60,40)
  -- ... 其余 setMapColor*（见 05 §6.3）
  S.drawMap(mx,my,zo)

  -- 用 screenToMap 求屏幕对角对应的世界坐标 -> 得到可见范围
  local x1,y1 = SM(mx,my,zo,w,h, 0,h)
  local x2,y2 = SM(mx,my,zo,w,h, w,0)
  x1 = math.floor(x1/grid)*grid                      -- 对齐到网格，防线条随镜头蠕动
  y1 = math.floor(y1/grid)*grid

  S.setColor(0,0,0,20)
  for xx=x1,x2,grid do                               -- 竖线
    local x,y = MS(mx,my,zo,w,h, xx,y1)
    S.drawLine(x,0,x,h)
  end
  for yy=y1,y2,grid do                               -- 横线
    local x,y = MS(mx,my,zo,w,h, x1,yy)
    S.drawLine(0,y,w,y)
  end
end
```

**要点**
- 🔑 **触控三分区**：用 `tx<10` / `ty<13` 把屏幕切成「缩放滑条 / 航路点栏 / 地图区」。
  小屏上这是**唯一可行**的交互布局思路（没有足够空间做独立按钮）。
- 🔑 **缩放 → 网格 → 图标联动**：`zooms/grids/sis` 三个等长数组下标对齐。
  改缩放档位时网格自动切换，是地图类 HUD 的通用范式。
- **非线性滑条**：`Fz = sin((tz/H)² · π/2) · 50` 让滑条下半段对应低倍率（精细）、上半段高倍率（粗略），手感远好于线性映射。
- **网格对齐**：`math.floor(x1/grid)*grid` 让网格线吸附到世界坐标整数倍，
  否则线条会随镜头移动而"蠕动"——这是地图网格最容易忽略的细节。
- **只画可见范围**：先 `screenToMap` 求屏幕对角的世界坐标，再按 `grid` 步进画——
  不管缩放到哪一级，绘制量都恒定。
- **多屏适配**：`if w==W` 判断当前屏是否主屏（W 由复合输入传入），
  主屏跟随镜头、副屏固定跟随本机。这是 `onDraw` 被多次调用时的正确用法。

## §7 多轴车辆**阿克曼转向几何※**（每根轴独立算内外轮角）

- 来源：steam id 3791064111 · 描述页 https://steamcommunity.com/sharedfiles/filedetails/?id=3791064111 · 载具（VNR ATOM 核动力卡车）
- 更新时间：2026-08-28
- 用到：车轮（转向输入 -1~1）、属性滑块（轴距 / 轮距 / 转向极限 / 轴在枢轴前后）
- 亮点：**用 `atan(本轴距 / (最远轴距/tan(极限角) ± 轮距) × 转向输入)` 直接解析出每根轴的内外轮转角**——多轴车、挂车、全轮转向都可套，比逐轴试 PID 稳得多。

```lua
-- 属性：本轴到枢轴距离 / 最远轴到枢轴距离 / 同轴轮距 / 转向极限(度) / 本轴在枢轴后方?
-- 输入 N1 = 转向输入(-1~1)；输出 N1 = 左轮角、N2 = 右轮角（弧度）
flipn = 1
function onTick()
  local thisAxle    = property.getNumber("Axle Distance from Pivot (m)")
  local furthestAxle= property.getNumber("Furthest Axle's Distance from Pivot Point (m)")
  local wheelDist   = property.getNumber("Distance Between Wheels (m)")
  local steerLimit  = property.getNumber("Steering limit")   -- 度
  local flip        = property.getBool("Axle is behind Pivot")

  local wheelPos = input.getNumber(1)                        -- 方向盘 -1 ~ 1
  if flip then flipn = -1 end                                -- 枢轴后方的轴要反相

  -- 阿克曼核心：转弯半径 R = 最远轴距 / tan(最大转角)，再按本轴距求本轴转角
  local R  = furthestAxle / math.tan(steerLimit)             -- 基准转弯半径(m)
  local inner = math.atan(thisAxle /  R            * wheelPos) * flipn
  local outer = math.atan(thisAxle / (R + wheelDist) * wheelPos) * flipn

  local left, right
  if wheelPos >= 0 then left, right = outer, inner           -- 右转：左轮在外圈
  elseif wheelPos <= 0 then left, right = inner, outer end   -- 左转：右轮在外圈

  output.setNumber(1, left * -1)   -- 左轮装向相反，取负
  output.setNumber(2, right)
end
```

**几何含义**（理解了这个就能改任意轴数）

- `R = 最远轴距 / tan(极限角)` 是**最远那根轴**在满舵时的转弯半径，把它当基准；
- 同一转弯中心下，距枢轴 `d` 的轴应有转角 `atan(d / R)` —— 轴越靠内，转角越大，这正是阿克曼「内外轮不同角」的解析解；
- `+ wheelDist` 一项是**同轴左右轮的半径差**：外侧轮半径大一整个轮距，故转角略小。

**要点与坑**

- `math.tan` 吃的是**弧度**，属性滑块给「度」时必须自己 `math.rad(...)`；原脚本直接用 `math.tan(steerLimit)`，等于把「度」当弧度，实车靠重新标定滑块值绕开——**照抄时先确认你的滑块单位**。
- 每个转向轴挂**一个本脚本实例**，改属性即可，不用为每个轴重写几何。
- 输出取 `left * -1` 是安装朝向所致：左轮被镜像装配，正角度会往反方向打。按你的悬挂朝向试一次决定哪一个取负。
- 与 `09` §3（履带差速转向）互补：轮式走阿克曼解析解，**履带**走左右速差。
- 完整脚本：`../../../AI相关/_提取暂存/_new/3791064111_vehicle_0.lua`

## §8 地图叠加三件套：**2 的幂自适应网格 + 像素/公里标定 + 拖动平移**

- 来源：steam id **3792551514** · 描述页 <https://steamcommunity.com/sharedfiles/filedetails/?id=3792551514> · **载具**（ABM "21X" Large Tender RHIB，`_vehicle_3`）
- 更新时间：2026-08-30
- 用到：GPS、指南针（圈）、雷达、触摸屏、属性滑块（默认缩放 / 雷达量程 / 配色）
- 亮点：网格间距用 **`2^(floor(log2(...)))`** 跳档，任何缩放级别下线密度恒定；所有「米 → 像素」的换算都归口到一个 `pxKm` 标定值；拖动平移只靠一次 `atan` + 象限补偿。

```lua
function onDraw()
  local mx, my = gpsX + mapOX, gpsY + mapOY          -- 地图中心（可被拖动偏移）
  screen.drawMap(mx, my, zoom)

  -- ① 网格间距按 2 的幂跳档：31.25 m 是游戏地图的最小格，0.1953125 = 31.25/160
  if GRID and zoom > 0 then
    local g = 2^(math.floor(math.log(zoom/0.1953125, 2))) * 31.25
    local xt, yt = math.floor(mx/g), math.floor(my/g)
    screen.setColor(255, 255, 255, 15)
    for G = xt-6, xt+6 do
      local ox = map.mapToScreen(mx, my, zoom, sw, sh, g*G, my)   -- 只取第 1 个返回值
      screen.drawLine(ox, 0, ox, sh)
    end
    for H = yt-6, yt+6 do
      local _, oy = map.mapToScreen(mx, my, zoom, sw, sh, mx, g*H) -- 只取第 2 个返回值
      screen.drawLine(0, oy, sw, oy)
    end
  end

  -- ② 像素/公里标定：把「地图上 1000 m 有多少像素」量出来，之后一切换算都除以它
  local ssx, ssy = map.mapToScreen(mx, my, zoom, sw, sh, gpsX, gpsY)
  local pxKm = math.max(0.01, math.abs(map.mapToScreen(mx, my, zoom, sw, sh, gpsX+1000, gpsY) - ssx))

  -- ③ 有了 pxKm，雷达量程圈、测向距离圈、比例尺全部统一
  local rPx = RRange/1000 * pxKm
  screen.setColor(0, 170, 0, 45)
  screen.drawCircle(ssx, ssy, rPx)
end
```

```lua
-- ④ 拖动平移：按触点相对屏幕中心的方向平移地图（onTick）
if TOUCH_MOVE and touched then
  if tX > 8 and tX < sw-8 and tY < sh-4 then          -- 避开左右两侧的按钮列
    local dx, dy = tX - sw/2, sh/2 - tY               -- ⚠ 屏幕 Y 向下，故 dy 取反
    local th = math.atan(dy/dx)                        -- 🔑 SW 没有 atan2（两参版在部分版本可用）
    if dx < 0 then th = th + math.pi end               --    用「单参 atan + 象限补偿」最稳
    mapOX = mapOX + math.cos(th)*zoom*12
    mapOY = mapOY + math.sin(th)*zoom*12
  end
end
```

**要点与坑**

- 🔑 **网格跳档为什么用 `2^floor(log2(...))`**：`zoom` 连续变化时，若网格间距固定，放大后线会稀到没有、
  缩小后密成一片。取 2 的幂后，间距只在**跨越倍率边界时翻倍**，屏幕上始终是 13 条线左右。
  这跟 `04` §9 的比例尺**二分跳档**是同一个思想的两个实现：§9 是「按屏幕占比反馈调节」，
  本例是「闭式解析一次算出」，后者无滞后、但依赖 `math.log(x, 2)` 两参形式可用。
- ⚠ `math.log(x, 2)` 的**第二参数是底数**。写成 `math.log(x)/math.log(2)` 更保险
  （个别版本对两参 `log` 支持不一致，见 `00_速查 §16`）。
- 🔑 **`pxKm` 是整套地图叠加的枢纽**：不硬编码「1 像素 = 多少米」，而是每次 `onDraw`
  现场量一次 1000 m 的像素长度。这样缩放、屏幕尺寸（1×1 / 2×2 / 3×3）怎么变都自动对，
  也不用背游戏地图的比例常数。
- **拖动平移用的是「触点方向」而非「触点位移」**：`mapOX += cos(θ)*zoom*12`，
  步长与 `zoom` 成正比（看得远时一次挪得多），手感恒定。代价是**不能做惯性/跟手拖拽**，
  要跟手请改成累加 `ΔtX/pxKm` 的世界位移。
- `if dx < 0 then th = th + math.pi end` 是**单参 `atan` 的象限补偿**标准写法。
  `00_速查` 里提到 SW 的 `math.atan` 行为，稳妥起见一律这么补，别赌两参版。
- 网格只画 `±6` 条（`xt-6 .. xt+6`）是**按屏幕覆盖范围裁剪**，与 `06` §4.3 用
  `screenToMap` 反推可见范围的做法等价，本例更省一次投影调用。

## §9 航路点**折线**（8 点链式连线）+ `...` 可变参数的自绘航向指针

- 来源：steam id 3788750037 / vehicle.xml block#34（REVENANT 导弹艇，地图航路规划屏）
- 更新时间：2026-08-23
- 用到：显示器、指南针、GPS、触控屏
- 亮点：把 8 个航路点批量 `map.mapToScreen` 投影后**链式 `drawLine` 连成折线**，第一段从本舰画起；
  `drawTextBox` 以点为中心自动居中编号，省掉手算字宽；指针函数用 `...` 收可选半角参数。

```lua
si, co, pi = math.sin, math.cos, math.pi
pi2 = pi*2

function onTick()
  GPSX, GPSY = input.getNumber(17), input.getNumber(18)
  zoom       = input.getNumber(19)
  MAPX, MAPY = input.getNumber(20), input.getNumber(21)   -- 地图中心(世界坐标)
  -- 8 组航路点世界坐标, 注意原作 X/Y 通道是交错倒序的
  WPX1, WPY1 = input.getNumber(16), input.getNumber(15)
  WPX2, WPY2 = input.getNumber(14), input.getNumber(13)
  -- ... WPX3..WPX8 同理
  WPA1 = input.getBool(1)                                 -- KEY: 每点一个"已设置"标志
  WPA2 = input.getBool(2)
  -- ... WPA3..WPA8
  compass = input.getNumber(23) * pi2 * -1                -- KEY: 圈 -> rad, 再翻符号
end

function onDraw()
  local w, h = screen.getWidth(), screen.getHeight()

  CPX,  CPY  = map.mapToScreen(MAPX, MAPY, zoom, w, h, GPSX, GPSY)
  WP1PX,WP1PY= map.mapToScreen(MAPX, MAPY, zoom, w, h, WPX1, WPY1)
  WP2PX,WP2PY= map.mapToScreen(MAPX, MAPY, zoom, w, h, WPX2, WPY2)
  -- ... 8 个点全部投影

  drawPointer(CPX, CPY, 10, compass)

  if WPA1 then                                  -- KEY: 第一段从本舰画到 WP1
    screen.drawLine(CPX, CPY, WP1PX, WP1PY)
    screen.drawTextBox(WP1PX, WP1PY, 7, 7, "1", 0, 1)
  end
  if WPA2 then                                  -- 之后每段 WP(n-1) -> WP(n)
    screen.drawLine(WP1PX, WP1PY, WP2PX, WP2PY)
    screen.drawTextBox(WP2PX, WP2PY, 7, 7, "2", 0, 1)
  end
  -- ... WPA3..WPA8 照抄
end

function drawPointer(x, y, s, r, ...)
  local a = ...                       -- KEY: 只取第一个额外参数
  a = (a or 30) * pi/360              -- KEY: 缺省 30, /360 => 传入值是"全角度数"
  x = x + s/2*si(r)                   -- 锚点前推半个身位, 让三角形绕原点转
  y = y - s/2*co(r)
  local x2, y2 = x + 100*si(r), y - 100*co(r)   -- 100 px 航向延长线, 出屏自动裁剪
  screen.setColor(10,10,10)
  screen.drawTriangleF(x, y,
                       x - s*si(r+a), y + s*co(r+a),
                       x - s*si(r-a), y + s*co(r-a))
  screen.drawLine(x, y, x2, y2)
end
```

**要点与坑**

- 🔑 **折线的「第一段从本舰起」是航路屏的关键细节**：`WPA1` 段连的是 `CPX,CPY -> WP1`，
  之后才是点到点。这样航线永远从当前位置出发，不会出现「船在航线外面」的割裂感。
  与 `06` §4 的航路点管理器（只画点、不连线）相比，本例是纯显示端，增删逻辑在上游 MC 里。
- ⚠ **`WPA_n` 必须从 1 开始连续为真**。因为第 n 段用的是 `WP(n-1)`，若 `WPA1=false` 而 `WPA2=true`，
  代码仍会画 `WP1 -> WP2`，而 WP1 的坐标是未初始化的 0,0 —— 屏幕上会甩出一条通往地图原点的长线。
  上游必须保证「启用标志是前缀连续的」。要容错就得改成「记录上一个有效点」的循环写法。
- 🔑 **`drawTextBox(px, py, 7, 7, "1", 0, 1)` 是「以点为中心放标签」的省字数写法**：
  7x7 的框、水平居中(`0`)、垂直靠下(`1`)，等价于手算 `drawText(px-1, py-2, "1")` 但不用care字宽。
  注意框的左上角就是 `px,py`，所以标签实际在点的**右下方 7x7 区域内居中**，不是精确压在点上；
  要压在点上得传 `px-3.5, py-3.5`。
- 🔑 **`compass * pi2 * -1`：圈 → 弧度，外加一次符号翻转**。乘 `pi2` 是因为指南针通道是「圈」
  （0~1 一整圈，参见 `03` §10.6 单位速查）；`* -1` 是因为该罗盘通道的旋转正方向与
  `x+s*sin(r) / y-s*cos(r)` 这套「0=屏幕上、正=顺时针」的绘制公式相反。
  ⚠ 抄的时候**必做验证**：把船头对准北看指针是否朝上，再右转 90 度看指针是否朝右；不对就删掉 `* -1`。
  这是 SW 地图屏最高频的方向 bug 来源。
- 🔑 **`...` + `a = ...` + `a or 30` 是 SW Lua 的「可选参数」标准写法**（`function f(x,y,...)`）。
  这里 `*pi/360` 而非 `*pi/180`，意味着传入的 30 表示**三角形总张角 30 度**、内部用半角 15 度算两个底角
  —— 一个乘法同时完成「度转弧度」和「取半」。与 `05` §17 的可变参数默认值同族。
- **`drawLine(x,y, x+100*si(r), y-100*co(r))` 的 100 是「肯定超出屏幕」的魔数**，靠 SW 自动裁剪当成
  无限长航向线。屏幕最大 96x96（3x3），100 px 足够；换更大的屏组合（SW 单屏上限 3x3）无需改。
- 完整脚本：`../../../AI相关/_提取暂存/_new/3788750037_vehicle_34.lua`

## §10 声纳/渔探落点标记（GPS + 方位+距离 → 世界坐标 + 按船艏旋转绘制 + 寿命过期）

- 来源：steam id 3791125295 · 描述页 https://steamcommunity.com/sharedfiles/filedetails/?id=3791125295 · 载具（Bay Bee Charter Fishing boat）
- 更新时间：2026-08-28
- 用到：GPS 复合输出（x,y 世界坐标）、物理传感器/罗盘（复合方位，圈）、触控输入
- 亮点：把「在地图上记一个点」做成通用模式——把相对(方位+距离)换算成世界坐标存表，再按当前船艏旋转回屏幕
- 关联：`06` §9（航路点）、`03` §5（PPI）、`00_速查 §4`（圈→弧度）

```lua
-- 按「鱼群标记」键且本次深度与上次不同 → 落一个新点
-- gpsx,gpsy = 自身世界坐标（GPS 复合）；tyaw = 罗盘方位(圈)*pi2；ba = 相对方位(圈)
if fish and (#T<=0 or tdepth ~= T[#T].z) then
  -- 相对偏移：距离 tdist 沿 (船艏+相对方位) 方向，sin/cos 直接吃弧度
  local x,y = gpsx + ms(tyaw+ba)*tdist, gpsy + mc(tyaw+ba)*tdist
  table.insert(T, {x=x, y=y, z=tdepth, sx=0, sy=0, sz=r*2+tdepth*scale, l=0})
end

-- 每 tick：按自身朝向 ba 把世界点旋转到「以船为中心的屏幕系」
local scb, ssb = scale*mc(ba), scale*ms(ba)
for i=#T,1,-1 do
  local dx, dy = T[i].x-gpsx, T[i].y-gpsy
  T[i].sx = r-1 + scb*dx + ssb*dy     -- 旋转矩阵：cos -sin / sin cos 的 2D 版
  T[i].sy = r   - scb*dy + ssb*dx
  T[i].l = T[i].l + 1
  if T[i].l >= life then table.remove(T,i) end   -- 寿命过期（life=1800 tick≈30s）
end
```

## §11 触控缩放控制器（闭包 capacitor / counter，比例步长）

- 来源：steam id 3794382107 · 描述页 https://steamcommunity.com/sharedfiles/filedetails/?id=3794382107 · 载具（DLI Mongoose，作者 Domagoj29）

- 亮点：缩放值用"比例步长" `zoom = zoom ± zoom*k`（而非固定步长），点一下微调、按住加速（counter 计时放大步长）；capacitor 做"松手后短暂显示缩放层"的单稳
- 关联：`04` §9（按比例缩放 `z=z±z/170`）、`05` §18（`cBtn` 闭包按钮）、`05` §27（同作者闭包组件）

```lua
local function clamp(value, min, max) return math.max(min, math.min(value, max)) end

-- ① 切换：上升沿翻转（自锁按钮）
local function createToggle()
  local oldVariable=false; local toggleVariable=false
  return function(variable)
    if variable and not oldVariable then toggleVariable=not toggleVariable end
    oldVariable=variable; return toggleVariable
  end
end
-- ② 单稳电容：charge 期间蓄满、松手后放电一段时间（做"松手仍显示 N 帧"）
local function createCapacitor()
  local oldCharge=false; local chargeCounter=0; local dischargeCounter=nil
  return function(charge,chargeTicks,dischargeTicks)
    if dischargeCounter==nil then dischargeCounter=dischargeTicks end
    if charge then chargeCounter=math.min(chargeCounter+1,chargeTicks)
    else chargeCounter=0 end
    if oldCharge and not charge then dischargeCounter=0 end
    if not charge and dischargeCounter<dischargeTicks then dischargeCounter=dischargeCounter+1 end
    oldCharge=charge
    return (dischargeCounter>0 and dischargeCounter<dischargeTicks) or (chargeCounter==chargeTicks and charge)
  end
end
-- ③ 计数器：按下加/减、可 reset、带 clamp（做连续可调数值）
local function createCounter(startValue)
  local counter=startValue
  return function(down, up, increment, min, max, reset)
    if down then counter=counter-increment end
    if up then counter=counter+increment end
    if reset then counter=0 end
    counter=clamp(counter,min,max); return counter
  end
end

-- 用法：缩放按钮 → 比例步长更新 zoom
local zoomingCapacitor=createCapacitor()
local zoomTimeCounter, zoomCounter = createCounter(1), createCounter(DefaultZoom)
function onTick()
  ...
  if ScreenMode=="Map" then
    local zoomDecrease = isPressed and touchRectF(...,Coords.Minus...)
    local zoomIncrease = isPressed and touchRectF(...,Coords.Plus...)
    local zooming = zoomDecrease or zoomIncrease
    DrawZoomOverlay = zoomingCapacitor(zooming, 0, 60)            -- 松手后还显示 60 tick
    local zoomTimeMultiplier = zoomTimeCounter(false, zooming, 0.1, 1, 3, not zooming)
    Zoom = zoomCounter(zoomIncrease, zoomDecrease,               -- 比例步长：当前值 × 系数
                        0.03*zoomTimeMultiplier*ZoomMultiplier, 0.1, 50, false)
  end
end
```

**要点速记**
- 🔑 **缩放用比例步长**：`Zoom = zoomCounter(inc, dec, 0.03*...*ZoomMultiplier, 0.1, 50)`，步长正比于当前 `Zoom`，点一下微调、按住时 `zoomTimeMultiplier` 从 1 涨到 3 让步长变大——**既不跳变又能快速拉远**。
- 🔑 **`createCapacitor` 单稳**：`chargeTicks` 蓄满、`dischargeTicks` 松手后还保持一阵，用来做"松手后缩放层再显示 60 tick 再淡出"，纯显示逻辑不占状态。
- 🔑 **三个闭包各管一件事**：toggle（自锁）/ capacitor（单稳）/ counter（连续可调），组合出"地图缩放 UI"只需要几行调用。

- 🔑 **`screenToMap` 的参数顺序极易记反**：`(本舰世界x, 本舰世界y, zoom, 屏宽, 屏高, 屏幕像素x, 屏幕像素y)` —— **先"地图中心在哪"，后"点第几列第几行"**。`mapToScreen` 完全同构，只是后两个参数换成目标世界坐标。记不住就想成「先给地图、再给点」。

- 🔑 **圈 → 弧度的 -90° 修正**：`math.cos(compass-0.5*math.pi)`。`compass` 是圈（0..1），`*2*pi` 后即 `-0.5*pi` 就是减 90°，让 0（北）指向屏幕上方（Y 轴负方向）。**漏掉这个修正会看到指针永远偏 90 度**（关联 `06` §9「指针转反了」的坑）。
- 🔑 **一个方块三种语义**：右上角 7×8 的方块在"未设点 + 自定义模式"下是设点键（显示 d + 屏幕中心准星），在"已设点"下是清点键（显示 c）。**用状态决定同一个控件的行为**，比堆一排按钮省屏面积，1×1 屏上尤其关键。
- 🔑 **单位自适应两段**：`>=1000` 切 km；`width==32`（1×1 屏）再省掉一位小数。小屏上 `12.3km` 会占掉近半个屏宽，`12k` 才放得下。
- ⚠ **本脚本的 `touchFlag` 从未被赋值**，`not touchFlag` 恒为真 → 按住不放会**每帧重复设点/清点**。这是原作品的真实缺陷，照抄时务必自己补一条 `touchFlag=isTouched`（或改用 `05` §31 的松手边沿）。**把它当反面教材记**：`if isTouched and not touchFlag` 这种写法，只要忘了在末尾写 `touchFlag=isTouched`，边沿检测就完全失效且不报错。

## §15 航线编辑器：**编辑游标 / 当前航段双指针** + 剩余航程累加 + 到达滞环 + 预设航线定点压缩

- 来源：steam id 3788103164 · 描述页 https://steamcommunity.com/sharedfiles/filedetails/?id=3788103164 · 载具（L176 Paveload，运输船※，`_vehicle_0` 航线管理微控制器）
- 更新时间：2026-08-23
- 用到：10 个布尔按钮（录入 / 删除 / 首 / 末 / 当前 / 设为当前 / 上 / 下 / 清空 / 载入）、到当前航段距离 `Dis`、两块微控制器之间的复合通道
- 亮点：**两个下标各管一件事**——`indx` 是「编辑游标」（人手操作），`act` 是「当前正在航行/飞行的航段」（自动驾驶推进）。解耦后「一边改航线一边跟着航段走」不会互相打断；另：**预设航线坐标除以 100 存整数**，一张表塞进几行
- 关联：`06` §4（另一套航路点管理器：增删选 + 平滑镜头）、`06` §12（航段使能门控 + 链式连线）、`09` §10（双阈值滞环）、`01` §3（大表搬进属性文本）、`00_速查 §6`（`#` 与空洞）

```lua
-- 🔑 预设航线：{航线号, {x1,x2,...}/100, {y1,y2,...}/100}   坐标除 100 存整数
sRTE={
  {8888,{80,80,-80,-80},{80,-80,-80,80}},
  {78,{-100,-220,-220,-270},{43,420,820,865}}

RTEx,RTEy={},{}
indx,act = 1,1        -- indx=编辑游标    act=当前航段
DTG = 0               -- 剩余航程
Lindx = 1             -- 预设航线选择游标

function onTick()
  inX,inY,Dis = inN(1),inN(2),inN(3)
  setA,first,last,curr = inB(1),inB(2),inB(3),inB(4)
  enter,delete = inB(5),inB(6)
  selUp,selDn,clr,load = inB(7),inB(8),inB(9),inB(10)

  if clr then RTEx,RTEy,indx,act,DTG = {},{},1,1,0 end

  -- 🔑 table.insert(T, 位置, 值) 是插入不是追加——「在游标处插一点」全靠它
  if enter and not loadMode then
    table.insert(RTEx,indx,inX or 0)
    table.insert(RTEy,indx,inY or 0)
    indx=indx+1
  elseif delete and RTEx[1]~=nil and not loadMode then
    table.remove(RTEx,indx)          -- 删游标所在的那一格
    table.remove(RTEy,indx)
  end

  if RTEx[1]~=nil then               -- ⚠ 判空用 T[1]~=nil，别用 #T>0（可能有空洞）
    if not loadMode then selX,selY = RTEx[indx],RTEy[indx] end
    actX,actY = RTEx[act],RTEy[act]

      if selDn and (indx-1)>0     then indx=indx-1 end
    end

    if #RTEx>1 then

      for i=act,#RTEx do
        if RTEx[i+1]~=nil then
          DTG=DTG+math.sqrt((RTEx[i+1]-RTEx[i])^2+(RTEy[i+1]-RTEy[i])^2)
        end
      end
    end
    opN(7,DTG or 0)

    -- 🔑 到达判定 + 滞环闩锁：进 0.5 就锁住，必须退出到 0.51 之外才解锁
    if Dis<0.5 and not block then
      act=act+1 block=true
    elseif Dis<0.5 and act>#RTEx then
      act=1
    end
    if RTEx[indx]==nil then output.setBool(1,true) else output.setBool(1,false) end
  end
  if Dis>0.51 then block=false end

  -- 载入模式：一个模式位把同一排按钮切成另一套语义
  if load then loadMode=true end
  if loadMode then
    output.setBool(2,true)

    selY = #sRTE[Lindx][2]         -- 屏上显示点数

    if selDn and Lindx>1       then Lindx=Lindx-1 end
  else
    output.setBool(2,false)
  end

  opN(1,selX or 0) opN(2,selY or 0) opN(3,indx) opN(4,act)
  opN(5,actX) opN(6,actY)
end
```

**为什么这样写**

- **双指针是刚需**：`act` 由自动驾驶闭环推进（到了就 +1），`indx` 由人手操作。若共用一个变量，你正在编辑第 5 个点时船正好抵达第 2 段，编辑游标会被顶走；反过来你在插入点的时候 `act` 也不该动。
- **插入 vs 追加**：`table.insert(T, pos, v)` 带位置参数时是**插入**（后面的元素整体后移），这正是「在第 n 个点前面插一个」要的；`table.remove(T, pos)` 同理删指定位置。
- **DTG 从 `act` 起算而不是从 1 起算**：剩余航程的定义就是「从当前航段到终点」。两个易错点：① 累加前必须 `DTG=0`，否则每帧叠加一次会指数增长；② 循环末尾的 `RTEx[i+1]~=nil` 判断不能省，否则最后一段会拿 `nil` 做减法。
- **到达判定的滞环**：`Dis` 是带噪声的量（GPS 抖动 + 船还在动）。只写 `if Dis<0.5 then act=act+1 end` 会在阈值附近每帧 +1，一瞬间把整条航线跑完。加 `block` 闩锁后：进圈锁住 → 必须退出到 `Dis>0.51` 才解锁（0.01 的回差，与 `09` §10 启动机的 2/2.5 RPS 双阈值同一套路）。
  - ⚠ 原文把「跑完归位」写成了 `elseif`，因此回到第 1 段需要 `Dis` **连续两帧**都 <0.5（第一帧 `act+1` 并上锁，第二帧才轮到 `elseif`）。实用上没问题，但别照着改成「只允许一帧」的写法，否则永远回不到第一段。
- **预设航线定点压缩**：世界坐标动辄六位（±1e5），直接写进表每个数 6 字符；除以 100 后每个数 3 字符，一条 4 点航线从 12 个长数变成 8 个短数，加载时 `v*100` 还原。代价是精度到 100 m——跨海航线够用，进港航线不够（那就改除 10，或干脆塞进属性文本，见 `01` §3）。
- **`loadMode` 一套面板两种语义**：10 个按钮已经把通道占满了，再给「载入预设」加 4 个专用键就爆。用一个模式位把 `enter/delete/上下` 复用成「确认 / 取消 / 换航线」，是纯 Lua 侧的做法，不需要存储器方块。
  - ⚠ **`loadMode` 是脚本变量，多人下两端各一份不同步**（`00_速查 §15`）。要联机一致，就把 `loadMode` 也从一个输出布尔回环读回来（模式类状态一律走回环，见 `02` §2）。

## §16 双点测距测方位：**第二触点当量角器** + `acos` 象限修正 + 控件区排除

- 来源：steam id 2948687255 · 描述页 https://steamcommunity.com/sharedfiles/filedetails/?id=2948687255 · 载具（26m V80 Superyacht 导航屏，`_vehicle_0` 同屏的第二段逻辑）
- 更新时间：2023-03-19
- 用到：两块触控屏（或一块屏的两组触点通道）、`map.screenToMap`
- 亮点：**用第二个触点做「量角器」**——第一点定起点、第二点定终点，屏幕上直接读出世界距离与方位；落点前先**排除右下角控件区**，按按钮时不会顺手在地上戳一个点
- 关联：`06` §14（点屏设航路点，同一个 `screenToMap`）、`05` §13（触控区优先级仲裁）、`03` §7.3（点在圆内设角度）、`08` §14（点选容差与挂起确认）

```lua
function Norm(x,y) return M.sqrt(x^2+y^2) end
function Button(x,y,rx,ry,rw,rh)
  return x>rx and y>ry and x<rx+rw and y<ry+rh
end

function onDraw()
  ...
  -- 🔑 控件区排除：右下角 45×35 是缩放/归位/摇杆区，落在这里的点不算测点
  if tp and not Button(tx,ty,w-45,h-35,45,35) then
    sC(0,100,100) dCF(tx,ty,2)
    p1x,p1y = map.screenToMap(x,y,z,w,h,tx,ty)      -- 屏幕像素 → 世界坐标
    dTx(3,19,sf("X:%.0f",p1x))
    dTx(3,25,sf("Y:%.0f",p1y))
  end

  -- 第二触点（同一块屏的第二组通道，或第二块屏）
  if tp2 and not Button(tx2,ty2,w-45,h-35,45,35) then
    sC(100,100,100) dCF(tx2,ty2,2)
    p2x,p2y = map.screenToMap(x,y,z,w,h,tx2,ty2)
    dTx(3,32,sf("X:%.0f",p2x))
    dTx(3,38,sf("Y:%.0f",p2y))
    dL(tx,ty,tx2,ty2)                                -- 两点连线
    dTx(3,45,"Distance:")
    dTx(3,51,sf("%.0fm",Norm(p1x-p2x,p1y-p2y)))      -- 🔑 距离用世界坐标算，不是像素
    dTx(3,58,"Bearing:")
    -- 🔑 acos 值域只有 0..π，下半平面会被镜像，必须按 dx 的符号补回来
    A = M.acos((ty-ty2)/Norm(tx-tx2,ty-ty2))
    if tx>tx2 then A = 2*M.pi - A end
    dTx(3,64,sf("%.1f",M.deg(A)))
  end
end
```

**为什么这样写**

- **两个触点 = 两组独立通道**：`input.getNumber(3/4)` + `getBool(1)` 是第一点，`(5/6)` + `getBool(2)` 是第二点。同一块触控屏也能同时报两组；两块屏就各接一组。
- **距离必须用世界坐标算**：两点都过一遍 `map.screenToMap` 拿到世界坐标再求 `Norm`，这样**缩放、平移都不影响读数**。千万别用像素差乘一个换算系数——那要自己维护标定，缩放一变就错（对照 `06` §10「记点存世界坐标」的同一个道理）。
- **`acos` 的象限坑**：`acos` 值域 0..π，算出的方位在下半平面会被镜像到上半平面。原文用 `if tx>tx2 then A=2π-A` 补回。更稳的写法是直接用 **`math.atan(dx, dy)`（SW 的 `atan` 是两参版）**，一行出完整 0..2π，不用手动补象限（见 `00_速查 §4`）。
- ⚠ **原文的方位是屏幕坐标系的方位**（`tx/ty` 是像素差），不是世界方位。地图「北朝上」时两者一致；若屏支持旋转或做成船艏朝上，就必须再叠加一个航向修正（`- compass` 那一项）。
- **控件区排除的两种做法**：本例是「落在控件区内就不当测点」（**后验排除**）；另一种是先判控件、命中就 `return`（**先验仲裁**，见 `05` §13 的 `touched` 标志）。
  - 后验排除的隐患：按钮的「按下」与「落点」会在同一帧同时成立。如果某个按钮回调依赖「这一帧没有落点」，就会出错。要严格就改先验仲裁。

## §17 航点**队列**模型：投影法过点检测（`pass`）+ **修订号**广播（与 §15 的指针模型对比）

- 来源：steam id 3795317652 · 描述页 https://steamcommunity.com/sharedfiles/filedetails/?id=3795317652 · 载具（Sleipnir 6x6 01A1，`_vehicle_3` VEGVISIR 地图模块）
- 更新时间：2026-09-04
- 用到：GPS（东/北）、罗盘（圈）、触控屏、属性滑块（`Waypoint Radius` / `Pass Waypoint Detection` / `Default Zoom Level`）
- 亮点：**航线当 FIFO 队列消费**（到达首个点就整体前移），而不是 §15 的「`act` 指针推进」；过点判定用**投影 + 横向偏移**而非纯半径，高速通过不会漏触发；**每次航线变更让 `rev` +1 并广播**，下游 MC 靠版本号判断「航线被改过」
- 关联：`06` §15（另一种模型：`indx`/`act` 双指针）、`06` §12（航段使能门控）、`07` §8（状态型数据周期重发）、`09` §10（滞环）

```lua
local rad = math.max(1, property.getNumber("Waypoint Radius"))   -- 到达半径(m)
local pass= property.getBool("Pass Waypoint Detection")          -- 允许「路过」判定
local z   = {.8,1.2,1.8,3,5,7.5,10,15,20}                       -- 🔑 离散缩放档位表
local zl  = math.max(1, math.min(#z, zl))                        -- 只改下标，不连续插值
local maxwp = 10
local we,wn = {},{}     -- 航路点东/北坐标（平行数组，不是二维数组）
local wc = 0            -- 当前点数
local rev, near = 0, false
local function rv() rev=(rev+1)%4096 end     -- 🔑 修订号：每次航线变更 +1

-- 队列消费：删掉队首，后面整体前移
local function drop1()
  if wc<1 then return end
  for i=1,wc-1 do we[i],wn[i] = we[i+1],wn[i+1] end
  we[wc],wn[wc] = nil,nil
  wc = wc-1
  near=false
  rv()
end

local function add()                          -- 在队尾追加
  if ssel and wc<maxwp then
    wc=wc+1 we[wc],wn[wc]=se,sn rv()
  end
end

local function del()                          -- 删队尾
  if wc>0 then we[wc],wn[wc]=nil,nil wc=wc-1 if wc==0 then near=false end rv() end
end

local function route()
  if wc<1 then return end
  local x,y = e-we[1], n-wn[1]                -- 自机 → 队首点的向量
  local d   = math.sqrt(x*x+y*y)
  local ar  = rad*2.5                         -- 过点判定的「走廊半宽」= 到达半径的 2.5 倍
  if d<=ar then near=true end                 -- 进入邻域：置位，供 pass 分支用
  if d<=rad then drop1() return end           -- 真的到了：出队
  if pass and wc>1 and near then
    -- 🔑 投影法：把「自机−队首」投影到「队首→队次」的方向上
    local vx,vy = we[2]-we[1], wn[2]-wn[1]
    local l = math.sqrt(vx*vx+vy*vy)
    if l>.001 then
      vx,vy = vx/l, vy/l                      -- 单位方向向量
      local f    = x*vx + y*vy                -- 纵向投影：>0 表示已经越过队首点
      local side = math.abs(x*vy - y*vx)      -- 横向偏移：叉积的模
      if f>0 and side<=ar then drop1() end    -- 越过了 且 没偏离走廊 → 出队
    end
  end
end

local function nav()
  local ok = wc>0
  local r,d,x,y = 0,0,0,0
  if ok then
    x,y = we[1],wn[1]
    local de,dn = x-e, y-n
    d = math.sqrt(de*de+dn*dn)
    r = wh(w01(a2(de,dn)/pi2) - w01(-c))      -- 圈最短角差，见 04 §1.2b 写法③
  end
  output.setBool(1, ok)
  output.setNumber(1,r) output.setNumber(2,d)
  output.setNumber(3,x) output.setNumber(4,y)
  output.setNumber(5,wc) output.setNumber(7,rev)  -- 🔑 rev 走一个通道广播出去
end
```

**为什么这样写**

- **队列模型 vs 指针模型（§15）**：

  | | 队列消费（本例） | 指针推进（§15） |
  | --- | --- | --- |
  | 状态 | 只有「队首」是目标，`wc` 是长度 | `act` 下标 + 完整历史保留 |
  | 跑完 | 队列空了，`wc==0` | `act` 归 1，可循环跑 |
  | 回看/回退 | **做不到**（点已删除） | 可以（改 `act` 即可） |
  | 剩余航程 | 要每次遍历累加 | 同样累加（§15 的 DTG） |
  | 适合 | 一次性送贷/巡逻航线 | 可循环的作业航线 |

- **投影法过点为什么更稳**：纯半径判定（`d<=rad`）在**高速**时会出问题——一 tick 走 30 m、半径 20 m，可能两帧都在圈外直接穿过去，永远触发不了。投影法把判据换成「**是否越过了队首点所在的横截面**」：
  - `f = x·v > 0` → 自机已经在队首点的前方（朝下一段的方向）；
  - `side = |x × v| <= ar` → 且没有偏离航线走廊太远（防止绕远路时误触发）。
  - 两个条件合起来对速度不敏感，`pass` 属性让玩家可以关掉（例如需要精确停点时就该关）。
- **`rev` 修订号是「跨 MC 同步」的低成本方案**：下游拿到 `rev` 变了，就知道航线被改过、该重画/重算了——不必把整张表逐条比对，也不必像 `03` §19 那样每 tick 轮询搬表。代价是 `rev` 只有 4096 个值（`%4096`），下游必须**只比较「变没变」而不比较大小**（否则回绕时判断错）。
- **缩放用离散档位表 `z={...}`**：按钮只改下标 `zl`，档位是作者挑好的整齐值。对比 `04` §9.1 的连续对数缩放——离散档位**手感更可预期**（每档固定），连续缩放**更自由**；做导航屏推荐离散档。
- ⚠ `route()` 里没有滞环：`d<=rad` 判定后立刻 `drop1()` 出队，队首立刻变成下一个点，不存在「在阈值附近反复触发」的问题——**这是队列模型相对指针模型的一个天然优势**（§15 需要 `block` 闩锁是因为 `act` 会连续 +1）。
- **平行数组 `we`/`wn` 而不是 `{{x,y},...}`**：省字符、遍历快；代价是插入/删除要同步操作两个表，容易漏。本例 `drop1` 的 `we[wc],wn[wc]=nil,nil` 就是同步清尾，**千万别漏了清尾**——不清的话 `#we` 不减，队列会「越跑越长」。

## §18 自驾航向指令链：`atan(dx,dy)` → 圈 → 折差 → ×2 转向 + **幂函数缩放** + 用「值变化」做边沿

- 来源：steam id 3794992381 · 描述页 https://steamcommunity.com/sharedfiles/filedetails/?id=3794992381 · 载具（BlackHawk，`_vehicle_13` 自动驾驶 + 航路点地图）
- 更新时间：2026-09-03
- 用到：GPS、罗盘（圈）、到目标的距离、属性滑块（`ap_distance` 到达判定）
- 亮点：完整给出「**世界坐标差 → 转向指令**」这一条最常见的链路，并把转向量映射到 ±1 的执行器行程；顺带两个小手法——**幂函数缩放** `zoo^zoom`、用**数值通道的值变化**代替布尔脉冲做边沿检测
- 关联：`06` §1（三轴姿态 PID 自驾）、`04` §1.2b（折差的三种写法）、`04` §9.1（另两套缩放写法）、`05` §34（同一脚本的连线内缩）

```lua
zoo, zoom = 5, -1.431          -- 🔑 缩放 = 底数 ^ 指数（第三套写法）
local pi2 = math.pi*2
local AutoP = false
local BAP,BAP2 = false,false   -- 「开」按钮的当前值 / 上一帧

function onTick()
  tX,tY = i.getNumber(3), i.getNumber(4)
  gpsx,gpsy = i.getNumber(6), i.getNumber(7)
  Comp = (i.getNumber(8)+1.5)%1          -- 罗盘(圈)，+1.5 是作者的传感器安装方向修正
  BAP  = i.getBool(31) and not BAP2      -- 边沿：这一帧刚按下
  BAP2 = i.getBool(31)
  SAP  = i.getBool(32)                   -- 「强制关」按钮（电平，不是边沿）

  -- 🔑 用「数值通道的值变了」代替布尔脉冲：上游发来新航路点才录入
  local nx,ny = i.getNumber(10), i.getNumber(11)
  if nx ~= lastx and nx ~= 0 and ny ~= lasty and ny ~= 0 then
    AWP(nx,ny)                            -- 追加航路点
    lastx,lasty = nx,ny
  end

  if BAP then AutoP = not AutoP end       -- 按一下切换
  if SAP and AutoP then AutoP = false end -- 🔑 强制关：优先级高于开

  if #TX ~= 0 and AutoP then
    local disx,disy = gpsx-TX[1], gpsy-TY[1]
    o.setNumber(3,disx) o.setNumber(4,disy)
    local mid  = math.atan(disx,disy)     -- 🔑 两参 atan：直接得到 -pi..pi 的绝对方位
    local bear = ((1-Comp)%1)*360
    local steer = (((Comp+mid/pi2)%1 + 1.5)%1 - 0.5)*2   -- 折到 ±0.5 后 ×2 → ±1
    local forward = math.cos(0.5*pi2)*-1                 -- 恒等于 1（cos(pi)*-1）
    o.setNumber(1,forward) o.setNumber(2,steer) o.setBool(1,true)
    -- 到达判定：两轴差绝对值都小于阈值才删点
    if math.abs(math.floor(disx-disy)) <= property.getNumber("ap_distance") then
      RWP(1)
    end
  else
    o.setNumber(1,0) o.setNumber(2,0) o.setBool(1,false)
  end

  cal = 5/(zoo^zoom)                      -- 像素标定：随缩放变化（见 05 §34）
  if cal > 5 then cal = 5 end
end
```

**为什么这样写**

- **指令链拆成四步**，任何一步都可以单独替换：
  1. `math.atan(disx, disy)` → **绝对方位（弧度）**；
  2. `/pi2` → 转成**圈**（与罗盘同单位，才能相加相减）；
  3. `((x%1+1.5)%1-0.5)` → **折到 ±0.5**（最短角差，见 `04` §1.2b）；
  4. `*2` → 映射到 **±1**，正好是 SW 转轴/舵面的行程区间。
- ⚠ **`Comp` 的零位与方向必须自己验**：原文的 `(raw+1.5)%1` 是作者罗盘传感器的安装方向修正（转半圈），`bear` 又用了 `1-Comp`（反向）。**照抄一定不对**。验证方法：把载具摆在目标正东方，看 `steer` 是不是该往左打——不对就把 `Comp` 取 `-Comp` 或 `(Comp+0.5)%1`，别改后面三步。
- **用「值变化」代替布尔脉冲**：上游 MC 只发了两个数值通道（新航路点 X/Y），没有专门的「写入」布尔。本例用 `nx ~= lastx and nx ~= 0` 判断「来了新值」。
  - 适用前提：上游不会重复发同一个值（否则只触发一次）。`~= 0` 是防未接线时的 0 被当成有效点。
  - 代价：如果连续录入**同一个**坐标（合法需求），第二次不会触发。真要支持就还是得走布尔脉冲通道。
- **「开」+「强制关」双按钮**：`BAP` 用边沿做切换，`SAP` 用电平做强制关且**写在 `if BAP` 之后**，所以同一帧两个都按下时「关」胜出。这个「后写的覆盖先写的」优先级约定在工坊代码里很常见（对照 `02` §9 腿式步态的「后写覆盖动作」）。
- **幂函数缩放 `zoo^zoom`**：底数固定（5）、指数可变，是除「`z±z/170`」（`04` §9）与「`exp(Z)`」（`04` §9.1）之外的第三套。好处是**档位天然等比**且只需调一个变量；坏处是 `zoom` 的绝对值没有直观含义（不像 `z` 直接是倍率）。
- ⚠ **到达判定写错了**：`math.abs(math.floor(disx-disy))` 判的是「两轴差之差」，不是「距离」。正确写法是两轴差的**平方和开方**（或至少 `abs(disx)+abs(disy)` 的曼哈顿距离）。**这是反面教材，别照抄**——它会让「正东北方向、两轴差相等」的任意远点都被判成已到达。
- 完整脚本：`../../../AI相关/_提取暂存/_r7c/3794992381_vehicle_13.lua`


## §19 FMS 航点 CRUD：**插入到选中项之后** + DIRECT 提到队首 + 26 路并行输出

- 来源：steam id 3794758528（飞行管理系统 FMS，载具，2026-09-01）
- 用到：GPS、触控屏、5 个物理按钮（添加/删除/复位/直飞/选择）、32 路复合输出
- 亮点：把「平行数组 + 选中下标」这套最小结构用满——增、删、改序、自动出队全都靠
  `table.insert` / `table.remove` 两个函数完成，没有任何自写链表
- 区别于 `06` §15（航线编辑器：编辑游标 / 当前航段双指针，适合**边飞边改**）与
  §17（航点队列：投影法过点 + 修订号广播，适合**单向流水**）：
  本节是**可编辑的队列**，允许在任意位置插入、把任意一项提到队首

### 数据模型：两条平行数组 + 一个选中下标

```lua
Xtable = Xtable or {}        -- 航点 X（世界坐标）
Ytable = Ytable or {}        -- 航点 Y
wptselected = input.getNumber(13)   -- 由另一块微控制器（FMS 选择页）给进来的 1-based 下标
```

`Xtable or {}` 这种写法让脚本**重新加载时不丢数据**（Lua 脚本方块重载会清空全局），
是工坊里常见的续命技巧；多人联机时不成立，见 `01` §5。

### 增：插入到选中项之后，未选中则追加

```lua
if add and not lastAdd then
  if wptselected > 0 and wptselected <= #Xtable then
    local idx = wptselected + 1
    table.insert(Xtable, idx, Xtarget)
    table.insert(Ytable, idx, Ytarget)
  else
    table.insert(Xtable, Xtarget)
    table.insert(Ytable, Ytarget)
  end
end
```

`table.insert(t, pos, v)` 在 `pos` **之前**插入，所以「插到第 n 个之后」= `pos = n+1`。

### 删：选中则删选中，否则删末尾（最后一个则直接清空）

```lua
if remove and not lastRemove then
  if wptselected > 0 and wptselected <= #Xtable then
    table.remove(Xtable, wptselected)
    table.remove(Ytable, wptselected)
    output.setNumber(1, #Xtable)
  elseif #Xtable <= 1 then
    Xtable, Ytable = {}, {}
    output.setNumber(1, 0)
  else
    table.remove(Xtable)                 -- 省略 pos 即删末尾
    table.remove(Ytable)
    output.setNumber(1, #Xtable)
  end
end
```

`output.setNumber(1, #Xtable)` 每次都**主动广播数量**，让下游（航线绘制屏）知道表变了。

### 改序：DIRECT 直飞 = 把选中项搬到队首

```lua
if directPressed and not lastDirect and wptselected > 0 then
  if wptselected ~= 1 then
    local x, y = Xtable[wptselected], Ytable[wptselected]
    table.remove(Xtable, wptselected)
    table.remove(Ytable, wptselected)
    table.insert(Xtable, 1, x)
    table.insert(Ytable, 1, y)
  end
end
```

**先取值、再删、再插**——顺序不能颠倒，`table.remove` 之后下标就失效了。
这正是"平行数组 + `table.*`"最容易出错的地方：两条表必须**成对、同序**操作，
任何一次只对一条表做 `insert`/`remove` 都会让 X/Y 错位。

### 自动出队：接近首点就删掉它

```lua
if #Xtable > 0 then
  local dx, dy = Xtable[1] - Xpos, Ytable[1] - Ypos
  local distToFirst = math.sqrt(dx*dx + dy*dy)
  if distToFirst <= nextwpt then                    -- nextwpt = 属性「Next WPT Treshhold(m)」
    if #Xtable <= 1 then
      Xtable, Ytable = {}, {}
      output.setNumber(1, 0)
    else
      table.remove(Xtable, 1)
      table.remove(Ytable, 1)
    end
  end
end
```

⚠ 出队**没有滞环**：恰好在阈值附近抖动时，会先删掉首点、然后下一目标是"刚才的第二点"，
不会来回加删（因为只出不进），所以安全。但若你加了"过点自动重插"逻辑，
就必须配 `06` §15 的到达滞环，否则会反复增删。

### 26 路并行输出：把队列摊平成通道

```lua
maxOutputs = 26        -- 脚本方块的数字输出上限

for i = 1, #Xtable do
  local X1F, Y1F
  if i == 1 then
    X1F = Xtable[i] - Xpos          -- 第 1 个点输出**相对自机**的坐标（给自驾用）
    Y1F = Ytable[i] - Ypos
  else
    X1F = Xtable[i] - Xtable[i-1]   -- 其余输出**相对上一点**（给航线绘制用）
    Y1F = Ytable[i] - Ytable[i-1]
  end
  ...                                -- 写入 output.setNumber(5 + (i-1)*2) 之类
end
```

两种编码各有用途：
- **相对自机**：自驾直接拿去算 `atan(dx,dy)`，不需要再减一次。
- **相对上一点**：绘制折线时从当前点累加即可，**整条航线随自机平移时只需更新第 1 段**，
  后续段不变，省去每帧重算（对比 `06` §12 的链式连线）。

超过 13 个航点就装不下 26 路（每点 2 通道），本例靠 `maxOutputs` 硬截断。
要支持更长航线，改用 `07` 的**轮询广播**（一次发几个点，配状态位）。

### 边沿检测的三个 `last*`

```lua
lastAdd, lastRemove, lastDirect = lastAdd or false, lastRemove or false, lastDirect or false
...
lastAdd = add
lastRemove = remove
lastDirect = directPressed
```

每个物理按钮都要一个 `last` 变量——**不要**共用一个，否则同时按下时会互相吞边沿
（见 `02` §1）。写成数组 `last = {}` 可以省字符：
`if add and not last[1] then ... end; last[1] = add`。

## §20 地图镜头：**指数平滑跟随 + 比例缩放** + 网格**步长跳档表** + 负步长画横线

- 来源：steam id 3794217539（战术地图显示器，载具，2026-08-31）
- 用到：GPS、罗盘、高度计、触控屏、6 组 `setMapColor*`
- 亮点：镜头不瞬移也不匀速，而是每帧朝目标推进 5%；网格步长用**查表跳档**而不是公式
- 区别于 `06` §4（三分区触控 / 缩放分级 / 平滑镜头）与 §11（闭包计步的比例步长）：
  本节给出**最简单的 4 行平滑镜头**与**可读性最好的跳档表**，适合字符预算紧张时抄

### 手法一：朝目标推进固定百分比（指数平滑）

```lua
if focusZone then
  if pressed and inputX > 6 then                                  -- 点选新目标点
    tx, ty = map.screenToMap(mx, my, zoom, rx, ry, inputX, inputY)
  end
  cx, cy = map.screenToMap(mx, my, zoom, rx, ry, rx/2, ry/2)      -- 当前屏幕中心的世界坐标
  mx = cx + (tx - cx) * 0.05                                      -- 每帧走完剩余差距的 5%
  my = cy + (ty - cy) * 0.05
else
  mx, my = gpsx, gpsy                                             -- 未聚焦时跟随自机
end
```

三个关键点：
1. **先求「当前中心」再插值**：`cx,cy` 用的是 `screenToMap(..., rx/2, ry/2)`，
   即屏幕正中那个像素对应的世界坐标。这样即使 `mx,my` 因为缩放而变化，
   插值基准也始终是当前真实中心。
2. `0.05` 是**比例**而非绝对距离 —— 离得远走得快、离得近走得慢，天然带缓动，
   且不会出现"永远逼近不到位"的可见残留（60 tick/s 下 1 秒内走完 95%）。
3. ⚠ **首帧 `tx/ty` 是 `nil`**：没点过屏幕时 `mx = cx + (nil-cx)*0.05` 直接报错。
   本例靠 `focusZone` 只在点击后才置真来规避（见下），但保险起见应初始化 `tx,ty = gpsx,gpsy`。

`focusZone` 的切换逻辑：

```lua
reset = isPressed and iPIR(inputX, inputY, 0, ry/5*3, 6, ry/5)   -- 左侧第三个按钮：复位
if reset then focusZone, zoom, grid = false, 1.5, 250 end
if isPressed and inputX > 6 then focusZone = true end             -- 点左侧按钮区之外 → 自由查看
```

左侧 6 px 宽是三个竖排按钮区（`ry/5`、`ry/5*2`、`ry/5*3`），
`inputX > 6` 一句就把"点在地图内容区"和"点在按钮上"分开——比逐个按钮取反更省字符
（对比 `05` §13 的 `touched` 仲裁：本例是先验分区，§13 是后验仲裁）。

### 手法二：按比例的缩放（`zoom = zoom * 0.98`）

```lua
if zoomingIn and zoom > 0.1 then
  zoomScale = zoom + zoom                    -- = 2*zoom
  zoom = zoom - zoomScale/100                -- = zoom*0.98
end
if zoomingOut and zoom < 50 then
  zoomScale = zoom + zoom
  zoom = zoom + zoomScale/100                -- = zoom*1.02
end
```

每 tick 变化 2%：低倍（zoom=0.2）时一格只走 0.004，高倍（zoom=20）时走 0.4。
**这就是"缩放高倍跳太快、低倍几乎不动"的通用解**（`04` §9 写成 `z ± z/170`，本例是 `z ± z/50`，
只是倍率不同）。`zoomScale` 变量纯粹是为了可读性，等价于 `zoom = zoom*0.98`。

### 手法三：网格步长跳档（查表 vs 公式）

```lua
if zoom > 0  and zoom < 0.2 then grid = 25   end
if zoom > 0.2 and zoom < 0.5 then grid = 50  end
if zoom > 0.5 and zoom < 1   then grid = 100 end
if zoom > 1  and zoom < 2   then grid = 250  end
if zoom > 2  and zoom < 5   then grid = 500  end
if zoom > 5  and zoom < 10  then grid = 1000 end
if zoom > 10 and zoom < 20  then grid = 2000 end
if zoom > 20 and zoom < 40  then grid = 4000 end
if zoom > 40                then grid = 8000 end
```

| | 本例查表 | `06` §8 公式 `2^floor(log2(zoom/k))` |
| --- | --- | --- |
| 字符 | 9 行 × 约 45 字符 ≈ 400 | 1 行 |
| 档位 | 可任意指定（25/50/100/250…） | 只能是 2 的幂 |
| 漏档风险 | 有：`zoom == 0.2` 恰好时**两个条件都不成立**，`grid` 保持上帧值 | 无（全覆盖） |

⚠ 实测漏档：边界用 `>` 与 `<` 双向开区间，`zoom` 正好等于 0.2 / 0.5 / 1 / 2 …时
**没有任何分支命中**，`grid` 沿用上一帧的值（不会崩，但档位滞后一档）。
改成 `>=` 即可；`06` §15 的同类坑见 README 坑表。抄的时候优先用公式版。

### 手法四：网格线画法（含 y 轴方向陷阱）

```lua
x1, y1 = map.screenToMap(mx, my+alt, zoom, w, h, 0, 0)      -- 左上角
x2, y2 = map.screenToMap(mx, my+alt, zoom, w, h, w, h)      -- 右下角
x1 = math.floor(x1/grid) * grid                             -- 原点吸附到 grid 整数倍
y1 = math.floor(y1/grid) * grid

for xx = x1, x2, grid do                                     -- 竖线：世界 x 递增
  x, y = map.mapToScreen(mx, my+alt, zoom, w, h, xx, y1)
  screen.drawLine(x, 0, x, h)
end
for yy = y1, y2, -grid do                                    -- 🔑 横线：世界 y 递增 → 步长取负
  x, y = map.mapToScreen(mx, my+alt, zoom, w, h, x1, yy)
  screen.drawLine(0, y, w, y)
end
```

- 🔑 **`for yy = y1, y2, -grid` 的负步长不是笔误**：世界坐标 y 向**北**增大，
  而屏幕 y 向**下**增大；左上角（屏幕 y=0）对应的世界 y 比右下角**大**。
  所以从 `y1` 走到 `y2` 必须递减。写成正步长会一次都不执行。
- 只遍历屏幕四角覆盖的世界范围，天然做完了视口裁剪；配合原点吸附
  （`floor(v/grid)*grid`，等价 `04` §9.1 的 `Ox - fmod(Ox,u)`），
  网格线**钉在世界整 25/50/100 米上**，镜头移动时网格不会跟着漂。

### 手法五：高度视差补偿

```lua
alt = input.getNumber(13)
if alt < 0 then alt = 0 end
...
```

## §21 地图**标图台账**：世界坐标存储 + 每帧重投影 + 删除时**批量修正索引引用**

- 来源：steam id **3793573510**
- 描述页：<https://steamcommunity.com/sharedfiles/filedetails/?id=3793573510>
- 类型：载具 · 更新时间：**未取到**（本轮 Steam Web API 不可达，下轮补）

在地图上标友军 / 目标 / 航路点，最直觉的做法是「点哪儿就把屏幕像素存哪儿」。但只要镜头一平移、缩放一变，标记就全跑位。这一节的做法是：**表里只存世界（GPS）坐标，屏幕坐标每帧由 `mapToScreen` 重算**，两者都缓存在同一个对象里，命中判定用像素、距离计算用米。

**用到**：地图屏（GPS 中心、缩放档位）、触控屏、属性（比例 Scalar）、数字输出（航向 / 距离）

**亮点**：① `wXY` / `pXY` 一对互逆函数（点屏建标走 `screenToMap`，绘制走 `mapToScreen`）；② 每个单位同时存 `pos`（世界）与 `p1..p5`（屏幕），两套坐标各司其职；③ **`kill` 删除元素后批量修正所有引用它的索引**；④ `dis(u1, u2, pix)` 一个函数给两种口径；⑤ 缩放用**档位表**而不是连续插值。

```lua
-- ① 互逆投影：wXY 从屏幕建标，pXY 每帧把世界坐标投回屏幕
function wXY(u) u.pos.x, u.pos.y = map.screenToMap(gps.x, gps.y, zoom[z], w, h, u.p1.x, u.p1.y) end
function pXY(u) u.p1.x, u.p1.y = map.mapToScreen(gps.x, gps.y, zoom[z], w, h, u.pos.x, u.pos.y) end
```

```lua
-- ② 删除第 n 个标（name 是 0 起的编号，units 是 1 起的数组 → 差 1）
function kill(n)
  for i = 1, #units do
    local u = units[i]
    if     u.link == n  then u.link = -1        -- 指向被删项的：断开
    elseif u.link >  n  then u.link = u.link-1  -- 指向其后的：整体前移一位
    end
  end
  table.remove(units, n+1)
end
function link(u1, u2) units[u1+1].link = u2 end  -- link 存的是 name（0 起）
```

```lua
-- ③ 距离双口径：pix==1 用屏幕像素（命中 / 绘制），否则用世界米（导航）
function dis(u1, u2, pix)
  local p1, p2 = u1.pos, u2.pos
  if pix == 1 then p1, p2 = u1.p1, u2.p2 end
  return ((p2.x-p1.x)^2 + (p2.y-p1.y)^2)^(1/2)
end
-- ④ 屏幕方位：atan 两参直接给「从 +Y 轴起算、向 +X 为正」，省掉象限特判
function brg(u1, u2) return math.atan(u1.p1.x-u2.p1.x, u2.p1.y-u1.p1.y)*180/math.pi + 180 end
```

- 🔑 **索引引用的三个必查项**：① 指向被删项置 −1（本例 `u.link == n`）；② 指向其后的整体 −1（本例 `u.link > n`）；③ **被删项自己不能留在表里**。漏掉 ② 是最常见的——删完前几个还正常，删到中间才开始串行引用。
- ⚠ **0 起 / 1 起混用**：`u.name` 是 0 起的编号、`units` 是 1 起的 Lua 数组，所以 `kill` 里要 `table.remove(units, n+1)`、`link` 里要 `units[u1+1]`。**建议统一成 1 起**（`u.name = #units+1`），可以省掉所有 ±1。
- ⚠ `brg` 末尾的 `+180` 不是必需的：它把方位零点挪到了下方以匹配该作品的绘制方向。**按自己的绘制约定决定要不要加**；直接用 `math.atan(dx, dy)` 就是「+Y 为 0、向 +X 递增」。
- 🔑 **缩放用档位表 `zoom = {2,10,20,40,50}`**：只改索引不插值，非整数缩放会让地图瓦片在相邻档位间抖动。`06` §20 的网格步长跳档表是同一思路。
- ⚠ **`pXY` 必须每帧全量重算**：只在建标时算一次的话，镜头一动标记就错位。单位多时这是 O(n) 的每帧开销，n 上百要考虑只重算视口内的。

## §23 直升机**四轴共模**增稳：一个公式模板 + 八路多重赋值 + 欧拉矩阵解三轴倾角

- 来源：steam id **3765180788** · 描述页 <https://steamcommunity.com/sharedfiles/filedetails/?id=3765180788> · **载具**（Shahed Drone，`_vehicle_1` 飞控）

- 亮点：与 `06` §1（三轴 PID 自动驾驶仪）不同，本节是**增稳（SAS）**——而且横滚与俯仰**共用一个公式**，差异全部塞进 `local x,y,z,w,a,b,c,d = ...` 这一行八路多重赋值里。改增益只改一处，省下的字符比逐轴写四份多得多。

**① `physconvert`：欧拉矩阵一次性解出倾角与机体系角速度**

```lua
function physconvert()
  x, y, z = input.getNumber(4), input.getNumber(5), input.getNumber(6)   -- 欧拉角（弧度）
  cx, sx = m.cos(x), m.sin(x)
  cy, sy = m.cos(y), m.sin(y)
  cz, sz = m.cos(z), m.sin(z)
  m00 = cy*cz
  m01 = -cx*sz + sx*sy*cz
  m02 =  sx*sz + cx*sy*cz
  m10 = cy*sz
  m11 =  cx*cz + sx*sy*sz
  m12 = -sx*cz + cx*sy*sz
  m20 = -sy
  m21 =  sx*cy
  m22 =  cx*cy

  -- 🔑 三轴倾角：用 atan(分量, sqrt(另两分量平方和))，避开 asin 在 ±90° 的奇点
  tilt_x = m.atan(m10, m.sqrt(m00*m00 + m20*m20)) / pi2     -- /2π 转成「圈」
  tilt_y = m.atan(m11, m.sqrt(m01*m01 + m21*m21)) / pi2
  tilt_z = m.atan(m12, m.sqrt(m02*m02 + m22*m22)) / pi2

  -- 🔑 角速度换基：矩阵的三列分别点乘世界角速度（等价于 R^T * w）
  angular_x = m00*ax + m10*ay + m20*az
  angular_y = m01*ax + m11*ay + m21*az
  angular_z = m02*ax + m12*ay + m22*az

  old_altitude = altitude
  altitude     = input.getNumber(2)
  v_speed      = (altitude - old_altitude) * 60             -- m/tick → m/s
end
```

**② 四轴共用一个公式模板**

```lua
function roll(...)
  local x,y,z,w,a,b,c,d = Roll_Seat, Right_SPD, old_Right_SPD, Left_Tilt,
                          Z_Ang_SPD, Roll_Gain, nil, autohover_num
  return clamp(b/100*((1+d/5)*x - d*clamp(y/5+2*(y-z), -(1+x)/5, (1+x)/5)
                      - d*(2*pi2*w - (pi2*w)^3/3) - pi2*-a), -1, 1)
end

function pitch(...)   -- 与 roll() 逐字相同，只多一个系数 2
  local x,y,z,w,a,b,c,d = Pitch_Seat, Front_SPD, old_Front_SPD, Back_Tilt,
                          X_Ang_SPD, Pitch_Gain, nil, autohover_num
  return clamp(2*b/100*((1+d/5)*x - d*clamp(y/5+2*(y-z), -(1+x)/5, (1+x)/5)
                        - d*(2*pi2*w - (pi2*w)^3/3) - pi2*-a), -1, 1)
end

function yaw(...)
  local x,y,z,w,a,b,c,d = Yaw_Seat, nil, nil, nil, Y_Ang_SPD, Yaw_Gain, nil, autohover_num
  return clamp(b/100*(2*x - pi2*a), -1, 1)                  -- 只有输入 + 角速度阻尼
end
```

- 🔑 **模板里四个项的含义**（`b` 是增益、`d` 是增稳强度权重）：
  1. `(1+d/5)*x` —— 操纵输入，`d` 越大输入被放得越狠；
  2. `d*clamp(y/5 + 2*(y-z), ...)` —— **速度阻尼 + 加速度阻尼**，`y/5` 压稳态速度、`2*(y-z)` 压速度变化，限幅随输入量 `x` 自适应；
  3. `d*(2*pi2*w - (pi2*w)^3/3)` —— **姿态回中**（增稳的核心），`w` 是倾角（圈），`pi2*w` 转弧度后走三阶泰勒；
  4. `-pi2*-a` 即 `+pi2*a` —— **角速度阻尼**，`a` 是机体系角速度（圈/tick），`×2π` 转弧度。
- 🔑 **倾角用 `atan(分量, sqrt(...))` 而不是 `asin`**：`asin` 在俯仰接近 ±90° 时会失去符号、且常伴随 `cos(pitch)→0` 的除零（对比 `03` §27 的反面教材）。这里分母是两个分量的平方和，只有三轴同时逼近奇异姿态才退化。
- 🔑 **八路多重赋值是字数压缩的关键**：`local x,y,z,w,a,b,c,d = ...` 一行把八个量接成统一形参，函数体就只剩一行公式。SW 的 8192 字符上限下，这种「形参表换函数体」的收益远大于缩变量名。
- ⚠ **反面教材：死代码**。`if autohover == 1 then autohover = true else autohover = false end` —— `autohover` 从未被赋过值，恒为 `nil`，永远走 else 分支；真正生效的是 `autohover_num`（= 通道 18，同时被当作 `UD_Seat` 使用）。这段代码是作者重构后的残留。
- ⚠ **反面教材：`output.setNumber(udch, STB_UD)` 的 `udch` 未定义**。脚本顶部只声明了 `rch, pch, ych = 5, 4, 3`，升降通道号 `udch` 从未赋值 → 传 `nil` 给 `setNumber`。
- ⚠ **泰勒展开的适用范围**：`2*pi2*w - (pi2*w)^3/3` 是 `2*sin(2*pi*w)` 的三阶展开（`u - u^3/6` 整体乘 2，其中 `u = 2*pi*w`）。省一次 `math.sin` 调用，但 **|w| 超过约 0.13 圈（≈47°）后误差迅速变大**，大姿态下会明显偏软。
- ⚠ `v_speed = (altitude - old_altitude)*60` 依赖 tick 恒为 60 Hz。大载具 / 多人联机会掉帧，精确定速要走外部 blinker 计时（见 `02` §3.2）。

- 来源：steam id 3792666295 · 描述页 <https://steamcommunity.com/sharedfiles/filedetails/?id=3792666295> · 载具（`_vehicle_4` 手持式 GPS 导航仪，1×1 小屏）

- 🔑 **`onTick` 里读不到屏幕尺寸**：`screen.getWidth()` / `getHeight()` 属于绘制期 API，在 `onTick` 里取不到有效值。凡是要**在 tick 里做触控命中判定**（本例、以及 `08` §14 的战术屏），都必须由外部把宽高用数值通道喂进来，并在 `onDraw` 里再用真值校正一次。
- 🔑 通道值为 0 时的护栏：`if rw>0 then w=rw end`。未接屏 / 通道未连线时 `rw` 为 0，若直接赋值会让所有命中区塌成一个点，命中判定全失效。
- 🔑 **对称缩放夹逼**：`zoom/1.5` 与 `zoom*1.5` 互为逆运算，配两个夹子 `math.max(.1, ...)` / `math.min(50, ...)` 即可，不需要写「当前档位」状态机。指数步长的好处是缩放到任何倍率手感一致。
- 🔑 **`inside()` 用 `>=` / `<=`**：`06` §14 等处用的是严格不等号（`x > rectX`），边界那一格点不中；小屏（1×1 只有 32×32 像素）上一格就是整条边，闭区间更实用。
- 🔑 **`atan(dx, dy)` 的参数顺序是（东向分量, 北向分量）**，返回值直接就是「从北起算的方位角」，加 360 取模消除负角，不需要再手工判象限。
- 🔑 **三角航向指针**：`a = -compass*pi*2`（圈 → 弧度且取负，因为屏幕 Y 轴向下），三个顶点用 `±2.45` rad（约 ±140°）张成箭头。注意 `sin` 配 `x`、`cos` 配 `y` 且 `y` 取负——这是「北为 -Y」的标准写法。
- 🔑 `drawTextBox(x, y, w, h, text, 0, 0)` 的**后两个 0 是水平 / 垂直居中**，用它在 12×12 的小方块里放一个字符最省事，不用手算字号偏移。

## §26 路网导航：**属性文本里存一张图** + 空间分桶 + 把车**投影到最近的边** + A\* 最短路

- 来源：steam id 3792829061 · 描述页 <https://steamcommunity.com/sharedfiles/filedetails/?id=3792829061> · 载具（`_vehicle_1` 车载导航主脚本，PonyIDE 压缩态，以下为反压缩 + 语义改名版）

- 亮点：把**整个路网塞进属性文本**——坐标用「42 进制变长整数 + ZigZag 有符号 + 差分累加」三重压缩；规划前先把车的位置**投影到最近的边**上造一个虚拟节点，这样起点不在节点上也能出路径。

```lua
-- ① 路网 = 4 条属性文本拼起来（单条属性文本有长度上限，装不下就分片）

-- ② 42 进制变长整数：字符表 84 个，前 42 个表示「本数结束」、后 42 个表示「还有下一位」
local ALPHA = "abcdefghijklmnopqrstuvwxyz0123456789-_~{}[]ABCDEFGHIJKLMNOPQRSTUVWXYZ!#$%*+./:=?@^|,"
local NODES = {}
local function decodeNodes()
  local acc, half, nx, ny = 0, nil, 0, 0
  local s = E:sub(1, 8) == "ultra!!!" and E:sub(9) or nil   -- 魔数区分紧凑 / 明文两种格式
  if not s then return end
  for i = 1, #s do
    local k = string.find(ALPHA, s:sub(i, i), 1, true)
    if k > 42 then
      acc = acc * 42 + (k - 43)                              -- 高位：继续累积
    else
      acc = acc * 42 + (k - 1)                                -- 低位：本数结束
      -- 🔑 ZigZag 还原符号：偶数 = 正数/2，奇数 = -(n+1)/2，省掉正负号字符
      acc = (acc % 2 == 0) and acc / 2 or -((acc + 1) / 2)
      if half == nil then
        half = acc                                            -- 第一个数是 dx
      else
        nx, ny = nx + half, ny + acc                          -- 🔑 差分：存的是增量不是绝对坐标
        NODES[#NODES + 1] = { x = nx, y = ny, way = {} }
        half = nil
      end
      acc = 0
    end
  end
end
```

```lua
function projectOnRoad(px, py)

  for _, a in ipairs(bucketOf(px)) do
    for _, nb in ipairs(a.nei) do
      local ex, ey = nb.x - a.x, nb.y - a.y
      local len2 = ex * ex + ey * ey
      local t = 0
      if len2 > 0 then                                   -- 投影参数夹到 0..1，保证落在线段内

      local d = dist2(px, py, x, y)
      if d < best then best, qx, qy, n1, n2 = d, x, y, a, nb end
    end
  end
```

```lua
-- ⑦ A*：open 表用数组 + 线性找最小；启发值取「到目标的直线距离」，规划前统一算进 node.dst
local function astar(start, goal)
  local dist, prio, prev, open = { [start] = 0 }, { [start] = start.dst }, {}, { start }
  while #open > 0 do
    local bi, cur, bp = 1, open[1], prio[open[1]]
    for i = 2, #open do
      if prio[open[i]] < bp then bi, cur, bp = i, open[i], prio[open[i]] end
    end
    open[bi] = open[#open] open[#open] = nil      -- 🔑 交换删除：O(1) 出队
    if cur == goal then                           -- 回溯路径（表作哈希键，不用给节点编号）
      local path, n = {}, cur
      while n do path[#path + 1] = n n = prev[n] end
      reverse(path)
      return path, dist[cur]
    end
    for i, nb in ipairs(cur.nei) do
      local old = dist[nb] or math.huge
      if nd < old then
        prev[nb], dist[nb] = cur, nd
        prio[nb] = nd + nb.dst
        if old == math.huge then open[#open + 1] = nb end   -- 🔑 只在首次到达时入队
      end
    end
  end
  return {}, 0
end
```

```lua
if toggle then mapX, mapY = selfX, selfY end
```

- 🔑 **`*3600` 的来历**：SW 是 60 tick/s，一分钟 = 3600 tick。单帧位移本身就是「每 tick 位移」，乘回去即每分钟位移。想要「30 秒后到哪」就乘 1800。
- ⚠ **差分 × 3600 会把单帧抖动也放大 3600 倍**：车停住时 GPS 的末位残差会让矢量乱甩。必须加死区：`if dist < 0.5 then travelX, travelY = selfX, selfY end`（原脚本没做，是它的主要缺陷）。
- ⚠ **`selfXPast` 的更新顺序**：一定要在算完差分之后赋值；写成先赋值就恒为 0，矢量永远是原点。
- 🔑 **平移步长与缩放成正比**是手感关键：`zoom/0.1` 意味着缩得越远（zoom 越大）一次点按移动的世界距离越大，屏幕上看到的位移量恒定。缩放用 `zoom ± zoom/70` 同理。
- 🔧 原脚本的罗盘换算 `comRad = (((-compass-1)*360%360)+360)/360*pi2` 里，`-1` 与 `+360` 都是**多余的**：Lua 的 `%` 对正除数已返回非负值。等价写法是 `(-compass % 1) * pi2`（SW 罗盘东为负，故取负号）。
- 关联：`06` §20（平滑镜头 + 网格跳档）、`05` §57（缩放控件三细节）、`04` §1.2（圈最短角差）

## §28 折线航线的**几何命中**：点用圆判据、线段用**椭圆判据** + 圆周航线按弧长自动布点

- 来源：steam id **3796375383** · 描述页 <https://steamcommunity.com/sharedfiles/filedetails/?id=3796375383> · **载具**（航点地图编辑器，原作者 Zizo，Bready 改）
- 更新时间：未取到（Steam Web API 连续多轮不返回新上架作品元数据，下轮 `fetch_meta.py` 补）
- 用到：GPS、触控屏、属性给「到达半径 / 默认缩放」
- 亮点：`06` §15 / §17 / §19 都在讲「航点表怎么组织与增删」，这一节补上**在地图上点选折线**这件事本身——两种命中判据都不需要向量投影。
- 区别于 `06` §17（投影法判过点）：投影法要做点积 + 归一，字符更贵；椭圆判据只要两条距离。

```lua
-- ① 点命中：圆判据（首尾点不参与，避免误删起点 / 终点）
function isp(x, y)
    for i, v in ipairs(W) do
        local d = math.sqrt((x-v.x)^2 + (y-v.y)^2)
        if d < arr_w and i > 1 and i < #W then return i end
    end
end

-- ② 线段命中：椭圆判据 —— 到两端距离之和 ≈ 弦长（留 0.5% 余量）
function isl(x, y)
    for i, v in ipairs(W) do
        local v2 = W[i+1]
        if v2 then
            local d1  = math.sqrt((x-v.x)^2  + (y-v.y)^2)
            local d2  = math.sqrt((x-v2.x)^2 + (y-v2.y)^2)
            local len = math.sqrt((v.x-v2.x)^2 + (v.y-v2.y)^2)
            -- 两端各让出 2 倍点半径，避免和「点命中」抢
            if d1 + d2 < len*1.005 and d1 > arr_w*2 and d2 > arr_w*2 then return i end
        end
    end
end

-- ③ 点选优先级：先删 → 再选点 → 再插点 → 最后改当前点
if math.sqrt((dx-W[sl].x)^2 + (dy-W[sl].y)^2) < arr_w and sl > 1 then
    table.remove(W, sl); sl = sl - 1
elseif isp(dx,dy) then
    sl = isp(dx,dy)
elseif isl(dx,dy) then
    local j = isl(dx,dy); table.insert(W, j+1, {x=dx, y=dy}); sl = j + 1
elseif sl > 1 then
    W[sl] = {x=dx, y=dy}
end

-- ④ 圆周航线自动布点：点数随半径线性增长 → 每段弧长恒定
cn = cr * 8 / 500                      -- cr=2000 m → 32 点，弧长约 393 m
W  = {{x = gpsX, y = gpsY}}            -- 起点永远是当前位置
local a0 = math.atan(gpsY-wy, gpsX-wx) -- 从「自机→圆心」方向起铺
for i = 1, cn - 1 do
    local an = a0 + (i-1) * (math.pi*2/cn)
    table.insert(W, {x = wx + cr*math.cos(an), y = wy + cr*math.sin(an)})
end

-- ⑤ 世界半径 → 屏幕半径：SW 的 zoom 是「屏宽覆盖多少公里」
darr_w = w * arr_w / (z * 1000)        -- 每米像素数 = w/(z*1000)
s.drawCircle(dx, dy, math.max(darr_w, 0.5))   -- 小屏也留 0.5 px 看得见
```

- 🔑 **椭圆判据的原理**：到两定点距离之和为常数的轨迹就是椭圆，焦距即线段两端。当常数取弦长时椭圆退化为线段本身，乘 `1.005` 把它「吹胖」成可点的容差带。比投影法省掉点积与归一化。
- 🔑 **两种命中必须互斥**：`d1 > arr_w*2 and d2 > arr_w*2` 让线段判据在端点附近失效，否则靠近端点时两个判据会同时命中、行为随机。
- 🔑 **`cn = cr*8/500` 是「按弧长定密度」**：点数 ∝ 半径 ⇒ 每段弧长恒为 `2π·cr/cn ≈ 785 m`（本例常数下），半径调大时圆周不会变成折线多边形。
- ⚠ **反面教材：`isp(x,y)` / `isl(x,y)` 有参数却不用**。两个函数体里读的是**全局** `dx, dy`（调用前刚赋值），参数 `x, y` 完全是摆设。能跑，但一旦在别处调用、或 `onDraw` 里复用就会读到脏值——改成纯函数（把 `dx,dy` 换成 `x,y`）只需替换 6 处，强烈建议改。
- 关联：`06` §15（航线编辑器：编辑游标 / 当前航段双指针）、`06` §19（FMS 航点 CRUD）、`04` §9.1（px ↔ m 标定）


## §29 **四轮下压力的姿态混控**（四角 = 基础项 ± 滚转 ± 俯仰）

- 来源：steam id **3795469150** · 描述页 <https://steamcommunity.com/sharedfiles/filedetails/?id=3795469150> · **载具**（R32 Hillclimb，`_vehicle_0` 悬挂 / 下压力分配）
- 更新时间：2026-09-06
- 用到：属性（Front Downforce / Rear Downforce，百分比）、复合数值 3 滚转、4 俯仰；4 路数值输出（四角下压力）
- 亮点：四个角的作动量 = 一个固定的基础量，再按当前姿态叠加 ±滚转、±俯仰。作者**把 4×3 的混控矩阵直接手写展开成 4 行赋值**——比写循环 + 系数表省字符，也比调用通用矩阵库省一大截。

```lua
m = math
gn, sn, co, si, atan, asin, gpn = input.getNumber, output.setNumber,
    m.cos, m.sin, m.atan, m.asin, property.getNumber

FrontDF = gpn("Front Downforce")/100             -- 属性给百分比，代码里用 0..1
RearDF  = gpn("Rear Downforce")/100

function PID()                                   -- 🔑 闭包工厂：每路一个独立积分器
    local prev, int = nil, 0
    return function (Sp, V, p, i, d, Lcl, Ucl)
        if prev == nil then prev = Sp - V end    -- 🔑 首帧把微分项归零，避免上电冲击
        local Er, diff = Sp - V, 0
        diff = Er - prev
        int  = m.min(m.max(int + Er*i, Lcl), Ucl)  -- 直接钳积分项本身
        prev = Er
        return p*Er + int + d*diff
    end
end

function onTick()
    Roll, Pitch = gn(3), gn(4)

    -- 🔑 四角混控：基础项 ± 滚转 ± 俯仰（符号 = 该角在该姿态下该增还是该减）
    FR = FrontDF + Roll + Pitch
    FL = FrontDF - Roll + Pitch
    RR = RearDF  + Roll - Pitch
    RL = RearDF  - Roll - Pitch

    sn(1, FR) sn(2, FL) sn(3, RR) sn(4, RL)
end
```

- 🔑 **为什么是这 8 个符号**：滚转时希望「外侧轮加压、内侧轮减压」→ 右轮 `+Roll`、左轮 `-Roll`；俯仰时希望「加速抬头压后轴、刹车点头压前轴」→ 前轮 `+Pitch`、后轮 `-Pitch`。四个角各取两个符号的乘积式组合，**本质是 4 行符号表**，改一个符号就换一种配平策略。
- 🔑 **不写循环反而更省**：`for i=1,4 do out[i] = base[i] + sgn_r[i]*Roll + sgn_p[i]*Pitch end` 要多存 3 张表（约 60 字符）；4 行直接展开只有 ~120 字符且**一眼能看出符号表**，调试时改哪个角一目了然。规模到 6 轮以上再考虑上表。
- 🔑 **`property.getNumber("...")/100`**：属性滑块给 0..100 的百分比，代码里统一用 0..1，避免后面每处都写 `/100`。
- 🔑 **`prev == nil` 的首帧处理**：PID 闭包若用 `prev = 0` 初始化，上电第一帧 `diff = Er - 0` 会等于整个误差，D 项输出一个巨大尖峰（舵面/悬挂会猛打一下）。用 `prev = Sp - V`（首帧误差）则 `diff = 0`，**首帧只有 P 和 I**。
- ⚠ **积分限幅写在 `int` 上、且没有除以 `i`**：`int = clamp(int + Er*i, Lcl, Ucl)` 是最直接的写法，但它的实际积分上限是 `iMax = Ucl`，**与增益 `i` 无关**；一旦调大 `i`，抗饱和的等效积分值会跟着变。想让「积分上限」与增益解耦，改用 `04` §12 的 `int = Clamp(int*kI, 0, iMax)/kI` 反推写法。
- ⚠ **别名压缩 `gn,sn,co,si,... = input.getNumber, ...` 的多重赋值一旦写错顺序就会静默错位**（Lua 不会报错，只是变量指向了别的函数）。改这行时**成对核对左右两边**，见 `01` §2。
- ⚠ **本例的 `att()`（由 sin/cos 反解欧拉角）被注释掉了**，最终直接吃外部滚转/俯仰通道。若你的车没有外部姿态源，可参照 `04` §13 的 `ltog`/`gtol` 或 `09` §28 的手写 3×3 欧拉矩阵自己解。
- 关联：`04` §12（区间映射与积分限幅反推）、`04` §13（向量闭包库换基）、`09` §12（PID 对象的 pause/reset 双模）、`01` §2（别名压缩）
