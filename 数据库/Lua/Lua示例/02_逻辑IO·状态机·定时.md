> 来源融合：日文 `wikiwiki.jp/sbarjp/Lua例文集`（Logic 再現系 / PID）+ BKN `docs/Tutorial/state_machine.md`、

> **核心原则**：脚本方块替代 Logic 方块时，**所有状态都从 `input`/`output` 通道进出**；
> 只存脚本变量的状态在多人下会分叉（见 `01` §5）。

## §1 pulse（边沿检测）

1 tick 前的输入与当前不同 → 仅变化那 1 tick 输出 true。**所有「按钮按一次只触发一次」的基础。**

```lua
prev=false
function onTick()
  v=GB(1)                  -- 接按钮/开关的 Bool 通道
  p=not (v==prev)          -- 上升沿 + 下降沿都触发
  SB(1,p)
  prev=v
end
```

只要上升沿：

```lua
p = v and not prev
```

只要下降沿：

```lua
p = prev and not v
```

**要点**
- `prev` 必须定义在 `onTick` **外面**，否则每次都是 false，检测失效。
- 触控屏的「按住」信号**不能直接当触发器**——一次触摸会连续触发几十次。
  要么用上面的沿检测，要么用外部逻辑电路造一个 tick 脉冲（见 `05` §4 的 A-10 实例）。

## §2 toggle（自锁翻转）

```lua
prev,toggle=false,false
function onTick()
  v=GB(1)
  p=not (v==prev); prev=v
  if p then toggle=not toggle end
  SB(1,toggle)
end
```

> ⚠ **纯脚本变量 `toggle` 在多人下会异步漂移**（`01` §5）。
> 联机可靠写法：把 `toggle` 经 `output` 写出、再 `input` 读回自身来对齐。

```lua
-- 联机版：N32 接回自身 N31 输出
function onTick()
  local p = GB(1) and not prev; prev = GB(1)
  local t = GN(32) > 0.5
  if p then t = not t end
  SN(31, t and 1 or 0)
  SB(1, t)
end
```

## §3 timer（定时 / 周期触发）

### 3.1 tick 累加（粗略定时）

```lua
CLK,INT=0,60               -- 60 tick ≈ 1 秒
function onTick()
  if CLK == INT then
    CLK = 0
    -- 到点要做的事
  else
    CLK = CLK + 1
  end
end
```

> ⚠ **onTick 频率不稳**（标称 60Hz，大载具/多人/低物理细节会掉）。
> 只适合粗略定时；**精确边沿定时改用外部 blinker 信号**（3.2）。

### 3.2 外部信号计时（稳定）

```lua
CLK=false
function onTick()
  clk=GB(1)                -- 接 blinker / 时钟方块
  if not clk then
    CLK=false
  elseif clk and not CLK then
    CLK=true
    -- 每个外部脉冲执行一次
  end
end
```

### 3.3 TON / TOFF

```lua
t,tick=0,120               -- 120 tick ≈ 2 秒
function onTick()
  t=t+1
  TON  = t>tick            -- 延时接通
  TOFF = t<tick            -- 延时断开
end
```

## §4 有限状态机（多步机械流程）

来源：BKN `docs/Tutorial/state_machine.md`（钻杆自动装填机）。
**原稿有两处错误，本集已修正并在下方标注。**

### 4.1 通用骨架（填 I/O 表 + `STATE_MACHINE()` 主体即可用）

```lua
STATE=0
I_BOOL={false,}
I_NUM={0,0,0,0,0,0,0}
O_BOOL={false,false,false}
O_NUM={0,0,0,0,0}

TIMER,TIMER_HOLDER=0,false

function onTick()
  GN,GB=input.getNumber,input.getBool
  SN,SB=output.setNumber,output.setBool
  for i,v in ipairs(I_BOOL) do I_BOOL[i]=GB(i) end
  for i,v in ipairs(I_NUM)  do I_NUM[i] =GN(i) end

  STATE_MACHINE()

  for i,v in ipairs(O_BOOL) do SB(i,v) end
  for i,v in ipairs(O_NUM)  do SN(i,v) end
end

function STATE_MACHINE()
  if STATE==0 then
    O_BOOL[1]=false
  end
end

-- 定时后切到指定状态
function NEXT_STATE_IN(time, state)
  if TIMER==0 and not TIMER_HOLDER then
    TIMER,TIMER_HOLDER=time,true
  elseif TIMER==0 then
    STATE,TIMER_HOLDER=state,false
  else
    TIMER=TIMER-1
  end
end

-- 运行滑轨到目标位置：返回 (需要上行, 需要下行)，留 ±0.1 死区
function RAIL_TO(a,b)
  return a-b>0.1, a-b<-0.1
end
```

### 4.2 完整实例（钻杆装填，5 个状态）

```lua
STATE=0; ROD_COUNT=0
TIMER,TIMER_HOLDER=0,false; BUTTON_HOLDER=false

function onTick()
  GN,GB=input.getNumber,input.getBool
  SN,SB=output.setNumber,output.setBool

  Button_1      = GB(1)
  Rail_1_Dist, Rail_2_Dist = GN(1), GN(2)

  -- 每 tick 先把输出重置为默认值，再由状态机覆盖（避免"幽灵输出"）
  Rail_1_Up,Rail_1_Down,Rail_2_Up,Rail_2_Down,Rod_Hold = false,false,false,false,false
  Rotate_1,Rotate_2,Rod_Slide = 0,0,0

  if Button_1 and not BUTTON_HOLDER then
    STATE=1; BUTTON_HOLDER=true
  elseif not Button_1 then
    BUTTON_HOLDER=false
  end

  STATE_MACHINE()

  SN(1,Rotate_1) SN(2,Rotate_2) SN(3,Rod_Slide)
  SB(1,Rail_1_Up) SB(2,Rail_1_Down) SB(3,Rail_2_Up) SB(4,Rail_2_Down) SB(5,Rod_Hold)
end

-- 0 idle : 两滑轨归位
-- 1      : 1/2 滑轨到钻杆位、夹持，180 tick 后进 2
-- 2      : 两滑轨到 0.5、钻杆滑动，300 tick 后进 3
-- 3      : 关节1旋转、滑轨到钻井处、钻杆反向滑动，600 tick 后进 4
-- 4      : 关节1保持、2 号滑轨升高、松开夹持，180 tick 后回 0
function STATE_MACHINE()
  if STATE==0 then
    Rail_1_Up,Rail_1_Down = RAIL_TO(Rail_1_Dist,1)
    Rail_2_Up,Rail_2_Down = RAIL_TO(Rail_2_Dist,1)
  elseif STATE==1 then
    Rail_1_Up,Rail_1_Down = RAIL_TO(Rail_1_Dist, 1+0.5*ROD_COUNT)
    Rail_2_Up,Rail_2_Down = RAIL_TO(Rail_2_Dist, 0)
    Rod_Hold=true; NEXT_STATE_IN(180,2)
  elseif STATE==2 then
    Rail_1_Up,Rail_1_Down = RAIL_TO(Rail_1_Dist, 0.5)
    Rail_2_Up,Rail_2_Down = RAIL_TO(Rail_2_Dist, 0.5)
    Rod_Slide=1; Rod_Hold=true; NEXT_STATE_IN(300,3)
  elseif STATE==3 then
    Rail_1_Up,Rail_1_Down = RAIL_TO(Rail_1_Dist, 0)
    Rail_2_Up,Rail_2_Down = RAIL_TO(Rail_2_Dist, 0.25)
    Rod_Slide=-1; Rotate_1=1; Rod_Hold=true; NEXT_STATE_IN(600,4)
  elseif STATE==4 then
    Rail_2_Up,Rail_2_Down = RAIL_TO(Rail_2_Dist, 2)
    Rotate_1=1; NEXT_STATE_IN(180,0)
  end
end
```

> 🔴 **原稿错误（已修正）**
> 1. `if STATE=0 then` —— 这是**赋值**不是比较，会把 `STATE` 改成 0 且条件恒为真。必须是 `if STATE==0 then`。
> 2. `SB(2,Rail_1_Down)s` —— 行尾多了一个 `s`，是语法错误。

**要点**
- **每 tick 先重置全部输出到默认值**，再由状态机覆盖——否则上一状态的输出会残留。
- `NEXT_STATE_IN(time, state)` 用 `TIMER` + `TIMER_HOLDER` 配对实现「延时跳转」，`HOLDER` 防止重复装载。
- `RAIL_TO(a,b)` 返回两个布尔（上行/下行）并留 **±0.1 死区**——滑轨速度不可调，没死区会在目标位反复抖动。
- 多人下 `STATE` 会分叉，联机必须走复合回环（`01` §5）。

## §5 延迟事件表（定时后执行某个函数）

来源：BKN `docs/Addon/timer.md`。适合「延迟执行 + 参数不同」的多个任务。

```lua
DELAY_EVENTS = {}

function addDelay(time, do_func, param)
  table.insert(DELAY_EVENTS, {TIME=time, DO=do_func, PARAM=param or {}})
end

function onTick()
  for k,v in pairs(DELAY_EVENTS) do
    if v.TIME > 0 then
      DELAY_EVENTS[k].TIME = v.TIME - 1
    else
      v.DO(table.unpack(v.PARAM))
      DELAY_EVENTS[k] = nil
    end
  end
end
```

> ⚠ `pairs` 遍历时置 `nil` 是**安全的**（置 nil 不等于 `table.remove`，不会导致下标前移）。
> 但 `table.remove` 在 `pairs` 里**不安全**，见 `07` §2 的 TCAS 实例说明。

## §6 PID 接执行器

PID 本体是通用控制算法，本集只标**游戏内接法**：误差/反馈走 `gn()` 通道，输出 `sn()` 到执行器（电机 RPS、舵机角度等）。

```lua
-- 通用 PID（多实例 + 抗积分饱和），来源 steam id 3242277101（2025-04-11）
Is={} Ds={}
function pid(id,v,s,p,i,d,plmt,ilmt,dlmt)
  if not Is[id] then Is[id]=0 Ds[id]=0 end
  Is[id] = cl(Is[id] + i*(s-v), -ilmt, ilmt)                  -- 积分单独限幅 = 抗饱和
  local rst = cl(p*(s-v), -plmt, plmt) + Is[id]
            + cl(d*(s-v-Ds[id]), -dlmt, dlmt)
  Ds[id] = s-v
  return rst
end
function cl(x,a,b) return math.max(math.min(b,v),a) end       -- 见下方勘误

function onTick()
  target = GN(1)                        -- 目标值走复合通道
  cur    = GN(2)                        -- 反馈值（编码器/传感器）
  out    = pid(1, cur, target,
               PN('P'), PN('I'), PN('D'),      -- 参数走属性滑块，便于调参
               1, 0.5, 0.5)                    -- P/I/D 各自限幅
  SN(1, out)                            -- 到执行器
end
```

> 🔴 **上例 `cl` 有笔误**，正确定义是：
> ```lua
> function cl(x,a,b) return math.max(math.min(x,b),a) end
> ```
> （原稿写成了 `math.min(b,v)` —— `v` 是外部变量，会导致限幅失效。）

**要点**
- **积分项必须限幅**（`ilmt`），否则长时间偏差会让 I 项爆掉，偏差消失后系统持续过冲。
- P/I/D 三项各自限幅（`plmt`/`ilmt`/`dlmt`），比只限总输出更稳。
- 参数走 `property.getNumber` → 用户不用改代码就能调参，是工坊作品的标配。
- **多人下 `Is`/`Ds` 是脚本变量会分叉**；联机控制回路建议把积分状态经复合信号回环。
- 日文例文集的做法是给 `integral` 夹 `maxInt=10`，思路相同。

## §7 边沿锁存供电 + 回环选档（车组站管理）

来源：steam id **3261800786** · <https://steamcommunity.com/sharedfiles/filedetails/?id=3261800786> · **载具**（ZTQ-15，脚本 `Crew Manager`）

「按下通电、再按别人断电」这类 **latch（锁存）** 要用边沿检测：上升沿置位、条件下降沿复位。回环选档则是「到头绕回」的步进器。

```lua
-- 边沿锁存：用上一帧状态 *_o 判上升沿
gnrpwr = GB(21); cmdpwr = GB(22)
if (gnrpwr and not gnrpwro) or (cmdpwr and not cmdpwro) then power = true end
if power and cmdpwro and not cmdpwr then power = false end     -- 车长松开→断电
if power and gnrpwro and not gnrpwr then power = false end     -- 炮长松开→断电
SB(1, power)
gnrpwro = gnrpwr; cmdpwro = cmdpwr                         -- 存本帧供下帧比对

-- 回环选档：sl 在 [-10,100] 步进，到边界绕回
if sla and not slao then sl = M.min(sl+10, 100) end        -- 上一步 +10
if slm and not slmo then sl = M.max(sl-10, -10) end        -- 下一步 -10
if sl == 100 then sl = 0 end                               -- 顶端绕回
if sl == -10 then sl = 90 end                              -- 底端绕回
slao = sla; slmo = slm
SN(11, sl); SN(12, Mf(sl/10)); SN(13, sl%10)              -- 输出值 + 十/个位(供显示)
```

**要点**
- 锁存 = **上升沿置位 + 条件下降沿复位**，必须存 `_o` 旧状态（见 §1 的 `pulse` 思路，这里是多源）。
- 回环选档 `sl==100→0 / sl==-10→90` 用**相等判断绕回**，比取模更直观；输出拆十/个位 `sl/10`、`sl%10` 便于数码管分两位显示（接 `09` §4 的 `DN`）。
- 命令模式三选一：`cmdonly`(只听车长) / `cmdadd`(车长+炮长叠加) / 否则自管：`outad = cmdonly and cmdad or (cmdadd and cmdad+gnrad or gnrad)`。
- 完整脚本：`../../../AI相关/_提取暂存/3261800786_vehicle_22.lua`

## §8 点动 + 长按连发（触控增减一个设定值）

- 来源：steam id **3788743617** · 描述页 <https://steamcommunity.com/sharedfiles/filedetails/?id=3788743617> · **载具**（`_vehicle_12` 航向保持面板）
- 更新时间：2026-08-29
- 用到：指南针、触控屏、显示器
- 亮点：**点一下走一格、按住 1/3 秒后才开始连发**——同一个触控区兼顾精调与快调；配套的度制最短角差与「无 I 项」PD 舵。

```lua
function angleDiff(target, cur)            -- 度制最短角差，结果落在 -180..180
  return (target - cur + 540) % 360 - 180
end

function onTick()
  local hdg   = input.getNumber(1)         -- 航向（度）
  local tx,ty = input.getNumber(3), input.getNumber(4)
  local press = input.getBool(1)

  if press then
    local step = 0
    if     tx >= 0  and tx <= 6  and ty <= 8 then step = -1     -- 左区：减
    elseif tx >= 25 and tx <= 31 and ty <= 8 then step =  1     -- 右区：加
    end

    if step ~= 0 then
      if not lastPress then                -- 按下沿：立刻走一格
        target, holdTicks = (target + step) % 360, 0
      else
        holdTicks = holdTicks + 1          -- 🔑 按住 20 tick 后每 6 tick 再走一格
        if holdTicks > 20 and holdTicks % 6 == 0 then
          target = (target + step) % 360
        end
      end
    elseif tx >= 7 and tx <= 24 and ty <= 8 then
      if not lastPress then
        hold = not hold
        if hold then target = hdg end      -- 接通瞬间以当前航向为设定值
      end
      holdTicks = 0
    else
      holdTicks = 0
    end
  else
    holdTicks = 0
  end
  lastPress = press

  local out = 0
  if hold then
    local err = angleDiff(target, hdg)
    out = err*0.03 + (err - lastErr)*0.15  -- PD，没有 I 项
    lastErr = err
    out = math.max(-1, math.min(1, out))
  else
    lastErr = 0                            -- 失能清零，重新接通不突跳
  end
  output.setNumber(1, out)
  output.setBool(1, hold)
end
```

**要点与坑**

- **两个常量决定手感**：`> 20` 是防误连发的死区（20 tick ≈ 1/3 s），`% 6` 决定连发速率（6 tick ≈ 每秒 10 格）。
  死区太小会「想点一下却走了三格」，太大会觉得按住没反应。
- `(target + step) % 360` 依赖 **Lua 的 `%` 对负数返回非负余数**（`-1 % 360 == 359`），
  正好等于罗盘环绕，不用写 `if < 0 then + 360`。这与 C / JS 的 `%` 行为不同，别照搬别的语言经验。
- **每个分支都要清 `holdTicks`**，包括「按着但手指移出按钮区」这一支。漏掉会出现「移出去再移回来直接连发」。
- 度制角差 `(a-b+540)%360-180` 与圈制版本（`04` §1.2）是同一个公式换单位：`540 = 360+180`。
- 舵机这类**位置型执行器**用 PD 就够，加 I 项会在浪/风里持续积累（见 `09` §9 的条件积分）。
  失能时只需清 `lastErr`：下一帧 `err` 本身≈0（`target` 被置为当前航向），D 项不会踢一脚。
- 完整脚本：`../../../AI相关/_提取暂存/_new/3788743617_vehicle_12.lua`

## §9 腿式载具步态：**一个相位累加器 + sin/cos 正交驱动**，动作靠「后写覆盖」

- 来源：steam id 3791574523 / vehicle.xml block#0（Brown Horse - RAMBO，四足步行）
- 更新时间：2026-08-30
- 用到：转轴（Pivot）、属性数字、属性开关、座椅输入
- 亮点：整个行走动画就是**一个自增变量 `X` 喂 `sin`/`cos`**，髋用 sin、膝用 cos 天然差 90 度相位；
  跳/坐/踢三个动作不写状态机，靠「在 onTick 末尾重复 `output.setNumber` 覆盖」实现优先级；
  全部姿态参数外提成属性，同一 MC 通装不同腿长的机体。

```lua
X = 1000                                     -- 相位累加器(任意偶整数起步 => sin=0 中立位)
RMS = property.getNumber("Reverse max speed")
Y   = property.getNumber("Hip max rotation")     -- 髋摆幅
Z   = property.getNumber("Hip starting position")-- 髋中立位
W   = property.getNumber("Knee max rotation")
A   = property.getNumber("Knee starting position")
B, C = property.getNumber("jump hip"), property.getNumber("jump knee")
G, H = property.getNumber("sit hip"),  property.getNumber("sit knee")
L, M = property.getNumber("kick hip"), property.getNumber("kick knee")
I, J = property.getNumber("Jump timing"), property.getNumber("Jump at")
N, O = property.getNumber("Turn step speed"), property.getBool("Toggle turn stepping")
E    = property.getBool("Inverse Clamp (limits max knee extension)")
tglR = property.getBool("Return to starting position when no input")

function onTick()
  WS = input.getNumber(2)                    -- 前后摇杆
  AD = input.getNumber(1)                    -- 左右摇杆
  FMS = input.getBool(3) and 0.14 or 0.07    -- KEY: 快/慢两档步频

  if WS > 0 then X = X + WS*FMS end          -- KEY: 相位速度 = 指令 x 步频
  if WS < 0 then X = X + WS*RMS end          -- 倒退用独立步频
  if math.abs(WS) < 0.1 and O then           -- KEY: 原地转向也踏步(仅无前进指令时)
    if AD > 0 or AD < 0 then X = X + AD*N end
  end
  if math.abs(WS) < 0.1 and math.abs(AD) < 0.1 and tglR then
    X = 0                                    -- KEY: 松手归零, 不是冻结
  end

  local A1, A2
  if E then A1, A2 = -1, A else A1, A2 = A, 1 end   -- KEY: 膝关节单向限位

  leftHip   = math.sin(X*math.pi)*Y + Z
  rightHip  = -math.sin(X*math.pi)*Y + Z           -- 反相 180 度
  leftKnee  = clamp( math.cos(X*math.pi)*W + A, A1, A2)   -- KEY: 膝用 cos => 差 90 度
  rightKnee = clamp(-math.cos(X*math.pi)*W + A, A1, A2)

  output.setNumber(1, leftHip)
  output.setNumber(2, rightHip)
  if math.abs(WS) > .1 then                  -- 静止时膝锁死在起始位, 避免转向踏步带抖
    output.setNumber(3, leftKnee)  output.setNumber(4, rightKnee)
  else
    output.setNumber(3, A)         output.setNumber(4, A)
  end

  -- 以下全是"覆写层": 靠最后一次 setNumber 生效, 行序即优先级
  if input.getBool(D) then jump1 = true end
  if jump1 then x = x + I end                -- x: 0..1 归一化跳跃时间线
  if x < J and jump1 then                    -- 第一段: 蓄力蹲下
    output.setNumber(1, G) output.setNumber(2, G)
    output.setNumber(3, H) output.setNumber(4, H)
  end
  if x > J and jump1 then                    -- 第二段: 爆发伸展
    output.setNumber(1, B) output.setNumber(2, B)
    output.setNumber(3, C) output.setNumber(4, C)
  end
  if x > 1 then x = 0  jump1 = false end

  if input.getBool(F) then                   -- 坐: 直接覆盖四个关节
    output.setNumber(1, G) output.setNumber(2, G)
    output.setNumber(3, H) output.setNumber(4, H)
  end
  if input.getBool(K) then                   -- 踢: 只覆盖右腿, 左腿继续走
    output.setNumber(2, L) output.setNumber(4, M)
  end
  output.setNumber(5, x)                     -- 跳跃相位输出给音效/动画
end
```

**要点与坑**

- 🔑 **髋 `sin` / 膝 `cos` 的 90 度相位差是步态的全部秘密**。同侧髋膝**同相**会变成「僵硬踢腿」，
  脚在地面上拖行；差 90 度才形成「抬起-前伸-落下-后蹬」的椭圆轨迹。
  左右腿再差 180 度（`-math.sin`）就是对角步（trot）。想做爬行步（crawl）把四条腿排成
  0/90/180/270 度相位即可 —— 全部只需给 `X*math.pi` 加不同常数偏移。
- 🔑 **相位速度直接乘操纵指令**：`X = X + WS*FMS`。摇杆推得越满，步频越高，
  **不需要任何额外的「速度-步频同步」逻辑**，也不会出现「腿在动但车不走」的滑步感
  （因为 SW 里腿的推力本来就来自关节转动）。前进/倒退用两个独立系数
  （`FMS` / `RMS`），符合真实步行动物倒退更慢的直觉。
- 🔑 **松手时 `X = 0` 归零，而不是停住累加**。冻结相位会把腿留在半抬空中，机体歪斜；
  归零让 `sin=0`、`cos=1`，四腿回到确定的站立姿态。由属性开关
  `Return to starting position when no input` 控制，因为某些机体（蜘蛛式）反而需要保持当前姿态。
- 🔑 **膝关节「单向限位」用一个开关切 clamp 上下界**：`if E then A1,A2 = -1,A else A1,A2 = A,1 end`。
  SW 转轴行程是 -1..1 全自由，不限位的话膝盖会往反方向折（腿反弯）。
  把界限的一头钉在起始位 `A` 上，膝就只能朝一个方向弯。属性名里作者写着
  "for smoother walking" —— 这不是美观问题，是**避免关节穿过奇异位形导致机体弹飞**。
- 🔑 **动作覆写靠「后写覆盖前写」，不写状态机**。SW 的 `output.setNumber(ch, v)` 同帧多次调用
  **最后一次生效**，所以跳/坐/踢直接在 onTick 末尾重复写同样的通道即可。
  比 `if jumping then ... elseif sitting then ... else 步态 end` 的大分支树省一半字数。
  ⚠ **优先级 100% 由代码行序决定**：这里「踢」写在最后所以优先级最高，插新动作必须想清楚放哪一行。
  另外「踢」只覆盖通道 2/4（右腿），左腿仍在走 —— 这种**部分覆盖**是分支树写法很难做到的。
- 🔑 **跳跃 = 一个归一化时间线 + 一个阈值分段**：`x` 每帧加 `I`（Jump timing），
  `x < J` 蹲、`x > J` 弹、`x > 1` 结束归零。两个属性（步进量 `I` 与切换点 `J`）就能调出
  蓄力时长和爆发时机的所有组合，比写 tick 计数器灵活。`output.setNumber(5, x)`
  把这个相位漏出去给音效/尾巴动画用 —— **「动作相位当公共信号广播」值得学**。
- ⚠ **原作有一处真 bug：`if D then D1=true D2=D2+0.1 end`**。`D = property.getNumber("Jump button")`
  是**数字**，Lua 里任何非 nil 值（**包括 0**）都为真，所以这个分支每帧都执行、`D2` 无限增长。
  正确写法是 `if input.getBool(D) then`（本例已改）。
  **这是 SW 最高频的陷阱之一：`property.getNumber` 拿到的通道号绝不能直接当布尔用**，
  必须显式 `> 0` 或拿去 `input.getBool(通道号)`。所幸 `D1`/`D2` 在后文没被引用，是死代码。
- ⚠ **`clamp` 在原作里没有定义**（依赖别处或 SW 环境），照抄前自己补：
  `function clamp(v,lo,hi) return math.max(lo, math.min(hi, v)) end`。
- **20 个 property 全参数化**的取舍：属性面板极长、调参靠试，但换一台腿长不同的机体
  只改属性不改脚本。SW 的 property 是编译期常量，不占运行时开销，
  所以「能外提就外提」在 SW 里几乎没有成本 —— 与 `03` §13 的 `Radar Shadow Zone` 同一思路。

## §10 国际象棋 negamax α-β 引擎（跑在 MC Lua 脚本方块内）

- 来源：steam id 3793531285 · 描述页 https://steamcommunity.com/sharedfiles/filedetails/?id=3793531285 · 载具（Chess - By Qbert BETA）
- 更新时间：2026-09-01
- 用到：位棋盘（0..120 一维 + sentinel 边界）、闭包生成走法、递归搜索、负极大值（negamax）、α-β 剪枝、复合 I/O 落子
- 亮点：把"评估 + 搜索 + 走子 + 悔棋"完整国际象棋 AI 塞进 8192 字符脚本方块；用 negamax 把 minimax 的"双方各写一套"化简成一套、靠 `o=-o` 翻方
- 关联：`04` §11（状态/历史表）、`02` §6（PID 对象同族的"闭包即对象"思路）

-- 棋盘：c[a] 是 0..120 一维数组（10x12，外圈 sentinel），空格=7、空=0；o=当前方(+1白/-1黑)
local abs=math.abs
local X=25000                        -- 胜负大数（fail value）
local x=7                            -- 空格标记
local P={100,320,330,500,900,20000} -- 兵/马/象/车/后/王的静态值

-- 走法偏移：马/王/兵/车/象/后（N[6]=N[5] 复用车的直线）
local N={{},{-21,-19,-12,-8,8,12,19,21},{-11,-9,9,11},{-10,-1,1,10},{-11,-10,-9,-1,1,9,10,11},}
N[6]=N[5]

local Y,O={},{}for V=1,8 do for S=1,8 do local b=20+(V-1)*10+S Y[(V-1)*8+S]=b O[b]=(V-1)*8+S end end

-- 评估：每子按"己方视角"求和后再乘 o（negamax 总是从当前行动方看棋盘）

      local q=abs(e) local k=P[q]
      if q==1 then k=k+(((e>0)and(88-a)or(a-31))//10)*6            -- 兵：越靠近升变/底线越值钱
      elseif q<5 then k=k+W[a] if q<4 and((e>0 and a>90)or(e<0 and a<29))then k=k-22 end end
      m=m+((e>0)and k or -k)
    end
  end

end

-- 落子/悔棋：ad 改棋盘并记旧值到 Z 栈、翻方；ae 还原、翻回方（闭包状态）
local Z,B={},0 for a=1,30 do Z[a]={}end

  if b[3]==3 then local k,M if v>r then k,M=r+3,r+1 else k,M=r-4,r-1 end f[10],f[11]=k,M c[M],c[k]=c[k],0 end

end

local L=0
local function aa(t,n,Q,u)
  L=L+1
  local z=t<=0
  local d
  if z then d=ag() if d>=Q then return d end if d>n then n=d end if t<=-3 then return d end
  else d=-99999 end
  local s=C[u] local p=T(u,z)              -- T 生成当前节点全部走法（含吃子/移动/升变）
  for i=1,p do

    if abs(c[b[2]])==6 then return X-u end  -- 王被吃 = 立即失败（越早将死分越高）
    local f=ad(b)                          -- 落子
    local h=-aa(t-1,-Q,-n,u+1)             -- 递归：负号翻估值，α/β 互换（negamax 精髓）
    ae(b,f)                               -- 悔棋
    if h>d then d=h end
    if h>=Q then return d end             -- β 剪枝
    if h>n then n=h end                  -- α 上探
  end

    o=-o local ah,ab=T(u+1,true),false
    for i=1,ah do if abs(c[C[u+1][i][2]])==6 then ab=true break end end
    o=-o if not ab then return 0 end
  end

**要点速记**
- 🔑 **negamax 把 minimax 砍半**：不再写"max 层/ min 层"两套，只用一套，递归时 `o=-o` 翻方、`-aa(...)` 翻估值。代码量直接少一半，且天然对称。
- 🔑 **α-β 剪枝的对称写法**：当前层下界是 `n`、上界是 `Q`；进递归时变成 `-aa(t-1, -Q, -n, ...)`——把"对方的 β"当"自己的 α"。死记这个符号翻转就不会写反。
- 🔑 **棋盘用 0..120 一维 + sentinel 边界**（10 列 × 12 行，外两圈当墙）：走马/车/象的偏移加法不会越界到对面，省掉一堆边界 `if`。代价是坐标映射要多一层 `Y/O` 表。
- 🔑 **悔棋比"复制棋盘"省得多**：`ad` 只改 1~2 个格子并把旧值压进 `Z` 栈，`ae` 弹栈还原。搜索每节点 O(1) 改盘，而不是 O(64) 深拷贝——这是 MC Lua 8192 字符内能跑搜索的关键。
- ⚠ **`X-u` 把"越早将死分越高"编码进剪枝**：`X=25000` 是 fail value，`u` 是搜索深度，越浅（早）将死返回越大。搜索里看到王被吃直接 `return X-u`。
- ⚠ **KV 分离不是重点，状态压栈才是**：这例证明"递归搜索 + 闭包栈式 undo"在 SW 脚本方块里完全可行，思路可迁移到任何需要"试错-回滚"的 AI（自动解谜、路径搜索）。

## §11 **多摄像头 LIFO 切换栈**：`lastCamera` 父指针 + 延迟断电倒计时

- 来源：steam id **3793679025** · 描述页 <https://steamcommunity.com/sharedfiles/filedetails/?id=3793679025> · **载具**（`_vehicle_4` 视频切换 + 彩条测试图）
- 更新时间：未取到（本轮 Steam Web API 不可达）
- 用到：复合布尔 1~6（6 路摄像头选择）、复合数值 1（一天中的时刻，「圈」）、6 路布尔输出（摄像头使能）、属性（切换延迟 tick 数、两行频道名文本）
- 亮点：6 路摄像头任意多选时「画面到底显示哪一个」是个调度问题。作者用一条 `lastCamera` **父指针链**做成 LIFO 栈——后选的压在上面，关掉它自动回退到上一个还在选的；并且**关掉不立即断电**，而是倒计时 N tick 后再断，避免切换瞬间的丢画面。

```lua
deactivateTime = property.getNumber("Camera switching time (ticks)")

function Camera()
  return {selected = false, lastCamera = nil, deactivateIn = 0}
end
selectedCamera = nil

function update(camera, select)
  if select ~= camera.selected then              -- 🔑 只在状态翻转那一下动作，别每 tick 重做
    if select then
      camera.selected    = true
      camera.lastCamera  = selectedCamera        -- 🔑 压栈：记住"上一个"
      selectedCamera     = camera
    else
      camera.selected    = false
      camera.deactivateIn = deactivateTime       -- 🔑 不立即断电，延迟 N tick
      if selectedCamera == camera then
        -- 🔑 弹栈：沿父指针一路回退，直到遇到一个还处于选中态的
        while selectedCamera ~= nil and not selectedCamera.selected do
          nextCamera = selectedCamera.lastCamera
          selectedCamera.lastCamera = nil
          selectedCamera = nextCamera
        end
      end
    end
  end
end

function toDeactivate(camera)
  if camera.deactivateIn > 0 then
    camera.deactivateIn = camera.deactivateIn - 1
    return true
  end
  return false
end

cameras = {Camera(), Camera(), Camera(), Camera(), Camera(), Camera()}

function onTick()
  for i = 1, 6 do
    update(cameras[i], input.getBool(i))
    -- 🔑 输出 = 「当前选中」或「正在延迟断电中」
    output.setBool(i, selectedCamera == cameras[i] or toDeactivate(cameras[i]))
  end
end
```

- 🔑 **父指针链 = 最省字符的栈**：不用 `table.insert/remove`，每个节点只存一个 `lastCamera`。栈顶就是全局 `selectedCamera`。弹出时把 `lastCamera` 置 `nil` 顺手断链，天然不会成环。
- 🔑 **`while selectedCamera ~= nil and not selectedCamera.selected` 是关键判据**：用户可能同时取消多选中的好几个，这一句让回退一次跳到「最新一个还选中的」，而不是逐级慢放。
- 🔑 **延迟断电是摄像头专有的必要设计**：摄像头发图有启动/停止延迟，立即拉低布尔会在切换瞬间丢画面。把「选中」与「使能」解耦——`selected` 是逻辑态，`deactivateIn` 是物理态。
- ⚠ **`toDeactivate` 有副作用（递减计数），一 tick 只能调一次**。写进 `output.setBool(i, cond or toDeactivate(c))` 时要小心：`or` 短路意味着 **`cond` 为真时根本不会递减**——本例恰好正确（正在显示就不用倒计时），但这属于「靠短路语义」的隐晦写法，改动前先想清楚。
- ⚠ **前提是 `selected` 只能通过 `update` 修改**。若在别处直接改 `camera.selected = false`，父指针链不会更新，弹栈逻辑会失配。这类「链表 + 状态字段」的结构，务必把状态修改收敛到唯一入口。
- 关联：`02` §7（边沿锁存供电 + 回环选档，同样是「多路选择」但用轮询而非栈）/ `03` §10（摄像头随雷达稳像）/ `01` §13（同一脚本的时刻格式化与调色板表）
- 完整脚本：`../../../AI相关/_提取暂存/3793679025_vehicle_4.lua`


## §12 **多屏共用一个状态**：副屏只发「单 tick 请求」，主屏边沿接受并回写

- 来源：steam id **3743234498** · 描述页 <https://steamcommunity.com/sharedfiles/filedetails/?id=3743234498> · **载具**（D.O.E. MEGA SUB，`_vehicle_4` 主控制器 96x32 + `_vehicle_5` 倒车控制器 64x32）
- 更新时间：2026-09-04
- 用到：主屏（复合布尔 1 触控 + 复合数值 1 远程请求 / 3-4 触控 XY / 输出 4 路布尔 + 1 路数值）；副屏（复合数值 1 主屏档位 / 2 引擎状态 / 3-4 触控 XY / 输出 2 路布尔 + 1 路数值）
- 亮点：同一辆车有两块屏都能改同一个「档位」，最自然的写法是各存一份 `mode` 互相广播——那必然打架。作者的方案是**状态只有一份真值（主屏持有），副屏改档位时只发一个宽度为 1 tick 的「请求脉冲」，主屏用边沿 + 值域白名单接受后再由自己回写**，副屏显示用的 `mode` 每 tick 从主屏取。

```lua
-- ============ 主控制器 _vehicle_4 ============
engine, mode, last, lastRemote = false, 0, false, 0

function hit(x,y,bx,by,bw,bh)          -- 闭区间：边界像素也算命中
    return x>=bx and x<=bx+bw and y>=by and y<=by+bh
end

function onTick()
    t = input.getBool(1)
    x, y = input.getNumber(3), input.getNumber(4)
    -- 🔑 数值通道传过来是 float，先四舍五入成整数档位再比较
    remote = math.floor(input.getNumber(1)+0.5)

    -- 🔑 接受副屏请求：边沿 + 值域白名单（副屏只要得到倒挡 4/5）
    if engine and (remote==4 or remote==5) and remote~=lastRemote then
        mode = remote
    end
    lastRemote = remote

    if t and not last then                       -- 触控边沿
        if hit(x,y,2,5,18,22) then engine = not engine end
        if engine then
            if     hit(x,y,24,6,18,20) then mode = 1
            elseif hit(x,y,44,6,18,20) then mode = 2
            elseif hit(x,y,64,6,18,20) then mode = 3 end
        end
    end
    last = t

    if not engine then mode = 0 end              -- 🔑 兜底写在最后，统一 clamp
    output.setNumber(1, mode)                    -- 档位广播给副屏（唯一真值出口）
end

-- ============ 倒车控制器 _vehicle_5 ============
mode, request = 0, 0

function onTick()
    t = input.getBool(1)
    x, y = input.getNumber(3), input.getNumber(4)
    mainMode = math.floor(input.getNumber(1)+0.5)
    engine   = input.getNumber(2) > 0.5

    mode = mainMode                              -- 🔑 主屏权威：每 tick 跟随，不持有独立状态
    request = 0                                  -- 🔑 单 tick 脉冲：先清零，命中才置位

    if t and not last and engine then
        if     hit(x,y,5,6,24,20)  then mode, request = 4, 4
        elseif hit(x,y,35,6,24,20) then mode, request = 5, 5 end
    end
    last = t
    if not engine then mode, request = 0, 0 end

    output.setBool(1, engine and mode==4)
    output.setBool(2, engine and mode==5)
    output.setNumber(1, request)                 -- 只在本 tick 非 0
end
```

- 🔑 **「单 tick 脉冲」是跨脚本传递事件最省事的形态**：`request = 0` 写在 `onTick` 开头，命中分支才赋值 —— 天然不会重复触发、不需要对端做边沿检测（对端做也无害）。
- 🔑 **主屏那侧的 `remote ~= lastRemote` 边沿不可省**：若改成 `if remote==4 or remote==5 then mode=remote end`，副屏的档位会**持续压制**主屏，主屏的 F1/F2/F3 按钮将永远无法生效（每次 tick 都被副屏当前值覆盖）。有了边沿，副屏只在「请求变化的那一帧」抢到一次控制权。
- 🔑 **值域白名单 `(remote==4 or remote==5)` 是权限控制**：一块屏能请求的档位集合被硬编码在接收方，任一端改错都不会越权。
- 🔑 **`math.floor(v+0.5)` 是把数值通道当整数用的标准动作**。复合数值是 float，`mode==1` 这类判等必须在取整之后做。
- 🔑 **兜底 `if not engine then mode=0 end` 放在 `onTick` 末尾**：所有输入处理完之后统一收敛状态，避免每个分支各写一次清理。
- ⚠ **副屏的 `mode` 是「上一 tick 主屏的值」**：请求发出的那一帧画面仍是旧档位，下一 tick 才跟上。作者特意让副屏本地 `mode` 立刻置 4/5，使**按下即时有反馈**，真值一两 tick 后被主屏拉回一致 —— 这是「乐观 UI + 权威回写」，写这类结构时要能接受短暂不一致。
- ⚠ **两块屏的 `hit()` 必须口径一致**：本例主屏用闭区间 `>= / <=`，同批另一辆车的脚本用开区间 `> / <`。相邻按钮共享边界像素时，闭区间会**同时命中两个**（本例按钮间有 2 px 间隙所以没事），没有间隙时必须统一成半开区间。
