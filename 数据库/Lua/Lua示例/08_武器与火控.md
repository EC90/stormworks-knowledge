## §1 瞄准门控与开火时序

- 来源：steam id **3242277101** · <https://steamcommunity.com/sharedfiles/filedetails/?id=3242277101> · **载具**（PYOs Tactical data link 3.6）
- 更新时间：**2025-04-11**
- 用到：物理传感器、GPS 传感器、陀螺仪、武器挂点、属性滑块（`atk range` / `aim ready threshold` / `aim offset vertical`）、属性开关（`aim pit`）
- 亮点：**「对准」是连续计数确认而非瞬时判定**（稳住 60 tick 才开火），杜绝抖动误射；瞄准时**直接覆盖姿态目标**而非另起控制回路。

```lua
ammo = PN('ammo'); atk=false; cntatk=0

function onTick()
  local trigger = GN(25)>0.5                            -- 手动扳机（优先）

  if GN(14)>0.5 and atkx~=0 and ammo>0 then atk=true end
  if GN(18)~=0 then atkx,atky,atkz = GN(18),GN(19),GN(20) end   -- 目标世界坐标

  -- （此处先按巡航/航路点算一遍姿态目标，见 06 §1）

  SB(1, false or trigger)                               -- 默认：手动扳机直通
  if atk then
    SN(27,atkx) SN(28,atky) SN(29,atkz)                 -- 目标坐标透传给后续方块

    if aptgtdst < PN('atk range')*0.9 then              -- 进入 90% 射程才瞄准
      APdir, pitT = G2CpsPit({atkx-mapx, atky-mapy, atkz-alt})
      if PB('aim pit') then
        pitT = pitT + PN('aim offset vertical')         -- 弹道下坠补偿 / 抬高瞄准点
      else
        pitT = 0
      end
      rolT = 0                                          -- 瞄准时锁平滚转

      -- 对准判定：航向误差与俯仰误差同时小于阈值
      if math.abs(CD(c,APdir)) < PN('aim ready threshold')
     and math.abs(p-pitT)      < PN('aim ready threshold') then
        cntatk = cntatk + 1
      end
      if cntatk > 60 then                               -- 连续 60 tick（约 1 秒）才算稳
        SB(1,true)
        cntatk = 0
        atk    = false
        ammo   = ammo - 1                               -- 本地记账，不依赖游戏反馈
      end
    end
  end

  if rps < 5 then ammo = PN('ammo') end                 -- 引擎停车 => 重新装填计数
end
```

**要点**
- 🔑 **连续计数确认**（`cntatk > 60`）是火控可靠性的核心：单帧阈值判定会在机体微抖时反复触发/中断。60 tick ≈ 1 秒，是手感与安全的折中。
- **双轴同时判定**：航向用圈单位角差 `CD(c,APdir)`（`04` §1.2），俯仰直接比 `p-pitT`。
- `rolT=0` **锁平滚转**——避免带坡度射击产生横向偏差。
- `ammo` 在**脚本内记账**，并在 `rps<5`（停车）时从属性重载：不依赖游戏的弹药反馈，逻辑自洽且可调。
- `SB(1, false or trigger)` 让**手动扳机始终优先**，自动开火只是并联一路——「手动直通 + 自动并联」的写法值得照抄。
- `PN('atk range')*0.9` 留 10% 余量，防止在极限距离反复进出判定。
- 射程、对准阈值、弹道补偿**全部走属性**：同一脚本换载具只需调属性，不改代码。

- 完整脚本：`../../../AI相关/_提取暂存/3242277101_vehicle_84.lua`
- 关联：`06_导航制导与自动驾驶.md` §1（`G2CpsPit` / `CD` / `pid`）

## §2 雷达目标 ⇄ 世界坐标（`R2G` / `G2L` / `L2AE`）

- 来源：steam id **3267716101** · <https://steamcommunity.com/sharedfiles/filedetails/?id=3267716101> · **载具**（PYO's ANTICAUSAL FCS Modern Tank Build Demo）
- 更新时间：**2026-06-25**
- 用到：雷达（8 目标 × 4 值）、物理传感器（欧拉角）、GPS 传感器、激光测距仪
- 亮点：一套自洽的球面/笛卡尔互转函数；**矩阵函数在这里是真被调用的**（对比 `06` §1 里 3242277101 的同名函数全是死代码）。

### 2.1 工具函数

```lua
Math=math; pi=Math.pi; P2=pi*2
MathCos,MathSin,MathAtan = Math.cos, Math.sin, Math.atan
MathFlr,MathSqr,MathAbs  = Math.floor, Math.sqrt, Math.abs
Tbl = table
function MathRnd(f) return Math.floor(f+0.5) end
function MathClamp(v,min,max) return Math.max(min,Math.min(v,max)) end

-- 把「允许的横向偏移(米)」换算成「允许的角度(圈)」：距离越远，同样的米数对应越小的角度
function Dist2Turn(Dist,Delta) return MathAtan(Delta,Dist)/P2 end

-- 欧拉角(弧度) -> 3x3 旋转矩阵
function E2R(e)
  local x,y,z = e[1],e[2],e[3]
  return {
    { MathCos(y)*MathCos(z), MathCos(x)*MathCos(y)*MathSin(z)+MathSin(x)*MathSin(y), MathSin(x)*MathCos(y)*MathSin(z)-MathCos(x)*MathSin(y)},
    {-MathSin(z),            MathCos(x)*MathCos(z),                                  MathSin(x)*MathCos(z)                              },
    { MathSin(y)*MathCos(z), MathCos(x)*MathSin(y)*MathSin(z)-MathSin(x)*MathCos(y), MathSin(x)*MathSin(y)*MathSin(z)+MathCos(x)*MathCos(y)}
  }
end
function tM(e) local k={{},{},{}} for i=1,3 do for j=1,3 do k[i][j]=e[j][i] end end return k end
function Mv(m,u)                                     -- 矩阵 × 列向量
  local o={}
  for i=1,3 do local s=0 for j=1,3 do s=s+m[j][i]*u[j] end o[i]=s end
  return o
end
```

### 2.2 三个核心换算

```lua
-- Radar(距离m, 方位角圈, 仰角圈) -> GPS 世界坐标(东, 北, 上)
function R2G(d)
  local k = Mv(tM(E2R(SelfEul)), {                       -- 注意是 转置(M)·局部
    d[1]*MathCos(d[3]*P2)*MathSin(d[2]*P2),              -- 东：sin 给 X
    d[1]*MathCos(d[3]*P2)*MathCos(d[2]*P2),              -- 北：cos 给 Y
    d[1]*MathSin(d[3]*P2)                                -- 上：sin(仰角)
  })
  return {k[1]+SelfPos[1], k[2]+SelfPos[2], k[3]+SelfPos[3]}
end

-- GPS 世界坐标 -> 机体系局部坐标
function G2L(O)
  return Mv(E2R(SelfEul), {O[1]-SelfPos[1], O[2]-SelfPos[2], O[3]-SelfPos[3]})
end

-- 局部笛卡尔 -> (方位角, 仰角)，单位「弧度」
function L2AE(P)
  local f,j,n = P[1],P[2],P[3]
  return MathAtan(f,j), MathAtan(n,j)                    -- atan(东, 北), atan(上, 北)
end
```

**要点**
- ✅ 本例**再次印证**权威的球面分解约定：**sin 给东(X)、cos 给北(Y)、sin(仰角) 给上(Z)**
  （与 `../../方块数据/17_传感器与雷达.md` 一致，也与 `03` §3 相同）。
- `R2G` 用 **`tM(E2R(...))`（转置）**，`G2L` 用 `E2R(...)` 本身——正交矩阵的转置即逆，
  所以「局部→世界」与「世界→局部」互为逆转，**不用写求逆**。
- `Dist2Turn(Dist, Delta) = atan(Delta, Dist)/2π` 是个很实用的小工具：
  把「物理尺度」直接换算成「角度阈值」，让合并/门限判定随距离自动缩放。
- `SelfEul` 必须是**弧度**。物理传感器欧拉角输出是**圈**，记得 `*P2`（见下）。

### 2.3 ⚠ 两套方位角约定，混用必错

| 约定 | 表达式 | 东的符号 | 用在 |
| --- | --- | --- | --- |
| **游戏罗盘** | `-atan(东, 北)/2π` | **东为负** | 与游戏罗盘方块 / `compass` 通道对接（`06` §1 `G2CpsPit`） |
| **数学方位角** | `atan(东, 北)` | 东为正 | 内部自洽计算，本例 `L2AE`/`R2G` |

两者都**自洽**——只要 `R2G` 与 `L2AE` 用同一套，`sin/cos` 往返就闭合。
**出错点在于跨界**：拿游戏罗盘的读数直接喂给本例的 `R2G`，或把本例的 `MergedA` 当成罗盘值去驱动舵机，
都会得到**符号相反**的结果（东变成西）。

```lua
-- 若需要从「游戏罗盘」转到「数学方位角」：取负即可
mathAzimuth = -compassReading
```

**输入单位核对**（本例 `onTick` 的取值）：

```lua
SelfPos = {GN(4), GN(8),  GN(12)}      -- 本例用的是已换算过的东/北/上
SelfEul = {GN(16), GN(20), GN(24)}     -- ⚠ 原始物理传感器是「圈」，进 E2R 前须 *P2
```

## §3 多目标管理与数据关联（距离自适应合并阈值）

- 来源：同上（3267716101，block#1「radar to gps for fcs rebuild」）
- 亮点：**判定新回波「是不是已有目标」时，阈值随距离自动收紧**；快速目标自动放宽；每帧多回波先求质心再入历史。

```lua
MergeDist = PN('merge dist')
for inputN=1,8 do                                  -- 8 路雷达目标
  if GN(4*inputN-3) > 25 then                      -- 距离 > 25m 才采纳
    same = 0
    local tempTGT = {rdr = {GN(4*inputN-3), GN(4*inputN-2), GN(4*inputN-1)}}
    tempTGT.pos = R2G(tempTGT.rdr)

    for TGTn=1,#TGT do                             -- 与已有目标逐一比对
      local dA = MathAbs(TGT[TGTn].rdr[2]-tempTGT.rdr[2])   -- 方位角差
      local dE = MathAbs(TGT[TGTn].rdr[3]-tempTGT.rdr[3])   -- 仰角差
      local dR = MathAbs(TGT[TGTn].rdr[1]-tempTGT.rdr[1])   -- 距离差
      -- 允许的角差 = 基础 0.002 圈 + (合并距离 + 目标速度) 在该距离上对应的角度
      local tol = Dist2Turn(TGT[TGTn].rdr[1], MergeDist + TGT[TGTn].va)
      if dA < 0.002 + tol
     and dE < 0.002 + tol
     and dR < 0.02*TGT[TGTn].rdr[1] + MergeDist + TGT[TGTn].va then
        table.insert(TGT[TGTn].pb, tempTGT.pos)    -- 归入已有目标：本帧多回波先收集
        TGT[TGTn].life = 0                         -- 刷新存活计时
        same = 0
        break
      else
        same = 1
      end
    end
    if same > 0 then                               -- 都不匹配 -> 新建目标
      tempTGT.pb={tempTGT.pos}; tempTGT.bfr={}; tempTGT.vel={0,0,0}
      tempTGT.va=0; tempTGT.life=0; tempTGT.id=NewID
      NewID = NewID + 1
      table.insert(TGT, tempTGT)
    end
  end
end

-- 过期剔除：life > 10 tick 视为丢失
for i=1,#TGT do
  if TGT[i].life > 10 then table.remove(TGT,i) break end
end
```

**要点**
- 🔑 **阈值随距离自动收紧**：`Dist2Turn(距离, 合并距离)` 把「米」换算成「圈」。
  远处同样的角度误差对应更大的横向距离，所以远处必须更严格——这是正确的方向，别写反。
- **速度参与容差**：`MergeDist + TGT.va`（va = 速度模长）。快速目标一帧内位移大，合并窗口必须放宽，
  否则会被反复判定成新目标（**这是多目标跟踪最典型的 bug**）。
- **本帧多回波先求质心再入历史**（`pb` → `bfr`），避免同一目标被 8 个通道重复计数。
- 过期判定用 `life` 计数器而非时间戳，配合 `life=0` 刷新，简单可靠。
- `table.remove(TGT,i)` 后立刻 `break` —— **每 tick 只删一个**，既避免遍历中删除的下标错位，
  又把最坏耗时压到 O(1)（下一 tick 继续删）。这是高频 list 清理的实用写法。

## §4 提前量解算（速度外推 + 自适应平滑窗口）

- 来源：同上（3267716101）
- 亮点：**平滑窗口长度随目标距离自适应**（远目标用更多样本压噪声）；用平均速度外推得到**提前量 `guess`**。

```lua
AvrgT = PN('average ticks')          -- 平滑窗口基准（属性可调）
VelT  = PN('v ticks')

-- 本帧多回波 -> 质心 -> 入历史缓冲
local SplS = #TGT[CurTGT].pb
local Sx,Sy,Sz = 0,0,0
for pbn=1,SplS do
  Sx = Sx + TGT[CurTGT].pb[pbn][1]
  Sy = Sy + TGT[CurTGT].pb[pbn][2]
  Sz = Sz + TGT[CurTGT].pb[pbn][3]
end
table.insert(TGT[CurTGT].bfr, {Sx/SplS, Sy/SplS, Sz/SplS})

-- 窗口裁剪
if #TGT[CurTGT].bfr > AvrgT then
  for t=1,#TGT[CurTGT].bfr-AvrgT do table.remove(TGT[CurTGT].bfr,1) end
end

-- 🔑 自适应：距离越远 -> 参与平均的样本越多（远处噪声大，需要更强的平滑）
SplCal = MathClamp(MathRnd(TGT[CurTGT].rdr[1]/2000*AvrgT), 1, #TGT[CurTGT].bfr-1)
TGT[CurTGT].spl = SplCal

if #TGT[CurTGT].bfr > 2 then
  local SumXYZ = {0,0,0}
  for n=#TGT[CurTGT].bfr, #TGT[CurTGT].bfr-SplCal+1, -1 do      -- 倒序取最近 SplCal 个
    for xyz=1,3 do SumXYZ[xyz] = SumXYZ[xyz] + TGT[CurTGT].bfr[n][xyz] end
  end
  for xyz=1,3 do
    local newPos  = TGT[CurTGT].pos[xyz]
    local avgPos  = SumXYZ[xyz]/SplCal
    TGT[CurTGT].pos[xyz] = avgPos
    -- 速度 = 位置差分的滑动平均
    TGT[CurTGT].vel[xyz] = Avrg(TGT[CurTGT].vb[xyz], avgPos-newPos, VelT)
    -- 🔑 提前量：当前位置 + 速度 × 预测时间
    --    预测时间 ∝ (spl+5)*0.5，spl 随距离增大 = 弹丸飞行时间补偿
    TGT[CurTGT].guess[xyz] = avgPos + TGT[CurTGT].vel[xyz]*(TGT[CurTGT].spl+5)*0.5
  end
  TGT[CurTGT].va = MathSqr(TGT[CurTGT].vel[1]^2
                         + TGT[CurTGT].vel[2]^2
                         + TGT[CurTGT].vel[3]^2)
end
```

### 4.1 `Avrg`：O(1) 摊销的滑动平均

```lua
function Avrg(tbl,value,time)
  time = Math.max(MathRnd(time),1)
  Tbl.insert(tbl,value)                 -- 总是先插入
  if #tbl > time then
    -- ⚠ 注意 break：每 tick 只删一个，而非一次删到目标长度
    for i=1,#tbl-time do Tbl.remove(tbl,1) break end
  else
    time = #tbl
  end
  local sum=0
  for i=1,time do sum = sum + tbl[i] end
  return sum/time
end
```

> **这是刻意的性能取舍**：一次删到位的写法每 tick 是 O(n)；只删一个是 O(1)，
> 代价是表长稳定在 `time+1` 而非 `time`（多留一个元素）。在每 tick 都要跑的跟踪循环里，这个取舍是划算的。

**要点**
- 🔑 **自适应平滑**：`SplCal = clamp(round(距离/2000 × AvrgT), 1, 样本数-1)`。
  远目标噪声大 → 多用样本平均；近目标响应要快 → 少用样本。**比固定窗口好得多**。
- **速度用"位置差分 + 滑动平均"**得到，而不是直接差分——直接差分的噪声会被提前量放大。
- **提前量 = 位置 + 速度 × 预测时间**，其中预测时间随距离增大（弹丸飞行时间）。这就是简化的**前置量解算**。
- 倒序取最近 N 个样本（`for n=#bfr, #bfr-SplCal+1, -1`）比正序切片省字符。
- 全部阈值走属性（`merge dist` / `average ticks` / `v ticks`），换炮换弹只需调属性。

## §5 🔑 反因果火控核心：实测散布修正表（广播 + 逐发解码）

- 来源：steam id **3267716101** · block#4「HAC Build Accuracy Data」（广播端）+ block#0（解码端）
- **「ANTICAUSAL（反因果）」名字的由来**：Stormworks 火炮散布是**伪随机但确定性**的——同一门炮的散布序列由内部种子决定、逐发推进，第 N 发偏多少是可复现的。作者实测 100 发、记下每发落点偏移做成修正表；实战中**第 N 发开火之前就把炮口预先反向偏移**，让散布被表"抵消"。在原因（开火）发生前就知道了结果（落点），故名反因果。

### 5.1 广播端：每打一发推进一格

```lua
ofst = { 101521,392249,350689, ... ,846491 }   -- 100 个六位整数 = 100 发的实测散布
cnt2 = 1
function onTick()
  if loaded and not GB(1) then cnt2 = cnt2 + 1 end   -- 装填→击发的下降沿：换下一发
  loaded = GB(1)
  if loaded then add = 1e6 else add = 0 end
  out = (cnt2 > #ofst) and 500500 or ofst[cnt2]       -- 越界给哨兵值
  SN(1, out + add)                                     -- 数据 + 状态位同路传输
end
```

- ⚠ 推进节奏是**每发一格**（loaded 下降沿），不是每 tick——这保证「表下标 = 弹序」。
- 源码里的 `cnt1=-200` 是**死代码**（模板残留，未参与任何逻辑），别被它误导去找"上电延迟"逻辑。
- 🔑 一路数字通道三用：**散布修正值 + 装填状态位（`+1e6`）+ 哨兵值 `500500`（表尾）**。

### 5.2 修正量编码：六位整数 = XXX/YYY 双轴偏移

一个数字同时装下左右与上下两个偏移量（解码端在炮塔主控 block#0）：

```lua
FixRaw = GetNum(12) % 1e6                          -- 剥掉高位状态位
FixRawX = kAcc * (MathFlr(FixRaw/1e3) - 5e2) / 5e5 -- 高 3 位：X 左右，500=零点
FixRawY = -kAcc * (FixRaw % 1e3 - 5e2) / 5e5       -- 低 3 位：Y 上下（负号=俯仰约定）

-- 旋转到炮管当前朝向后叠加进瞄准（BreechDir 由属性+传感器合成）：
-- ⚠ 必须先存 FixRawX/FixRawY 再旋转，直接原位更新会用到被覆盖的值
FixX = FixRawX*MathCos(BreechDir) + FixRawY*MathSin(BreechDir)
FixY = -FixRawX*MathSin(BreechDir) + FixRawY*MathCos(BreechDir)
GunX = Pid(1, Cps2Delta(-GunCps, AimTGTX + AimOfstX + FixX)*Pi2, ...)
GunY = Pid(2, GunPit, AimTGTY + AimOfstY - ShellDrop/Pi2 + FixY, ...)
```

| 位段 | 含义 | 换算 |
| --- | --- | --- |
| 高 3 位 `XXX` | 左右偏移，500=居中 | `kAcc×(X−500)/5e5` 圈 |
| 低 3 位 `YYY` | 上下偏移，500=居中 | `−kAcc×(Y−500)/5e5` 圈 |
| `+1e6` 状态位 | 「炮已装填」 | `kLoaded=floor(v/1e6)`，兼作高低机增益复位 |

- 修正量在**所有瞄准模式**（锁定/稳定/手操）里都叠加进 PID 目标；未锁定时瞄准镜还画 `ScpX=−FixX*8` 让炮手看见偏移。

## §6 导弹飞行控制：三段制导 + 增益调度 + 近炸引信

- 来源：steam id **3524040776**（FFG171 Mini Aegis 'Changjiang'，2026-06-25，×28 份）
  / steam id **3584922070**（M500 Demo，2026-07-04）—— **两者用的是同一套 `FireEye MP FlightCon`**，M500 是该弹的演示载具。
- 用到：物理传感器、GPS、雷达/导引头、舵机、属性滑块（制导律全部参数化）
- 亮点：**中段 PID 追提前点 → 中末段半主动雷达 → 末段比例导引(PN)** 三段自动切换；
  目标丢失时**靠最后已知速度外推**；ETA 与提前量由接近速率反解；**近炸引信**由 ETA 与「已错过」双条件触发。

### 6.1 目标更新与记忆外推（coasting）

```lua
-- tgt  = 数据链/导引头给出的目标坐标；tgtv = 外部给的目标速度（可能为 0）
-- life = 距上次收到目标更新经过的 tick
if tgt[1]~=0 then                                   -- ① 有更新
  if life>0 then
    -- 外部没给速度时自估：位置差分 / 帧数；用「位移/帧 < 8」滤掉目标跳变
    if tgtv[1]==0 and dst(tgto,tgt)/life<8 and life<600 then
      tgtgv = {(tgt[1]-tgto[1])/life, (tgt[2]-tgto[2])/life, (tgt[3]-tgto[3])/life}
    else
      tgtgv = {0,0,0}
    end
  else
    tgtgv = (tgtv[1]~=0) and tgtv or {tgt[1]-tgto[1], tgt[2]-tgto[2], tgt[3]-tgto[3]}
  end
  life=0; tgtg=tgt; tgto=tgt                        -- 刷新基准
else                                                -- ② 丢失更新：外推
  life=life+1
  if life<PN('lifespan') then
    tgtg = {tgto[1]+tgtgv[1]*life, tgto[2]+tgtgv[2]*life, tgto[3]+tgtgv[3]*life}
  else
    tgto={0,0,0}; tgtg={0,0,0}; tgtgv={0,0,0}       -- 超时放弃
  end
end
```

**要点**
- 🔑 **`life` 计数 + 速度外推**就是导弹的「记忆」：数据链瞬时中断时不会立刻失控，靠最后已知速度继续飞。
- 速度自估的**有效性判据** `dst(tgto,tgt)/life < 8` 很关键——目标 ID 跳变或数据跳点会让差分速度爆掉，必须先过滤。
- `PN('lifespan')` 是外推上限，超过就放弃目标（避免无限期追一个陈旧航迹）。

### 6.2 ETA 与提前量

```lua
-- tgtd = 当前距离；tgtdd = 接近速率（负值表示在接近）
tgtdd = Av(temp, Mp(dst(tgtg,Sp)-tgtd, -3*vz, 3*vz), 4)    -- 滑动平均 4，并用 ±3倍弹速限幅
tgtd  = dst(tgtg,Sp)
eta   = Mp(-tgtd/tgtdd + PN('Lead offset'), 0, PN('Max Lead'))
-- 提前点 = 目标当前位置 + ETA × 目标速度 + 弹道高度偏置
aim   = {tgtg[1]+eta*tgtgv[1], tgtg[2]+eta*tgtgv[2], tgtg[3]+eta*tgtgv[3]+zofst}
```

**要点**
- **ETA = −距离 / 接近速率**。接近速率**必须先平滑再限幅**：雷达测距抖动会让 ETA 剧烈跳变。
  限幅用 `±3×弹速`（物理上不可能超过），滤掉异常值。
- 提前量 = `ETA × 目标速度`，再叠加弹道高度偏置 `zofst`。

### 6.3 弹道规划：高抛 / 低伸自动切换

```lua
if tgtg[3] < PN('path active alt')+zstart then        -- 目标高度低于「弹道激活高度」
  local tgtdh = dst({tgtg[1],tgtg[2],0},{Sp[1],Sp[2],0})     -- 水平距离
  if Sp[3]<PN('path height') and tgtdh>PN('path active dist')*2 then
    zofst = 30000*Mp(tgtdh/PN('path active dist'),0,1)       -- 远距离：大幅拉高
  else
    zofst = Mp((tgtdh-PN('path active dist'))/PN('path active dist'),0,1)*PN('path height')
  end
else
  zofst = 0                                            -- 目标够高：直接瞄准
end
```

打**低空/地面目标**时先爬到弹道高度再俯冲（省能量、避开地形、改善导引头视角），
接近到 `path active dist` 后线性下降到目标高度。打高空目标则直接瞄准。

### 6.4 🔑 三段制导切换

```lua
-- 增益调度：发射渐入 × 速度渐入 × 近距放大
Ksd   = Mp(launch/PN('Start Delay'),0,1)
Kv    = Mp(vz/60,0,1)
Knear = 1+PN('K end')*Mp(200-tgtd,0,1)
K     = Ksd*Kv*Knear

if tgtd < PN('PN active distance') then
  -- ① 末段：比例导引（PN）—— 把「视线角速度」驱到 0
  ao = pid(3, GN(18), 0, PN('K pn'), 0.06*PN('K pn'), 0, 1,   0.3)
  eo =-pid(4, GN(19), 0, PN('K pn'), 0.06*PN('K pn'), 0, 1,   0.3)
elseif tgtd < PN('radar fin active distance') and GN(20)~=0
   and (-tgtdd*60>vz*PN('radar fin active velocity') or GN(23)>0.5) then
  -- ② 中末段：半主动雷达舵 —— 直接跟随雷达偏差 × 固定增益
  ao = GN(20)*PN('K radar fin')
  eo = GN(21)*PN('K radar fin')
else
  -- ③ 中段：PID 追踪提前点（ta/te = 提前点的方位/仰角误差）
  ao =-pid(1, ta, 0, PN('P')*K, PN('I')*K, PN('D')*K, PN('P max'), PN('I max')*K)
  eo =-pid(2, te, 0, PN('P')*K, PN('I')*K, PN('D')*K, PN('P max'), PN('I max')*K)
end
```

| 段 | 判据 | 制导律 | 特点 |
| --- | --- | --- | --- |
| 中段 | 距离最大 | PID 追**提前点** | 省能量、修正弹道偏差 |
| 中末段 | 进入雷达舵距离 且 接近速度够大 | 比例放大雷达偏差 | 响应快、无需积分 |
| 末段 | 进入 PN 距离 | **比例导引**（视线角速度→0） | 命中率最高 |

**要点**
- **PN 的本质**是「把视线角速度驱到 0」——即让导弹速度矢量与目标视线的相对转动为零，此时必然碰撞拦截。
  实现上就是拿导引头给出的视线角速度（GN(18)/GN(19)）当误差做 PID。
- **增益调度三项相乘**：`Ksd`（发射后渐入，避免离轨瞬间满舵）、`Kv`（速度未建立时减小增益）、`Knear`（近距放大，提高末端精度）。
  这是导弹自动驾驶的标准做法，比固定增益稳得多。
- **切换条件带速度判据**：`-tgtdd*60 > vz*K`（接近速度换算成 m/s 后要大于弹速的某个倍数），
  防止低速接近时过早切到雷达舵导致振荡。

### 6.5 速度矢量补偿与 PID 积分清空

```lua
-- 用弹体自身速度方向修正瞄准角（补偿风偏 / 弹道弯曲）
Kv = Mp(vz/60,0,1)
if vz>30 then
  ta,te = taa - Ma(vx,vz)*Kv, tea - Ma(vy,vz)*Kv
else
  ta,te = taa, tea
end

-- 🔑 目标切换（guess 标志上升沿）时清空 PID 积分，防饱和与突变
if GN(22)>0.5 and guessolf<0.5 then Is={} Ds={} end
guessolf = GN(22)
```

> **积分清空是目标切换场景的必做动作**：带着上一个目标的积分去追新目标，会让导弹先朝错误方向猛打舵。
> 用「标志位上升沿」（当前为 1、上一 tick 为 0）触发，而不是每 tick 判断。

### 6.6 近炸引信（VT fuze）

```lua
-- 条件①：ETA 小于引信阈值，且距离处于有效区间
fseta  = (-tgtd/tgtdd < PN('VT Fuse tick')) and tgtdo>0 and tgtdo<50
-- 条件②：已经错过目标 —— ETA 变大 且 距离开始增大 且 已足够近
fsmiss = eta>etao and tgtdd>1 and tgtdo<50 and tgtdo>0 and tgtd<50 and etao<10
vtfuse = fseta or fsmiss
```

**要点**
- **双条件**：既看 ETA 到阈值，也看「距离由减转增」（已经飞过目标）。
  只用 ETA 会在接近速率异常时漏炸；只用距离会在高速下错过窗口。
- `tgtdo`/`etao` 是**上一 tick 的值**——判断"由减转增"必须保存历史。
- `tgtdo>0 and tgtdo<50` 是有效性区间，防止距离刚初始化时误触发。

### 6.7 配套细节：滑动平均的启动保护

引信脚本（同作品 `_vehicle_102`）里的 `Av` 多了一道保护：

```lua
function Av(tbl,value,samples)
  samples = M.max(Mf(samples),1)
  table.insert(tbl,value)
  if #tbl>samples then for h=1,#tbl-samples do table.remove(tbl,1) break end end
  local g=0; for h=1,#tbl do g=g+tbl[h] end
  if #tbl<10 then return 0 end        -- ⚠ 样本不足时返回 0，而非垃圾均值
  return g/#tbl
end
```

> **这是很值得抄的细节**：滑动平均在启动阶段样本不足时，均值会被最初的几个值主导，
> 直接喂给控制律会造成启动冲击。返回 0（或哨兵值）直到攒够样本。

## §7 导弹数据链：跳频 + ID 匹配下发目标

- 来源：steam id **3464467373**（PYO's HQ-11E Area Defense System，2025-04-30，**×39 份 = 每枚导弹一份**）
- 用到：无线电收发、属性/复合通道（密钥与目标 ID）
- 亮点：**发/收两端用同一个「时间 + 密钥」函数生成跳频图案**，无需同步信号；目标坐标按 **ID 匹配**下发，只接收属于自己的那一份。

```lua
function Mf(x) return M.floor(x+0.5) end
mF = M.floor
P  = M.pi*2
SLID = {0,0,0,0,0}          -- 自身的分级 ID
Key  = 0                    -- 跳频密钥（发射前由载具写入）

function onTick()
  local parent = GN(13)~=0                       -- 是否还挂在发射架上
  if parent then                                 -- 在架上时：从载具读取配置
    SLID     = {GN(2),GN(3),GN(4),0,0}
    Key      = GN(8)
    parentID = GN(13)
    target   = {GN(27),GN(28),GN(29)}
    timer1   = 0
  end

  Time = GN(9)
  -- 🔑 跳频图案：时间 + 密钥 伪随机，收发两端同式即可对齐（无需额外同步信道）
  mainFreq = mF(100 + 400*(M.sin(1000*Time+Key)+1))

  if timer1<120 and not parent then timer1=timer1+1 end

  if timer1>10 then                              -- 计算本弹的转发频率
    if SLID[1]~=0 then
      rtFreq = mainFreq+SLID[1]; SLID[4]=SLID[2]; SLID[5]=SLID[1]
    elseif SLID[3]~=0 then
      rtFreq = mainFreq+parentID; SLID[4]=SLID[3]; SLID[5]=parentID
    end
    Freq = rtFreq
  end

  if timer1>11 and timer1<20 then                -- 窗口①：尝试转发频
    if GN(17)~=0 then rt=true end
  end

  if timer1>20 then                              -- 窗口②：按是否收到决定用哪个频
    if rt then
      Freq = rtFreq
      if SLID[4]==mF(GN(20)/1e3) then            -- ID 匹配才接受目标
        target = {GN(17),GN(18),GN(19)}
      end
    else
      Freq = mainFreq                            -- 回退主频
      if GN(1)==SLID[5] then
        if SLID[4]==1 then
          target = {GN(5),GN(6),GN(7)}
        elseif SLID[4]==mF(GN(15)/1e5) then
          target = {GN(10),GN(11),GN(12)}
        end
      end
    end
  end

  SN(1,target[1]) SN(2,target[2]) SN(3,target[3])
  SN(4,GN(13))
  SN(32,Freq)                                    -- 把本弹当前频率写回无线电
end
```

**要点**
- 🔑 **跳频靠「同式推导」而非「信令同步」**：收发两端各自算 `f(Time, Key)`，
  只要时钟（tick）与密钥一致就自动同频。`mainFreq = 100 + 400*(sin(1000*Time+Key)+1)` 映射到 `[100,900]`。
  **密钥 `Key` 在发射前由载具写入**（挂在架上时读 `GN(8)`），发射后固定。
- **ID 匹配**：`SLID[4] == mF(GN(20)/1e3)` —— 把 ID 编码进数值的高位（除以 1e3 再取整），
  一路通道同时传「数据 + 归属 ID」，只接收属于自己的目标更新。
  这个「**数值里塞 ID**」的思路与 `08` §5 的「数值里塞状态位」是同一类技巧。
- **三级频率协商**：主频 → 转发频（尝试窗口 tick 11~20）→ 失败则回退主频。
  `timer1` 单一计数器驱动整个时序，比多个标志位清晰。
- **×39 份副本**说明这套脚本是**每枚导弹独立一份**（各自算自己的频率与 ID），
  而不是载具统一广播——这是多弹齐射时避免互相干扰的关键。

## §8 坦克炮火控：迭代弹道积分解算（落角 + 提前量 + 稳定器）

来源：steam id **3261800786** · <https://steamcommunity.com/sharedfiles/filedetails/?id=3261800786> · **载具**（ZTQ-15，脚本 `ztq15cmdf2`）——在 §2 的 `R2G/G2L` 与 §4 的提前量基础上，进一步把**弹道下坠**和**飞行时间**纳入闭环，用迭代积分求命中角。

**武器弹道档案**（每型弹一组，落角/初速/阻力都不同）：

```lua
WP = {
  {rg=1000, lf=150, v0=1000, dg=0.98, dw=0.002},   -- rg=有效射程 lf=积分步数 v0=初速 dg=每步速度保持率
  {rg=1000, lf=120, v0=1600, dg=0.975, dw=0.0025},
}
```

**飞行时间 `eta` 与落角 `dP`** 用射程 `D` 的二次多项式拟合（实弹标定得到）：

```lua
eta = 1.56 + 0.0695*D + 9.53E-06*D^2           -- 弹飞到目标的时间（s）
dP  = -1.06E-03 - 2.08E-05*D - 4.21E-09*D^2    -- 所需仰角补偿（圈）
```

**迭代积分求提前点 + 落角修正**（靶在动 → 先用 `eta` 外推提前点 `A`，再一步步积分弹道看是否越过靶距，越界就修正 `dP`）：

```lua
if arm then                                       -- 在射程内才解算
  A = {Tp[1]+Tv[1]*eta, Tp[2]+Tv[2]*eta, Tp[3]+Tv[3]*eta}   -- 提前点 = 目标 + 速度*飞行时间
  for h=1,4 do                                     -- 最多迭代 4 次收敛
    B = {Sp[1],Sp[2],Sp[3]}                        -- 从炮口积分
    Bv = {vW[1]+bX, vW[2]+bY, vW[3]+bZ}            -- 初速 = 载具速度 + 弹速(在提前点方向)
    for i=1,WP[wp].lf do
      for j=1,3 do B[j]=B[j]+Bv[j]/60 end          -- 每步 1/60s 推进
      Bv[j] = Bv[j]*WP[wp].dg + Ag[j]              -- 速度按阻力衰减 + 重力 Ag
    end
    PD = Dst(B, Sp)
    if PD > D then                                  -- 飞过头了 → 修正落角再算
      dP = dP + Ma(B[3]-Tp[3], D); eta = i; A = {... 回退一步 ...}
      break
    end
  end
end
```

**稳定器**：炮手手抖 `mA%10>0` 时，用陀螺 `GN(10)/GN(11)` 做微调 `Sx,Sy`，PID 把炮稳定在目标：

```lua
if stb then Sx = -GN(10)*1.6; Sy = -GN(11)*0.05 else Sx,Sy = 0,0 end
Xg = pid(3, CD(-gC, (Ta+Ox)/P)*P, 0, 2, 0.002, 3, 0.5, 0.05)   -- 方位闭环
Yg = pid(4, gP, (Te+Oy-dP)/P, 0, 0.2, 0.2, 0.5, 0.25)          -- 高低闭环（含落角 dP）
```

**数据链目标 vs 直瞄目标**：`GN(12)>9` 表示目标来自数据链（敌方被友军标记），否则用本车观瞄 `GN(21..26)`。

**要点**
- 这比 §4 的「匀速外推提前量」更接近实弹：多了**阻力衰减 `dg` + 重力 `Ag`** 的逐步积分，落角 `dP` 才准。
- `eta/dP` 用**二次多项式**而非查表，省字符、够平滑（`00` §7 的预置大表适合更不规则的弹道）。

## §10 来袭导弹探测与自动干扰弹（定方位 + 递减距判据）

- 来源：steam id **2892569502**（ZTZ-96 MBT）

**判据**：来袭导弹 = **方位几乎不动 + 距离快速减小**（碰撞航线特征）。对 8 路雷达逐路判定：

```lua
-- ADD/ADA/ADE = 本帧与上帧的 距离/方位/仰角 差（已先 avg 平滑 30 tick）
if ADD[i] < -0.6 and ADD[i] > -10              -- 距离在快速减小
   and AD[i] > 150 and AD[i] < 700             -- 且在威胁距离窗内
   and math.abs(ADA[i] - clp(dcps,-0.003,0.003)) < 10/62  -- 方位≈不动(扣本机转向)
   and math.abs(ADE[i]) < 10/62 then           -- 仰角也不动
  accta = accta + 1
  if AD[i]/-ADD[i] < 3*62 and AD[i]/-ADD[i] > 0.5*62 then   -- ETA 0.5~3 秒
    acctb = acctb + 1
    aclr = aclr + AA[i]                        -- 累加来袭方位
  end
end
-- 威胁计数经滑动平均确认后才放干扰弹 + 冷却（ct>180 tick）
if acctba > 0.5 and ct > 180 then aclc = true; ct = 0 end
```

**要点**
- **定方位+递减距**是裸雷达识别导弹的最简可靠判据；扣掉本机转向速率 `dcps` 后「方位不动」才成立。

- 滑动平均确认 + 冷却计时，避免单帧虚警把干扰弹打光。

## §11 舰载自动防御：CPA 威胁评估 + 危险等级滞回 + 火力通道分配

- 来源：steam id **3603910667**（CG-32 Asgard，block#90）

8 路雷达目标 → 航迹 → **按 CPA（最近会遇点）算威胁**，按危险等级分配给 4 个火力通道：

```lua
-- 相对位置/速度（扣本舰速度 dsp）
x0,y0 = curt.p[1]-sp[1], curt.p[2]-sp[2]
vx,vy = curt.a[1]-dsp[1], curt.a[2]-dsp[2]
curt.e = -(x0*vx + y0*vy) / (vx^2 + vy^2 + curt.a[3]^2)   -- 🔑 到 CPA 的时间(点积投影)
curt.m = math.abs(x0*vy - y0*vx) / Mr(vx^2 + vy^2)        -- 🔑 CPA 脱靶量(叉积/速率)

-- 危险等级 d=1..3：按 (脱靶量 vs AutoDefendRange) × (CPA时间 vs d1t/d2t) 打分 mc
-- 等级变化带滞回：mc 超过 ±dlsw 才换挡，防止边界抖动
if curt.mc > dlsw and curt.d < 3 then curt.d = curt.d+1; curt.mc = 0
elseif curt.mc < -dlsw and curt.d > 1 then curt.d = curt.d-1; curt.mc = 0 end

-- 火力分配：Dd[等级] 内按 ETA 排序取前 5，slot[5..8] 四通道，
-- 每个通道独立 Fire wait 计时，到点进 fireplan 队列，SB(1) 给发射脉冲
```

**要点**
- 🔑 **CPA 两件套**：相遇时间 = 位置·速度/速率²；脱靶量 = 位置×速度/速率。比「当前距离」更能代表真实威胁（飞掠而过的不打）。
- **危险等级滞回**（计数过 ±dlsw 才换挡）是防等级抖动的标准写法，与 `02` §2 toggle 的迟滞同思想。
- **通道槽位** `slot[e]={x,y,z,id,age,wait}`：age 超时释放、wait 按 ETA 提前点火，多目标时火力不抢同一通道。
- 友军表 F（数据链 fid）先从交战列表剔除，再算威胁。

## §12 导弹制导律大全（PP→MEPN + ZEM 系 + 变导航比 + 双段制导）

- 来源：steam id **2900758088**（Ozelot，NNTC Missile Guidance V5）

同一框架下实现 9 种制导律——核心是把 **LOS（视线角速率）逐阶差分**出来：

```lua
-- LOS 速率的高阶导数链：acc(速度)/jerk(加加速度)/snap
accX  = LOSX - oldLOSX
jerkX = accX - oldAccX
snapX = jerkX - oldJerkX
closingV = clamp((srrDist - oldsrrDist)*60, -10000, -1)   -- 接近速率(负)
tgo = srrDist / math.abs(closingV)                        -- 命中时间

-- ZEM（零效脱靶量）：角误差外推到命中时刻
x1 = math.sin(LOSX*srrDist)
ZEMX = x1 + (x1 - oldx1)*c1tgo

-- 变导航比：越接近命中导航比越小（防末段过修正）
if varnav and tgo > 1 then nc = nc/tgo end

-- 各制导律（command = 横向加速度指令）
if guidlaw==2 then commandX = nc*LOSX end                              -- PN
if guidlaw==3 then commandX = nc*LOSX*closingV end                     -- TPN
if guidlaw==5 then commandX = nc*LOSX*closingV + nc*accX*0.5 end       -- APN(+目标加速度)
if guidlaw==6 then commandX = APN + nc*jerkX*0.25 end                  -- EPN(+jerk)
if guidlaw==7 then commandX = EPN + nc*snapX*0.0625 end                -- MEPN(+snap)
if guidlaw==8 then commandX = srgain*ZEMX / c2tgo^2 end                -- ZEMPN
if guidlaw==9 then commandX = ZEMPN + srgain*accX*0.1 end              -- ZEMAPN
```

**要点**
- **PN 家族系数规律**：PN→TPN 乘 closingV；APN 加 `acc×0.5`、EPN 加 `jerk×0.25`、MEPN 加 `snap×0.0625`——每高一阶系数减半，是抑制差分噪声的标准配置。
- **ZEM 系用 `ZEM/tgo²`**：脱靶量换加速度要除时间平方（匀加速位移公式），这是 ZEM 制导的关键量纲。
- **双段制导**：远距段（`srrDist>=500`）把指令叠加到 LOS 保持上（`command/nc + srr*lrgain`），末段纯 PN——与 §6 的三段制导互补。
- 差分链噪声大，配合 §6.7 的滑动平均保护使用；滚转弹（ras）把横向指令转滚转速率。
- 完整脚本：`../../../AI相关/_提取暂存/2900758088_vehicle_11.lua`

  return px>=bx and px<bx+bw and py>=by and py<by+bh end
function onTick()
  ox=input.getNumber(11) oz=input.getNumber(12) hd=input.getNumber(18)  -- 本舰 x/z/航向(圈)
  locked=input.getBool(1)

    end
  end

  local i=1

    if tracks[i].age>360 then

- 🔑 **平方距离比大小，不开根号**：`d=dx*dx+dz*dz` 与阈值（也是平方）直接比。24 条航迹每帧省 24 次 `math.sqrt`，且完全等价。
- 🔑 **触控"挂起-确认"两段判定**：`tpend`（第一帧）→ 第二帧才读坐标并置 `tfired`。SW 的触控坐标在按下的第一帧往往还是旧值（或 0），直接取会选到错误目标。**"按下后的第二帧才采坐标"是一条通用经验**。
- 🔑 **老化 + 容量双上限**：`age>360`（6 秒）剔除 + `#tracks>tcnt` 砍尾。`tcnt` 由外部通道给，可以随时改变显示条数（如按威胁等级过滤后只留 8 条）。
- 🔑 **`while` + 不前进的 `i` 做原地删除**：`table.remove(tracks,i)` 之后元素前移，所以删除分支里**不能 `i=i+1`**；不删才前进。这是 `for` 循环里删除会漏项的安全替代写法（关联 `07` §2.2 的重建表方案——那里是重建，这里是原地删，都可取，别混用）。
- 🔑 **删除选中目标要同步清空 `sel`**：`if tracks[i].id==sel then sel=nil sout=0 end`，否则输出通道会一直广播一个已不存在的 id。
- 🔑 **D-pad 平移步长 `max(20/zoom, zoom*2)`**：放大视野（zoom 小）时每步走得多、缩小时走得少，手感恒定。中心键一键 `vpx=vpz=0` 并恢复跟随（`lk=true`）。

## §15 弹道落差查表插值※ + FOV↔倍率互换 + 每米像素数测距刻度

- 来源：steam id **3476409039** · 描述页 <https://steamcommunity.com/sharedfiles/filedetails/?id=3476409039> · **载具**（`_vehicle_2`，瞄具屏）
- 更新时间：未取到（本轮 Steam Web API 不可达，下轮补）
- 用到：数值输入 1（激光测距仪※ 距离 0-4000 m）、数值输入 2（FOV 0.0-1.0）、属性文本、显示器
- 亮点：**把实测弹道落差存成稀疏键查表**（键 = 整百米，值 = 该距离的下坠米数），运行时线性插值，**不做外推**；FOV 与光学倍率互相换算；用「目标实高 → 屏上像素高」反推距离刻度（密位测距※ 的正向用法）。

```lua
-- ① 实测落差表：{ [距离 m] = 落差 m }，键稀疏、不必等距、不必从 0 起
local DROP = {
  MG  = { [0]=0.000, [100]=0.269, [200]=1.267, [300]=3.532, [400]=8.484, [500]=24.468 },
  LAC = { [0]=0.000, [100]=0.183, [200]=0.717, [300]=1.798, [400]=3.622, [500]=6.589,
          [600]=11.520, [700]=20.673 },
}

-- ② 查表 + 线性插值：表是哈希，不能按序访问，只能遍历找左右邻居
local function dropAt(tbl, dist)
  if not tbl then return 0 end
  if tbl[dist] then return tbl[dist] end              -- 正好命中整键
  local lo, hi = 0, 0
  for d in pairs(tbl) do
    if d <= dist and d > lo then lo = d end
    if d >= dist and (hi == 0 or d < hi) then hi = d end
  end
  if lo == 0 then return tbl[hi] end                  -- 比表内最近键还近：夹到最近端
  if hi == 0 then return tbl[lo] end                  -- 超出表尾：夹到最大值，不外推
  local r = (dist - lo) / (hi - lo)
  return tbl[lo] + r * (tbl[hi] - tbl[lo])
end

-- ③ FOV(0..1) ↔ 光学倍率：135° 最广（约 1×），1.43° 最窄
local WIDE, TELE = 135, 1.43
local function fovToDeg(f)   return WIDE - f * (WIDE - TELE) end
local function zoomToFov(z)  return 1 - (2 * math.atan(math.tan(math.pi / 180 * 35 / z)) * 180 / math.pi) / (WIDE - TELE) end
local function fovToZoom(f)
  local deg = fovToDeg(f)
  return math.tan(math.pi / 180 * 35) / math.tan(math.pi / 180 * deg / 2)
end

-- ④ 每米占多少像素：已知目标实高，算它在该距离下于屏上占多少像素
local function pxPerMeter(fov, dist, realH, screenDim)
  if dist <= 0 then return 0 end
  local deg = fovToDeg(fov)
  return realH / (2 * dist * math.tan(deg * math.pi / 360)) * screenDim
end

function onTick()
  RANGE = clamp(math.floor(input.getNumber(1)), 0, 4000)
  FOV   = clamp(input.getNumber(2), zoomToFov(7.0), zoomToFov(1.7))   -- 把倍率上下限换算成 FOV 上下限
  output.setNumber(1, FOV)
end

-- ⑤ 测距刻度：把 100/200/…/800 m 处「2.25 m 高的目标」的像素高度画成横向刻度
local function drawRangeScale()
  local baseX, baseY = CX - R * 0.75, CY - CFG.rangeLineY
  local endX = CX + R * 0.5
  screen.drawLine(baseX, baseY, endX, baseY)
  screen.drawTextBox(endX + 1, baseY - 2, 5 * CFG.charWidth + 1, 6, tostring(CFG.targetH), 0, -1)
  for i, rf in ipairs(CFG.ringRanges) do              -- {1,2,3,4,5,6,7,8} → ×100 m
    local dist = rf * 100
    local hpx  = pxPerMeter(FOV, dist, CFG.targetH, R * 2)
    local y    = baseY - hpx
    if y < CY - R then break end                      -- 超出瞄具圆就不再画
    screen.drawLine(endX - (i-1)*12, y, endX - (i-1)*12 - 4, y)
  end
end
```

**要点**

- **为什么是查表而不是公式**：SW 的弹道有空气阻力，且不同口径/初速的衰减曲线完全不一样，解析式写不出来也不准。作者的做法是**在靶场逐百米实测下坠量**，把数字直接填进表里——这是工坊里火控脚本的主流做法，比套抛物线公式靠谱得多。表里的数字必须**自己实测**，不能抄（版本、弹药、倍率都影响）。
- **稀疏键 + `pairs` 找邻居**：表是哈希表，不能 `tbl[i]` 顺序访问，只能遍历。6~8 个键的遍历开销可忽略；但如果要在 `onDraw` 里对上百个目标各查一次，就该预先把键抽成有序数组再二分（或直接把表补成等距数组，用 `dist/100` 当下标）。
- **两端夹取而不是外推**：`lo == 0`（比表内最近键还近）返回 `tbl[hi]`，`hi == 0`（超出表尾）返回最大值。⚠ 这一步很关键——线性外推在 500 m 之后会给出**负落差**或荒谬的大数，炮口直接朝天/朝地。夹取至少保证超程时行为可预测。
- **FOV 归一化**：SW 的缩放输入是 0..1，用 `WIDE - f*(WIDE-TELE)` 映射到实际视场角；倍率↔视场角通过 `tan` 互转（视场角减半时 `tan` 不是减半，必须走三角函数）。⚠ **135 / 1.43 是作者按自己镜头实测的常数，换武器或换瞄具必须重测**。
- **每米像素数是密位测距的核心**：`realH / (2*d*tan(fov/2)) * screenDim`。本例**正着用**（已知距离 → 画刻度）；反过来（已知像素高、已知目标实高 → 解出 `d`）就是密位估距，一份公式两种用法。
- `if y < CY - R then break end`：刻度一旦顶出瞄具圆就跳出循环，`break` 而不是 `continue`——因为距离越远像素高越小、刻度越靠上，一旦出界后面全出界。
- **反面教材（原脚本）**：落差表写成字面量塞在脚本里，两种枪就占了 8 行、约 300 字符；弹种再多会直接撑爆 8192 预算。正确做法是挪到属性文本（见 `01` §10 的 base64 常量流，或 `03` §18 的 16 进制方案）。另外 `dropAt` 若在 `onDraw` 里对每个目标调用，8 键遍历 × 上百目标会让帧率明显下降。
- 关联：`08` §14（坦克炮迭代弹道 FCS——公式派；本例是查表派，两者可互相校验）、`01` §10（大常量挪到属性文本）、`05` §39（同一类屏的控件思路）。

## §16 转塔火控：解析弹道**不动点迭代** + 输出**变化率限幅**驱动 + 丢失转扫描

来源：steam id **3793781426** · <https://steamcommunity.com/sharedfiles/filedetails/?id=3793781426> · **载具**（boat time ST- 001，炮艇）· 更新时间 **2026-09-02**

与 `08` §8（逐步数值积分求落角）不同，这一门走的是**解析弹道 + 不动点迭代求飞行时间**，并且把注意力几乎全放在「**怎么把大减速比转塔驱动得不抖**」上——这是 §8 完全没有覆盖的部分。

**用到**：雷达（距离 / 方位角 / 仰角，**圈**）、转塔角度传感器（圈，可选装减速比前或后）、转管自动火炮（初速 1000 m/s）、1:4 减速齿轮组、机械枢轴（俯仰，±0.25 圈）

**亮点**：① 迭代 4 次的**不动点**求弹丸飞行时间；② 每 tick 只允许输出变化 `MAX_ACCEL` 的**变化率限幅**；③ 目标丢失后按最后速度**惯性外推**，超时转入 270° 扫描（扫描同样走限幅）；④ 用软件状态量 `virtual_barrel_pitch` 代替第二个俯仰传感器。

```lua
-- ① 雷达球坐标 → 机体系：先俯仰、后方位的两级旋转（X东/Y上/Z北，见 17_传感器与雷达）
local rx = dist * math.sin(r_az) * math.cos(r_el)      -- r_az/r_el 已由「圈」×2π 转弧度
local ry = dist * math.sin(r_el)
local rz = dist * math.cos(r_az) * math.cos(r_el)
local yx, yy = rx, ry*math.cos(p_pitch) - rz*math.sin(p_pitch)
local yz      =     ry*math.sin(p_pitch) + rz*math.cos(p_pitch)
local bx = yx*math.cos(p_yaw) + yz*math.sin(p_yaw)
local bz = -yx*math.sin(p_yaw) + yz*math.cos(p_yaw)
```

```lua
-- ② 速度：单帧差分 ×60 → EMA；锁靶头 2 tick 不采样（刚捕获那一帧位置跳变最大）
if lock_ticks > 2 then
  vx = vx + ((bx - last_bx)*60 - vx) * VEL_SMOOTH     -- VEL_SMOOTH = 0.75
end
```

```lua
-- ③ 解析弹道不动点迭代：4 次足够收敛
--    无目标时用最后速度外推，有目标时用当前量测点，两条路径必须写同一个 aim_*
local aim_x, aim_y, aim_z = last_bx, last_by, last_bz
local tof = math.sqrt(aim_x^2 + aim_y^2 + aim_z^2) / BULLET_SPEED
for i = 1, 4 do
  aim_x = last_bx + vx*tof
  aim_y = last_by + vy*tof + 0.5*GRAVITY*tof*tof      -- 只有 Y 吃重力
  aim_z = last_bz + vz*tof
  tof = math.sqrt(aim_x^2 + aim_z^2) / BULLET_SPEED   -- 🔑 迭代用「水平距离」而非斜距
end
local req_yaw   = math.atan(aim_x, aim_z) / pi2                                -- 转回「圈」
local req_pitch = math.atan(aim_y, math.sqrt(aim_x^2 + aim_z^2)) / pi2
```

```lua
-- ④ 变化率限幅（slew-rate limiter）：本例最值钱的一段

if math.abs(req_yaw - cur_yaw) < YAW_DEADBAND then target_speed = 0 end   -- 死区 ~0.36°
if target_speed >  1 then target_speed =  1 end
if target_speed < -1 then target_speed = -1 end

if cur_yaw <= MIN_YAW and target_speed < 0 then target_speed = 0 end

if cmd_diff >  MAX_ACCEL then cmd_diff =  MAX_ACCEL end          -- MAX_ACCEL = 0.08
if cmd_diff < -MAX_ACCEL then cmd_diff = -MAX_ACCEL end
current_yaw_cmd = current_yaw_cmd + cmd_diff                    -- 每 tick 最多变 0.08
output.setNumber(1, current_yaw_cmd)

if lost_ticks > 90 then
  if     cur_yaw >= MAX_YAW - 0.01 then scan_dir = -1
  elseif cur_yaw <= MIN_YAW + 0.01 then scan_dir =  1 end
  local t = scan_dir * SCAN_SPEED
  if cur_yaw >= MAX_YAW and t > 0 then t = -SCAN_SPEED end      -- 端点强制反向
  if cur_yaw <= MIN_YAW and t < 0 then t =  SCAN_SPEED end
  local d = t - current_yaw_cmd
  current_yaw_cmd = current_yaw_cmd + math.max(-MAX_ACCEL, math.min(d, MAX_ACCEL))
  virtual_barrel_pitch = virtual_barrel_pitch * 0.9              -- 扫描时俯仰缓慢回中
  output.setNumber(2, virtual_barrel_pitch * PITCH_GEAR)
  return
end
```

**要点**

- **为什么限幅**：转塔是 1:4 减速的大惯量机构，直接输出 `P×误差` 在误差大时会一步给满速，到目标附近又来不及停 → 来回过冲抖动。`MAX_ACCEL` 把「速度指令」当成**有惯性的一阶系统**来推，实测比加大 D 更稳（D 会放大雷达噪声）。取值经验：先设成满量程的 1/10（这里是 0.08/1.0），抖就再减半。
- **迭代变量选谁**：`tof` 的迭代式用**水平距离 / 初速**。因为重力只作用在 Y 上、水平方向匀速，所以水平距离才是「弹丸真正要走的水平路程」；用斜距迭代会系统性高估。4 次内收敛，再多次纯浪费字符。
- **传感器装在哪**：`SENSOR_ON_OUTPUT` 是个编译期开关。传感器装在减速齿轮**输出端**读数就是真实转塔角；装在**输入端**（机械枢轴侧）要 `×YAW_GEAR` 才是转塔角。接线改了只改这一行，比改公式省事。
- **虚拟炮管俯角**：俯仰由机械枢轴驱动（±0.25 圈，经 1:4 减速到炮管 ±0.0625 圈）。脚本把「枢轴指令 ÷ 减速比」自己积分成 `virtual_barrel_pitch`，**省掉一个俯仰传感器**；代价是它只在自己发指令时准，被外力顶动就失准。
- **同一作品的双轨时间基准**：`lock_ticks` 与 `lost_ticks` 是互斥的两个计数器（有目标时前者 +、后者归零）。想加「锁定 N 秒才开火」就直接判 `lock_ticks > 5`，不必另起计时器。

**反面教材**

- `last_bx` 在两条路径里更新（有目标时 `= bx`，无目标时 `+= vx/60`），**量纲必须一致**（都是机体系米）。本例写对了；若一条存世界系、一条存机体系，重新捕获时提前量会瞬间跳飞。
- 速度用**单帧差分**（不是 §4 的滑动平均）。雷达本身抖动大时这一步会明显放大噪声——本例靠 `VEL_SMOOTH = 0.75` 的 EMA 硬压换来响应速度，取舍与 §4「远目标用多样本」正好相反。

**关联**：`08` §8（逐步积分求落角，精度更高但字符贵）· `04` §12（`Clamp`，本例的限幅是裸比较写法）· `17_传感器与雷达.md`（圈 vs 弧度、机体系约定）· 完整脚本 `../../../AI相关/_提取暂存/_r10c/3793781426_vehicle_0.lua`

## §18 **弹链 / 膛室两级状态的软件推断**：靠「弹药计数下降沿」当移位寄存器 + 全屏按压切 FOV

- 来源：steam id **3793561327** · 描述页 <https://steamcommunity.com/sharedfiles/filedetails/?id=3793561327> · **载具**（M411 ASV，`_vehicle_5` 自动火炮瞄具屏）

- 亮点：游戏里**没有**「弹链里是什么弹 / 膛室里是什么弹」的传感器。这个作品只用「余弹计数减了 1」这一条信息，就推断出两级弹药的流动——本质是一个**两级移位寄存器**，下降沿触发。

```lua

ammoRprev, ammoRtype = 20, 'AP'      -- 右鼓：AP

function onTick()

  inputX, inputY = input.getNumber(3), input.getNumber(4)
  isPressed = input.getBool(1) or input.getBool(2)     -- 兼容两路触控
  ammoL, ammoR = input.getNumber(7), input.getNumber(8)

  roundLoaded = num2bool(input.getNumber(10))

  -- 🔑 整块屏当按钮：命中区就是全屏，按住即放大（松手回 0.8，无需闩锁状态）
  isPressingRectangle = isPressed and isPointInRectangle(inputX, inputY, 0, 0, resX, resY)
  output.setNumber(1, isPressingRectangle and 3 or .8)

  -- 🔑 新弹进弹链 → 原来弹链里那发被推进膛室。两级移位，靠计数下降沿触发
  if ammoR == ammoRprev - 1 then
    inChamber = inBelt
    inBelt    = ammoRtype
    ammoRprev = ammoR
  elseif ammoL == ammoLprev - 1 then
    inChamber = inBelt
    inBelt    = ammoLtype
    ammoLprev = ammoL
  end

  -- 🔑 弹鼓打空时计数不再变化，下降沿抓不到 → 改用「击发沿 + 计数为 0」补一刀
  if roundLoaded and not roundLoadedPrev then
    roundLoadedPrev = true
  elseif not roundLoaded and roundLoadedPrev then
    roundLoadedPrev = false
    if (not ammoSelect and ammoLprev == 0) or (ammoSelect and ammoRprev == 0) then
      inChamber = inBelt
      inBelt    = '-'
    end
  end
end

function isPointInRectangle(x, y, rectX, rectY, rectW, rectH)
  return x > rectX and y > rectY and x < rectX+rectW and y < rectY+rectH
end

function num2bool(x)
  return x == 1          -- ⚠ 严格等于 1，0.999 会被判 false
end
```

- 🔑 **把「计数变化」当事件源**：游戏只暴露 `ammoL` / `ammoR` 两个总量，作者用 `ammo == prev - 1` 这一个判断，把「一发弹离开了弹鼓」翻译成「belt → chamber 移位一次」。凡是只有总量、没有明细的通道，都可以套这个模式。
- 🔑 **下限分支必须单独补**：弹鼓见底后计数恒为 0，下降沿永远不来，最后那发会卡在弹链里显示不出来。所以额外用 `roundLoaded` 的**击发沿**（`true→false`）+ `prev == 0` 把弹链清空。写这类「靠差分推断状态」的逻辑时，**先想清楚边界上差分会不会消失**。
- 🔑 **按住即放大，不需要闩锁**：`isPressingRectangle and 3 or .8` 是「按住」语义，松手自动回到 0.8。想做成「点一下切换」就要加一个 SR 闩锁（见 `05` §29），这里特意不要——瞄准镜按住放大符合直觉，且省掉一个状态变量。
- ⚠ `ammoLprev` / `ammoRprev` 的初值硬编码成 20，等于假设生成时满弹。若弹鼓容量不是 20 或生成时不满，第一发会漏判。稳妥做法是用「上电第一帧把当前值写进 prev」的一次性锁存（见 `01` §12 的属性哨兵值编码）。
- ⚠ `num2bool` 用 `x == 1` 而不是 `x ~= 0`：上游只要有一点噪声（0.98）就会静默判成 false。**做数值→布尔转换时，用 `x > 0.5` 比 `x == 1` 抗噪**。

## §19 航空 HUD 的**角度域投影**：世界坐标 → 方位/仰角 → 像素 → 整体滚转 + **落体时间解析解**

- 来源：steam id **3793553685** · 描述页 <https://steamcommunity.com/sharedfiles/filedetails/?id=3793553685> · **载具**（`_vehicle_2` 三模式 HUD 屏）
- 更新时间：未取到（本轮 Steam Web API 不可达，下轮补）
- 用到：物理传感器（本机 X/Y/Z、罗盘、俯仰、滚转）、目标世界坐标、复合数值 32（HUD 模式）、屏幕
- 亮点：不做完整的 4×4 投影矩阵，而是把「目标相对本机」拆成**水平方位角 + 垂直仰角两个角度**，各自除以半视场角归一到 ±1，再乘半屏尺寸——**滚转则留到最后在极坐标里整体转一次**。

**① 角度域投影 `xyzTransfer`**

```lua
hfov, vfov = 15, 15                 -- 半视场角（度），按自己的镜头标定
renderMargin = 2

function xyzTransfer(cx, cy, x, y, z, selfX, selfY, selfZ, compass, pitch, roll)
  local dx, dy, dz = x - selfX, selfY - y, z - selfZ   -- ⚠ 注意 y 取反：屏幕纵轴向下
  local angleH = math.atan(dx, dz)/math.pi*90 + compass/math.pi*90
  local angleV = math.atan(dy, dist(dx, dz))/math.pi*90 + pitch/math.pi*90
  local px = angleH/hfov*(cx - renderMargin)
  local py = angleV/vfov*(cy - renderMargin)
  -- 🔑 滚转：先转极坐标，加 roll 再转回笛卡尔，中心补回 cx/cy
  local tmpD, tmpA = dist(px, py), math.atan(py, px)
  return math.cos(tmpA + roll)*tmpD + cx, math.sin(tmpA + roll)*tmpD + cy
end
function dist(x, y) return math.sqrt(x*x + y*y) end
```

> ⚠ **调用侧的参数顺序**：SW 世界坐标是 **Y = 高度、Z = 北/南**，而函数签名里 `selfY` 是「竖直方向」。原作者调用时写成
> `xyzTransfer(cx, cy, lockX, lockY, lockZ, selfX, selfAlt, selfY, compass, pitch, roll)`——把**自机高度传给第 6 个参数、自机 Z 传给第 7 个**。
> 抄的时候务必先确认「你的 Y 到底是高度还是北向」，否则画面会上下与前后对调。

**② 落体时间解析解 + 命中点外推**（给定初速与高度差，直接解出落地时间，再乘水平速度得落点）

```lua
vvstart = -tvv_speed * math.sin(tvv_pitch + pitch)   -- 初始垂直速度（向下为正）
vh      =  tvv_speed * math.cos(tvv_pitch + pitch)   -- 水平速度
rh      =  selfAlt - setAlt                          -- 待落的高度差
eti     = (-2*vvstart + math.sqrt(4*vvstart*vvstart + 4*g*rh)) / (2*g)   -- 二次方程正根
targetX = selfX + eti*vh*math.sin(-compass + tvv_hd)
targetY = selfY + eti*vh*math.cos(-compass + tvv_hd)
```

**③ AOA 游标**：目标偏离屏幕中心的**像素距离反推成角度**，画在右侧竖条上

```lua
AOA = dist(px-cx, py-cy) / dist(hfov, vfov) * (hfov+vfov)/2
-- 竖条：10 格刻度，每 5 度标一次数字；游标画两个短斜线当箭头
if AOA <= 40 and AOA >= 0 then
  pygc = (1 - AOA/40)*(pye - pys) + pys
  Line(px-1, pygc, px-4, pygc-3)
  Line(px-1, pygc, px-4, pygc+3)
end
```

- 🔑 **为什么走「角度域」而不是投影矩阵**：HUD 只需要「目标在屏幕哪个方位」，不需要透视正确的大小。把方位角/仰角线性映射到像素（`angle/hfov * halfWidth`）在 ±15° 内误差肉眼不可见，代码量却只有矩阵法的零头。要做**透视缩放 / 遮挡 / 3D 线框**才需要 `05` §42 那套 4×4 管线。
- 🔑 **滚转放在最后一步，用极坐标整体旋转**：先算好「无滚转时的 (px, py)」（相对中心），再 `tmpD = 距离`、`tmpA = 角度`、加 `roll` 后转回，最后补 `cx/cy`。比「对每个顶点套旋转矩阵」省一半代码，也不会因为旋转中心搞错而偏。
- 🔑 **`atan(dx, dz)` 两参直接给方位角**，不用自己判象限（见 `04` §1.2b）。**第一个参数是横向、第二个是纵向**，写反了方位会镜像。
- ⚠ **落体时间的根号可能开出 nan**：`4*vvstart^2 + 4*g*rh` 在「高度差为负（目标比自己高）且上升速度不够」时是负数，`math.sqrt` 返回 nan 并一路污染到下游坐标。抄的时候加一句 `local det = ...; if det < 0 then det = 0 end`（或判定为「够不着」直接不画）。
- ⚠ **反面教材：原脚本的 `roll = GN(9)*pi*2*90/(90 - pitch/math.pi*90)` 不要抄**。分母是 `90 - 俯仰角(度)`，俯仰到 90° 时除零 → `inf`/`nan`；而且把一个「度数量纲」的数和常数 90 相减再当除数，量纲本身就不对。正确做法是让 `roll` 直接等于传感器给的滚转（圈 ×2π），需要补偿时另写显式系数。
- ⚠ **`AOA` 的量纲依赖 `hfov/vfov` 的单位一致**：本例 `hfov` 与 `vfov` 都是 15 度，所以 `dist(px-cx,py-cy)/dist(hfov,vfov)*(hfov+vfov)/2` 化简后就是像素距离按视场角归一化。两轴视场角不同（宽屏）时要分开算，不能合并成一个 `dist`。
- 关联：`05` §42（真正的 3D 软件渲染管线，需要透视时）/ `03` §20（雷达目标叠到地图，同样是「角度 → 像素」）/ `04` §1.2b（最短角差与手写 `atan2`）/ `06` §22（地标表的世界坐标 → 地图）/ `08` §16（转塔火控的迭代弹道；本节是**解析解**，只适用于无阻力自由落体）/ `17_传感器与雷达.md`（圈 vs 弧度）

## §20 吊舱相机的**完整透视投影**：世界点 → 相机系 → 屏幕像素（含变焦与身后裁剪）

- 来源：steam id **3795868371** · 描述页 <https://steamcommunity.com/sharedfiles/filedetails/?id=3795868371> · **载具**（MH-60 Jayhawk 海岸警卫救援直升机，`_vehicle_15` 吊舱准星屏）
- 更新时间：2026-09-05
- 用到：物理传感器欧拉角（**弧度**）、吊舱本体世界坐标、目标世界坐标、激光测距、相机变焦通道、屏幕（1×1，逻辑画布 288×160）
- 亮点：`08` §19 是「把目标拆成两个角度再归一到屏幕」（角度域投影，不用矩阵）；本节是**另一条路**——搭出完整的 3×3 相机模型：飞机姿态矩阵 × 云台矩阵，转置后把世界向量变到相机系，再按**垂直 FOV 与宽高比分别求 f_x / f_y** 做透视除法；`p_cam.z <= 0`（目标在相机背后）直接返回 `nil` 不画。

**① 欧拉角 → 3×3 姿态矩阵（展开成 9 个标量，不用表）**

```lua
function eulToMat(ex,ey,ez)                 -- 输入是弧度（物理传感器 ch4-6 直接给弧度）
  sx = math.sin(ex)  cx = math.cos(ex)
  sy = math.sin(ey)  cy = math.cos(ey)
  sz = math.sin(ez)  cz = math.cos(ez)
  r00 = cz*cy
  r01 = cz*sy*sx - sz*cx
  r02 = cz*sy*cx + sz*sx
  r10 = sz*cy
  r11 = sz*sy*sx + cz*cx
  r12 = sz*sy*cx - cz*sx
  r20 = -sy
  r21 = cy*sx
  r22 = cy*cx
  return r00, r01, r02, r10, r11, r12, r20, r21, r22
end
```

**② 先解出云台该转到的角，再拼相机矩阵**

```lua
function getTurretAngles(cx,cy,cz, ax,ay,az, ex,ey,ez)   -- 相机位置 / 目标 / 本机欧拉
  r00, r01, r02, r10, r11, r12, r20, r21, r22 = eulToMat(ex,ey,ez)
  dx = ax - cx  dy = ay - cy  dz = az - cz
  -- 🔑 世界→机体系：矩阵的三列分别点乘 d（等价于 R^T * d）
  lx = r00*dx + r10*dy + r20*dz
  ly = r01*dx + r11*dy + r21*dz
  lz = r02*dx + r12*dy + r22*dz
  yaw = math.atan(lz, -lx)                 -- ⚠ SW 的 atan 是 atan(y, x)，参数顺序勿反
  px, py, pz = rotateAroundY(lx,ly,lz, -yaw)
  pitch = math.atan(py, math.sqrt(px*px + pz*pz))
  return yaw, pitch
end

function worldToScreen(ex,ey,ez, cx,cy,cz, ax,ay,az, fov, ox,oy,oz)
  R_aircraft = eulToMatTable(ex,ey,ez)
  ty, tp = getTurretAngles(cx,cy,cz, ax,ay,az, ex,ey,ez)
  -- 🔑 云台矩阵：先绕 Y 转 (yaw - pi/2)，再绕 X 转 (-pitch)；左乘飞机姿态
  R_gimbal = matMul( rotationMatrixY( ty - math.pi/2 ), rotationMatrixX( -tp ) )
  R_cam    = matMul( R_aircraft, R_gimbal )
  p = { x = ox - cx, y = oy - cy, z = oz - cz }
  p_cam = vecMul(matTrans(R_cam), p)       -- 🔑 旋转阵正交：转置 = 求逆，比写求逆省一大截
  halfW, halfH = 144, 80
  f_y = halfH / math.tan(fov/2)
  -- 🔑 宽屏不能只用一个焦距：先由宽高比反算水平 FOV，再求 f_x
  horizontalFOV = 2 * math.atan((halfW/halfH) * math.tan(fov/2))
  f_x = halfW / math.tan(horizontalFOV/2)
  if p_cam.z <= 0 then return nil, nil end  -- 目标在相机背后
  return halfW + f_x*(p_cam.x/p_cam.z), halfH - f_y*(p_cam.y/p_cam.z)
end
```

**③ 变焦与绘制**

```lua
function onTick()
  -- ...
  fov = 1.43 + (135 - 1.43) * (1 - CamZ)      -- CamZ: 变焦通道 0..1，1 = 最窄
  screen_x, screen_y = worldToScreen(ex,ey,ez, cx,cy,cz, ax,ay,az, math.rad(fov),
                                     ox, oz, oy)   -- ⚠ 见下方「参数错位」
end
function onDraw()

    center(math.floor(screen_x), math.floor(screen_y))   -- 画准星
  end

```

- 🔑 **世界→相机用转置而不是求逆**：旋转矩阵是正交阵，`R^-1 = R^T`。`matTrans` 只有 9 行，写通用求逆要几十行，8192 字符下必须用转置。
- 🔑 **`f_x` 与 `f_y` 必须分开求**：作者先由垂直 FOV 定 `f_y = halfH/tan(fov/2)`，再由宽高比反算水平 FOV 得 `f_x`。若两轴共用一个焦距，非正方形画布上的准星会横向拉伸。
- 🔑 **`p_cam.z <= 0` 的裁剪不能省**：透视除法在 z 过零时会把坐标翻到无穷远，准星会「跳到屏幕另一侧」。
- ⚠ **反面教材：参数错位**。函数签名是 `(..., ox, oy, oz)`，调用处传的是 `(ox, oz, oy)`。原作者的命名里 `oy` 是「水平（horizontal）」、`oz` 才是高度，与 SW 的 Y=高度 / Z=北 正好相反——所以传参时才要倒一下。**抄的时候直接改成 `tx, ty(高度), tz`，别沿用 `ox/oy/oz`。**
- ⚠ **反面教材：把 FOV 当角度线性插值**。`fov = 1.43 + (135-1.43)*(1-CamZ)` 假设变焦通道与视场角成线性；相机部件实际 FOV 与 zoom 是非线性的（见 `03` §10.4 的实测常数 `FW=2.2 / FN=0.025`）。近距离准星会有可察觉偏差，要准得按 `03` §10.4 的公式反解。
- ⚠ `math.atan(lz, -lx)` 是**双参数** `atan(y, x)`（SW 无 `atan2`），且要的是弧度——物理传感器 ch4-6 已经是弧度，**不要再乘 2π**（`17_传感器与雷达.md` §1.1）。

## §21 近炸引信的**剩余 tick 外推**：环形缓冲均值 + 用最旧样本求变化率 + 保险延时

- 来源：steam id **3765180788** · 描述页 <https://steamcommunity.com/sharedfiles/filedetails/?id=3765180788> · **载具**（Shahed Drone，`_vehicle_0` 引信控制器）
- 更新时间：2026-09-02
- 用到：测距数值通道、布尔（已探测 / 撞击 / 已发射）、属性滑块（`Sample Count` / `Arm Delay(Sec)` / `Explode Distance (m)` / `Time to Self Destruct (Sec)` / `Collision Explode Tick`）
- 亮点：**引爆判据不是「当前距离 < 阈值」，而是「按当前接近速度外推，还有多少 tick 会到达起爆距离」**——测距有噪声、帧率会抖，单点差分会误触发，所以用环形缓冲的平均值、并用**最老那个样本**当差分基准（拉开样本间距，等效低通）。

```lua
local Sample_Count = pgN("Sample Count")     -- ⚠ 脚本顶部只读一次，改属性要重启脚本
local History, History_Index, Is_Filled = {}, 1, false

function onTick()
  local Raw_Val = igN(1)
  local Detected, Impact, Launch = igB(1), igB(9), igB(10)
  local Arm_Delay_Ticks = pgN("Arm Delay(Sec)") * 60        -- 秒 → tick
  local Target_Val      = pgN("Explode Distance (m)")

  History[History_Index] = Raw_Val
  History_Index = History_Index + 1
  if History_Index > Sample_Count then
    History_Index = 1
    Is_Filled = true                                        -- 🔑 绕回一圈才算填满
  end
  if not Is_Filled then osN(1, -1) return end               -- 数据不够 → 下游不起爆

  local Current_Avg  = Get_Average()
  local Oldest_Index = History_Index                        -- 🔑 写指针指向的就是最老槽位
  local Velocity     = (Raw_Val - History[Oldest_Index]) / Sample_Count
  local Distance        = Target_Val - Current_Avg
  local Remaining_Ticks = -1
  if Velocity ~= 0 and (Distance * Velocity > 0) then       -- 🔑 同号 = 正在接近
    Remaining_Ticks = Distance / Velocity
  end
  osN(1, Remaining_Ticks)

  local Near_Detonate = Threshold(Remaining_Ticks, 0, pgN("Collision Explode Tick"))
                        and Threshold(Raw_Val, 0.01, Target_Val + 30)
  local Explode = ((Near_Detonate or Impact) and Arm_Delay_Complete) or S_D
  osB(1, not Detected)   -- 雷达：只在还没探测到时开机，进入末制导即关
  osB(2, Explode)
end

function Threshold(val, min, max) return val >= min and val <= max end
function Get_Average()
  local Sum, Count = 0, #History
  if Count == 0 then return 0 end
  for i = 1, Count do Sum = Sum + History[i] end
  return Sum / Count
end
```

- 🔑 **`Oldest_Index = History_Index`**：写指针刚推进过，它当前指向的位置就是最老的那条。环形缓冲因此**不需要额外的头/尾指针**，也不需要在每次移位时搬数据（`table.insert(t,1,v)` 是 O(n)，见 `04` §4）。
- 🔑 **`Is_Filled` 门控**：未填满一圈时输出 `-1`，下游看到负数就知道「数据不可信」。比输出 0 安全——0 会被误读成「立刻起爆」。
- 🔑 **符号门控 `Distance * Velocity > 0`**：`Distance > 0`（还没到起爆距离）且 `Velocity < 0`（距离在减小）时同号为负……实际作者判的是同号为正，即二者方向一致。**没有这个判据时，远离目标也会算出正的剩余 tick 数并误起爆。**
- 🔑 **两级引爆 + 自毁**：`Arm_Delay_Complete`（发射后延时解锁，防刚出膛就炸）+ `S_D`（自毁计时，`S_D_Ticks > 0` 才启用）+ `Impact`（撞击开关兜底）。三者是或关系，任一满足即起爆。
- ⚠ **`Sample_Count` 在脚本顶层读了就不再更新**。SW 的属性滑块可以在运行时改，但这里 `local Sample_Count = pgN(...)` 只在脚本加载时执行一次。要在运行时生效就得挪进 `onTick`。
- ⚠ **`Get_Average` 用 `#History`**：环形缓冲填满后长度恒为 `Sample_Count`，未填满时是已填数量——这个语义刚好对。**但表里一旦出现空洞（被置 nil），`#` 的行为就未定义了**，别在别处给 `History` 的元素赋 nil。
- ⚠ **除法保护只有 `Velocity ~= 0`**：`Velocity` 极小时 `Remaining_Ticks` 会变成很大的数，虽不会误炸（`Threshold` 上界是 `Collision Explode Tick`），但下游若直接拿它做倒计时显示会出现巨数。
- 关联：`03` §23（移位寄存器做去抖，同一环形缓冲思路）/ `08` §16（转塔火控的输出限幅）/ `04` §3（卡尔曼：若要同时估计距离与速度）/ `02` §3.2（精确定时走外部 blinker，本节用 tick 计数即可）
