## §0 单位与坐标速查（先核对再动手）

| 项 | 约定 |
| --- | --- |
| 角度单位 | **圈（turn）**，1 圈 = 360°。传感器 / 雷达 / 罗盘 / 舵机**全部**输出圈 |
| 进 `math.sin/cos` | **必须 ×2π** |
| 出 `math.atan` | 结果是弧度，**÷2π** 回到圈 |
| `math.atan2` | **不存在**；用 `math.atan(y, x)` 两参形式（第一参是 **y 分量**） |
| 物理传感器 12 通道 | 1-3 位置(X/Y/Z)、4-6 欧拉角(**圈**)、7-9 线速度、10-12 角速度 |
| 物理传感器轴向 | **X 东、Y 上（高度）、Z 北** |
| GPS 坐标轴向 | **X 东、Y 北、Z 高度** |
| 两系互换 | `GPS_X = ps_X`，`GPS_Y(北) = ps_Z`，`GPS_Z(高) = ps_Y` |
| 罗盘读数 | 0=北，**-0.25=东**，±0.5=南，+0.25=西（**东为负**） |
| 球面→笛卡尔 | `X(东) = r·cos(仰角)·sin(方位角)`，`Y(北) = r·cos(仰角)·cos(方位角)`，`Z(上) = r·sin(仰角)` |

> 🔑 **「sin 给东、cos 给北」是记忆口诀**（`17_传感器与雷达.md`）。
> 而方位角本身是圈、仰角也是圈，都要先 ×2π。

## §1 物理传感器欧拉角 → 自机姿态

### 1.1 标准解算（Z-Y-X 欧拉序）

```lua
pi2 = math.pi*2
s,c = math.sin, math.cos

function onTick()
  -- 圈 -> 弧度（务必！原日文例文集漏了这一步，见下方勘误）
  ex,ey,ez = GN(4)*pi2, GN(5)*pi2, GN(6)*pi2
  cx,sx = c(ex), s(ex)
  cy,sy = c(ey), s(ey)
  cz,sz = c(ez), s(ez)

  -- Z-Y-X 欧拉序旋转矩阵
  R = {
    { cz*cy,  cz*sy*sx - sz*cx,  cz*sy*cx + sz*sx },
    { sz*cy,  sz*sy*sx + cz*cx,  sz*sy*cx - cz*sx },
    { -sy,    cy*sx,             cy*cx            }
  }

  Elev = math.asin( R[3][1] * -1 )          -- 仰角（矩阵第 3 行第 1 列取负）
  Azim = math.atan(R[2][1], R[1][1])        -- 方位角：atan(y, x) 两参
  Roll = math.atan(R[3][2], R[3][3])        -- 横滚
end
```

> 🔴 **原稿（日文例文集 §4）两处错误，已修正**
> 1. **单位错**：原稿注释写「物理传感器 4/5/6 = 欧拉角(**弧度**)」，实际是**圈**。
>    不 ×2π 会得到完全错误的姿态（`17_传感器与雷达.md` §1.3 明确单位为圈）。
> 2. **笔误**：`cx,sy=math.cos(ey),math.sin(ey)` 把 `cos(ey)` 赋给了 `cx`，
>    导致矩阵里的 `cy` 从未定义 → `nil` 运算报错。应为 `cy,sy=math.cos(ey),math.sin(ey)`。

### 1.2 更稳的写法：用 `atan(分量, 投影)` 代替 `asin`

`asin` 在接近 ±90° 时数值不稳定。改用 `atan(垂直分量, 水平投影长度)`，全程平滑。
实测来源：steam id **3119724150**（All in one radar，2023-12-27）。

```lua
function onTick()
  local x,y,z = GN(4)*pi2, GN(5)*pi2, GN(6)*pi2   -- 圈 -> 弧度
  local cx,sx = c(x), s(x)
  local cy,sy = c(y), s(y)
  local cz,sz = c(z), s(z)

  local m00, m01, m02 = cy*cz, -cx*sz+sx*sy*cz,  sx*sz+cx*sy*cz
  local m10, m11, m12 = cy*sz,  cx*cz+sx*sy*sz, -sx*cz+cx*sy*sz
  local m20, m21, m22 = -sy,    sx*cy,           cx*cy

  -- 倾角（圈）：atan(垂直分量, 水平投影)
  tilt_x = math.atan(m10, math.sqrt(m00*m00 + m20*m20))/pi2
  tilt_y = math.atan(m11, math.sqrt(m01*m01 + m21*m21))/pi2
  tilt_z = math.atan(m12, math.sqrt(m02*m02 + m22*m22))/pi2

  -- 三轴罗盘（圈）：列向量的水平方位角；负号因「东为负」
  compass_x = math.atan(m00, m20)/-pi2
  compass_y = math.atan(m01, m21)/-pi2
  compass_z = math.atan(m02, m22)/-pi2

  -- 全局角速度 -> 机体系：乘转置矩阵（正交矩阵的转置即逆）
  local ax,ay,az = GN(10),GN(11),GN(12)
  angular_x = m00*ax + m10*ay + m20*az
  angular_y = m01*ax + m11*ay + m21*az
  angular_z = m02*ax + m12*ay + m22*az
end
```

**要点**
- 三轴罗盘不是「一个航向角」，而是**每条机体轴在水平面投影的方位角**——多方向安装传感器/天线时有用。
- **全局→机体**用转置矩阵即可（旋转矩阵正交，`Mᵀ = M⁻¹`），省掉求逆。
- 欧拉序是 **Z→Y→X**（`17_传感器与雷达.md` §1.3）。**要换成其它顺序不能只做数值置换**，必须经四元数等中间表示重算。

## §2 雷达数据解包（新雷达 8 目标 × 4 值）

新雷达（1.2.30+）复合输出：**距离(m) · 方位角(圈) · 仰角(圈) · 检测后未更新的时间(tick)**，共 8 个目标。

```lua
function onTick()
  TARGET={}
  for k=1,8 do
    TARGET[k] = {
      lock = GB(k),                                -- 布尔 1-8：是否发现目标
      dist = GN(k*4-3),
      ang  = GN(k*4-2),                            -- 方位角，圈
      tilt = GN(k*4-1),                            -- 仰角，圈
      time = GN(k*4)                               -- 检测后经过的 tick
    }
  end
end
```

> ⚠ **通道顺序陷阱**：旧「雷达(巨)」的顺序是 **距离·信号强度·仰角·方位角**，
> 新版是 **距离·方位角·仰角·时间**——**新版没有「信号强度」这一项**，第 4 值改成了 tick 计时器。
> 混用旧存档会整体错位（`17_传感器与雷达.md`）。
> 另有 16 目标版本（声纳/雷达）：布尔 1-16、数值 1-32，每目标 2 值（**只有方位角·仰角，无距离**）。

## §3 雷达目标 → 世界绝对坐标

### 3.1 球面 → 笛卡尔（**注意 sin/cos 的分配**）

```lua
-- dist(m), azi(方位角/圈), ele(仰角/圈)  ->  X东 / Y北 / Z上
function toXYZ(dist, azi, ele)
  local a, e = azi*math.pi*2, ele*math.pi*2        -- 圈 -> 弧度
  local horiz = dist * math.cos(e)                 -- 距离投到水平面用 cos(仰角)
  return horiz*math.sin(a),                        -- 东：sin 给 X
         horiz*math.cos(a),                        -- 北：cos 给 Y
         dist*math.sin(e)                          -- 上
end
```

> 🔴 **BKN `docs/Tools/Radar/data-transfer.md` 的 `simpleXYZ` 与本写法 sin/cos 相反**：
> ```lua
> -- BKN 原版（局部系：x = 正对方向）
> function simpleXYZ(dist, angle, pitch)
>   local xy = dist*math.cos(pitch)
>   return { xy*math.cos(angle), xy*math.sin(angle), dist*math.sin(pitch) }
> end
> ```
> BKN 用的是**雷达局部系**（x = 雷达正对方向、y = 侧向、z = 上），
> 本文件用的是**世界系**（X 东、Y 北、Z 上，与 `17_传感器与雷达.md` 一致）。
> **两者物理等价但轴名与 sin/cos 分配相反，混用会差 90°，务必二选一。**

### 3.2 旋转 + 平移得到绝对坐标（权威版）

```lua
-- 输入约定
--   N1,2,3 = 物理传感器 X / Y(高度) / Z(北)
--   N4,5,6 = 欧拉 X / Y / Z（圈）
--   N7     = 雷达目标距离(m)
--   N8     = 目标方位角（圈）    N9 = 目标仰角（圈）
-- 输出 N1,2,3 = 目标绝对 X(东) / Y(北) / Z(高度)
pi2 = math.pi*2
function onTick()
  -- ① 物理传感器坐标 -> GPS 坐标：Y 与 Z 互换
  local sX = GN(1)
  local sY = GN(3)                    -- 北
  local sZ = GN(2)                    -- 高度

  -- ② 圈 -> 弧度
  local al, ga, be = GN(4)*pi2, GN(5)*pi2, GN(6)*pi2
  local dst, azi, ele = GN(7), GN(8)*pi2, GN(9)*pi2

  -- ③ 姿态旋转矩阵（Z-Y-X 欧拉序）
  local m = {
    { c(be)*c(ga),                      -s(ga),      s(be)*c(ga)                      },
    { c(al)*c(be)*s(ga)+s(al)*s(be),    c(al)*c(ga), c(al)*s(be)*s(ga)-s(al)*c(be)   },
    { s(al)*c(be)*s(ga)-c(al)*s(be),    s(al)*c(ga), s(al)*s(be)*s(ga)+c(al)*c(be)   }
  }

  -- ④ 相对偏移（球面约定：sin 给 X、cos 给 Y）
  local lX = dst * s(azi) * c(ele)
  local lY = dst * c(azi) * c(ele)
  local lZ = dst * s(ele)

  -- ⑤ 旋转 + 平移（注意是 mᵀ · local）
  SN(1, m[3][1]*lZ + m[2][1]*lY + m[1][1]*lX + sX)
  SN(2, m[3][2]*lZ + m[2][2]*lY + m[1][2]*lX + sY)
  SN(3, m[3][3]*lZ + m[2][3]*lY + m[1][3]*lX + sZ)
end
```

### 3.3 矩阵工具（BKN `docs/Tools/Math/`）

```lua
function matMul(m1, m2)
  local res={}
  for i=1,#m1 do
    res[i]={}
    for j=1,#m2[1] do
      res[i][j]=0
      for k=1,#m2 do res[i][j]=res[i][j]+m1[i][k]*m2[k][j] end
    end
  end
  return res
end

function transpose(m)
  local res={}
  for i=1,#m[1] do
    res[i]={}
    for j=1,#m do res[i][j]=m[j][i] end
  end
  return res
end
```

## §4 只有测距时的三角定位（无雷达转台）

来源：steam id **3664940456**（PYO's Transponder Locator，**2026-02-13**，同功能最新的作品；
Zizo 版 2774712393 为 2023-11-26，手法相近但更旧）。

**原理**：应急信标只给距离不给方位，所以必须**本机移动**积累多个测距圆，用圆的交点定出目标。

```lua
-- A,B 定基线，用第 3 点 C 消歧；返回唯一交点
function solve_3_circles(A,B,C)
  local d = math.sqrt((A.x-B.x)^2+(A.y-B.y)^2)
  if d>A.r+B.r or d<math.abs(A.r-B.r) or d==0 then return nil end   -- 无交点 / 内含
  local a = (A.r^2-B.r^2+d^2)/(2*d)
  local h = math.sqrt(math.max(0, A.r^2-a^2))
  local x2,y2 = B.x-A.x, B.y-A.y
  local x0,y0 = A.x+a*x2/d, A.y+a*y2/d
  local rx,ry = -y2*h/d, x2*h/d
  local p1 = {x=x0+rx, y=y0+ry}
  local p2 = {x=x0-rx, y=y0-ry}
  -- 用第 3 个圆的半径误差选解
  local e1 = math.abs(math.sqrt((p1.x-C.x)^2+(p1.y-C.y)^2)-C.r)
  local e2 = math.abs(math.sqrt((p2.x-C.x)^2+(p2.y-C.y)^2)-C.r)
  return (e1<e2) and p1 or p2
end
```

采样与基线管理（要点在注释）：

```lua
BUF_SIZE=20 MIN_DIST=50 MAX_TICKS=900
BASELINE_STORE=0.33 BASELINE_SWITCH=0.50      -- 基线半径的 33% / 50%

function onTick()
  ticks = ticks + 1
  local sig = GB(1)                            -- 信标回波
  if sig and not last_sig then                 -- 上升沿 = 一个应答脉冲
    local delta = ticks - last_pulse_tick
    if delta>10 and delta<MAX_TICKS then
      local slant = 250 + (delta-10)*50        -- 脉冲间隔 -> 斜距
      local r = slant>math.abs(alt) and math.sqrt(slant^2-alt^2) or 0   -- 斜距 -> 水平距
      -- 移动不足 MIN_DIST 的采样丢弃：基线太短解不出
      local ok = (#buf==0) or (math.sqrt((x-buf[#buf].x)^2+(y-buf[#buf].y)^2) >= MIN_DIST)
      if ok and r>0 then
        table.insert(buf,{x=x,y=y,r=r})
        if #buf>BUF_SIZE then table.remove(buf,1) end
      end
    end
    last_pulse_tick = ticks
  end
  last_sig = sig
end
```

**要点**
- **第 3 点取「离基线最远」的采样**：交点对测距误差最不敏感。用点到直线距离挑选。
- **基线切换**：本机动出基线半径 33% 时记录候选点、50% 时正式换基线，避免基线缓慢漂移导致解抖。
- **三级离群剔除**：结果离历史均值超过 `OUTLIER_DIST` 计数 +1，满 3 次整体复位重来。
- **精度可视化**：把结果集合的最大散布半径 `precision` 输出到屏幕画圆，让用户直观看到收敛程度。
- 只有两个圆时用**历史结果均值**选离均值近的那一半（无法几何消歧时的兜底）。

## §5 雷达 PPI 扫描显示 + 余晖衰减

来源：steam id **1899288562**（NJ EXAMPLE LUA RADAR，2021-10-13）。

```lua
targets = {} targetstime = {}                  -- [像素 x] = 像素 y / 存活 tick
function onTick()
  w,h = GN(2), GN(3)                           -- 屏幕尺寸走复合输入（onTick 不能调 screen API）
  r   = h/2
  rg  = GN(7)                                  -- 期望量程 m
  rdrspd = (100 - GN(10)) * 6                  -- 转速 -> 余晖时长(tick)
  local rot = GN(8) * math.pi*2                -- 雷达偏航：圈 -> 弧度

  if GB(1) then                                -- 雷达开
    local d = GN(6)
    local dad = (d/rg)*r                       -- 距离 -> 像素半径
    local x1 = w/2 + r  *math.cos(rot-1.5708)  -- 扫描线端点（-90° 使 0 在正上方）
    local y1 = h/2 + r  *math.sin(rot-1.5708)
    local x3 = w/2 + dad*math.cos(rot-1.5708)  -- 目标点
    local y3 = h/2 + dad*math.sin(rot-1.5708)
    if GB(11) and d<=rg then
      targets[x3]=y3 targetstime[x3]=0         -- 以像素 x 为键：天然同列去重
    end
    for k,t in pairs(targetstime) do
      targetstime[k] = t+1
      if t >= rdrspd then targets[k]=nil targetstime[k]=nil end   -- 老化 = 余晖
    end
  end
end
```

## §6 激光扫描成像（96×96 距离网格）

来源：steam id **3001288106**（3D scanner，2023-07-09）。

```lua
-- 固定尺寸预填充，避免 nil 稀疏表导致 #/ipairs 失效
data={}
for i=1,96 do data[i]={} for j=1,96 do data[i][j]=0 end end

function onTick()
  local dst = GN(5)                                   -- 激光测距（斜距）m
  local agl = math.atan(math.sqrt(lxo^2+lyo^2), 1)    -- atan(y, x) 两参
  dst = dst * math.cos(agl)                            -- 斜距 -> 水平距（云台倾斜修正）

  if ti then                                           -- 云台已稳定
    mav, miv = fmax(data), fmin(data)                  -- 归一化极值
    data[m][n] = dst
    n = n + istep
  else
    s = s + 1
    if s >= 3 then ti=true s=0 end                     -- 空转 3 tick 等云台到位
  end
end

-- 归一化 + 逐像素渲染
function sk(u,v,l) return (u-v)/(l-v) end
function onDraw()
  for m,row in ipairs(data) do
    for n,f in ipairs(row) do
      local k = sk(f,miv,mav)
      screen.setColor(C[1]*255*k, C[2]*255*k, C[3]*255*k)
      screen.drawRectF(n-1,m-1,1,1)
    end
  end
end
```

## §8 雷达多目标跟踪器（门控关联 + 滑动平均测速 + 预测）

来源：steam id **3261800786** · <https://steamcommunity.com/sharedfiles/filedetails/?id=3261800786> · **载具**（ZTQ-15，脚本 `datalink3radarDenoiser`）——把 §3 的「单次坐标转换」升级成**持续跟踪**：新回波和已有航迹做门控关联，匹配则更新、否则建新航迹，并用历史点算速度、外推预测点。

```lua
U = {}                                              -- 航迹表，每条含位置/历史/速度
AT = 200                                            -- 历史缓冲最长 200 点
function onTick()
  sp = {GN(4),GN(8),GN(12)}; Eu = {GN(16),GN(20),GN(24)}   -- 自车位置/姿态
  -- 1) 新回波：8 路雷达通道，幅度>25 视为有目标
  for i=1,8 do
    if GN(4*i-3) > 25 then
      r = R2G({GN(4*i-3), GN(4*i-2), GN(4*i-1)})    -- 雷达球面→世界(见 §3)
      -- 2) 门控关联：与已有航迹比 方位/仰角/距离 是否在门限内
      F = 1
      for j=1,#U do
        da = Ma(U[j].a - r.a)/P; de = Ma(U[j].e - r.e)/P; dd = Ma(U[j].d - r.d)/P
        if da < 0.002 + D2T(U[j].d, mw) and de < 0.002 + D2T(U[j].d, mh)
           and dd < 0.02*U[j].d + md then
          T.insert(U[j].dN, {r[1],r[2],r[3]}); U[j].l = 0; F = 0; break  -- 归入该航迹
        end
      end
      if F > 0 then r.id = id; id = id+1; T.insert(U, r) end   -- 无匹配→新航迹
    end
  end
  -- 3) 每帧把本 tick 回波求平均追加进历史；用历史算速度
  for i=1,#U do
    if U[i].l == 0 then
      if #U[i].dN > 1 then                       -- 多回波→平均
        _u,_v,_w = 0,0,0
        for j=1,#U[i].dN do _u=_u+U[i].dN[j][1]; _v=_v+U[i].dN[j][2]; _w=_w+U[i].dN[j][3] end
        T.insert(U[i].dB, {_u/#, _v/#, _w/#})
      else T.insert(U[i].dB, U[i].dN[1]) end
      U[i].dN = {}
      E = M.min(#U[i].dB-1, Mf(U[i].d/2000*AT))   -- 用近大远小的窗口取速度
      U[i].vx = Av(U[i].xv, (新x-旧x)/E, 99)       -- 滑动平均测速
      U[i].xg = U[i][1] + U[i].vx*E/2              -- 预测点 = 当前 + 速度*半窗口
      U[i].d = Dst(U[i], sp)                       -- 刷新距离/方位/仰角
      U[i].a, U[i].e = L2AE(G2L({U[i].xg,U[i].yg,U[i].zg}))
    end
    U[i].l = U[i].l + 1
    if U[i].l > 10 then T.remove(U,i); break end   -- 连续 10 帧无回波→删航迹
  end
end
```

**要点**
- **门控关联**用「距离自适应角度门限」`da < 0.002 + D2T(d, mw)`：目标越远允许方位误差角越大——近处不串扰、远处不漏跟。
- 速度是**历史点的滑动平均**（`Av`），比单帧差分稳；预测点 `xg = pos + v*E/2` 给火控提前量用。
- 航迹生命周期两条线：本帧有无回波（`l`）、总存活时间（超时 `t>300` 删）。**删除用 `table.remove` 且 `break`**，因为遍历中删元素会错位（见 `07` §2）。
- 输出最近航迹 + 用 `cur/total` 在多目标间循环切换。

## §10 摄像头随雷达稳像（残差 → Pivot，零滞后）—— 实测标定版

- 来源：**本机实测**（`RADAR_TEST.xml` + `SW示波器v0.1.3`，rt_1~rt_16，动对静 659~785 m）
- FOV 常数与工坊 3168029480 互证一致
- 完整结论、调参旋钮与陷阱清单：**`../../../方块数据/雷达与摄像头稳定_阶段总结.md`**

### 10.1 架构第一原理：Pivot 是「无惯性逻辑轴」

| | 座圈（物理云台） | 摄像头 Pivot |
|---|---|---|
| 性质 | 电机 / 质量 / 转速上限 | **逻辑轴，无惯性** |
| 响应 | 有真实滞后 | 给角度 → **瞬间指向** |
| 控制 | 比例 **K=5** + 死区（增益受稳定边界约束 ≈10） | **纯残差 + 轻滤波 α=0.3** |

> 🔑 摄像头**不要**用「解算世界坐标 + ABF」的重滤波 —— 那会引入 **~10 tick 滞后**，
> 而座圈用的是**原始 az（0 滞后）**，两者不同步 → 画面永远落后座圈半拍。
> 雷达与摄像头同轴装于同一座圈子网格时，**az/el 本身就是残差**，直接补偿即可，**无需解算世界坐标**。

### 10.2 稳像主模板（✅ 实测标定，可直抄）

```lua
-- in : B1=发现  N28=距离  N29=雷达方位(圈,右正)  N30=仰角(圈,上正)
-- out: N1=Pivot X(圈)  N2=Pivot Y(圈)  N32=FOV
at=math.atan
AZF,ELF=0,0
SPAN=10
FW,FN=2.2,0.025            -- camera_med FOV: 0→2.2 rad 最宽 / 1→0.025 rad 最窄，中间线性
function onTick()
    found=input.getBool(1)
    pvx,pvy,fov=0,0,0
    dst=input.getNumber(28)
    if found and dst>0 then
        az=input.getNumber(29)
        el=input.getNumber(30)
        AZF=AZF+0.3*(az-AZF)                          -- EMA α=0.3，延迟约 3 tick (~55 ms)
        ELF=ELF+0.3*(el-ELF)
        pvx=-AZF                                       -- 符号：水平取负、垂直取正
        pvy=ELF
        pvx=math.max(-0.125,math.min(0.125,pvx))       -- Pivot 硬限 ±0.125 圈 = ±45°
        pvy=math.max(-0.125,math.min(0.125,pvy))
        fd=math.max(dst,1)
        fov=math.max(0,math.min(1,(FW-2*at(SPAN/2/fd))/(FW-FN)))
    else
        AZF,ELF=0,0                                    -- 失探清零，防下次捕获时甩头
    end
    output.setNumber(1,pvx)
    output.setNumber(2,pvy)
    output.setNumber(32,fov)
end
```

**实测效果**（rt_15 / rt_16，动对静）：

| 指标 | rt_15 | rt_16 |
|---|---|---|
| Pivot X std（az 的 1/x） | 0.00039（**1/3.4**） | 0.00024（**1/3.3**） |
| Pivot Y std（el 的 1/x） | 0.00056（**1/3.4**） | 0.00033（**1/3.4**） |
| 互相关滞后 | **0 tick** | **0 tick** |
| 相机净指向残差 | 0.329° | **0.196°** |

**唯一调参旋钮 = α**：大 → 同步更紧但略抖；小 → 更平滑但略滞后。
**α=0.3 为最优折中**。动对静微抖 → 调到 0.2；仍滞后 → 调到 0.4。

### 10.3 座圈控制（物理侧，与摄像头解耦）

```lua
K=5
DEAD=0.001
DIR=-1                       -- 正转速=左转；az 右为正，故右转需负
function onTick()
    found=input.getBool(1)
    az=input.getNumber(29)
    spd=0
    if found then
        e=az
        if DEAD>math.abs(e) then e=0 end      -- 死区压雷达噪声
        spd=DIR*K*e
        if spd>10 then spd=10 end
        if -10>spd then spd=-10 end           -- 注意：一律用 > 方向比较，见下方 ⚠
    end
    output.setNumber(1,spd)
end
```

⚠ **写进载具 XML 时绝对禁止半角 `<`（连注释里也不行），否则 XML 直接损坏**。
上例 `DEAD>math.abs(e)`、`-10>spd` 就是「把 `<` 翻成 `>`」的标准写法。

🔑 **不要用积分**：雷达 az 噪声（±0.001 圈）下积分极易发散/饱和 ——
Ki=30 直接满速空转；即便加抗饱和（误差<0.01 圈才积分、钳位 ±0.1）也是弊大于利。
**纯比例 + 死区**才是正解（bknsw 手册 `Utils/speed-pivot` 同思路）。

### 10.4 FOV 换算（与工坊常数完全一致）

```lua
fov = (FW - 2*at(SPAN/2/dist)) / (FW - FN)     -- FW=2.2, FN=0.025, SPAN=视野尺度(m)
```
工坊 3168029480 写作 `cfov=(2.2-angT*P2)/(2.2-0.025)`（P2 = 2π，angT = 半角弧度），
**常数 2.2 / 0.025 与 SPAN=10 完全相同** → 可放心复用。改视野尺度**只需改 SPAN**。

### 10.5 ⚠ 不要用速率前馈（离线仿真结论）

工坊 3168029480 用 `aim+(aim-aim_old)`（位置 + 速率前馈）实现零滞后紧跟。
在 rt_16 上仿真对比：

| | EMA α=0.3 | + 速率前馈 |
|---|---|---|
| 水平净残差 | 0.169° | 0.096°（改善） |
| **抖动** | 0.072°/tick | **0.173°/tick（恶化 2.4×）** |
| 垂直净残差 | 0.701° | **0.739°（反而变差）** |

**根因**：作者的前馈建立在**先降噪的目标位置**上（速率干净）；直接对**含噪 az/el 残差**取差分 = 放大噪声。
→ 若要追「零滞后紧跟移动目标」，应先对**位置降噪**，再走 `pos + rate`，而非对残差直接加前馈。

### 10.6 单位与符号速查

| 量 | 单位 | 喂 `sin/cos` 前 |
|---|---|---|
| 物理传感器 ch4-6（欧拉角 X/Y/Z） | **弧度**，值域 −π~+π | **直接用，勿 ×2π** |
| 雷达方位 / 仰角 | **圈** | **必须 ×2π** |
| 摄像头 Pivot X/Y | **圈**，±0.125 | — |

**要点**
- 「画面抖」多半是**把含噪原始信号直接喂给执行端** → 加轻滤波（α），而不是加积分。
- 「画面滞后/跟不上」多半是**给无惯性轴加了重滤波** → 换成残差直补，而不是调滤波增益。
- 判据用**互相关峰值位置**验证滞后：达标时应在 **lag=0**。
- 净指向残差 = `az + PivotX`（两者符号相反、相互抵消），这是衡量「是否真对准」的指标。
- 完整脚本：`<SW_SAVE>\data\vehicles\RADAR_TEST.xml` 中 object 96（摄像头联动）与 object 106（座圈控制）。

```lua
  if sT == 2 then                                     -- 主动声纳：自己计时测距
    ping = ping + 1
    local dist = (ping / 60) * (1480 / 2)             -- 60 tick/s；声速 1480 m/s；/2 是往返
    local _, y = map.mapToScreen(gx, gy, z, w, h, gx, gy + dist)
    local s_dist = cy - y                             -- 距离 -> 屏幕像素
    if s_dist > cy + 1 then ping = 0 end              -- 回波跑出屏幕就重新起 ping

    if input.getBool(1) and ping > 1 then             -- 有回波
      local ta  = pi2 * input.getNumber(1)            -- 目标方位（圈）
      local te  = corr_ea(-pi2 * input.getNumber(2), ta, roll, -pitch)
      local tra = ta - ba                             -- 转到艇体坐标
      local td  = dist
      local th  = math.sin(te) * td                   -- 仰角 -> 深度
      table.insert(S, {
        a = -ta - math.pi + ba,
        x = gx + td * math.sin(tra),                  -- 球面 -> 平面（sin 给东 X）
        y = gy + td * math.cos(tra),                  --                cos 给北 Y
        d = td, h = th, t = 255, tg = false,
      })
    end
  end
end

function onDraw()
  local scale = w / (z * 1000)
  local scb, ssb = scale * math.cos(ba), scale * math.sin(ba)
  for _, v in pairs(S) do
    local x, y
    if mm == 3 then                                   -- ① 艇体坐标（航向朝上）：手写 2D 旋转
      local dx, dy = v.x - gx, v.y - gy
      x = cx + scb*dx + ssb*dy
      y = cy - scb*dy + ssb*dx
    else                                              -- ② 世界坐标（北朝上）：交给地图投影
      x, y = map.mapToScreen(gx, gy, z, w, h, v.x, v.y)
    end
    v.sx, v.sy = x, y
  end
end
```

**要点与坑**

- `1480/2` 中的 **1480 m/s 是作者取的水中声速**；游戏里声纳只给方位/仰角不给距离，所以只能自己按「发射→收到回波」的 tick 数换算。`/2` 是声波走往返两程。
- **像素化判断是这段最巧的地方**：不自己算「多少米对应多少像素」，而是把「本舰位置 + 距离」送进 `map.mapToScreen`，看它落在屏幕坐标系的哪个 y，直接和 `cy`（屏幕中心）比。这样缩放 `z` 怎么变都自动跟随。
- `mm==3` 的 2D 旋转 `x=cx+scb*dx+ssb*dy; y=cy-scb*dy+ssb*dx` 是把世界偏移旋到**航向朝上**；注意屏幕 Y 向下，所以 y 项带负号。与 `05` §14 的导航显示器是同一套写法。
- 球面→平面用 **`sin` 给东(X)、`cos` 给北(Y)**，与 `03` §3 一致，写反会差 90°。
- `corr_ea(仰角, 方位, 横滚, 俯仰)` 是姿态补偿函数，同脚本内定义（此处未展开）——横滚/俯仰会把声纳基座的方位仰角读数扭曲，航海/航空平台必须补。

## §12 雷达接触点：**取整世界坐标当表键**去重 + TTL 老化 + 扫描线点亮

- 来源：steam id **3792551514** · 描述页 <https://steamcommunity.com/sharedfiles/filedetails/?id=3792551514> · **载具**（ABM "21X" Large Tender RHIB，`_vehicle_3` 导航/雷达显示器）
- 更新时间：2026-08-30
- 用到：雷达（6 目标 × 4 值：距离 / 方位 / 仰角 / 是否命中）、指南针（圈）、GPS、触摸屏
- 亮点：**不做门控关联、不存速度**，用「世界坐标取整拼成的字符串」当表键，把每帧刷新的雷达点沉淀成一份带寿命的接触档案——`03` §8 跟踪器的**极简替代方案**。

```lua
rTgts, sweepTrail = {}, {}
rTTL = 300                                  -- 接触寿命 5 秒（60 tick/s）

-- 极坐标 → 笛卡尔偏移：方位从北起算，故 sin 给 X(东)、cos 给 Y(北)
function gPOC(r, a) return r*math.cos(a*pi/180), r*math.sin(a*pi/180) end
function r2d(a) return (a*180/pi) % 360 end

function onTick()
  -- 雷达 6 个目标：第 i 个占 4 个通道，起始 b = i*4-3
  for i = 1, 6 do
    if not input.getBool(i) then break end          -- 未探测到就停（通道按序紧凑排列）
    local b   = i*4 - 3
    local dist = input.getNumber(b)
    local az   = r2d(input.getNumber(b+1) * (pi*2)) -- 方位是「圈」
    local tx, ty = gPOC(dist, myDir + az - 90)      -- myDir：本舰航向(度)，-90 把北基准旋到屏幕基准
    tx, ty = math.floor(gpsX + tx), math.floor(gpsY - ty)

    local k = tx .. ":" .. ty                       -- 🔑 取整后的世界坐标串当表键
    if not rTgts[k] then
      rTgts[k] = {x = tx, y = ty, ttl = rTTL, az = az, vis = false}
    else
      rTgts[k].ttl = rTTL                           -- 再次探到就续命
    end
  end

  -- 扫描线余辉：定长队列（插到头、删尾），配合 alpha 衰减画扇形
  table.insert(sweepTrail, 1, rDir + myDir - 90)
  if #sweepTrail > 18 then table.remove(sweepTrail) end

  -- 扫描线扫过 → 点亮（角度差 < 15°）
  local cSD = rDir + myDir
  for k, t in pairs(rTgts) do
    if not t.vis and (cSD - (myDir + t.az) % 360) % 360 < 15 then t.vis = true end
  end
end
```

**要点与坑**

- 🔑 **表键必须先 `math.floor` 取整**。雷达每帧报的距离/方位有浮点抖动，直接拿 `x..":"..y` 当键，
  同一个目标每帧都是新键 → 档案无限膨胀、永远判不出「同一个目标」。取整把目标量化到 1 m 网格，
  动得慢的目标稳稳落在同一个键上。
- 这套方案**只判「是不是同一个位置」**，不判「是不是同一个运动物体」：两个交叉而过的目标会短暂合并，
  高速目标会在网格间跳跃产生新键。要做速度外推/预测请用 `03` §8 的**门控关联**版本。
  取舍：本例 ~15 行、无矩阵运算；§8 是完整跟踪器。
- **TTL 放在 `onDraw` 里递减**是刻意的：屏幕 60 Hz、逻辑 60 tick/s，名义同频，但把渲染相关
  的状态更新跟着渲染走，语义更清晰；反过来，凡是**要驱动执行器**的状态一律放 `onTick`。
- `pairs` 遍历过程中对当前键置 `nil` 在 Lua 里是允许的（删除不影响继续遍历），
  但**不能新增键**——新增要另开一张表，见 `02` §5 延迟事件表的写法。
- `if not input.getBool(i) then break end`：雷达目标通道是**紧凑排列**的，探测不到第 i 个时
  后面必然也没有，直接 `break` 省掉 5 次无效读取。
- 扫描余辉 `sweepTrail` 是**定长队列**的标准写法：插到 `1` 号位、超过 18 删尾（`table.remove(t)`
  不传下标即删末尾）。与 `03` §5 的「整表记时间戳 + 每帧重算 alpha」相比，这里**只存角度**，
  靠队列位置推 alpha，省掉一张平行表。

## §13 雷达**阴影区（Shadow Zone）**属性门控 + 非正方形圆屏的平均半径

- 来源：steam id 3794617235 / vehicle.xml block#0（Big Typhoon-style sub diesel/electric）

**要点与坑**

- 🔑 **`Radar Shadow Zone` 是「自遮挡」建模，不是滤噪**。潜艇/大船把雷达装在中轴线上，桅杆、
  炮塔、直升机库都会在近距离产生固定回波；雷达部件本身不会替你屏蔽。做成属性而不是硬编码常量，
  同一个 MC 装到不同船上只改属性面板，不用改脚本 —— 这是 SW 里「一份 MC 通装全舰队」的标准做法。
  典型取值：小艇 15~30 m，驱逐舰 60~120 m。
- 🔑 **`r=(w+h)/4` 的取舍**：正方形屏时恰好 `=w/2`；`3x2` 屏（96x64）时得 40，圆会略超出上下边被裁，
  但换来「一行适配所有屏」。要严格内切改 `math.min(w,h)/2`，要铺满改 `math.max(w,h)/2`。
  与 `05` §0.1 的显式 `min` 写法相比，本例是**牺牲精确度换字数**的典型。
- ⚠ **`td` 直接当像素半径 = 量程被屏幕尺寸绑死**。1x1 屏 r=16 → 量程只有 16 m；换 3x3 屏量程自动变 48 m。
  想要独立量程必须乘缩放：`x4 = cw + td*(r/range)*math.cos(...)`。原作没做，是「小屏近距声纳/避碰屏」
  场景下的合理简化，抄的时候一定要想清楚自己要不要量程。
- ⚠ **目标点用了扫描线后缘角 `rcr-1.97` 而不是接触点自身方位**。看上去目标点挂在余晖尾巴上、
  视觉连贯，但实际把方位系统性滞后了 `0.4 rad ≈ 23 deg`。雷达每帧只输出「刚扫到的那个」接触点，
  所以配对是对的、角度是偏的。真要方位准确就用 `rcr-1.57`（前缘），或干脆读雷达自己的方位通道。
- **余晖三角形 vs 队列**：本例一个 `drawTriangleF` 就是全部余晖，角宽恒为 0.4 rad，与扫描速度无关；
  `03` §12 的定长队列能表现「转得快尾巴长」并支持逐段淡出，但要维护一张表。
  单目标简屏选三角形，多接触点 PPI 选队列。

## §14 雷达 PPI 渲染器（通道打包 + 圈→弧度 + 距离自适应 EMA + 遮挡合并 + 闭合速度）

- 来源：steam id 3793581819 · 描述页 https://steamcommunity.com/sharedfiles/filedetails/?id=3793581819 · 载具（ACV 78 装甲车）
- 更新时间：2026-09-01
- 用到：雷达复合输出（每目标 3 通道：距离 + x + y）、触摸屏输入、属性滑块（Max Target / 颜色 / 矩形尺寸 / 目标信息 / 偏移）
- 亮点：把「雷达目标 → 屏幕坐标」的完整渲染管线一次讲清，且每个手法都是 SW 独有的坑点组合
- 关联：`03` §2（雷达解包）、`00_速查 §4`（圈 vs 弧度）、`03` §8（门控关联版跟踪器）

```lua
-- ① 通道打包：第 i 个目标占 3 个复合输入通道（距离, x, y）
--    n = i + (i-1)*3  →  i=1:1,2,3  i=2:5,6,7  i=3:9,10,11 …
for i=1,tar do
  n = i + (i-1)*3
  dis[i] = ign(n)        -- 距离（米）
  xv[i]  = ign(n+1)      -- 方位（★圈单位 0..1）
  yv[i]  = ign(n+2)      -- 仰角/高低（圈单位）
  td[i]  = igb(i)        -- 该目标是否「地形遮挡 / 已锁定」
  Cal(i)
end

-- ② 距离自适应 EMA：越近越信任新值（v 越大越「吃老值」）
function Cal(num)
  v[num] = math.min(math.floor(dis[num])/1000, 0.8)   -- 近(百米级)v→0 远(千米)v→0.8
  xavg[num] = xavg[num]*v[num] + xv[num]*(1-v[num])
  davg[num] = davg[num]*v[num] + dis[num]*(1-v[num])

  -- ③ 可变长环形缓冲：buffer 长度随距离增长（远→历史更长→更平滑）
  ts[num] = math.min(math.floor(davg[num]/5), 150)
  table.insert(ri[num], davg[num])
  if #ri[num] > ts[num] then table.remove(ri[num], 1) end
  -- 缓冲均值 → 闭合速度（logic tick = 16 ms → 除以 0.016）
  ms[num] = -math.floor(((iavg[num]-od[num])/0.016) // 1)
  od[num] = iavg[num]

  -- ④ 圈→弧度：方位是圈，先 *360 成「度」再 rad() 才喂 tan()（否则方向乱飞，见 00 §4）
  xco = tan(rad(xavg[num]*360 - camx*45)) * (w/4/zx) * (h/w) + w/2
  yco = -tan(rad(yavg[num]*360 - camy*45)) * (h/4/zy) + h/2
end

-- ⑤ 遮挡合并（在 onDraw 里做）：两个目标挨太近且一近一远 → 只画近的
for i=1,tar do for j=1,tar do
  if not (i==j) then
    cmp[i][j]  = math.abs(d[i]-d[j])          -- 深度差
    cmpx[i][j] = math.abs(x[i]-x[j])          -- 屏幕水平差
    cmpy[i][j] = math.abs(y[i]-y[j])          -- 屏幕垂直差
  end
  if ((cmp[i][j] or 16)<15) and (cmpx[i][j]<=s[i]) and (cmpy[i][j]<=s[i]) then
    td[j] = false   -- 被更近的挡住 → 不画
  end
end end
```

**要点速记**
- 雷达每个目标固定占 3 通道，遍历时 `n=i+(i-1)*3` 取，别用 `3*i-2`（那是错的，会漏一个）。
- 方位/高低都是**圈**，凡是进 `tan/sin/cos` 必须 `*360` 转度再 `rad()`。
- 「近处抖、远处稳」用**距离自适应 EMA**（v 随距离变）比固定 α 更稳。
- 闭合速度：存滑动窗口均值、每 tick 减上一 tick 均值，再 `÷0.016`。
- 遮挡合并本质是「深度排序 + 包围盒重叠」的简化版，适合密目标 PPI 防重影。
- FOV→像素还要按宽高比修正：`zx = tan(ang*pi/180/2) / (1.82 - 0.15*(w/h-1))`。

**要点速记**
- 🔑 **两种余晖，别混用**：`03` §16 的声纳是「**按角度存** 360 槽环形缓冲，推进即移位」；本例是「**按目标存** `Data` 表，天线扫到哪个扇区就把那个扇区的旧点删掉，再插入本帧新点」。前者适合机械扫描的连续回波，后者适合雷达的离散目标通道。**后者不需要给每个点记时间戳**——"没被扫到"本身就是过期判据。
- 🔑 **`WG` 要跳过启动抖动**：`if LOK<6 then WG=RotA-Rot ... end`，前 6 帧只测速不淘汰，否则第一帧 `WG` 是 0（窗口宽度为 0）或莫名其妙的跳变值。
- 🔑 **`Rot=方位%1` + `>0.5 则 -1`**：把圈的 0..1 映成 ±0.5。屏幕左右对称绘制时这一步省不掉，否则 0.9 和 0.1 会画到屏幕两端（关联 `04` §1.2 最短角差）。
- 🔑 **属性文本存 RGBA**：`string.find(s,"(%d+),(%d+),(%d+)%p*(%d*)%s*")` 一次抓 4 组，`tonumber(A) or 255` 给缺省 alpha。比 `05` §17 的定宽切片更宽松（位数可变），代价是正则比 `gmatch` 慢——**只在 onTick 里解析一次**，别放 onDraw。
- 🔑 **一个属性翻转整套绘制**：`Q=pgB("Radar upside down") and -1 or 1`，之后所有横向坐标乘 `Q`。雷达装反了不用改代码。
- ⚠ **`DisCor` 的倾斜补偿实际是空转**（可验算，不是猜测）：它构造两个旋转矩阵 `T_12`(横摇) / `T_23`(纵摇) 去乘位置向量，但**旋转矩阵是正交阵、保长度**，所以 `|L_1| == |L_3|` 恒成立，返回值与 `tiltL/tiltF` **完全无关**：

  ```
  L_3 = { cos(Ea)*Dis*cos(Rot),  cos(Ea)*Dis*sin(-Rot),  sin(Rot)*Dis }
  |L_3| = Dis*sqrt( cos(Ea)^2 + sin(Rot)^2 )      -- 与 tiltL / tiltF 无关
  ```

  而且第三分量写成了 `sin(Rot)`（方位角）而不是 `sin(Ea)`（仰角），主项恒等于 `Dis`，所以本机上它约等于原斜距、显示"看起来正常"。
  **结论**：真要做纵横摇补偿，应该取旋转后向量的**某个分量**（例如竖直分量当地面投影的基准），或者显式做 `水平距离 = Dis*cos(有效仰角)`；**用模长当输出，等于把倾斜补偿做成了恒等变换**。这是"用了矩阵但没检查它到底改变了什么"的典型。
- ⚠ `Data` 用 `table.insert` + `pairs` 遍历删除，删除时 `Data[i]=nil` 是安全的（`pairs` 允许在遍历中把当前键置 nil；但**不要**在 `pairs` 里置其它键为 nil，行为未定义）。对比 `08` §14 的 `while` 原地删除。

**要点速记**
- 🔑 **16 进制 4 字符切片**：`FONT:gmatch("....")` 每 4 字符一段、`tonumber(n,16)` 转成一个 **16 bit 字模**（15 位像素 + 1 位标志）。比 `05` §22 的十进制/定宽更紧凑——一个 4 字符槽存满 16 bit，属性文本能塞下的字形更多。
- 🔑 **bit0 兼作字宽标志**：`if FONT_D[ci]&1==1 and not m then i=2*s else i=4*s end` —— 用字模的**最低位**表示"这是个窄字符（如 I、1、.）"。代价是 bit0 不能当像素用（所以像素只用了 i=1..15），换来**不占额外字节就实现了变宽字体**。
- 🔑 **旋转 4 向的实现**：`r%2==1` 横排 / `r%2==0` 换轴（`x+5-yy, y+xx`）；`r>2` 时**字符串先 `reverse()`、位序也从 `2^(16-i)` 改成 `2^i`**。**字形旋转时位序必须跟着反**，否则 180/270 度会拿到镜像字。
- 🔑 **船艏相对投影**：`sx=r-1+scb*dx+ssb*dy` / `sy=r-scb*dy+ssb*dx`，其中 `scb=scale*cos(ba)`、`ssb=scale*sin(ba)` **提到循环外算一次**。所有点共用同一组系数，批量变换时这是最直接的省算力写法。
- 🔑 **寿命衰减驱动全部视觉**：`life=1800`（30 s）统一管理透明度 `100*(life-l)/life`、颜色 `50*l/life`、年龄圈半径 `l/24`。**一个计数器，三种视觉表达**。
- 🔑 **倒序 `for i=#T,1,-1` 删除**：与 `08` §14 的 `while` 原地删除、`07` §2.2 的重建表并列为三种安全写法。倒序 `for` 的要点是**从尾部往头部走**，删除不会影响尚未访问的下标。
- 🔑 **逐行三角扇画圆盘**：`for i=1,h` 每行一个 `drawTriangleF`，第三个顶点**贴到屏幕边**（`x>r and 2*r-1 or 0`），保证边缘填满不留缝。这是没有 `drawCircleF` 填充时的通用画法（对比 `05` §5.7 `drawArc` 用多边形逼近）。
- ⚠ **记点去重靠深度变化**：`if fish and (#T<=0 or tdepth~=T[#T].z)` —— 同一条鱼悬停时不重复记点。这是个取巧但有效的判据；若两条鱼深度恰好相同则会被漏记，工程上可接受。
- ⚠ **输入符号约定**：`tyaw=-iN(1)*pi2` 与 `sy=r-scb*dy+ssb*dx` 的减号都是本作品自己的接线约定，**照抄前必须按你的罗盘方向验证一次**（关联 `06` §9「指针转反了」的坑）。

## §19 多雷达 TWS 航迹器：**安装角补偿 + EMA 合并 + 环形游标把整张航迹表搬给另一块微控制器**

- 来源：steam id 3789229957 · 描述页 https://steamcommunity.com/sharedfiles/filedetails/?id=3789229957 · 载具（Ranger Class Corvette，轻型护卫舰※，`_vehicle_20` = MC1 跟踪器）
- 更新时间：2026-08-28
- 用到：最多 4 部雷达（各给 距离/方位/仰角 + 检测布尔）、GPS、罗盘航向（圈）、两块微控制器之间的复合通道
- 亮点：**每部雷达的安装角（相对船艏的圈值）直接加在方位上**再进笛卡尔转换，四部雷达共用一套关联逻辑；航迹表用**环形游标每 tick 只搬一条**给显示端，输出通道数不随航迹数增长
- 关联：`03` §8（单雷达门控关联 + 测速 + 预测）、`08` §3（合并阈值要含速度项）、`03` §3（球面→笛卡尔权威版）、`07` §8（状态型数据周期重发）

```lua
local TWO_PI=2*math.pi
local MAX_TRK=24      -- 航迹上限（防表无限膨胀）
local TMO=420         -- 老化时间：7 秒 × 60 tick
local MRAD=500        -- 关联门限(m)
local SMTH=0.3        -- EMA 系数
local tick=0
local tracks={}       -- 航迹表
local nid=1           -- 自增 id
local sel=nil         -- 🔑 选中的是 id，不是下标
local oidx=1          -- 轮询游标
local ox,oy,oz,heading=0,0,0,0

local function d3(ax,ay,az,bx,by,bz)
  local dx,dy,dz=ax-bx,ay-by,az-bz
  return math.sqrt(dx*dx+dy*dy+dz*dz)
end

-- 雷达极坐标(圈) → 相对 XYZ；SW 约定：X=东 Y=上 Z=北
local function pol2xyz(dist,az,el)
  local ar,er=az*TWO_PI,el*TWO_PI
  local h=dist*math.cos(er)
  return h*math.sin(ar), dist*math.sin(er), h*math.cos(ar)
end

-- 老化清理：while 版安全删除（删除分支不前进 i）
local function prune()
  local i=1
  while i<=#tracks do
    if (tick-tracks[i].last)>=TMO then
      if tracks[i].id==sel then sel=nil end   -- 删掉的正好是选中项，必须同步清
      table.remove(tracks,i)
    else i=i+1 end
  end
end

-- 门控关联：只在 MRAD 半径内取最近的旧航迹，取不到就新建
local function nearest(x,y,z)
  local bi,bd=nil,MRAD
  for i,t in ipairs(tracks) do
    local d=d3(x,y,z,t.x,t.y,t.z)
    if d<bd then bd=d bi=i end
  end
  return bi
end

local function contact(dist,az,el)
  local rx,ry,rz=pol2xyz(dist,az,el)
  local hr=heading*TWO_PI
  local ch,sh=math.cos(hr),math.sin(hr)
  -- 🔑 绕航向旋转到世界系（船体→世界）；Y 是竖直轴，不参与 yaw 旋转
  local ax,ay,az2 = ox+rx*ch+rz*sh, oy+ry, oz-rx*sh+rz*ch
  local i=nearest(ax,ay,az2)
  if i then
    local t=tracks[i]
    -- 🔑 EMA 合并而非覆盖：命中即向新观测靠 30%
    t.x=t.x+SMTH*(ax-t.x)
    t.y=t.y+SMTH*(ay-t.y)
    t.z=t.z+SMTH*(az2-t.z)
    t.last=tick t.az=az t.el=el t.dist=dist
  elseif #tracks<MAX_TRK then
    table.insert(tracks,{id=nid,x=ax,y=ay,z=az2,last=tick,az=az,el=el,dist=dist})
    nid=nid+1
  end
end

-- 🔑 四部雷达 = 一张通道映射表 {距离, 方位, 仰角, 检测布尔}
local RN={{1,2,3,1},{8,9,10,5},{11,12,13,6},{14,15,16,7}}
local cprev,dprev=false,false

function onTick()
  tick=tick+1
  ox=input.getNumber(4)
  oy=7                       -- 水面船：自机高度当常数（雷达仍用仰角算目标高度，空中目标照样跟）
  oz=input.getNumber(5)
  heading=input.getNumber(7)

  local rcnt=math.floor(input.getNumber(17)+0.5)
  if rcnt<1 then rcnt=1 elseif rcnt>4 then rcnt=4 end
  for r=1,rcnt do
    local c=RN[r]
    local d=input.getNumber(c[1])
    if input.getBool(c[4]) and d>0 then
      -- 🔑 安装角（圈，相对船艏）直接加在方位上：两者同单位，可直接相加
      contact(d, input.getNumber(c[2])+input.getNumber(17+r), input.getNumber(c[3]))
    end
  end
  if tick%60==0 then prune() end        -- 老化每秒扫一次就够

  -- 循环选择下一个目标（边沿触发 + 环形取下一个）
  local cnow=input.getBool(3)
  if cnow and not cprev and #tracks>0 then
    if sel==nil then
      sel=tracks[1].id
    else
      for i,t in ipairs(tracks) do
        if t.id==sel then sel=tracks[(i%#tracks)+1].id break end
      end
    end
  end
  cprev=cnow

  -- 选中项：按 id 反查，查不到就自动取消选中
  local ft=nil
  if sel then
    for _,t in ipairs(tracks) do if t.id==sel then ft=t break end end
    if not ft then sel=nil end
  end
  output.setBool(1, ft~=nil)
  if ft then
    output.setNumber(1,ft.x) output.setNumber(2,ft.z) output.setNumber(3,ft.y)
    output.setNumber(4,ft.dist) output.setNumber(5,ft.az) output.setNumber(6,ft.el)
  else
    for i=1,6 do output.setNumber(i,0) end
  end

  -- 🔑 环形轮询：每 tick 只搬一条航迹给显示端 MC
  local n=#tracks
  output.setNumber(11,ox) output.setNumber(12,oz) output.setNumber(14,n)
  if n>0 then
    if oidx>n then oidx=1 end
    local t=tracks[oidx]
    output.setNumber(7,t.x)  output.setNumber(8,t.z)
    output.setNumber(9,t.id) output.setNumber(10,tick-t.last)
    output.setNumber(13,t.dist) output.setNumber(15,t.az)
    output.setBool(2,true)
    oidx=oidx+1
  else
    output.setBool(2,false) output.setNumber(9,0)
  end
end
```

**为什么这样写**

- **安装角加在方位上**：雷达给的是「相对雷达朝向」的方位（圈），安装角也是圈，**同单位可直接相加**；加完之后再和航向一起送进 `pol2xyz`。千万别先转弧度再加——那样很容易把两个不同原点的角混在一起。四部雷达共用一张通道映射表 `RN`，换雷达数量只改 `rcnt`。
- **EMA 合并而不是覆盖**：直接 `t.x=ax` 会把单帧噪声原样搬到输出，表现为目标抖动、舵面打颤。`t.x=t.x+0.3*(ax-t.x)` 相当于一阶低通；代价是快速机动目标有滞后。追得上就用 0.3，追不上再往 0.5 调（与 `04` §1.4 的 EMA 同一套）。
- **`sel` 存 id 不存下标**：`tracks` 会 `table.remove`，下标每帧都可能变；存自增 `nid` 后，删掉中间一条也不会选错目标（同类坑见 `08` §14）。
- **老化清理的三个约束**：① 用 `while` 且删除分支**不前进 `i`**（`table.remove` 后元素前移，前进就漏删，对照 `07` §2.2 的重建表写法）；② 删除时同步清 `sel`，否则会继续广播一个已经不存在的 id；③ `tick%60==0` 每秒扫一次即可，不必每帧。
- **用固定通道传变长表**：显示端 MC 的通道数是固定的（本例 6 个数 + 2 个布尔），航迹数却可变。每 tick 搬一条、`oidx` 到头归 1，整张表一秒内刷完一遍。代价是显示端看到的各条航迹最多相差 `n` tick，画出来会「错帧」——要严格同帧就把表改成定长数组一次搬 N 条。

## §20 雷达目标叠到地图上：**罗盘符号约定 + FOV 双三角扇 + 属性存定点整数 + 视口裁剪**

- 来源：steam id 2948687255 · 描述页 https://steamcommunity.com/sharedfiles/filedetails/?id=2948687255 · 载具（26m V80 Superyacht，`_vehicle_1` 雷达叠加屏）
- 更新时间：2023-03-19
- 用到：雷达（8 路检测布尔 + 各目标距离/方位）、GPS、罗盘（圈）、属性滑块 `Radar Range (m)` / `Radar FOV X (x100)` / `Allways draw all circles`
- 亮点：**属性里存「FOV 的百分之一」这类定点整数**，滑块一格一格跳、读数直观；**同心距离环一旦跑出视口就停止绘制**，并留一个属性可强制全画
- 关联：`03` §3（球面→笛卡尔）、`08` §2.3（游戏罗盘东为负）、`04` §9.1（十进制跳档 + px→m 标定）、`05` §5.1（三角扇）

```lua
S=screen M=math
dC=S.drawCircle dCF=S.drawCircleF dTF=S.drawTriangleF sC=S.setColor
iN=input.getNumber iB=input.getBool
c=100          -- 环距兜底值
ctcs={}        -- 目标点表 {世界X, 世界Y, alpha}

function onTick()
  w,h = iN(1), iN(2)
  x,y,z = iN(7), iN(8), iN(9)     -- 地图中心 + 缩放（上游屏给）
  e = iN(10)                       -- 🔑 1 m 对应多少像素（上游标定好传进来）
  rx,ry = iN(11), iN(12)           -- 雷达所在的世界坐标
  b = iN(13)*2*M.pi                -- 罗盘（圈 → 弧度）
  R = property.getNumber("Radar Range (m)")*e
  cx,cy = map.mapToScreen(x,y,z,w,h,rx,ry)

  local j=#ctcs
  for i=0,7 do
    if iB(i+4) then                -- 第 i 个目标被探测到
      j=j+1
      -- 🔑 东(X) 用 -sin、北(Y) 用 +cos：与「游戏罗盘东为负」的约定一致（见 08 §2.3）
      ctcs[j] = { rx - M.sin(iN(15+i*2)*2*M.pi)*iN(14+i*2),
                  ry + M.cos(iN(15+i*2)*2*M.pi)*iN(14+i*2),
                  255 }           -- 第三项既是亮度也是寿命
    end
  end
  if j>1 then
    for i=1,j do ctcs[i][3]=M.max(ctcs[i][3]-1,0) end    -- 每帧 -1，255 帧淡出
    local i=j
    while i>1 do                                          -- 倒序 while 安全删除
      if ctcs[i][3]<1 then table.remove(ctcs,i) end
      i=i-1
    end
  end
end

function onDraw()
  sC(0,255,0)     dCF(cx,cy,2)              -- 本舰
  sC(0,255,0,100) dC(cx,cy,R) dC(cx,cy,R/2) -- 量程环 + 半量程环

  -- 🔑 FOV 扇形 = 两个三角扇拼出 [b-fov, b+fov]
  local fov=(property.getNumber("Radar FOV X (x100)")/200)*2*M.pi
  dTF(cx,cy, cx-M.sin(b+fov)*R, cy-M.cos(b+fov)*R, cx-M.sin(b)*R, cy-M.cos(b)*R)
  dTF(cx,cy, cx-M.sin(b)*R,     cy-M.cos(b)*R,     cx-M.sin(b-fov)*R, cy-M.cos(b-fov)*R)

  -- 十进制跳档选环距 c（见 04 §9.1）
  if     e*10000<w/2-10 then c=e*10000
  elseif e*1000 <w/2-10 then c=e*1000
  elseif e*100  <w/2-10 then c=e*100
  elseif e*10   <w/2-10 then c=e*10 end

  sC(0,100,0,50)
  local i=0
  -- 🔑 视口裁剪：环心跑到 2c 之外就停画，别画上百个看不见的圆环
  while i*c<R and (property.getBool("Allways draw all circles")
                   or (cx<w+2*c and cx>-2*c and cy<h+2*c and cy>-2*c)) do
    dC(cx,cy,i*c)
    i=i+1
  end

  for i=1,#ctcs do
    local tx,ty=map.mapToScreen(x,y,z,w,h,ctcs[i][1],ctcs[i][2])
    sC(0,255,0,ctcs[i][3])
    if tx<cx-1 or tx>cx+1 or ty<cy-1 or ty>cy+1 then dCF(tx,ty,1) end
  end
end
```

**为什么这样写**

- **属性存定点整数**：SW 的属性滑块只有浮点，想让它一格一格跳就得自己处理。作者把 FOV 存成「实际角度 ×100」（属性名带 `x100`），取用时 `/200*2π`——**除以 200 是因为属性存的是全角，而画扇形需要半角**。`Allways draw all circles` 这类布尔属性则用来给「省绘制」留一个关闭开关。
- **罗盘符号要对表**：本例 `-sin` 给东、`+cos` 给北，前提是雷达方位已是「0=北、顺时针」的圈值。若你的方位来自物理传感器，先按 `03` §1 核对单位（欧拉角是**弧度**），别照抄符号。
- **一个字段当两个数用**：`ctcs[i][3]` 从 255 每帧 -1，既做亮度又做寿命，省一个字段——8192 字符上限下这种「一值两用」很常见（对照 `03` §18 字模 bit0 兼作窄字符标志）。
- **视口裁剪**：高倍缩放下同心环可能有几百个，`while` 条件里加一句包围盒判断就能砍掉绝大部分绘制调用。代价是环心刚出屏时环会突然消失，所以留了「强制全画」属性兜底。
- ⚠ **跳档变量没有兜底**：四个 `elseif` 都不成立时（例如 `e` 极大、连 10 m 都超过半屏宽），`c` 保持上一帧的值。抄的时候给它一个初值（本例 `c=100`）。

## §21 雷达多目标**轮询采样保持**：把 7 个通道轮流锁存成稳定航迹点

- 来源：steam id 3794762394（雷达目标 HUD，独立微控，2026-09-01）
- 用到：雷达（距离/方位/有效标志）、属性滑块 `Minimum draw distance`
- 亮点：雷达每帧只保证**一个**目标通道有效时，用「轮询调度 + 触发帧锁存」把 7 个目标都留在屏上
- 区别于 §19（TWS 航迹器用 EMA 合并与环形游标搬表）：本例是**同一块微控制器内部**的
  通道轮询，不搬表、不合并，只做采样保持，成本最低

### 问题背景

一块微控制器接多部雷达时，常见做法是「每帧读全部通道」。但若雷达是**共用总线/轮换上报**
（或作者刻意分时），任意一帧只有部分通道有效。直接读会导致目标点闪烁、乱跳。

### 手法一：可重触发保持计时器

```lua
wt = 150                       -- 保持时长（tick）
function Timer(detected, t)    -- 检测到就重新灌满，否则递减到 0
  if detected and t == 0 then
    return wt
  elseif t <= 0 then
    return 0
  else
    return t - 1
  end
end

-- 只有「本目标正在被轮询 或 保持计时未归零」才维护计时器
if Target == 1 and Target1 or wt1 > 0 then wt1 = Timer(Target1, wt1) end
if Target == 2 and Target2 or wt2 > 0 then wt2 = Timer(Target2, wt2) end
```

`wt1 == wt` 就是**触发帧**的判据（刚被灌满，还没开始递减）。

### 手法二：只在触发帧采样，其余帧保持

```lua
if input.getNumber(1) > MinDist and wt1 == wt then
  Distance1 = input.getNumber(1) / (Scale * (Range/1000))
  local a = (input.getNumber(2)*360 - Offset) * math.pi/180   -- 圈→度→弧度，再减安装偏置
  x1 = w/2 + Distance1*math.cos(a - 1.58)                     -- -1.58≈-π/2：把 0 方位转到屏幕上方
  y1 = h/2 + Distance1*math.sin(a - 1.58)
else
  x1 = x1 y1 = y1      -- 采样保持：不更新就原地不动，绝不让坐标跳变
end
```

`Scale = w/2`，`Range` 是量程（km 档），`MinDist` 过滤贴脸噪声。

### 手法三：轮询调度器 + 双计时器超时复位

```lua
wait = wt/24
if Target1 and Target == 1 and timer == 0 then
  Target = 2  timer = wait  timer2 = wait/2      -- 命中下一个 → 前进
-- ... 2~7 同构 ...
elseif timer <= 0 and timer2 > 0 then
  timer = 0  timer2 = timer2 - 1                 -- 主冷却到了，等兜底窗口
elseif timer2 <= 0 then
  timer, timer2, Target = 0, 0, 1                -- 兜底窗口也超了 → 回到 1 号重新扫
else
  timer = timer - 1  timer2 = timer2 - 1
end
```

`timer` 是**跳档冷却**（防一次回波把 7 档全推完），`timer2 = wait/2` 是**兜底复位窗口**
（某一档迟迟等不到回波时把扫描指针拉回起点，避免卡死在空档）。

### ⚠ 两处实测缺陷（抄之前先改掉）

1. **平行展开的复制粘贴会错**：本例第 4 个目标的判据写成 `wt5 == wt`（应为 `wt4`），
   导致 4 号目标除极其偶然的时序外**永远不更新**。7 路同构代码手写展开是最易出错的地方，
   应改成 `for i=1,7` + 数组（`T[i]` / `wt[i]` / `x[i]` / `y[i]`），见 `01` §7 批量 IO。
2. **配色变量写法错误**：`red=255,0,0` 只留下 `255`，见 **`01` §9**。

### 何时用这套

| 场景 | 用哪套 |
| --- | --- |
| 每帧全部通道都有效 | 直接读，不需要采样保持 |
| 通道轮换上报 / 想省 tick | **本例**（轮询 + 触发帧锁存） |
| 多雷达融合、要速度与预测 | `03` §19 TWS 航迹器 |

## §22 雷达 PPI：把**余晖衰减速率绑到 RPS**，换转速视觉一致

- 来源：steam id 3795293475（可变量程雷达显示器，载具，2026-09-02）
- 用到：雷达（距离/俯仰/方位/有效标志）、GPS、高度计、指南针、4 档量程与 RPS 属性
- 亮点：余晖寿命与扫描线拖尾长度都用 `rps/60` 归一化，改转速不会让画面"变糊"或"变闪"
- 区别于 `03` §15 / §16 / §17：那三节解决"余晖怎么存"（数组 / 360 槽环形缓冲 / 扫描窗口淘汰），
  本节解决"**衰减该多快**"这个参数怎么取——答案是与扫描周期挂钩

### 核心：一个 tick 转多少圈

```lua
rps = property.getNumber("Radar RPS")     -- 每秒转多少圈
-- 每 tick 的角度增量，同时也是每 tick 的衰减量
step = rps / 60                            -- rps=2 → 每 tick 1/30 圈

CurYaw = CurYaw % 1 + step                 -- 扫描线推进
if CurYaw > 0.5 then CurYaw = CurYaw - 1 end   -- 归一到 ±0.5 圈
```

游戏逻辑固定 60 tick/s，所以 `rps/60` 就是**一个 tick 转过的圈数**。
转满一整圈需要 `60/rps` 个 tick，每 tick 衰减 `rps/60`，乘积恰好为 1：

```lua
for i = 1, #Mas do
  Dec[i] = Dec[i] - rps/60        -- 目标亮度：一整圈衰减 1.0（从满亮到熄灭）
  if Dec[i] < 0 then Dec[0] = 0 end   -- ⚠ 原脚本下标写错，见文末
end
```

**收益**：把雷达从 1 RPS 调到 4 RPS，目标的余晖寿命自动从 60 tick 缩到 15 tick，
屏幕上"拖尾占圆周的比例"恒定不变。若写成固定 `Dec[i] = Dec[i] - 0.02`，
高速扫描时目标会亮成一片，低速时会一闪就灭。

### 波束拖尾：多线渐暗，步长同样是 `step`

```lua
linewidth = 16
for i = 1, linewidth do
  local k = 1 - i/(linewidth+1)
  setC(0, 255*k, 0, 255*k)                       -- 越靠后越暗
  drawL(cx, cy, cx + r*cos2p(CurYaw - 0.25 - i*step),
                cy + r*sin2p(CurYaw - 0.25 - i*step))
end
```

`i*step` 让第 i 条线正好落在 **i 个 tick 之前**的扫描位置，
于是 16 条线天然拼出一个"过去 16 tick"的渐暗扇形，不需要存历史。

> `sin2p/cos2p` 是圈→弧度的包装：`function sin2p(x) return math.sin(x*pi2) end`。
> 这样全脚本内部一律用「圈」，只在三角函数入口处乘一次 `2π`，读代码时不用再换算。

### 量程点击循环 + 只画内圈

```lua
if Pulse(isPr, isPr_old) then                 -- 按下沿：见 02 §1
  DispMode = DispMode + 1
  if DispMode == 4 then DispMode = 0 end
end
Rad = ({Rad1, Rad2, Rad3, Rad4})[DispMode+1]  -- 4 档量程

-- 目标点只画在内圈 46% 以内，避免贴边溢出圆外
if TrgDsti/Rad < 0.46 then
  screen.drawRectF(cx + (w/2*TrgDsti/Rad)*cos2p(angle),
                   cy + (h/2*TrgDsti/Rad)*sin2p(angle), 1, 1)
end
```

注意 x 用 `w/2` 缩放、y 用 `h/2` 缩放 —— **非正方形屏上这是刻意的**：
PPI 被拉成随屏幕形状的椭圆，铺满整屏。要正圆请统一用 `min(w,h)/2`
（见 `03` §13 的平均半径 `(w+h)/4`）。

### 手写 `atan` 的象限修正（只有单参数 `math.atan` 时）

```lua
local m = dY / dX
if     dX > 0 and dY >= 0 then TrgOriX = math.atan(m)/pi2
elseif dX > 0 and dY <  0 then TrgOriX = math.atan(m)/pi2 + 1
elseif dX < 0              then TrgOriX = math.atan(m)/pi2 + 0.5   -- 二三象限：直接 +0.5 圈
elseif dX == 0 and dY > 0 then TrgOriX = 0.25                      -- 奇点
elseif dX == 0 and dY < 0 then TrgOriX = 0.75
else                           TrgOriX = 0
end
```

`atan` 的值域是 ±0.25 圈（±π/2），周期是 0.5 圈。所以 `dX < 0` 时**统一 +0.5 圈**
就能同时覆盖第二、三象限——不必再按 `dY` 细分（见 `04` §1.2b 的写法对比）。

### 罗盘 0 点转到 X 轴

```lua
if (-0.25 <= Comp and Comp < 0.5) then OriX = Comp + 0.25
else                                   OriX = Comp + 1.25 end
```

指南针读数是圈，0 = 正北；这里 +0.25 把北挪到屏幕上方，再取模归一到 0..1。

### ⚠ 三处实测缺陷

1. `Dec[0] = 0` —— 下标写死成 0，本该是 `Dec[i] = 0`。结果是衰减到负数后**不再钳位**，
   `screen.setColor(0,255,0, 255*Dec[i])` 的 alpha 变成负数，表现为目标忽明忽暗或直接消失。
2. 折差归一阈值不对称：
   ```lua
   if TrgOri > 0.4  then TrgOri = TrgOri - 1
   elseif TrgOri < -0.5 then TrgOri = TrgOri + 1 end
   ```
   上界用 0.4、下界用 -0.5，于是 **0.4~0.5 区间不会被折回**，目标被画到对称的另一侧。
   正确是对称的 ±0.5（或统一用 `04` §1.2b 的 `nm(v) = (v+.5)%1-.5`）。
3. 目标高度 `TgZ = Alt + TrgDst*math.tan((Pitch + TrgPit)*pi2)` —— `tan` 在仰角接近
   ±0.25 圈时趋于无穷，高俯角目标会得到荒谬的高度值；应先 `clamp` 到 ±0.2 圈以内。

## §23 雷达目标 **5 帧移位寄存器**：确认计数 + 均值去重 + 主/次锁定分级

- 来源：steam id **3795274874** · 描述页 <https://steamcommunity.com/sharedfiles/filedetails/?id=3795274874> · **载具**（FX-91A "Reaper"，`_vehicle_36` 雷达 HUD，LifeBoatAPI 压缩态）
- 更新时间：2026-09-04
- 用到：雷达（8 目标 × 4 值：距离 / 方位角 / 仰角 / 发现标志）、多功能屏、属性（最小距离、安装朝向、配色、距离单位、HUD 位置）
- 亮点：**每个目标留 5 帧历史做滑动平均**，并用「有效帧数 ≥ 4」确认，滤掉闪烁假目标；再按**平均角度差 < 0.008 圈**合并被多路同时看到的同一目标，最后把目标分成**锁定（红）/ 最近威胁（黄）**两级。

> 与既有章节的分工：`§19` 是「EMA 平滑 + 环形游标搬表」，`§21` 是「轮询采样保持」，
> 本例是第三种——**固定长度移位寄存器 + 确认计数 + 均值去重**，适合每帧都能拿到全部通道、但要抑制抖动的场合。

```lua
N_TGT, HIST = 8, 5
az, el, dst, seen = {}, {}, {}, {}          -- 每路：方位角 / 仰角 / 距离 / 本帧有无目标
avgAz, avgEl, avgDst, confirmed = {}, {}, {}, {}

for i = 1, N_TGT do
  az[i], el[i], dst[i], seen[i] = {}, {}, {}, {}
  for k = 1, HIST do az[i][k], el[i][k], dst[i][k], seen[i][k] = 0, 0, 0, false end
end

function onTick()
  azLimit, elLimit = input.getNumber(12), input.getNumber(16)   -- 视场边界（圈）
  rMin, rMax, lockRange = input.getNumber(20), input.getNumber(24), input.getNumber(28)
  orient = property.getBool("Radar Orientation") and -1 or 1    -- 雷达可倒置安装：整路取号
  minR   = property.getNumber("Minimum Radar Distance")

  for i = 1, N_TGT do
    -- ① 右移一格腾出队首：必须从尾往头搬，否则会把同一个值铺满整行
    for k = HIST, 2, -1 do
      az[i][k], el[i][k], dst[i][k], seen[i][k] = az[i][k-1], el[i][k-1], dst[i][k-1], seen[i][k-1]
    end
    dst[i][1] = input.getNumber((i-1)*4 + 1)
    az[i][1]  = input.getNumber((i-1)*4 + 2) * orient
    el[i][1]  = input.getNumber((i-1)*4 + 3) * orient
    seen[i][1]= input.getBool(i)

    -- ② 只对有效帧求平均，cnt 顺带当确认计数
    local sa, se, sd, cnt = 0, 0, 0, 0
    for k = 1, HIST do
      if seen[i][k] then sa, se, sd, cnt = sa + az[i][k], se + el[i][k], sd + dst[i][k], cnt + 1 end
    end
    if cnt > 0 then                    -- 🔴 cnt == 0 时绝不能除，nan 会顺着 avg 表污染后面所有判定
      avgAz[i], avgEl[i], avgDst[i] = sa/cnt, se/cnt, sd/cnt
    end
    confirmed[i] = cnt > HIST - 1      -- ③ 5 帧里 ≥ 4 帧有效才算真目标
  end
end

function onDraw()
  local primary, secondary, bestD = 0, 0, 1e9
  local w, h = screen.getWidth(), screen.getHeight()
  for i = N_TGT, 1, -1 do
    dup = false
    if confirmed[i] and avgDst[i] > minR
       and azLimit > math.abs(avgAz[i]) and elLimit > math.abs(avgEl[i])
       and avgDst[i] > rMin and avgDst[i] < rMax then
      for j = i - 1, 1, -1 do          -- ④ 与编号更小的目标比对，角度几乎相同就只画一次
        if math.abs(avgEl[i] - avgEl[j]) < 0.008 and math.abs(avgAz[i] - avgAz[j]) < 0.008 then dup = true end
      end
      if not dup then
        if avgDst[i] < lockRange and primary == 0 then
          primary = i                                     -- 锁定：门限内（倒序遍历，取编号最大的那路）
        elseif avgDst[i] > lockRange and primary == 0 and avgDst[i] < bestD then
          secondary, bestD = i, avgDst[i]                 -- 最近威胁：门限外的距离最小者
        end
      end
    end
    if confirmed[i] and not dup then
      -- 圈 → 弧度要 ×2π；c 是按「座舱到屏的格数」查表得到的 HUD 半径
      local X = w/2 + math.sin(avgAz[i]*math.pi*2) * c
      local Y = h/2 - math.sin(avgEl[i]*math.pi*2) * c
      if i == primary then screen.setColor(255, 0, 0)
      elseif i == secondary then screen.setColor(255, 255, 0) end
      screen.drawText(X, Y, fmtDist(avgDst[i]))
      screen.drawRectF(X - 2, Y - 2, 4, 4)
    end
  end
  if primary > 0 then secondary = 0 end
end

-- 距离读数：公制过 1000 m 改一位小数 km；英制 *3.28084，过 5280 ft 改英里
function fmtDist(d)
  if units == 2 then
    d = d * 3.28084
    if d > 5280 then return (math.floor(d/528)/10) .. "mi" end
    return math.floor(d/100)*100 .. "ft"
  end
  if d > 1000 then return (math.floor(d/100)/10) .. "km" end
  return math.floor(d/100)*100 .. "m"
end
```

**要点**

- **移位寄存器 vs EMA**：EMA（`§19`）只存一个值、最省内存，但对阶跃响应慢；移位寄存器存 5 帧，能同时拿到**平滑值**和**置信度（有效帧数）**，代价是 `8×5×4 = 160` 个槽位（本例用 4 张平行表，也可合成一张 `hist[i][k] = {az, el, dst, seen}`）。
- **确认计数是去抖的关键**：目标在波束边缘进出时通道会单帧闪断，`cnt > HIST-1` 让目标必须连续出现才画，画面不闪。
- **去重靠比较平均角度**（`< 0.008 圈 ≈ 2.9°`）：同一目标常被相邻通道同时看到，不去重会出现两个重叠目标框；阈值取在雷达角分辨率量级即可。
- **反面教材（原脚本两处）**：
  1. 目标选择写在 `onDraw` 里，而 `output.setBool(1, primary > 0)` 写在 `onTick` 里 → **输出用的是上一帧的结果，慢一帧**。要同步就整个搬进 `onTick`。
  2. 同一段角度→像素换算在 `onDraw` 里被算了**两遍**（先筛目标、再绘制），多花约 300 字符；应在筛选时把 X/Y 存进表，绘制阶段直接取。

> **这是什么**：飞行员戴头盔显示器（HMD※），视线看向哪，雷达就指哪（ACM 模式）；
> 雷达发现的目标用一个小标记画在头盔视野里，视线对准即锁定。
> ※`HMD` / `Helmet` 未收录于汉化补丁，此处按行业通译「头盔显示器」。

```lua
-- CONFIG：角度门、寿命、锁定确认帧数
AZ, EL = 8*math.pi/180, 6*math.pi/180     -- 关联的角度门
LIFE, LOCKT, MIN = 120, 15, 25            -- 寿命 tick / 自动锁定确认帧 / 最小距离 m
N = 8                                     -- 雷达目标数
W, H, TPP = 256, 192, 165                 -- 屏宽 / 屏高 / 每弧度像素数
U, ID, L = {}, 1, 0                       -- 航迹表 / 自增 id / 锁定的 id（不是下标！）

function CD(a, b) return ((a - b + .5) % 1) - .5 end      -- 圈最短角差（见 04 §1.2）

-- ① 门控关联：在【雷达量测空间】比较，省掉一次世界坐标转换
function Find(d, a, z)
  local k, q = nil, 999
  for i = 1, #U do
    local t = U[i]
    local da = math.abs(CD(t.a/P, a/P)) * P     -- 方位角差
    local de = math.abs(t.z - z)                -- 仰角差
    local dd = math.abs(t.d - d)                -- 距离差
    if da < AZ and de < EL and dd < .02*d + 25 then   -- 🔑 相对距离门：远处放宽
      local v = da + de + dd/(d + 1)                  -- 代价 = 角差 + 归一化距离差
      if v < q then q, k = v, i end
    end
  end
  return k
end

-- ② 头部坐标系：世界目标 -> 相对视线的方位 / 仰角
function G2AE(g)
  local v = MV(RM, {g[1]-sp[1], g[2]-sp[2], g[3]-sp[3]})
  return math.atan(v[1], v[2]), math.atan(v[3], v[2])    -- atan(y, x) 两参；0 角 = +轴2
end

-- ③ 投影到屏幕：视角差 -> 像素
function AE2S(a, z)
  local da = CD(a/P, lx/P) * P      -- 与 视野X轴 的角差
  local de = z - ly                 -- 与 视野Y轴 的角差
  return W/2 + da*TPP/math.cos(da), -- ⚠ 是 tan 的近似，见下方核验
         H/2 - de*TPP/math.cos(de)  -- 屏幕 Y 向下，故取负
end

function onTick()
  sp = {GN(1), GN(2), GN(3)}        -- 传感器世界坐标（多功能物理传感器 ch1-3）
  RM = E2R({GN(4), GN(5), GN(6)})   -- 欧拉角（⚠ 弧度，勿 ×2π，见 §1）
  lx, ly = GN(7)*P, GN(8)*P         -- 驾驶座椅 数9/数10：视野 X / Y（圈 -> 弧度）

  for i = #U, 1, -1 do              -- 倒序遍历才能安全 table.remove（见 07 §2）
    U[i].l = U[i].l + 1
    if U[i].l > LIFE then
      if U[i].id == L then L = 0 end     -- 锁定的目标过期 -> 解锁
      table.remove(U, i)
    end
  end

  for n = 1, N do
    local b = 9 + (n - 1) * 3
    local d, a, z = GN(b), GN(b+1)*P, GN(b+2)*P
    if d > MIN then
      local g = R2G(d, a, z)             -- 雷达极坐标 -> 世界坐标（见 §3）
      local k = Find(d, a, z)
      if k then
        local t = U[k]
        t[1], t[2], t[3] = g[1], g[2], g[3]
        t.d, t.a, t.z, t.l = d, a, z, 0  -- 命中 -> 寿命归零
      else
        table.insert(U, {g[1], g[2], g[3], d=d, a=a, z=z, l=0, id=ID, acm=0})
        ID = ID + 1
      end
    end
  end

  -- 手动锁定：快捷键 1 上升沿 -> 锁定 / 解锁切换
  local b = GB(1)
  if b and not old then
    if L > 0 then L = 0 else local k = Best() if k then L = U[k].id end end
  end
  old = b

  -- 自动锁定：快捷键 2 按住时，连续 LOCKT 帧都是最优 -> 锁定
  if GB(2) and L == 0 then
    local k = Best()
    for i = 1, #U do
      if i == k then
        U[i].acm = U[i].acm + 1
        if U[i].acm >= LOCKT then L = U[i].id end
      else U[i].acm = 0 end                -- 🔑 失去最优 -> 计数清零，要重新数
    end
  else
    for i = 1, #U do U[i].acm = 0 end
  end

  local k = nil
  for i = 1, #U do if U[i].id == L then k = i break end end   -- 按 id 回查下标
  if k then
    local t = U[k]
    SN(1, t[1]); SN(2, t[2]); SN(3, t[3]); SB(1, true)
  else
    L = 0; SN(1, 0); SN(2, 0); SN(3, 0); SB(1, false)
  end
end
```

**要点**

- **锁存的是 `id` 不是下标**：航迹表会被 `table.remove` 打乱下标，锁 id 才不会「锁定目标自己跳到别人身上」；删除时同步 `if U[i].id == L then L = 0 end`。同思路见 `03` §19。
- **门控空间的选择**：本例在雷达量测空间（方位/仰角/距离）比较，`§8` / `§19` 在世界坐标里比较。
  前者**省一次坐标转换**、且直接吃雷达自身的角度分辨率；后者对目标机动更稳（世界坐标不会因自机转向而整体旋转）。
  自机机动剧烈时用世界坐标门，目标慢、自机稳时用量测空间门。
- **`dd < .02*d + 25`** 与 `§8` 的 `dd < 0.02*U[j].d + md` 是同一招：相对距离门，远处放宽、近处收紧。
- **自动锁定用「唯一最优 + 连续计数」**：只有当前最优的那条航迹 `acm` 自增，其余清零——
  所以必须是**连续** LOCKT 帧都最优才锁，目标一晃就前功尽弃。比 `§23` 的 5 帧移位寄存器更省内存，但没有「历史平均」的抗抖能力。
- **确认进度直接画出来**：`DT(x+6, y+5, string.format("%1.0f", t.acm/LOCKT*100))`，让玩家看到锁定进度百分比。

### ⚠ 离线数值核验（本例数学有三处需要知道）

用 Python 复刻脚本逻辑仿真（`random` 姿态 + 解析对照），结论：

| 项 | 结论 |
| --- | --- |
| `MV(m, v)` 的真实语义 | 是 **mᵀ·v**，不是 m·v（`result[j] = Σᵢ v[i]·m[i][j]`）。抄的时候要么改名，要么按转置理解 |
| 因此本例生效的旋转算子 | 经比对是 **Rx(ex)·Rz(ez)·Ry(ey)**，与 `§1.1` 标准 Z-Y-X（Rz·Ry·Rx）**不是同一个序** |
| 与标准矩阵的偏差 | 姿态幅度 0.05 rad → 元素差 0.0015（可忽略）；0.2 rad → 0.025；**0.5 rad → 0.15；1.0 rad → 0.46** |
| `da*TPP/cos(da)` 相对严格 `TPP*tan(da)` | 10° +0.5% · 20° +2.1% · **30° +4.7%** · 40° +8.6% |
| `atan(v[3], v[2])` 当仰角（分母该用 `sqrt(v1²+v2²)`） | 离轴 15° 时读高 0.35°~0.77°；**30° 时读高 1.5°~3.3°；45° 时读高 4°~8.4°** |

- **要用就先改两处**：① 旋转矩阵换成 `§1.1` 的标准 Z-Y-X，并明确 `MV` 是转置；② 仰角分母改成水平距离 `math.atan(v[3], math.sqrt(v[1]*v[1]+v[2]*v[2]))`。投影近似误差在 ±20° 视场内 < 2%，可以保留。
- 🔴 **坐标系红线**：本脚本把多功能物理传感器 ch1/2/3 直接当「东 / 北 / 上」用，
  但按 `17_传感器与雷达.md` §1.1 的权威口径，**ch2 = 高度、ch3 = 北**——即本例**漏做了 §1.2 的 Y/Z 互换**，
  是那个「最高频 bug」的真实样本。平飞时表现为前后与上下装反，机动时旋转轴也跟着错。抄之前先按 §1.2 改。

## §25 雷达扫描调度：**折返扫描 + 仰角分层（bar）** + 模式循环 + ACM「视线指向」

- 来源：**本地导出** `D:/Downloads/ACM HMD.xml`（同一微控制器的第二块脚本）
- 更新时间：未知（文件修改时间 2026-09-04）
- 用到：雷达（设为**手动模式**，方位/仰角由复合输入给定）、雷达指向轴、驾驶座椅（数 9/10 视野轴、开关 3 切模式）、开关 1（已锁定）
- 亮点：一个 10 行的 `Sweep()` 同时给出方位与仰角——**扫到端点自动反向并切下一根仰角条**；ACM 模式下干脆不扫描，把天线指向「飞行员视线前方 CUE_D 米处」
- 关联：`03` §15 / §16 / §17（另外三种扫描显示画法，都是**显示**侧；本例是**控制**侧）、`02` §7（回环选档的另一种写法）、`05` §41（本例脚本画的扇形指示器）

```lua
-- CONFIG
RO     = {0, 3, 0}          -- 雷达相对座椅的安装偏移（X 右 / Y 前 / Z 上，格）
CUE_D  = 1500               -- ACM 模式假定的目标距离 (m)
SAZ, SELS, SSPD = 60*math.pi/180, {-8, 0, 8},    .04   -- 对空：半角 / 仰角条 / 每 tick 步进
GAZ, GELS, GSPD = 45*math.pi/180, {-12, -22, -32}, .03  -- 对地：更窄、更低、更慢

scan, dir, bar = 0, 1, 1

-- 🔑 折返扫描：返回 (方位, 仰角)；到端点反向，并切到下一根仰角条
function Sweep(limit, speed, bars)
  scan = scan + speed * dir
  if scan >= limit then
    scan, dir = limit, -1
    bar = bar % #bars + 1                  -- 到头 -> 换下一根（取模回环）
  elseif scan <= -limit then
    scan, dir = -limit, 1
    bar = bar % #bars + 1
  end
  return scan, bars[bar] * math.pi / 180   -- 仰角条按度写、这里转弧度
end

-- ACM：视线前方 CUE_D 米处的点 -> 雷达该指的方位/仰角
function LookPoint(d)
  local v = MV(RM, {d*math.cos(ly)*math.sin(lx),
                    d*math.cos(ly)*math.cos(lx),
                    d*math.sin(ly)})
  return {sp[1]+v[1], sp[2]+v[2], sp[3]+v[3]}
end

function onTick()
  sp = {GN(1), GN(2), GN(3)}
  RM = E2R({GN(4), GN(5), GN(6)})          -- 欧拉角：弧度
  lx, ly = GN(7)*P, GN(8)*P                -- 座椅视野轴（圈 -> 弧度）

  local switch = GB(2)
  if switch and not switcho then md = md % 3 + 1 end    -- 回环选档（取模版，见 02 §7）
  switcho = switch

  local locked, smode, ag = GB(1), md == 2, md == 3
  local a, z
  if locked then  MODE = 3                              -- ① 已锁定：死盯目标（最高优先级）
    a, z = RadarAE({GN(9), GN(10), GN(11)})
  elseif ag then MODE = 2; a, z = Sweep(GAZ, GSPD, GELS) -- ② 对地扫描
  elseif smode then MODE = 1; a, z = Sweep(SAZ, SSPD, SELS) -- ③ 对空扫描
  else MODE = 0                                          -- ④ ACM：看哪指哪
    a, z = RadarAE(LookPoint(CUE_D))
  end
  RA, RE = a, z
  SN(1, a/P)                               -- ⚠ 弧度 -> 圈，喂给指向轴
  SN(2, z/P)
end
```

**要点**

- **`Sweep()` 把「方位折返」和「仰角分层」合成一个函数**：`bar` 只在折返点推进，所以扫描轨迹是标准的「之」字形光栅——一根扫完再换下一根，不会跳行。
- **仰角条用数组配置**：`SELS={-8,0,8}` / `GELS={-12,-22,-32}`，对空三根、对地三根且逐根下压；改配置不改代码。
- **模式优先级 = `if/elseif` 的书写顺序**：锁定 > 对地 > 对空 > ACM。用优先级链代替状态机，省一个 `MODE` 的转移表（需要显式转移表时见 `02` §4）。
- **`md = md % 3 + 1` 是回环选档的取模写法**：比 `02` §7 的「`sl==100→0` 相等判断绕回」更短，但只在档位连续时可用。
- **ACM 模式的精髓**：不扫描，而是把「视线方向 × 假定距离」当成一个虚拟目标点，反算雷达该指的方位/仰角——
  `CUE_D` 是假定距离，只影响俯仰/方位的一点点视差，**目标远近不影响指向精度**（瞄准的是方向不是点）。
- ⚠ **输出单位是圈**：`SN(1, a/P)`。雷达手动模式 / 指向轴的复合输入都吃「圈」，凡是 `math.atan` 出来的弧度一律 ÷2π（见 §0）。
- ⚠ **`RO`（雷达安装偏移）必须按实际装位置填**，否则远距离上「座椅算出的目标方位」与「雷达实际指向」会差出一个固定角度，近距离尤其明显。
- 完整脚本：`../../../AI相关/_提取暂存/ACM_HMD_microcontroller_1.lua`

## §26 扇形声呐 PPI：**用扫描角反解扇形几何** + 对数分层距离环 + `drawText(".")` 当像素

来源：steam id **3792648310** · <https://steamcommunity.com/sharedfiles/filedetails/?id=3792648310> · **载具**（fat boat/speed boat f23nik）· 更新时间 **2026-08-30**

`03` §9 / §15 的扇区 PPI 是「先算包围盒、再比 `w/bx, h/by` 缩放」。机械扫描声呐只有 ±45°~±90° 的扇面，画法可以反过来：**先定屏宽，再由扫描半角反解扇形半径与圆心**——扇面永远正好铺满屏幕，不需要任何自适应缩放分支。

**用到**：距离/探测传感器（距离 + 探测布尔）、旋转座圈（扫描角）、触控屏、外部数字（扫描速度、倒车方向）

**亮点**：① `radius = screenW/(2*sin(sran))*0.9` 由扇宽反解半径；② 圆心随扫描角下移，扇面几何居中；③ **对数分层距离环** `k = floor(log(r))`，环数随半径自动增长、层距恒定；④ 没有 `drawPoint`，`drawPixel` 用 `drawText(x-1,y-4,".")` 顶；⑤ 折返扫描用 ±翻转的方向变量，一行三角波。

```lua
srans = {45,60,90,180}          -- 可选半扫描角（度）；180 表示全向
mode, sran, tyaw, yawup = 1, 45, 0, 1
zoom = {5000,2500,1000,500,50}  -- 量程档
found = {}                      -- 回波缓存 {角度, 距离, 余晖 alpha}

function onTick()
  -- ① 折返扫描：越界就翻转方向，一行三角波
  if (math.abs(tyaw) > sran) and (sran ~= 180) then yawup = yawup*-1 end
  tyaw = tyaw + yawup*sspd/5
  if tyaw >= 180 then tyaw = -180 end

  for i = #found, 1, -1 do      -- ⚠ 必须倒序：正序 table.remove 会跳过下一项
    found[i][3] = found[i][3]-1
    if found[i][3] < 0 then table.remove(found, i) end
  end
  if tdet then found[#found+1] = {tyaw, tdis, 255} end   -- 命中即入缓存，带满 alpha
end

function drawPixel(x, y)        -- ④ SW 没有 drawPoint
  screen.drawText(x-1, y-4, ".")
end

function drawArcDash(x, y, r, st, w)   -- 逐度画弧：弧短时够用且省字符
  for i = st, (st+w)-1 do
    drawPixel(x + r*math.cos(math.rad(i)), y + r*math.sin(math.rad(i)))
  end
end

function onDraw()
  screenH, screenW = screen.getHeight(), screen.getWidth()
  -- ① ② 由扫描半角反解扇形几何：扇宽恒等于屏宽，圆心随之下移补偿
  if sran ~= 180 then
    radius  = screenW/(2*math.sin(math.rad(sran)))*0.9
  else
    radius  = screenH/2*0.9
  end
  centerH = screenH/2 + screenH*(180-sran)/300
  drawBackground(screenW/2, centerH, radius, 270-sran, 2*sran)

  -- 扫描线（-90° 把 0° 摆到正上方，符合罗盘约定）
  x3 = screenW/2 + radius*math.cos(math.rad(tyaw-90))
  y3 = centerH   + radius*math.sin(math.rad(tyaw-90))
  screen.drawLine(screenW/2, centerH, x3, y3)

  for i, v in ipairs(found) do                  -- ⑤ 余晖：alpha 逐 tick 递减
    screen.setColor(0, 255, 0, v[3])
    rr = radius*v[2]/zoom[zoomMode+1]           -- 距离 → 半径（按当前量程线性）
    drawPixel(screenW/2 + rr*math.cos(math.rad(v[1]-90)),
              centerH   + rr*math.sin(math.rad(v[1]-90)))
  end
end

function drawBackground(x, y, r, st, w)
  local k = math.floor(math.log(r))                   -- ③ 对数分层：环数随半径增长
  for i = 1, k do drawArcDash(x, y, r*i/k, st, w) end --   层距恒为 r/k，视觉均匀
  if sran ~= 180 then                                 --   扇形的两条边
    screen.drawLine(x, y, x + r*math.cos(math.rad(st)),   y + r*math.sin(math.rad(st)))
    screen.drawLine(x, y, x + r*math.cos(math.rad(st+w)), y + r*math.sin(math.rad(st+w)))
  end
end
```

- **反解 vs 包围盒缩放**：`getArcBox`（§9）要算包围盒再比两次除法，每帧多两次三角函数；反解只要一次 `sin`，且扇面宽度**恒定等于屏宽**，切扫描角时画面不跳。
- ⚠ **正序 `table.remove` 是静默 bug**：`for i,v in ipairs(t) do ... table.remove(t,i) end` 删掉 i 后，原 i+1 前移到 i，而下一轮检查的是 i+1 → **每次跳过一项**，缓存里留下 alpha 为负的僵尸点。本例原脚本正是这么写的，须改为倒序（与 `03` §18 同一处坑）。
- **触控分流**：`clicked` 在按下时置位、**松手时才消费**，用它把「点按钮 = 切量程」与「点画面其他地方 = 切扫描角」分开，避免按下期间连发。
- 关联：`03` §9（扇区 PPI 包围盒缩放）/ `03` §15（扫描扇形）/ `03` §16（360 槽环形缓冲余晖）/ `00_速查 §16`（screen API）


## §27 单目标 **SR / TR（搜索 / 跟踪）** 转塔雷达：扇扫生成 + 关联门限 + 丢失后扫描范围随时间膨胀

- 来源：steam id **3793572595**
- 描述页：<https://steamcommunity.com/sharedfiles/filedetails/?id=3793572595>

`03` §25 讲的是「怎么让天线扫起来」（扫描调度本身）；这一节是**扫到东西之后怎么办**——一套完整的单目标搜索 / 跟踪状态机：搜索时用扇扫，捕获后转入跟踪，目标丢失则**扫描范围随丢失时长逐步放大**做重新捕获。

```lua
-- ① 乒乓三角波：x 每次走 dx，撞到 ±xMax 就反向；sign 与 x 一起返回
function pnpn(x, xMax, dx, sign)
  x = x + sign*dx
  if math.abs(x) > xMax then
    x = math.abs(x)/x * xMax      -- ⚠ 见「反面教材」：这里 sgn(0) 会出 nan
    sign = -sign
  end
  return x, sign
end
-- 搜索模式：绕中心整圈扫；跟踪模式：在目标方位附近来回扫
function RadYawS(yw) return angFix(yw + rpt) end            -- rpt = rps/60，每 tick 的角度增量
function RadYawT(yw, yw0)
  local TRrng = math.atan(10/tsr)/pi2 + lostT/10*fov        -- 🔑 丢得越久，扫得越宽
  local dyw = angDif1(yw, yw0)
  if math.abs(dyw) > TRrng then
    yw = yw0                                                 -- 目标角超出窗口 → 直接对准
  else
    dyw, trs = pnpn(dyw, TRrng, fov/2, trs)
    yw = dyw + yw0
  end
  return angFix(yw)
end
```

```lua
-- ④ 圈制角差与归一化：先 ×2π 转弧度再走 atan(sin,cos)，结果除回圈
function angDif1(a, b) a, b = a*pi2, b*pi2 return math.atan(math.sin(a-b), math.cos(a-b))/pi2 end
```

- 🔴 **反面教材：`LocalToWorld` 的欧拉角预处理会除零**。原脚本开头是 `qx, qz = asin(sin(qx)/cos(qy)), qz - atan(tan(qx)*tan(qy))`——`cos(qy)` 在横滚接近 ±90° 时趋近 0，直接爆掉；而且 `asin` 值域只有 ±π/2，翻过 90° 姿态就翻车。**载体不做大横滚时可用**（车 / 船），全姿态飞行器请改用 `04` §13 的 `ltog` / `gtol` / `axang` 换基三件套。
- ⚠ **`sgn(x) = x/math.abs(x)` 在 x=0 时得到 `nan`**（0/0）。本例 `pnpn` 的 `dx` 恒非零所以没炸，但通用工具函数要写成 `x < 0 and -1 or 1`（`05` §30 记过 `sgn(0)` 返回 1 的一行写法）。
- ⚠ **`table.insert(t, 1, v)` 是 O(n)**：n=5 无所谓，n 上百就必须换环形缓冲（`03` §23 的移位寄存器写法）。
- 🔑 **跟踪一定要用最短角差**：`dyw = angDif1(yw, yw0)` 而不是 `yw - yw0`。跨 ±0.5 圈（正北）时，原始差值会突然从 +0.49 跳到 −0.49，转塔会反向猛打一整圈。
- 🔑 **双门限关联**：只用空间距离，会在两目标交错时误挂；加上「回波时间差 `abs(TRm - tm) < dM`」这一维，能把「同一目标的前后两次回波」与「不同目标」区分开。
- 🔑 **`lostT` 同时驱动两个行为**：扫描范围膨胀（`lostT/10*fov`）与 HUD 上的丢失提示。用一个计数器做两件事，比各设一个计时器省字符。

```lua
fov = 120
function onTick()
  camx = clamp(-1, 1, ign(30))                        -- 转塔 / 摄像头视线偏移
  camy = clamp(-1, 1, ign(31))
  zoom = clamp(0, 1, ign(32))
  ang  = math.max(fov*(1-zoom), 1)                    -- 变焦 = 缩视场角，下限 1°
  zx   = tan(ang*pi/180/2)/(1.82 - 0.15*(w/h - 1))    -- ① 横向比例随宽高比修正
  zy   = tan(ang*pi/180/2)/1.82                       --    纵向固定（1.82 ≈ 半宽/半高）

  for i=1, tar do
    n = i + (i-1)*3                                   -- ② 通道交错：数值 1-3 / 4-6 / 7-9 …
    dis[i], xv[i], yv[i] = ign(n), ign(n+1), ign(n+2)
    td[i] = igb(i)                                    -- 布尔第 i 路 = 第 i 个目标
    Cal(i)
  end
end

function Cal(num)
  -- ③ 距离自适应 EMA：越远越平滑，上限 0.8 防止完全冻结
  v[num]    = math.min(math.floor(dis[num])/1000, 0.8)
  xavg[num] = xavg[num]*v[num] + xv[num]*(1-v[num])
  yavg[num] = yavg[num]*v[num] + yv[num]*(1-v[num])
  davg[num] = davg[num]*v[num] + dis[num]*(1-v[num])

  -- ④ 变长滑动窗口：窗口长度随距离增长（远目标要更长才稳）
  ts[num] = math.min(math.floor(davg[num]/5), 150)
  table.insert(ri[num], davg[num])
  if #ri[num] > ts[num] then table.remove(ri[num], 1) end
  isum[num] = 0
  for i=1, #ri[num] do isum[num] = isum[num] + ri[num][i] end
  iavg[num] = isum[num]/#ri[num]

  -- ⑤ 接近率：窗口均值的每 tick 差分 / 0.016 s（1 tick = 1/60 s），负号 = 在变近
  ms[num] = -math.floor(((iavg[num] - od[num])/0.016)//1)
  od[num] = iavg[num]

  a = math.floor(davg[num])
  b = 1 - (a/5000)
  c = 1/(a/(5 - b*2.5))                               -- 框尺寸随距离收缩的经验式

  -- ⑥ 双轴 tan 投影：横竖各用自己的比例系数
  xco  =  tan(rad(xavg[num]*360 - camx*45))*(w/4/zx)*(h/w) + w/2
  yco  = -tan(rad(yavg[num]*360 - camy*45))*(h/4/zy) + h/2
  size =  math.max(rs*c*(w/32), 0)*(fov/ang)*(h/w)
end
```

- 🔑 **距离自适应 EMA 系数**：`v = min(floor(dist)/1000, 0.8)`——近处 `v` 小（跟手），远处 `v` 大（平滑），一个表达式同时解决「近处抖、远处飘」。**上限 0.8 是必须的**：若让 `v` 接近 1，目标一旦远离就永久冻结在当前值。
- 🔑 **变长滑动窗口**：窗口长度 `ts = min(floor(davg/5), 150)` 随距离线性增长（5 m → 1 帧，750 m → 150 帧）。远处回波噪声大，需要更长窗口；近处要跟手，窗口必须短。`table.insert` + 超长 `table.remove(t, 1)` 是最省字数的 FIFO。
- 🔑 **接近率 = 窗口均值的逐 tick 差分**：`ms = -(iavg - od)/0.016`（0.016 s = 1 tick @60 Hz）。**必须用窗口均值而不是原始距离**——原始距离的差分会剧烈跳动。
- 🔑 **双轴 tan 投影 + 宽高比修正**：`zx` 与 `zy` 分开算，横向多一项 `0.15*(w/h-1)`。屏幕不是正方形时，同一个视场角对应的横竖像素比例不同，不修正的话方框会被拉扁。
- 🔑 **两两点距去重**：`距离差 < 15 m` 且 `横纵屏幕位移都在框内` → 判为同一目标，把后者标记为不显示。这是「多通道各自报同一目标」时的通用清理步骤（`03` §12 的接触点去重是同一问题的另一种写法）。
- ⚠ **短路求值顺带当下标越界保护**：`i == j` 时 `cmp[i][j]` 是 `nil`，`(cmp[i][j] or 16) < 15` 为 false，`and` 直接短路，**第二段的 `cmpx[i][i] <= s[i]` 不会被执行**——否则就是 `nil <= number` 报错。重排条件顺序会让这段代码当场崩溃，改动时务必小心。
- ⚠ **O(N²) 比较写在 `onDraw` 里**：目标数一多会明显掉帧。去重属于「状态判定」，正确位置是 `onTick`；只有最后的绘制才该留在 `onDraw`。
- ⚠ `clamp(min, max, value)` 的**参数顺序是（下界, 上界, 值）**，与很多库里的 `clamp(value, lo, hi)` 相反；且它是纯函数，**不赋回等于没写**。
- 🔑 **并行表（struct-of-arrays）**：`x` / `y` / `s` / `d` / `v` / `la` / `lm` 各自按目标下标存一列，配一个 `Table(n)` 一次性初始化。比 `{dist=, azi=}` 的对象数组省掉大量键名字符，是多目标脚本的常规写法。
- 🔑 **通道交错编排**：数值通道按 `n = i + (i-1)*3` 排（每目标 3 路），布尔通道每目标 1 路，最大目标数由属性给。接线时「第 i 个目标占数值 3i-2..3i、布尔第 i 路」。
- 关联：`03` §28（航迹台账生命周期）、`03` §12（接触点去重）、`04` §12（NaN 安全与 `Clamp`）、`04` §9.1（对数域缩放，与此处 `fov/ang` 的变焦同源）、`00_速查 §4`（圈 vs 弧度）

- 来源：steam id 3793116238 · <https://steamcommunity.com/sharedfiles/filedetails/?id=3793116238> · **载具**（雷达 PPI 显示器）
- 更新时间：未取到（Steam Web API 对本批新 id 不返回元数据）
- 用到：7 路雷达（Bool 在 1/5/9/13/17/21/25，距离/方位/仰角紧跟其后）、`screen.drawCircle` 距离环、复合输入量程
- 亮点：一条回波只用**一个亮度字段 + 一个方向标志**就实现了「啪地出现 → 停留 → 慢慢消失 → 自动淘汰」的完整生命周期，淘汰条件就是亮度归零，**不需要额外计时器**。

```lua
-- 每条回波 = {距离, 方位(弧度), 仰角, 亮度, 是否已到顶}
targets  = {}
resetTgt = {false,false,false,false,false,false,false}  -- 7 路各自的「已在册」标志
bspeed   = 1                                            -- 淡出速度；淡入是它的 2 倍

function refTargets()
  oldTargets = {}
  for x,y in ipairs(targets) do
    if y[4] >= 255-bspeed then
      y[5] = true                                   -- 到顶 -> 转成淡出
    elseif y[4] <= bspeed and y[5] then
      table.insert(oldTargets, x)                   -- 淡到 0 -> 标记删除
    end
    if not y[5] then y[4] = y[4] + bspeed*2         -- 淡入（2 倍速）
    else             y[4] = y[4] - bspeed end       -- 淡出
  end
  for x,y in pairs(oldTargets) do table.remove(targets, y) end   -- ⚠ 见反面教材
end

function getTargets()
  for i=1,25,4 do                                   -- i = 1,5,9,...,25 共 7 路
    if input.getBool(i) and (not resetTgt[(i+3)/4]) then
      resetTgt[(i+3)/4] = true                      -- 🔑 只在「从无到有」时录入
      table.insert(targets, {
        input.getNumber(i),
        input.getNumber(i+1)*(2*math.pi) % (2*math.pi),   -- 方位：圈 -> 弧度并归一
        input.getNumber(i+2),
        0, false })
    elseif not input.getBool(i) then
      resetTgt[(i+3)/4] = false                     -- 该通道本帧无回波 -> 解锁
    end
  end
end

function onTick()
  rotation = (input.getNumber(32)*(2*math.pi)) % (2*math.pi)
  myRange  = input.getNumber(31)
  if myRange ~= 0 then range = myRange end          -- 量程 0 视为「未接」，沿用旧值
  getTargets(); refTargets()
end
```

**要点**

- 🔑 **三角波，不是单调衰减**：`y[4]` 从 0 加到 255（步进 `bspeed*2`），到顶置 `y[5]=true`，再以 `bspeed` 降回 0 后删除。
  淡入是淡出的 **2 倍速** → 新目标「啪」地出现、老目标缓慢消失，**扫过一次就能看清，转一圈后自然清空**。
  与既有章节的分工：`03` §17 是「扫到即清」（一帧删）、§22 是「衰减率绑 RPS」（单调减）；本例多了一个**淡入阶段**，
  视觉上是完整生命周期，代价只是多一个布尔字段。
- 🔑 **通道边沿锁存 `resetTgt`**：只有「该通道从无回波变成有回波」才插入一条新记录，通道空了就清零标志。
  不做这一步，雷达每帧照到同一目标就会**无限塞点**（一分钟 3600 条，帧率崩）。
  ⚠ 但它**只防重复录入、不做去重/合并**——同一目标每转一圈仍会新增一条，靠生命周期自然淘汰，
  屏上会有几个重影，这正是作者要的「余晖」。若要唯一化，配 `03` §12 的「取整坐标当表键」。
- **距离环按屏尺寸分档**（响应式）：`squareC = min(w,h)/2`，默认 2 环；`squareC >= 32` 补到 4 环；`>= 48` 补到 8 环。
  小屏自动减环，避免糊成一团。与 `03` §20「环跑出视口就停画」互补：那个管**外边界**，这个管**密度**。
- **超出量程的目标钳到边缘**：`if distance > range then distance = range-2 end`，贴在圈内侧显示而不是直接消失，
  让操作者知道「外面还有东西」。
- ⚠ **反面教材：正序 `table.remove` 会错位**。`oldTargets` 是按下标**升序**收集的，`pairs` 也按升序遍历，
  删掉第 2 条后第 5 条实际已经挪到第 4 位——同时删多条时必然漏删（对照 `03` §12 / `07` §2）。
  修法二选一：**倒序收集下标**，或收集后 `table.sort(oldTargets, function(a,b) return a>b end)`。
  本例因为一帧内同时到期的点很少才侥幸没出问题。

**关联**：`03` §17（扫描窗口淘汰式余晖）/ `03` §22（衰减率绑 RPS）/ `03` §12（接触点去重 + 倒序删）/ `07` §2（遍历中删元素）

## §32 多目标 HUD 的**视场偏移校正** + **安装偏移随视线旋转** + **跳变门限滤波**

- 来源：steam id **3795883030** · <https://steamcommunity.com/sharedfiles/filedetails/?id=3795883030> · **微控**（雷达目标指示 HUD）
- 更新时间：未取到（Steam Web API 对本批新 id 不返回元数据）
- 用到：复合数值 1~32（每目标 3 路：距离 / 方位圈 / 仰角圈）、布尔 1~8（每目标 1 路探测标志）、属性（`offset x/y/z` 传感器安装偏移）
- 亮点：与 `03` §30 是同一件事的另一种解法——§30 在**变焦**上做 `tan(FOV/2)` 修正；本节处理两个它没覆盖的问题：**视线转动时标注要怎么补偿**、**雷达没装在质心上怎么修**。另外给出一条很省字的自适应滤波：**动得狠就直跟，动得少才平滑**。

```lua
fov_factor = 16 / tan(rad(10/2))            -- ① 半 FOV=5° 对应的像素比例，先算一次

-- ② 视线偏移的「非线性」补偿：屏上像素按角度线性铺，但透视是 tan
if math.abs(viewX) > 0.25 then              -- 小角度没必要修，直接置 0 省事
    viewOfstdX = viewX - tan(viewX * pi2) * fov_factor
else
    viewOfstdX = 0
end

-- ③ 传感器安装偏移：把固定的机体偏移旋到「当前视线」坐标系
local phi, theta = -viewX*pi2, -viewY*pi2
radarOfstFxd = {
    ( rX*cos(phi) - rY*sin(phi))*cos(theta) + rZ*sin(theta),
      rX*sin(phi) + rY*cos(phi),
    -(rX*cos(phi) - rY*sin(phi))*sin(theta) + rZ*cos(theta) }

-- ④ 跳变门限滤波：位移大 = 真机动 -> 直跟；位移小 = 量测噪声 -> 重平滑
if getRange(tgtVec[i][1],preData[i][1], tgtVec[i][2],preData[i][2],
            tgtVec[i][3],preData[i][3]) > 5 then
    pitchFiltd[i] = pitchFixd[i]            -- 直接跟
    yawFiltd[i]   = yawFixd[i]
else
    pitchFiltd[i] = 0.3*pitchFixd[i] + 0.7*preData[i][4]
    yawFiltd[i]   = 0.3*yawFixd[i]   + 0.7*preData[i][5]
end

-- ⑤ 距离分档：远了只报百位，近了报个位，字号不跳
if tgtSts[i][1] > 100 then
    prevDist[i] = string.format("%2.0f", 100*math.floor(tgtSts[i][1]/100))
else
    prevDist[i] = string.format("%3.0f", tgtSts[i][1])
end
colorDeep[i] = clamp(255 - tgtSts[i][1]/500, 50, 255)   -- 越远越暗，下限 50
```

- 🔑 **③ 的顺序不能反**：先把偏移按 `phi`（方位）转，再按 `theta`（仰角）转，最后加上目标向量 `viewVec = tgtVec + radarOfstFxd`。只加不转会随着视线转动越偏越多。
- 🔑 **④ 比固定 α 的 EMA 更实用**：固定 α 在「目标真机动」时会拖尾、在「静止目标抖动」时又会跳。用**位移量**做开关，两者都躲开。阈值 `5` 是米，按雷达精度调。
- ⚠ **本例用了 12 个并行表**（`Ra/Rd/Re/Rt/...`）存同一批目标的不同字段，插入/删除要 `table.remove` 十几次且必须同序——见 `03` §33 的反面教材，建议改成一条记录表。
- ⚠ ⑤ 的 `%2.0f` / `%3.0f` 会让 999 m 以上显示成 `900`（百位截断），属**刻意的降精度**，别当 bug 修。

## §33 目标关联必须在**绝对方位域**做：罗盘补偿 + 已知目标给更长寿命

- 来源：steam id **3795829882** · <https://steamcommunity.com/sharedfiles/filedetails/?id=3795829882> · **载具**（扫描雷达 + TWS 态势屏）
- 更新时间：未取到（Steam Web API 对本批新 id 不返回元数据）
- 用到：复合数值 1~24（6 路雷达，每路 4 个：距离 / 方位圈 / 仰角圈 / 上次更新时间）、27~32（自身 GPS / 罗盘 / 倾角 / 量程）
- 亮点：一条关联判据解决「载具一转弯，已锁定目标全丢」这个高频顽疾；顺带给出「已知目标比新目标更难被淘汰」的寿命分配。

```lua
-- 关键：比较的是「绝对方位」，不是「雷达相对方位」
--   绝对方位 = 雷达方位 - 罗盘   （雷达方位与罗盘都是「圈」）
--   于是判据写成 (历史方位 - 历史罗盘) 与 (当前方位 - 当前罗盘) 之差
if math.abs(Ra[j] - az - Rc[j] + compass) < 0.065     -- 方位差 < 约 23°
   and math.abs(Rd[j] - dist) < 750 then              -- 距离差 < 750 m
    Ra[j], Rd[j], Re[j] = az, dist, ele
    Rc[j]  = compass                                  -- 🔑 连「记录时的罗盘」一起更新
    Rt[j]  = 750                                      -- 已确认目标：寿命加满
    found  = true
    break
end

-- 未关联上 -> 新建，新目标只给 500（比已知的 750 短，避免杂波常驻）
if not found and dist < scale and dist > 200 then     -- dist>200 滤掉近处杂波
    table.insert(Ra, az)  table.insert(Rd, dist)
    table.insert(Re, ele) table.insert(Rt, 500)
    table.insert(Rc, compass)                         -- 出生时记下当时的罗盘
end
```

- 🔑 **`Ra[j] - az - Rc[j] + compass` 展开就是 `(Ra[j]-Rc[j]) - (az-compass)`**。忘了减罗盘，载具转向 30° 后同一批目标全部关联失败，屏上目标数会翻倍。
- 🔑 **距离差用绝对值 750 m** 而不是比例，是因为雷达量程 `scale` 本身会变；比例门限在大量程下会把两个目标糊成一个。
- 🔑 **寿命分两档**（新 500 / 旧 750）：扫描一圈约 750 tick，已知目标多给一整圈的余量，不会被「刚错过一次扫描」误删。
- ⚠ **反面教材 · 12 个并行表同步删除**：本例 `Ra/Re/Rd/Rt/Ri/Rc/Rti/Px/Py/Pz/ORi/DLid` 一个字段一张表，淘汰时要 `table.remove` **12 次且顺序不能错**，漏一个就全表错位。
  正确做法是一条记录表 `tracks[k] = {az=, dist=, ele=, life=, compass=, x=, y=, z=}`，删除只 `table.remove(tracks, k)` 一次。
  并行表唯一的好处是 MC 里省字符，但在这里它反而更费（`table.remove` 重复 12 遍）。

## §34 声纳 ping 的**代数淘汰** + **B 型扫描**（方位 × 深度直角坐标）

- 来源：steam id 3222088811 · <https://steamcommunity.com/sharedfiles/filedetails/?id=3222088811> · **载具**（驱逐舰，声纳屏 `block#13` = B 型 / `block#14` = PPI）
- 更新时间：2024-04-14
- 用到：13 路声纳通道（Bool 1-13 + 成对数值）、倾斜传感器（横滚/俯仰）、量程与深度标尺走数值通道
- 亮点：声纳只给方位/仰角不给距离，距离靠 ping 计时。本例的过期清理**不给每个目标存时间戳**，
  只记「每一 ping 用掉了多少个槽位」两个整数，就能在 ping 边界整段清掉过期回波——
  与 `03` §17「按角度扇区清」、§31「每个点存亮度」是完全不同的第三条路。

```lua
pi2 = 2*math.pi
cos, sin = math.cos, math.sin

-- ① 罗盘方位（圈）-> 数学角（弧度），顺带把「北」转到屏幕正上方
function deg(x)  return ((-x*360+450)%360)/360*pi2  end

-- ② 倾斜补偿：横滚 x / 俯仰 y（圈）在目标方位 z 上的一阶投影，直接减
function stabilizer(x, y, z)  return -(cos(z)*x + sin(z)*y)*pi2  end

function onTick()
  r      = input.getNumber(27)*1000     -- 量程 km -> m
  tiltx  = input.getNumber(28)          -- 横滚（圈）
  tilty  = input.getNumber(29)          -- 俯仰（圈）
  maxd   = input.getNumber(30)          -- 最大显示深度（B 型用）
  scale  = input.getNumber(31)/10
  active = input.getBool(17)
  system = input.getBool(18)

  if active and system then t = t + 1 else t = 0 end

  -- ③ ping 计时：t tick × 声速 1430 m/s；跑满约 2 倍量程就重新起 ping
  if active and (t == 0 or t/60*1430/r*96/2 > 96) then
    ping = true; output.setBool(1, true); ping = false   -- 一帧高电平脉冲
    t = 0
    pc = pc + 1              -- 🔑 ping 代数 +1
    tgcm[pc] = {tgc}         -- 记下「上一 ping 结束时槽位用到第几个」
    tgc = 0                  -- 槽位游标归零
  end

  for i = 1, 13 do           -- 13 路：{有回波, 方位(弧度), 仰角(弧度)}
    tg[i] = {input.getBool(i), deg(input.getNumber(i*2-1)), input.getNumber(i*2)*pi2}
  end

  if active then
    for i in pairs(tg) do
      if tg[i][1] then
        tgc = tgc + 1
        ymod = tg[i][3] - stabilizer(tiltx, tilty, tg[i][2])   -- 倾斜补偿后的仰角
        tgs[tgc] = {tg[i][2], ymod, t/120*1430}                -- 🔑 距离 = 声速 × 往返 tick /2 /60
      end
      -- ④ 代数淘汰：上一 ping 比这一 ping 目标多 -> 多出来的尾部槽位整段清空
      if pc > 2 and tgcm[pc-1][1] > tgcm[pc][1] then
        for m = tgcm[pc][1], tgcm[pc-1][1] do tgs[m] = nil end
      end
    end
  end
  if not active then for k in pairs(tgs) do tgs[k] = nil end pc = 0 end
end
```

画法一 —— **PPI**（`block#14`，极坐标）：

```lua
for k in pairs(tgs) do
  screen.drawCircleF(w/2 + tgs[k][3]/r*h/2*cos(tgs[k][1]),
                     h/2 - tgs[k][3]/r*h/2*sin(tgs[k][1]), 1)
end
screen.drawCircle(w/2, h/2, t/120*1430/r*h/2)   -- ⑤ 当前 ping 的波前圈（外扩动画）
```

画法二 —— **B 型扫描**（`block#13`，横轴方位、纵轴深度）：

```lua
for j = -20, 20 do
  screen.drawLine(w/2+h/8*j, h, w/2+h/8*j, 0)                    -- 竖线：等方位间隔
  screen.drawLine(0, (10*j+maxd)*scale, w, (10*j+maxd)*scale)    -- 横线：等深度间隔
  if j%2 == 0 then
    screen.drawText(1, (10*j+maxd-1)*scale, string.format("%+.0f", 10*(-j)))
  end
end
for k in pairs(tgs) do
  screen.drawCircleF(w/2 + tgs[k][3]/r*h/2*cos(tgs[k][1]),        -- x：方位的水平投影
                     (-tgs[k][3]*sin(tgs[k][2]) + maxd)*scale, 1) -- y：距离 × sin(仰角) 当深度

```

**要点**

- 🔑 **三种过期清理，别混用**：
  `03` §16 声纳是「**按角度存** 360 槽环形缓冲，推进即移位」；`03` §17 雷达是「**按目标存**，扫到哪个扇区就删哪个扇区」；
  本例是「**按 ping 代数存**，槽位下标本身就是年龄」——`tgcm[pc]` 只存一个整数（该 ping 用了几个槽），
  **每个目标零额外字段**，比存时间戳 / 亮度省得多。代价是**只能在 ping 边界清理**，ping 中途不会过期。
- 🔑 **`t/120*1430` 一行出距离**：`120 = 60 tick/s × 2`（往返），`1430` 是作者取的水中声速
  （`03` §11 取的是 1480，两者都是近似值，按自己世界的设定选一个）。`t/60*1430/r` 再乘半屏像素就是波前半径。
- 🔑 **`deg()` 一步完成三件事**：`(-x*360+450)%360` 里，负号翻转旋向（游戏罗盘顺时针、数学角逆时针），
  `+450`（= 360+90）把北从 0° 抬到 90°；配合 `y = cy - d*sin(a)` 就是「北在屏幕上方」。
  比「先取负再 +0.25 圈」的常见写法少一次取模。
- **一帧高电平脉冲**：`ping=true → output.setBool(1,true) → ping=false` 三行造出**单 tick 脉冲**，
  不需要边沿检测（对照 `02` §1）。⚠ 只在 `onTick` 末尾不再改写该通道时才成立。
- ⚠ **反面教材：代数淘汰依赖「通道顺序稳定」**。`tgs` 的槽位下标是按 `pairs(tg)` 的遍历顺序分配的，

## §35 RWR / 雷达告警显示：**绘制角与判定角解耦的三张并行表** + 主 / 次目标分级

- 来源：steam id **3796690599** · 描述页 <https://steamcommunity.com/sharedfiles/filedetails/?id=3796690599> · **载具**（Su-57，脚本 `SPO-15 processing: targets -> markers`）
- 更新时间：未取到（Steam Web API 连续多轮不返回新上架作品元数据，下轮 `fetch_meta.py` 补）
- 用到：雷达目标复合数值（1~24，每目标 4 路 x/z/y/id）、自身 GPS、罗盘、96×96 屏
- 亮点：真实 RWR 的灯位是**非均匀**的（两侧密、中间疏），所以「画在哪」和「判什么」必须分开：三张下标对齐的并行表，改灯位不用动判定逻辑。
- 区别于 `03` §7（把圈量化成等宽 200 格存缓存）：本节是**不等宽分桶**，且桶的**绘制位置与判定中心故意不一致**。

```lua
MARK_ANGLES      = { 15, 35, 55, 75,145,-15,-35,-55,-75,-145} -- 画在哪（屏幕角）
REAL_ANGLES      = { 10, 30, 50, 90,150,-10,-30,-50,-90,-150} -- 判定中心（真实方位）
ANGLE_THRESHOLD  = { 25, 25, 25, 65, 65, 25, 25, 25, 65,  65} -- 每个槽的全角宽(度)
NMARK = #MARK_ANGLES

-- 罗盘「圈」→度：SW 罗盘东为负，故取负号
hdgDeg     = -(hdgTurns*360 + 360) % 360     -- 0=北 +90=东 -90=西
absBearing = rad2deg(atan(dx, dz))           -- atan(东, 北)：0=北 +90=东
relBearing = normDeg(absBearing - hdgDeg)    -- 相对方位，归一到 -180..180

function inMarkerWindow(bearingDeg, centerDeg, fullWidthDeg)
    local d = normDeg(bearingDeg - centerDeg)          -- 先归一再比，跨 ±180 才不会漏
    return abs(d) <= fullWidthDeg*0.5 + 1e-6           -- 1e-6 兜住浮点边界
end

-- 主目标点亮主环，其余目标点亮次环；每帧先整段复位再点亮
for i=1,NMARK do primaryLit[i]=false; secondaryLit[i]=false end
for i=1,NMARK do
    if inMarkerWindow(P.rel, REAL_ANGLES[i], ANGLE_THRESHOLD[i]) then primaryLit[i]=true end
end
```

- 🔑 **三张表下标对齐 = 一张「灯光位映射表」**：`MARK_ANGLES[i]` 只管画，`REAL_ANGLES[i]`/`ANGLE_THRESHOLD[i]` 只管判。想让某盏灯在屏幕上挪 5 度，只改第一张表，判定逻辑一行不动。
- 🔑 **`normDeg` 必须先归一再比**：`rel` 是 -180..180，`REAL_ANGLES` 里有 ±150/±90，直接减会跨 ±180 边界而漏判。
- 🔑 **主 / 次分级**：先按「空中优先，其次最近」挑出 `priIdx` 当主目标，剩下的全部当次目标；主目标的输出（绝对方位 / 距离 / 高度）单独走数值通道，屏幕上是两套配色。
- ⚠ **NaN 过滤**：`if id and id ~= 0 and tx==tx and ty==ty then` —— `x==x` 是 SW Lua 里判 NaN 的唯一写法（见 `04` §12）。雷达丢目标时坐标会是 NaN，不拦会让 `atan` 传染出一堆 NaN。
- 关联：`04` §12（NaN 安全三件套）、`03` §33（目标关联必须在绝对方位域做）

## §36 **声纳的固定方位盲区黑名单** + 主/被动双模式（俯仰角当半径画同心圆）

- 来源：steam id **3743234498** · 描述页 <https://steamcommunity.com/sharedfiles/filedetails/?id=3743234498> · **载具**（D.O.E. MEGA SUB，`_vehicle_0` 声纳 PPI）
- 更新时间：2026-09-04
- 用到：复合布尔 1~16（16 路声纳有回波）、31（调试）、32（主动 ping 中）；复合数值 奇数通道方位、偶数通道俯仰（圈）
- 亮点：本艇自己的螺旋桨 / 舱室会在若干**固定方位**上持续产生假回波。作者不去滤波，而是**硬编码一张 13 项的方位黑名单常量表**，回波落进任何一个 ±0.002 圈的窗口就直接丢弃，并且**把盲区画成暗红放射线**让操作手看见。另外主动 / 被动两种模式共用同一套绘制，只是数据来源不同。

```lua
--*** Constants ***（顶层常量，别写进 onTick，否则每 tick 重建表）
mute_a = {0, 0.5, -0.5, 0.038, -0.038, 0.462, -0.462, 0.25, -0.25,
          0.074, -0.074, 0.156, -0.156}   -- 本艇噪声方位（圈）
mute_w = 0.002                             -- 盲区半宽（圈）
age_delay = 5
pt = 90                                    -- Ticks per Ping-Kilometer：距离标定常数

ping_t = 0
snr_tgt, snr_dir, snr_pit, snr_age = {}, {}, {}, {}

function onTick()
    ping = input.getBool(32)
    if ping then                                   -- 主动：ping 发出去，回波陆续到达
        ping_t = ping_t + 1
        for i = 1, 16 do                           -- 只 insert 命中的，累积成航迹
            if input.getBool(i) then
                table.insert(snr_tgt, true)
                table.insert(snr_dir, input.getNumber(i*2-1))
                table.insert(snr_pit, input.getNumber(i*2))
                table.insert(snr_age, 0)
            end
        end
    else                                           -- 被动：清空累积，每 tick 直接列当前值
        ping_t = 0
        snr_tgt, snr_dir, snr_pit, snr_age = {}, {}, {}, {}
        for i = 1, 16 do
            snr_tgt[i] = input.getBool(i)
            snr_dir[i] = input.getNumber(i*2-1)
            snr_pit[i] = input.getNumber(i*2)
            snr_age[i] = 0
        end
    end
end

function onDraw()
    w, h = screen.getWidth(), screen.getHeight()
    w2, h2 = w/2, h/2

    for i = 1, #mute_a do                          -- 🔑 把盲区画出来，别藏起来
        x = math.sin(mute_a[i]*math.pi*2)*h2 + w2  -- 圈 → 弧度：*2π；y 取负 cos（屏幕 y 向下）
        y = -math.cos(mute_a[i]*math.pi*2)*h2 + h2
        screen.setColor(16,0,0)
        screen.drawLine(x, y, w2, h2)
    end

    for i = 1, #snr_tgt do
        if snr_tgt[i] then
            sgn = true
            for j = 1, #mute_a do                  -- 🔑 黑名单过滤：落在任一窗口内即判无效
                if snr_dir[i] < mute_a[j]+mute_w and snr_dir[i] > mute_a[j]-mute_w then
                    sgn = false
                end
            end
            if sgn then
                -- 🔑 声纳只给方位+俯仰、不给距离：拿俯仰角当半径画成同心圆
                r = h2*(1 - math.abs(snr_pit[i]/0.25))
                x = math.sin(snr_dir[i]*math.pi*2)*r + w2
                y = -math.cos(snr_dir[i]*math.pi*2)*r + h2

                if ping then                       -- 主动：按年龄三段配色（红→蓝→透明）
                    age = snr_age[i]/age_delay
                    if age < 256 then      screen.setColor(255-age, 0, age)
                    elseif age < 512 then  screen.setColor(0, 0, 255, 511-age)  -- 第 4 参是 alpha
                    else                   screen.setColor(0, 0, 0, 0)
                    end
                else                               -- 被动：统一青色
                    screen.setColor(0,255,255)
                end
                screen.drawText(x-1, y-2, "+")
                screen.drawLine(x, y, w2, h2)
                snr_age[i] = snr_age[i] + 1        -- ⚠ 见下方反面教材
            end
        end
    end

    if ping then                                   -- 主动模式显示 ping 已走过的距离
        screen.setColor(255,255,0)
        screen.drawText(1, h-6, "D: " .. string.format("%0.1f", ping_t/pt) .. "km")
    end
end
```

- 🔑 **黑名单常量表 > 动态滤波**：本艇噪声的方位是**结构性的、不随时间变**，写成顶层常量表既省字符又零抖动。`mute_w` 单独拎出来当半宽，调参只改一个数。
- 🔑 **`0` 与 `±0.5` 必在表内**：正前、正后是最常见的自噪声方位。表里的 `0.038 / 0.462 / 0.074 / 0.156 / 0.25` 及其相反数，是「左右对称 + 前后镜像」的成对写法 —— 手工铺盲区时按对称对填，不容易漏。
- 🔑 **盲区要可视化**：`setColor(16,0,0)` 的暗红放射线让操作手知道「这里本来就没有数据」，否则会被当成没探测到。
- 🔑 **俯仰角当半径**：声纳给的是「方位 + 俯仰」两路角度、不给距离（见 `03` §11）。本例不测距，直接用 `h2*(1-abs(pit/0.25))` 把俯仰映射到半径，水平方向（pit≈0）落在最外圈，俯仰越大越靠中心 —— 于是同一路数据在 PPI 上呈现为**一圈同心环**，代价是画面里没有真实距离。
- 🔑 **主动 / 被动共用一套绘制**：区别只在「数据从哪来」。主动时 `table.insert` 累积（配合 `ping_t` 计时测距），被动时**每次都把四张并行表整体清空重填**，保证画面上永远只有当前真实存在的目标。切模式不清表是这类显示最常见的 bug。
- 🔑 **`ping_t/pt` 就是把 tick 数换算成公里**：`pt=90` 是「每 ping 公里耗多少 tick」的标定常数（声速 1480 m/s、tick 60 Hz 下的近似值，见 `03` §11）。把它提成常量，换标定只改一行。
- ⚠ **反面教材一：`snr_age[i]` 在 `onDraw` 里递增**。绘制帧率与 tick 率不同（SW 里 `onDraw` 可能每帧多次或跳帧），把计时放在绘制里会让**老化速度随帧率漂移**，高帧率下回波瞬间消失。计时一律放 `onTick`。
- ⚠ **反面教材二：`snr_age[i]` 只在 `if sgn` 分支内累加**，被黑名单过滤掉的目标永远停在 `age=0`。一旦某天黑名单失效（改船体、换螺旋桨），会突然冒出一堆「全新」回波。年龄递增应放在过滤之外，或至少在过滤分支里也 +1。
- ⚠ **`else screen.setColor(0,0,0,0)` 并不能「不画」**：SW 的 `setColor` 第四参 alpha=0 时确实不可见，但紧随其后的 `drawText` / `drawLine` 仍然执行，白花字符。想省事直接 `if age < 512 then ... end` 包住绘制。
- 关联：`03` §11（声纳 ping 往返计时测距）、`03` §16（360 槽环形缓冲余晖）、`03` §34（声纳 ping 代数淘汰 + B 型扫描）、`00_速查 §4`（圈 vs 弧度）
- 同族进阶注记（夜轨补）：来源：steam id **3363121501** · <https://steamcommunity.com/sharedfiles/filedetails/?id=3363121501> · **载具**（20+ 块，`_vehicle_8` 为 64 分代表）——**360 方位噪声底表** `noise[1..360]`（每方位一格的噪声自适应，与 §36 固定方位黑名单互为静态/动态两面）；`range={4500,9000,18000}`×`stp={1,2,4}` 量程-步进档位表联动；`pulse(c,b)` 单行通用边沿闭包（`a[b].pulse = c~=a[b].touch and c`——按钮去抖的紧凑写法，值得 `01` 册参考）；`circloid` 极坐标点圈（360×drawCircleF 0.5）。`_v6`/`_v9` 为传感器/HUD 页。

## §37 声纳主动 ping 的**距离门控**去杂波 + 回波签名查表分类 + 雷达/声纳共用一张方位键表

- 来源：steam id 3796799293 · 描述页 https://steamcommunity.com/sharedfiles/filedetails/?id=3796799293 · 载具（Liffey Class SAR Vessel，搜救船声纳/雷达台 `_vehicle_0`）
- 更新时间：2026-09-06
- 用到：声纳（旋转 + 主动 ping）、雷达、罗盘（圈）、GPS、属性（声纳量程 / 探测门限 / 地图模式）、触控屏
- 亮点：**把「回波距离」和「ping 波前半径」都换算成屏幕像素再做门控**，缩放怎么变都自动跟随；雷达与声纳**共用一张以方位弧度为键的表**；再用一张标定签名表把回波分成六种目标类型。

```lua
pi2 = math.pi*2
sr  = property.getNumber("Sonar Range")        -- 声纳量程 (m)
df  = property.getNumber("Detection Filter")
-- 距离 × 声速系数 的签名标定表（实测），命中即判为对应目标
M   = {60500, 266.5, 500, 517.3, 703.6, 1143.5, 1151.5, 1349, 1364.7,
       1795.7, 1813.4, 1869.6, 1064.6, 25, 50, 2500}

function onTick()
  ba = iN(9); rd = iN(10); ra = iN(11)        -- 罗盘(圈)、雷达距离、雷达方位(圈)
  sd = iN(12); sss = iN(13); sh = iN(14)      -- 声纳距离、声速系数、俯仰
  z  = iN(5)                                  -- 地图视野半宽 (km)

  -- ① 雷达：键 = 「雷达方位 - 罗盘」的弧度；绘制角 a 在录入时就反算好
  if rT and rd > df then
    rla = ra*pi2 - ba
    R[rla] = {f=1, a=(-ra-.5)*pi2+ba, x=gX+rd*math.sin(rla), y=gY+rd*math.cos(rla),
              t=400, d=rd}
  end

  -- ② 声纳：sp = 本次 ping 的波前进度 0→1；sa = 声纳头方位 -0.5→0.5 圈
  if sT then
    sp = sp + 0.005 if sp >= 1 then sp = 0 end
    sa = sa + 0.003 if sa >= 0.5 then sa = -0.5 end
    if sd > df then
      for i, v in pairs(M) do                 -- ③ 签名查表判目标类型
        if math.abs(math.floor(sd*sss*10)/10 - v) <= 0.1 then
          mdf = (i == 1) and "meg"  or (i <= 13) and "shrk" or
                (i == 14) and "krak" or (i == 15) and "npc"  or
                (i == 16) and "crte" or "whle"
        end
      end
      sla = sa*pi2 - ba
      R[sla] = {f=2, a=(-sa-.5)*pi2+ba, x=gX+sd*math.sin(sla), y=gY+sd*math.cos(sla),
                t=400, d=sd, m=sd*sss, mdf=mdf, h=sh}
      mdf = nil                               -- ⚠ 见下方说明
    end
  end

  for i, v in pairs(R) do
    if v.f == 1 then                          -- 雷达回波：纯 TTL 老化
      if v.t > 0 then R[i].t = v.t - 1 else R[i] = nil end
      if not rT then R[i] = nil end
    else
      -- 🔑 声纳：新回波 (t==400) 必须落在「当前波前半径 ±5 像素」内才被采纳
      if v.t > 0 and (v.t < 400 or
         math.abs((v.d*cy/(500*z)) - (sr*cy/(500*z))*sp) < 5) then
        R[i].t = v.t - 1
      else
        R[i] = nil
      end
      if not sT then R[i] = nil end
    end
  end
end
```

```lua
  x = cx + (v.d*h/(z*1000))*math.sin(v.a - ba)
  y = cy + (v.d*h/(z*1000))*math.cos(v.a - ba)
else
  x, y = map.mapToScreen(gX, gY, z, w, h, v.x, v.y)
end
screen.setColor(0, 0, 255, 255*v.t/400)       -- 余晖就是 alpha
screen.drawCircleF(x, y, 1)
```

- 🔑 **门控用像素而不是米**：一次真实 ping 的回波在时刻 `sp` 返回的距离必然 ≈ `sr*sp`。作者把两边都换算成**屏幕像素**（`d*cy/(500*z)` 与 `(sr*cy/(500*z))*sp`，分母 `500*z` 就是「米 → 沿屏高的像素」），于是阈值 `5` 是像素值——地图缩放 `z` 一变，门控窗口自动跟着缩放，不需要再维护一套米制阈值。这比在物理量纲上做门控省心得多。
- 🔑 **共用一张 `R`，键是「已减罗盘的弧度」**：雷达取 `ra*2π-ba`、声纳取 `sa*2π-ba`，同一方位的新回波直接覆盖旧值，天然形成按方位分桶的稀疏环形缓冲。相比 `03` §16 的 360 槽定长数组，这里省掉下标取整与长度维护，代价是**一个方位只能留一个目标**。浮点键能命中，是因为两侧的键由**同一条算式**产生（位模式一致）；千万别拿两条不同公式算出的角度互相当键。
- 🔑 **`a` 字段在录入时就反算成绝对绘制角**（`(-ra-.5)*2π+ba`），`onDraw` 里只剩 `v.a - ba` 一个减法就能跟随罗盘。把每帧重复的角度运算从绘制循环搬进录入，是这类 PPI 最有效的省算手段。
- 🔑 **签名查表**：`sd*sss` 是「距离 × 声速系数」的合成量；`floor(x*10)/10` 留一位小数、再比 `<= 0.1`，等价于 ±0.1 的匹配窗。分档用 `i<=13` 这类**区间索引**而不是再建一张名字表，省字符。
- ⚠ **`mdf` 会跨目标残留**：它不是 `local`，查表没命中时保持上一次的值，作者靠录入后 `mdf=nil` 手动清。漏了这行，上一个回波的类型会串到下一个回波上。更稳的写法是查表前先 `mdf = nil`。
- ⚠ `v.t < 400` 那个 `or` 让门控**只在录入帧生效**：一旦被采纳就纯 TTL 衰减。想要「回波全程跟随波前」就去掉 `v.t<400`——那样回波会在一次 ping 中途消失，视觉更真实但读数更累。
- ⚠ 老化递减写在 `onTick` 是正确的；`03` §36 里那个放在 `onDraw` 递增的版本会因帧率漂移而失真，别互相抄。

## §38 多雷达 TWS 的「扇区拼接」部署：8 部雷达 × 同一脚本 8 份副本（只差一个角度常数）+ 每 tick 至多一个触点的流式汇聚

- 来源：steam id **3358095813**（[WIP]Pyo's TWS System Demo，`_vehicle_0`~`_10` 为 8 份 `tws radar v2`，`_vehicle_20` 为跟踪器 `radarDenoiser`）· 同族 CIWS 版：steam id **3378667462**（WIP RAC Auto CIWS with TWS，`TWS Radar Sub` ×8）
- 更新时间：2025-04-11（CIWS 版 2024-12-06）
- 用到：8 部搜索雷达各朝 45° 间隔方向、每部雷达配一块微控制器、GPS + 物理传感器姿态进每块微控
- 亮点：多雷达 TWS 不在脚本里做，而在**部署上做**——同一份脚本复制 8 份、每份只改一个扇区角常数，单雷达的探测扇区拼成全向；扇区微控把触点聚类合并后**每 tick 至多放行一个**下行，跟踪端不会被同一帧多触点淹没

```lua
-- 扇区片（tws radar v2，8 份副本仅此一行不同）
aoffset=0.5        -- 8 份各取 0/0.125/0.25/0.375/0.5/0.625/0.75/0.875（45° 步进铺满一圈）
r.r={GN(4*i-3),GN(4*i-2)+aoffset,GN(4*i-1)}      -- 雷达 d/a/e，方位加扇区偏移即回世界系
r.p=R2G(r.r)                                     -- 球面转世界坐标（自带姿态矩阵，08 §2 同款）
-- 同目标合并：门限 = 基础间距 + 角误差换算的弧长（角误差 × 距离）
if Dst(r.p,TGT[j].p)<mergedist+Ms(0.002*P)*r.r[1] then
  TS(TGT[j].pb,r.p)  TGT[j].l=0                  -- 并入位置缓冲，稍后取平均（多子 mesh 合一）
end
-- 流式门控：上一条没发完就不收新帧，每 tick 至多输出一个已合并触点
if #TGT==0 then ... end
SN(1,TGT[1].p[1])  T.remove(TGT,1)
```

```lua
-- 跟踪片（radarDenoiser）：8 路触点流做航迹管理，N 条航迹轮询成每 tick 一条输出
cur=cur+1  total=M.min(8,#U)  if cur>total then cur=1 end

-- 测速 = 窗口均值的差分再滑动平均；预测 = 均值 + 半窗前置 x+vx*E/2
```

**要点**
- 「同脚本多副本、只改一个常数」是载具编辑器里最省事的多雷达扩展：不写新代码，改常数 + 重接线即可横向扩容；CIWS 版把 8 个副本命名为 `TWS Radar Sub` 同构部署。
- 角门 0.002 圈就是雷达角度误差量级、距门比例项对应距离误差 ±1%，再加目标半宽 `atan(尺寸/距离)` 换算的角度余量——波门不是拍的，是按 `17_传感器与雷达.md` 的误差模型写死的。
- 航迹表输出与 `03` §19 的环形游标同思想：**表在微控里，总线上永远是流**，下游按「每 tick 一条 + 序号随行」消费。
