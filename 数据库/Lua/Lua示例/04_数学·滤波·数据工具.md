## §1 必背小函数

### 1.1 clamp（限幅）

```lua
function cl(x,a,b) return math.max(math.min(x,b),a) end
-- 短路版（更省字符）：
function cl(x,a,b) return x<a and a or (x>b and b or x) end
```

### 1.2 圈单位最短角差（**航向/罗盘/方位必用**）

```lua
-- 写法 A（最精炼，BKN speed-pivot）：返回 -0.5..0.5
function angDiff(a,b) local d=(a-b+0.5)%1-0.5 return d end

-- 写法 B（PYO 版，来源 steam id 3242277101，更易读）
function CD(c,t)
  c,t = c%1, t%1
  if (c-t)> 0.5 then t=t+1
  elseif (c-t)<-0.5 then t=t-1 end
  return (c-t)
end

-- 度数版
function angDiffDeg(a,b) return ((a-b+180)%360)-180 end
```

> **为什么必须有**：罗盘在 0/1 交界处（正北）会从 0.99 跳到 0.01，
> 直接相减得到 -0.98 圈（≈ -353°），控制器会命令载具绕一大圈。

### 1.2b 三种等价写法：**一行折差** / **展开式** / **手写 atan2**

> `04` §1.2 讲的是「为什么要做圈单位最短角差」。这一节给**可直接抄的三份实现**，来源都是 2026-09 的新鲜工坊代码。

```lua
-- ① 一行版（推荐）：把任意实数折到 [-0.5, 0.5)
function nm(v) return (v+.5)%1-.5 end

-- ② 展开版（同一件事，加 1.5 是为了避免负数取模）：
--    ((v+1.5)%1)-0.5   对 v ∈ [-1, 1] 与 ① 完全等价
steer = (((Comp + mid/pi2)%1 + 1.5)%1 - 0.5)*2   -- 末位 *2 把 ±0.5 映射到 ±1 的执行器行程

-- ③ 拆成两个函数版：w01 取小数部分（归一到 [0,1)），wh 折到 [-0.5,0.5)
local function w01(x) return x-math.floor(x) end
local function wh(x) return x-math.floor(x+.5) end
local function a2(y,x)                       -- 🔑 手写 atan2，处理 x==0 的两个奇点
  if x>0 then return math.atan(y/x) end
  if x<0 then return math.atan(y/x)+(y>=0 and math.pi or -math.pi) end
  if y>0 then return  math.pi/2 end
  if y<0 then return -math.pi/2 end
  return 0
end
r = wh( w01(a2(de,dn)/pi2) - w01(-c) )       -- 目标方位(圈) − 航向(圈) → ±0.5 的转向指令
```

**怎么选**

| 写法 | 出处 | 适用 |
| --- | --- | --- |
| ① `nm(v)=(v+.5)%1-.5` | steam id 3795011119（`_vehicle_14`） | **首选**。一行，输入可以是任意实数（含负数），Lua 的 `%` 对负数返回同号结果，`+.5` 后取模天然落在 [-0.5, 0.5) |
| ② `((v+1.5)%1)-0.5` | steam id 3794992381（`_vehicle_13`） | 作者为了**显式避开负数取模**才加 1.5；若你不确定 `%` 的负数行为，用这个更安心 |
| ③ `w01` + `wh` | steam id 3795317652（`_vehicle_3`） | 需要**分别**拿到「归一化方位」和「折差」时用；`w01` 还能单独用来把 `-0.25` 变成 `0.75` |

**关于手写 `atan2`（`a2`）**

- SW 的 `math.atan` **是两参版**（`math.atan(dx, dy)` 直接给 -π..π），所以手写通常不必要。但两件事值得知道：
  1. **参数顺序是 `atan(y, x)` 还是 `atan(x, y)` 要自己验**：`03` §1.2 用的是 `atan(分量, 投影)`，本例的 `a2(y,x)` 内部是 `y/x`。两者都出现在工坊代码里，照抄前先用「目标在正东」这一组值验一次。
  2. **`x==0` 是奇点**：`math.atan(y/0)` 得到 ±π/2 但符号取决于 `y` 的符号，而 `y==0` 时是 `0/0 = nan`。手写版显式处理了这两个分支——**`nan` 一旦产生，后续所有比较恒为 false，抗饱和分支全部失效**（见 `09` §11）。
- ⚠ `a2` 返回的是**弧度**，后面除 `pi2` 才变成圈。混用弧度和圈是工坊代码最常见的 bug（见 `00_速查 §4`）。

关联：`04` §1.2（为什么要最短角差）、`03` §1.2（`atan` 替代 `asin`）、`09` §11（`nan` 的危害）、`06` §18（把折差接到转向输出）

### 1.4b 归一化 `lerp` 与按步长取整 `round`

来源：steam id **2913735149**（Mig-21bis，2023-01-13，高度表）。

```lua
-- 归一化到 0..1（注意：不夹取，超出范围会返回 <0 或 >1）
function lerp(x,a,b) return (x-a)/(b-a) end

-- 四舍五入；给 nearest 则按该步长对齐
function round(x,nearest)
  return nearest and (x/nearest+.5)//1*nearest or (x+.5)//1
end

-- 保留 B 位小数（来源 2232448349，仪表用）
function roundTo(v,B) local m=10^(B or 0) return math.abs(math.floor(v*m+0.5)/m) end
```

**要点**
- `lerp(x,a,b)` 本例是**归一化**（把 x 从 [a,b] 映射到 [0,1]），不是插值的常见定义。需要夹取时自己加 `cl(...,0,1)`。
- `round(x, math.pi/4)` 这类「按步长对齐」在**画刻度线**时非常有用——能让刻度方向整齐地落在 45° 网格上。
- `(x+.5)//1` 用整除实现取整，比 `math.floor(x+.5)` 省字符，且**对负数行为与 floor 一致**（都向负无穷取整）。

### 1.5 滑动平均

```lua
-- 队列 + 求平均（BKN Utils/Expand/queue.md）
function stackPush(S,MAX,value)
  table.insert(S,value)
  if #S > MAX then table.remove(S,1) end
end
function tableAvg(S)
  local tmp=0
  for i=1,#S do tmp=tmp+S[i] end
  return tmp/#S
end

-- PYO 版：自动建表，返回窗口均值（来源 3242277101）
function Av(n,v,t)
  if n==nil then n={0} end
  t = math.max(math.floor(t),1)
  table.insert(n,v)
  local s=0
  if #n>t then for i=1,#n-t do table.remove(n,1) end end
  for i=1,#n do s=s+n[i] end
  return s/#n
end
```

> ⚠ 每 tick 都 `table.remove(t,1)` 是 **O(n)** 操作，窗口很大时改环形缓冲。

## §3 卡尔曼滤波

### 3.1 标量简化版（够用先用它）

A=1、H=1 的简化卡尔曼，来源 BKN `docs/Tools/kalman.md`。**注意针对不同用途调超参**：
`Q` = 过程激励噪声协方差，`R` = 测量噪声协方差。

```lua
KF,Q,R={},0.01,0.001

function kalmanFilter(data)
  if #KF==0 then
    for key,value in pairs(data) do
      local pminus = 1+Q
      local k = pminus/(pminus+R)
      KF[key]={xhatminus=0, pminus=pminus, k=k, xhat=k*value, p=(1-k)*pminus}
    end
  else
    for key,value in pairs(data) do
      local xhatminus = KF[key].xhat
      local pminus = KF[key].p + Q
      local k = pminus/(pminus+R)
      local xhat = xhatminus + k*(value-xhatminus)
      KF[key]={xhatminus=xhatminus, pminus=pminus, k=k,
               xhat=xhat, p=(1-k)*pminus}
    end
  end
end
```

用法：

```lua
data = {x=gps_x, y=gps_y, z=alt}    -- 原始读数
kalmanFilter(data)                  -- 滤波
-- 结果：KF.x.xhat / KF.y.xhat / KF.z.xhat
```

**调参直觉**
- `Q` 大 → 更相信新测量 → 响应快、抖动大。
- `R` 大 → 更相信模型预测 → 平滑、滞后明显。
- GPS 抖动大时典型取 `Q=0.01, R=0.001`；传感器噪声大时把 `R` 提到 `0.01~0.1`。

> ⚠ 多人下 `KF` 是脚本变量会分叉（`01` §5）。

### 3.2 完整多维版（含矩阵库，可估计速度）

来源：steam id **3750251471**（Radkampfwagen 90，2026 年更新）。
标量版只能平滑**单个量**；要同时估计**位置 + 速度**（从而在丢帧时外推、抑制延迟）必须用多维卡尔曼，
而多维卡尔曼需要**矩阵求逆**——这是本节的价值所在。

```lua
-- ============ 3x3 以内的矩阵库（全部可放进一个脚本方块）============
local M={}
function M.copy(a) local b={} for i=1,#a do b[i]={} for j=1,#a[i] do b[i][j]=a[i][j] end end return b end
function M.add(a,b) local c={} for i=1,#a do c[i]={} for j=1,#a[i] do c[i][j]=a[i][j]+b[i][j] end end return c end
function M.sub(a,b) local c={} for i=1,#a do c[i]={} for j=1,#a[i] do c[i][j]=a[i][j]-b[i][j] end end return c end
function M.mul(a,b)
  local R,C,C2=#a,#a[1],#b[1]
  local c={}
  for i=1,R do c[i]={} for j=1,C2 do
    local s=0 for k=1,C do s=s+a[i][k]*b[k][j] end c[i][j]=s
  end end
  return c
end
function M.sm(s,a) local c={} for i=1,#a do c[i]={} for j=1,#a[i] do c[i][j]=s*a[i][j] end end return c end
function M.tr(a) local c={} for i=1,#a[1] do c[i]={} for j=1,#a do c[i][j]=a[j][i] end end return c end
function M.id(n) local I={} for i=1,n do I[i]={} for j=1,n do I[i][j]= i==j and 1 or 0 end end return I end

-- 高斯-约当消元求逆（带部分主元选择，防除零）
function M.inv(m)
  local n=#m local a={}
  for i=1,n do
    a[i]={}
    for j=1,n   do a[i][j]   = m[i][j] end
    for j=1,n   do a[i][n+j] = i==j and 1 or 0 end   -- 右半接单位阵
  end
  for i=1,n do
    local p=i
    for k=i+1,n do if math.abs(a[k][i])>math.abs(a[p][i]) then p=k end end   -- 选主元
    if p~=i then a[i],a[p]=a[p],a[i] end
    local d=a[i][i]
    for j=1,2*n do a[i][j]=a[i][j]/d end
    for k=1,n do
      if k~=i then
        local f=a[k][i]
        for j=1,2*n do a[k][j]=a[k][j]-f*a[i][j] end
      end
    end
  end
  local inv={} for i=1,n do inv[i]={} for j=1,n do inv[i][j]=a[i][n+j] end end return inv
end

-- ============ 卡尔曼滤波器 ============
-- F 状态转移  H 观测  Q 过程噪声  R 测量噪声  x0 初态  P0 初协方差  B 控制矩阵(可选)
KF={}
function KF.new(F,H,Q,R,x0,P0,B)
  local o={F=F,H=H,Q=Q,R=R,B=B,n=#F}
  if x0 then o.x=M.copy(x0) else o.x={} for i=1,o.n do o.x[i]={0} end end
  if P0 then o.P=M.copy(P0) else o.P=M.id(o.n) end

  function o:pred(u)                                   -- 预测步
    local F,Q,B=self.F,self.Q,self.B
    if B and u then self.x=M.add(M.mul(F,self.x), M.mul(B,u))
    else            self.x=M.mul(F,self.x) end
    local FP=M.mul(F,self.P)
    self.P=M.add(M.mul(FP,M.tr(F)), Q)                 -- P = F·P·Fᵀ + Q
  end

  function o:upd(z)                                    -- 更新步（z = 观测列向量）
    local H,R,x,P=self.H,self.R,self.x,self.P
    local y   = M.sub(z, M.mul(H,x))                   -- 新息
    local S   = M.add(M.mul(M.mul(H,P), M.tr(H)), R)   -- S = H·P·Hᵀ + R
    local K   = M.mul(M.mul(P, M.tr(H)), M.inv(S))     -- K = P·Hᵀ·S⁻¹
    self.x    = M.add(x, M.mul(K,y))                   -- x = x + K·y
    local KH  = M.mul(K,H)
    self.P    = M.mul(M.sub(M.id(self.n), KH), P)      -- P = (I-K·H)·P
  end

  function o:state() return self.x end
  function o:cov()   return self.P end
  return o
end
```

用法（**匀速模型：同时估计位置与速度**，三轴各一个滤波器）：

```lua
dt = 1/60                                        -- 逻辑帧 60Hz
F  = {{1,dt},{0,1}}                              -- 状态 [位置, 速度]：x' = x + v·dt
H  = {{1,0}}                                     -- 只观测位置，不测速度
x0 = {{0},{0}}
P0 = M.id(2)
-- 连续白噪声加速度模型离散化后的 Q（专业做法，比手调单一数值准得多）
Q  = M.sm(0.015, {{dt^3/3, dt^2/2}, {dt^2/2, dt}})
R  = {{0.001}}

f1 = {}
for i=1,3 do f1[i] = KF.new(F,H,Q,R,x0,P0) end   -- X / Y / Z 三轴

function onTick()
  local z = {{gps_x},{gps_y},{gps_z}}
  for i=1,3 do
    f1[i]:pred()                                 -- 先预测（每 tick 必做）
    f1[i]:upd({{z[i][1]}})                       -- 有观测再更新
    local st = f1[i]:state()
    pos[i], vel[i] = st[1][1], st[2][1]          -- 位置 + 估计出的速度
  end
end
```

**要点**
- 🔑 **为什么需要多维**：标量版只能平滑位置；多维版状态向量是 `[位置, 速度]`，
  即使**某一帧丢了观测也能靠 `pred()` 外推**，还能顺带得到平滑的速度（省掉差分求速度的噪声）。
- **`H={{1,0}}`** 表示"只观测位置"——这正是卡尔曼的价值：用可测量的量反推不可测量的量（速度）。
- **`Q` 矩阵的构造**：`{{dt³/3, dt²/2},{dt²/2, dt}}` 是「连续白噪声加速度模型」的标准离散化结果，
  乘以一个强度系数（本例 `0.015`）即可。**比手动凑单个 Q 值科学得多**，改 dt 时自动适配。
- **矩阵求逆是刚需**：`K = P·Hᵀ·(H·P·Hᵀ+R)⁻¹`。2×2 求逆尚可硬编码，3 阶以上必须用 `M.inv`。
  本实现的**部分主元选择**（`pivot`）防止主元为 0 时除零崩溃。
- ⚠ **字符数**：这套库压缩前约 3.5KB，占 8192 上限约四成；旧版 4096 上限时代曾逼近上限，如今余量充足，但仍建议压缩。
  实际使用建议：① 只保留用到的矩阵函数（多数情况只需 `mul/tr/id/inv/add/sub`）；
  ② 或用 PonyIDE Minify 压到约 2KB 再放进脚本方块（见 `01` §2）。
- ⚠ 多人下滤波器状态是脚本变量会分叉（`01` §5）。

## §4 贝塞尔曲线

### 4.1 通用 N 阶（BKN `docs/Screen/bezier.md`）

```lua
function factorial(n) local r=1 for i=2,n do r=r*i end return r end
function comb(n,k) return math.floor(factorial(n)/(factorial(k)*factorial(n-k))) end

-- points[i] = {x, y}；poi = 1 取 x，2 取 y
function bezier(points, t, poi)
  local res,n = 0, #points-1
  for i=0,n do
    res = res + comb(n,i) * t^i * (1-t)^(n-i) * points[i+1][poi]
  end
  return res
end

function bezierCurve(points, total)
  local res={}
  for t=0,1,1/total do
    local tp={}
    for poi=1,#points[1] do table.insert(tp, bezier(points,t,poi)) end
    table.insert(res,tp)
  end
  return res
end
```

用法：

```lua
pts = {{2,h/2},{w/2-10,h/4},{w/2+10,h-20},{w-5,30}}
for i,p in ipairs(bezierCurve(pts, 300)) do
  screen.drawCircleF(p[1],p[2],0.5)
end
```

> ⚠ `total=300` 意味着 **300 次绘制 + 300×N 次幂运算**。画静态曲线可接受；
> 每帧重算会拖慢游戏，**应缓存结果**（曲线不变时只算一次）。

```lua
table.reduce = function (list, fn, init)
  local acc = init
  for k,v in ipairs(list) do
    if k==1 and not init then acc=v else acc=fn(acc,v) end
  end
  return acc
end
```

```lua
  if sep==nil then sep="%s" end
  local t={}
  for w in string.gmatch(s, "([^"..sep.."]+)") do table.insert(t,w) end
```

### 5.3 dump（table 转字符串，调试用）

```lua
function dump(o)
  if type(o)=='table' then
    local s='{\n'
    for k,v in pairs(o) do
      if type(k)~='number' then k='"'..k..'"' end
      s = s..k..' = '..dump(v)..',\n'
```

## §9 地图的**指数缩放**与比例尺的**二分跳档**

- 来源：steam id 3788946785 · 描述页 https://steamcommunity.com/sharedfiles/filedetails/?id=3788946785 · 载具（MV-24 倾转旋翼机※，`_vehicle_7` 导航显示器）
- 更新时间：2026-08-26
- 用到：触控屏、属性滑块（雷达/声纳量程）
- 亮点：缩放用**按比例增减**（`z = z ± z/170`）而不是固定步长，任何倍率下视觉变化速率都一致；比例尺长度用**二分跳档**自动落在固定像素区间内，永远不会画得太长或太短。

```lua
-- z = 视野半宽(km)；l = 比例尺长度(km)；rr/sr = 雷达/声纳量程(m)
z = math.min(math.max(rr, sr) * 2 / 1000, 50)      -- 初始视野按传感器量程定
l = 1

function onTick()
  -- ① 指数缩放：按住 +/- 按钮时每 tick 变化 1/170（约 0.59%）
  if z > 1 and B[2].p > 0 then                      -- 放大（缩小视野）
    z = z - z/170
  elseif z < math.max(rr, sr)*2/1000 and z < 50 and B[3].p > 0 then
    z = z + z/170                                   -- 缩小（放大视野）
  end

  -- ② 比例尺二分跳档：屏幕上占比 = l * w / z（像素）
  if     l*w/z > h/4 then l = l/2                   -- 太长 -> 档位减半
  elseif l*w/z < h/8 then l = l*2 end               -- 太短 -> 档位加倍
end

function onDraw()
  screen.setColor(100, 100, 100)
  screen.drawRectF(1, h-2, l*h/z, 1)                -- 比例尺条
  local lt = (l < 1) and (math.floor(l*1000) .. "M") or (math.floor(l) .. "KM")
  dt(1, h-8, lt)                                    -- 点阵字体标注，见 05 §1
end
```

**为什么这样写**

- **固定步长缩放（`z = z ± 0.1`）在低倍率时跳得飞快、高倍率时几乎不动**。改成 `z ± z/170` 后，每 tick 的**相对**变化恒定，手感全程一致；170 这个分母决定缩放速度，越大越慢（170 ≈ 按住 1 秒变 1.4 倍）。
- 缩放上下限别用常量：`z > 1` 是防除零/过载，`z < max(量程)` 是**不让视野超出传感器能力**——把限制绑到数据源上，换量程自动适配。
- **比例尺跳档的本质是「保持像素长度在区间内」**：`l*w/z` 就是比例尺的屏幕像素长（因为 `1 km -> w/z 像素`）。当它冲出 `[h/8, h/4]` 就把 `l` 折半/翻倍，档位永远是 1/2/5 式的整齐值。
- 与 `04` §1.3 的「限速跟随」互补：本例是**连续指数变化**（跟手、无插值），§1.3 是**每 tick 最多移动固定量**（平滑、有拖尾）。缩放/音量这类要跟手用本例，镜头平移要平滑动用 §1.3。
- 完整脚本：`../../../AI相关/_提取暂存/_new/3788946785_vehicle_7.lua`

### 9.1 变体：**对数域缩放**（`z = math.exp(Z)`）+ **十进制跳档**比例尺 + `fmod` 网格原点吸附

- 来源：steam id 2948687255 · 载具（26m V80 Superyacht 导航屏，`_vehicle_0`）· 更新时间：2023-03-19
- 与 §9 正文的分工：正文是「`z = z ± z/170` 直接改倍率 + **二分**跳档」，本变体是「**改对数 `Z`、取 `exp` 得倍率** + **十进制（10 的幂）跳档** + 网格原点吸附」。两者选一个用，不要混。

```lua
Z=0                                          -- 🔑 对数域缩放量（线性）
r=999                                        -- 环距/格距兜底值
function onTick()
  z=M.exp(Z)                                 -- 实际倍率恒 > 0，天然取不到 0 / 负值
  -- 放大：Z 减小；下限判在「真倍率」上，读起来最直观
  if tp and Button(tx,ty,w-44,h-23,6,6) and z>0.1 then Z=Z-0.01 end
  -- 缩小：Z 增大
  if tp and Button(tx,ty,w-44,h-13,6,6) and z<50    then Z=Z+0.01 end
end

function onDraw()
  S.drawMap(x,y,z)
  -- ① px→m 标定：量出「1 m 是多少像素」，后面所有换算都基于它
  Ox,Oy = map.mapToScreen(x,y,z,w,h,0,0)
  ex,_  = map.mapToScreen(x,y,z,w,h,1,0)
  e     = M.abs(Ox-ex)                                     -- px per meter

  -- ② 十进制跳档：从大到小试，取第一个在半屏以内的档位
  local u
  if     e*10000<w/2-10 then r=e*10000 R="10km" u=10000
  elseif e*1000 <w/2-10 then r=e*1000  R="1km"  u=1000
  elseif e*100  <w/2-10 then r=e*100   R="100m" u=100
  elseif e*10   <w/2-10 then r=e*10    R="10m"  u=10 end

  -- ③ 🔑 网格原点吸附到步长的整数倍：网格线才会落在 1000/2000/3000 这类整坐标上
  Ox,Oy = map.screenToMap(x,y,z,w,h,0,0)                   -- 屏幕左上角对应的世界坐标
  Ox,Oy = Ox-M.fmod(Ox,u), Oy-M.fmod(Oy,u)
  Ox,Oy = map.mapToScreen(x,y,z,w,h,Ox,Oy)                 -- 再投回屏幕像素

  sC(0,0,0,50)
  local i=0
  while i*r<w do dL(Ox+i*r,0,Ox+i*r,h) i=i+1 end
  i=0
  while i*r<h do dL(0,Oy+i*r,w,Oy+i*r) i=i+1 end

  -- ④ 比例尺条：固定 5 段黑白交替，总长恒为一个档位 r
  for i=0,4 do dL(3+i*2*r/10,h-5, 3+(i*2+1)*r/10,h-5) end
  dL(3,h-3,3,h-8) dL(3+r,h-3,3+r,h-8)
  dTx(4,h-13,R)
end
```

**为什么这样写**

- **`z=math.exp(Z)` 比 `z=z±z/170` 更省心**：`Z` 是线性量，按钮每 tick `±0.01` 就是恒定手感；`exp` 保证倍率恒正，省掉 `max(z,0.1)` 这类防零代码。上下限直接写在对数域上比较（`z>0.1` / `z<50`），可读性最好。代价是每 tick 多一次 `exp` 调用（可忽略）。
- **跳档的两种口味**：§9 正文的二分跳档档位密、条长变化平滑；本变体的十进制跳档档位稀疏，但**读数一定是 10 的幂**，配合网格一起看更直观。二者共用同一个判断——「像素长 = 档位 × 每米像素数」是否落在半屏内。
- **`fmod` 吸附是网格的灵魂**：不吸附的话网格线会跟着地图中心漂，中心一动整片网格跟着滑，看不出「我正在往哪走」；吸附后网格钉死在世界坐标的整数公里上，只有地图本身在动。
- ⚠ **跳档变量必须有兜底**：四个 `elseif` 全不成立时（例如 `e` 极大，连 10 m 都超过半屏宽），`r`/`R`/`u` 保持上一帧的值，`u` 甚至是 `nil` → `M.fmod(Ox,u)` 直接报错。抄的时候给 `r` 一个初值，并让 `u` 有默认档。
- 完整脚本：`../../../AI相关/_提取暂存/_r7/2948687255_vehicle_0.lua`

## §10 表盘绘制：**计算放 onTick、画弧放 onDraw**（跨函数共享全局）

- 来源：steam id 3790163661 · 描述页 https://steamcommunity.com/sharedfiles/filedetails/?id=3790163661 · 载具（Tanky McTankerface，`_vehicle_11` 温湿度表）
- 更新时间：2026-08-26
- 用到：数值输入（温度 / 湿度 / 最小最大量程）、显示器
- 亮点：SW 的 `onDraw` 每帧可能被调用**多次**（接多块屏时），把归一化这类纯计算放 `onTick` 只算一次；画弧用 `drawTriangleF` 拼扇形（比逐点 `drawRectF` 快得多）。

```lua
function onTick()
  inVal = input.getNumber(1)                       -- 温度
  x, y  = input.getNumber(2), input.getNumber(3)   -- 圆心
  min, max = input.getNumber(4), input.getNumber(5)
  rad   = input.getNumber(6)                       -- 半径
  Humd  = input.getNumber(7) * 100                 -- 湿度 0~1 -> 百分比
  fac   = factor()                                 -- ① 归一化只算一次
end

function onDraw()
  local w, h = screen.getWidth(), screen.getHeight()
  local cx, cy = x, y + rad
  screen.setColor(100, 100, 100); screen.drawClear()

  screen.drawTextBox(1, 25, 16, 8, string.format("%01.0fc", inVal), -1, 0)
  screen.drawTextBox(w/2, 25, 16, 8, string.format("%01.0f%%", Humd), 0, 0)

  -- ② 扇形色带：每 45 度一个三角扇（比逐点画弧快 10 倍以上）
  local cxp, cyp = cx, cy
  local a = 0
  for i = 1, 3 do
    local na = a + math.pi/4
    screen.drawTriangleF(cxp, cyp,
      cxp + rad*math.cos(a),  cyp - rad*math.sin(a),
      cxp + rad*math.cos(na), cyp - rad*math.sin(na))
    a = na
  end

  -- ③ 指针：0.9 倍半径，从 π(左) 转到 0(右)
  local angle = math.pi * (1 - fac)
  screen.setColor(5, 5, 5)
  screen.drawLine(cx, cy,
    cx + math.cos(angle)*rad*0.9,
    cy - math.sin(angle)*rad*0.9)
end

function factor()
  local range = max - min
  if range > 0 then return (inVal - min) / (max - min) end
  return 0
end
```

**要点与坑**

- **归一化 `factor()` 必须防 `range == 0`**（量程滑块被拖到 min=max 时会除零返回 `nan`，指针直接消失）。需要夹取就再套 `math.min(math.max(...,0),1)`，见 `04` §1.4b。
- `onDraw` 里读 `input.*` 是**无效**的（见 `00_速查 §9`）——所有输入必须在 `onTick` 里取好放进全局量。
- `screen.drawTextBox(x, y, w, h, text, hAlign, vAlign)` 的对齐参数是 **-1/0/1**（左/中/右、上/中/下），用它做「标签居左、数值居右」这种排版，比手算字符宽度（见 `05` §15）省事得多。
- 扇面用三角扇拼，段数按精度与字符预算折中；需要任意角度圆弧见 `05` §5.7 `drawArc`。

## §11 `vec3` 闭包向量库：机体系 ⇄ 世界系 + **按 tick 分桶**的历史

- 来源：steam id **3792899963** · 描述页 <https://steamcommunity.com/sharedfiles/filedetails/?id=3792899963> · **载具**（WENDIGO Trainer / Light Strike Jet Aircraft，`_vehicle_12` 雷达解算）
- 更新时间：2026-08-31
- 用到：GPS、多功能物理传感器（欧拉角 X/Y/Z，**圈**）、雷达（6 目标 × 4 值）
- 亮点：**12 行就写出一个可链式调用的三维向量类型**，坐标变换靠「投影到三轴 / 三轴线性组合」两个函数搞定；历史接触**按 tick 分桶整批裁剪**，比逐点记时间戳省一张平行表。

```lua
-- ① 向量：表内嵌方法 + 冒号调用（a:add(b) 等价于 add(a, b)），可无限链式
function vec(x, y, z) return {x = x or 0, y = y or 0, z = z or 0,
  add    = function(a, b) return vec(a.x+b.x, a.y+b.y, a.z+b.z) end,
  sub    = function(a, b) return vec(a.x-b.x, a.y-b.y, a.z-b.z) end,
  scale  = function(a, b) return vec(a.x*b, a.y*b, a.z*b) end,
  dot    = function(a, b) return (a.x*b.x + a.y*b.y + a.z*b.z) end,
  cross  = function(a, b) return vec(a.y*b.z-a.z*b.y, a.z*b.x-a.x*b.z, a.x*b.y-a.y*b.x) end,
  len    = function(a) return a:dot(a)^0.5 end,
  normalize = function(a) return a:scale(1/a:len()) end,
  clone  = function(a) return vec(a.x, a.y, a.z) end,
  -- 🔑 世界 ⇄ 机体：f/u/r 是由欧拉角算出的前/上/右单位向量
  tolocal  = function(a, f, u, r) return vec(r:dot(a), f:dot(a), u:dot(a)) end,
  toglobal = function(a, f, u, r) return r:scale(a.x):add(f:scale(a.y)):add(u:scale(a.z)) end}
end

function onTick()
  pos = vec(ign(1), ign(3), ign(2))        -- ⚠ GPS 给 (东, 北, 高度)，本库按 (x=东, y=上, z=北) 存
  rx, ry, rz = ign(4), ign(5), ign(6)      -- 物理传感器欧拉角，单位「圈」
  -- ② 由欧拉角直接展开机体三轴（Z-Y-X 序），不建 3×3 矩阵表
  cx,cy,cz = m.cos(rx), m.cos(ry), m.cos(rz)
  sx,sy,sz = m.sin(rx), m.sin(ry), m.sin(rz)
  r = vec( cy*cz,      -sy,       cy*sz    )
  f = vec( sx*sz+cx*sy*cz, cx*cy, -sx*cz+cx*sy*sz )
  u = r:cross(f)

  -- ③ 雷达球坐标 → 机体向量 → 世界坐标
  for i = 6, 1, -1 do
    dst[i], azm[i], elv[i] = ign(3+i*4), ign(4+i*4), ign(5+i*4)
    tgt[i] = rad2xyz(dst[i], azm[i], elv[i])
  end
end

function rad2xyz(dst, azm, elv)            -- 距离 / 方位 / 仰角，均为「圈」
  lVec = vec(m.sin(azm*pi2)*m.cos(elv*pi2)*dst,
             m.cos(azm*pi2)*m.cos(elv*pi2)*dst,
             m.sin(elv*pi2)*dst)
  gVec = lVec:toglobal(f, u, r)
  if gVec:len() > pgn("Minimum Range") then return pos:add(gVec) else return vec() end
end
```

```lua
-- ④ 历史接触：每 tick 一个桶，整批裁剪（history = 600 tick ≈ 10 s）
function pushContact(tickIndex, v)
  if v and v:len() > 0 then
    local bucket = contacts[tickIndex]
    if not bucket then bucket = {}; contacts[tickIndex] = bucket end
    bucket[#bucket + 1] = v:clone()
  end
end

function pruneContacts(nowTick)
  local cutoff = nowTick - history
  if cutoff <= 0 then return end
  for t = 1, cutoff do contacts[t] = nil end     -- 单调推进，不会重复扫
end
```

**要点与坑**

- **每次 `vec()` 都新建一张表**，`onTick` 里每帧几十次运算 = 每秒几千张表留给 GC。
  这是**可读性优先**的取舍：本例作者把 8 个雷达通道 × 6 目标的解算全写在里面仍然够用。
  真到性能吃紧（大网格激光成像、卡尔曼多维版）请改用 `04` §3.2 的**裸表 + 索引**写法。
- `tolocal / toglobal` 的本质是**换基**：把向量分别投影到 `r,f,u` 三轴上（点积），
  或用三轴加权求和（线性组合）。只要三轴是**单位正交**的，正反变换就是同一组系数——
  这也是为什么 `u = r:cross(f)` 必须在 `r`、`f` 都归一化之后算。
- ⚠ **轴序坑**：GPS 通道是 `(东, 北, 高度)`，本库内部按 `(x=东, y=上, z=北)` 存，
  所以入口要 `vec(ign(1), ign(3), ign(2))` 把第二、三通道**对调**。写反了在低高度时看不出来，
  一上万米全错。与 `03` §1 的欧拉角单位（圈，须 `×2π`）是同一个作品里两个最容易踩的坑。
- 分桶裁剪的前提是 **tick 索引单调递增**：`pruneContacts` 每帧从 1 扫到 `cutoff` 会随运行时间线性变长，
  更省的做法是记一个 `lastPruned` 游标，每帧只清 `(lastPruned, cutoff]`。
  与 `03` §12 的「逐点 TTL」对比：分桶**适合只按时间批量作废**的场景，TTL **适合每个点寿命不同**的场景。

## §12 **NaN 安全**的数值三件套：`Clamp` / `Lerp` / `CTR` + PID 的**零增益短路**

- 来源：steam id **3794083217** · 描述页 <https://steamcommunity.com/sharedfiles/filedetails/?id=3794083217> · **载具**（Type 95，`_vehicle_1` ECU）
- 更新时间：2026-09-02
- 用到：模块化引擎（空气 / 燃料 / 温度 / RPS）、属性滑块、油门推杆
- 亮点：**`v ~= v` 一行判 NaN**，把「除零 / 0/0」产生的 `nan` 在源头拦掉，避免它顺着表扩散成整屏失效；`Lerp` / `CTR` 两个区间映射各管一段；PID 里**增益为 0 就整项跳过**，既省算力又避开除零。

```lua
-- ① NaN 安全限幅：nan 是唯一「不等于自己」的值
function Clamp(value, min, max)
  return value ~= value and min or math.max(math.min(value, max), min)
end

-- ② Lerp：把「比例 0..1」映射成「实际区间」——先夹比例，再乘跨度
function Lerp(min, max, value)
  return Clamp(value, 0, 1) * (max - min) + min
end

-- ③ CTR（Convert To Range）：把「读数区间」线性映射到「另一区间」——注意它 **不做限幅**
function CTR(value, from1, from2, to1, to2)
  return (value - from1) / (from2 - from1) * (to2 - to1) + to1
end
```

```lua
-- ④ PID 对象：增益为 0 的项整项跳过（省算力 + 避开 /kI 除零）
update = function(s, setpoint, variable)
  deviation = setpoint - variable
  if not (s.kP == 0) then s.P = deviation * s.kP else s.P = 0 end
  if not (s.kI == 0) then
    s.i = s.i + deviation
    s.i = Clamp(s.i * s.kI, 0, s.iMax) / s.kI   -- 🔑 在「乘完增益」的量纲上限幅，再除回去
    s.I = s.i * s.kI
  else s.I = 0 end
  if not (s.kD == 0) then s.D = (deviation - s.pd) * s.kD else s.D = 0 end
  s.pd = deviation
  s.control = s.P + s.I + s.D
  if not (s.cm == 0) then s.control = Clamp(s.control, 0.0001, s.cm) end  -- 下限留 1e-4，不完全断油
end
```

**要点**

- **`v ~= v` 是 Lua 里判 NaN 的唯一可靠写法**（`math.abs(v) > 1e9` 之类启发式都不可靠）。在 SW 里 `nan` 几乎都来自 `0/0` 或 `inf - inf`，典型是「燃料为 0 时算空燃比 `air/fuel`」「两帧坐标相同算速度除零」。
- **不拦的后果很隐蔽**：`nan` 参与任何比较都返回 `false`，于是 `if x > limit` 不成立、`clamp` 原样返回 `nan`，最后 `screen.drawText(x, y, nan)` 把**整块屏**画没。拦在源头（本例的 `Clamp`）是唯一省事的做法。
- **积分限幅的「反推写法」**：`Clamp(i*kI, 0, iMax)/kI` 等价于把积分项输出夹在 `[0, iMax]`，好处是 `iMax` 与油门同一量纲、好调；代价是 **`kI == 0` 时会除零**——这正是外层 `if not (s.kI == 0)` 不能省的原因。
- **反面教材（原脚本）**：
  1. `CTR` 没有除零保护，`from2 == from1`（量程上下限填成一样）会直接 `inf`。调用前要么保证区间非零，要么套一层 `Clamp`。
  2. 积分限幅写死 `[0, iMax]` 是**单向**的，只适用于输出恒正的执行器（油门、舵面正偏）。需要双向输出时必须改成 `Clamp(v, -iMax, iMax)`。
- **何时用 `Lerp` / `CTR`**：`Lerp(min, max, t)` 用于「我手里是 0..1 的比例」；`CTR(v, a, b, c, d)` 用于「我手里是原始读数」——两者组合可以先归一再映射，例如 `rpsTarget = Lerp(idleRps, maxRps, CTR(throttle, 0, 1, 0, 1))`。
- 关联：`04` §1.1 的裸 `clamp`（无 NaN 保护版，字符更省）；`09` §12 的 PID 对象（`pause/reset` 双模抗饱和，与本例的「固定限幅」是两种取舍）。

## §13 向量闭包库的**换基三件套** `ltog` / `gtol` / `axang` + **双约定欧拉矩阵** + 透视投影画 HUD 符号

- 来源：steam id **3795592571** · 描述页 <https://steamcommunity.com/sharedfiles/filedetails/?id=3795592571> · **载具**（9K720 Iskander 短程弹道导弹，`_vehicle_17` 目标符号投影）
- 更新时间：2026-09-05
- 用到：雷达目标世界坐标、物理传感器欧拉角、座椅/炮塔视角、屏幕绘图
- 亮点：`04` §11 的 `vec3` 只解决「机体系 ⇄ 世界系」两系互转；本例把基向量**当成参数传进去**，于是**任意两系**都能一行换过去，还多一个绕任意轴旋转的 `axang`。

```lua
-- ① vc() 返回的既是数组又是方法表：a[1] 取值，a:dot(b) 调方法
function vc(x,y,z) return {
  x or 0, y or 0, z or 0,
  mag  = function(a) local m=a[1]^2+a[2]^2+a[3]^2 return m==1 and 1 or math.sqrt(m) end,
  dot  = function(a,b) return type(b)=="table" and a[1]*b[1]+a[2]*b[2]+a[3]*b[3]
                              or vc(a[1]*b, a[2]*b, a[3]*b) end,   -- 双语义：点积 / 数乘
  cross= function(a,b) return vc(a[2]*b[3]-a[3]*b[2], a[3]*b[1]-a[1]*b[3], a[1]*b[2]-a[2]*b[1]) end,
  add  = function(a,b) return vc(a[1]+b[1], a[2]+b[2], a[3]+b[3]) end,
  sbt  = function(a,b) return vc(a[1]-b[1], a[2]-b[2], a[3]-b[3]) end,
  norm = function(a) return a:dot(1/a:mag()) end,
  -- 🔑 换基：把「用 i/j/k 三个基向量表示的系数」还原成全局向量
  ltog = function(a,i,j,k) return i:dot(a[1]):add(j:dot(a[2])):add(k:dot(a[3])) end,
  -- 🔑 换基的逆：全局向量在 (i,j,k) 上的三个投影分量
  gtol = function(a,i,j,k) return vc(a:dot(i), a:dot(j), a:dot(k)) end,
  -- 绕任意轴 ax 旋转（旋转向量的模长即角度，罗德里格斯公式的闭包写法）
  axang= function(a,ax)
    local bi,bj = a:cross(ax):norm(), ax:norm()
    local bk = bj:cross(bi)
    bi,bk = vc(math.cos(ax:mag()),0,math.sin(ax:mag())):ltog(bi,bj,bk),
            vc(-math.sin(ax:mag()),0,math.cos(ax:mag())):ltog(bi,bj,bk)
    return vc(0, ax:norm():dot(a), ax:norm():cross(a):mag()):ltog(bi,bj,bk)
  end,
} end

-- ② 双约定欧拉矩阵：默认序给车/船用，末尾加 "aer" 是航空序（YXZ），两套不能混
function ijkraw(x,y,z,t)
  local sx,cx,sy,cy,sz,cz = math.sin(x),math.cos(x),math.sin(y),math.cos(y),math.sin(z),math.cos(z)
  return t~="aer"
    and {vc(cy*cz, cy*sz, -sy),
         vc(sx*sy*cz-cx*sz, sx*sy*sz+cx*cz, sx*cy),
         vc(cx*sy*cz+sx*sz, cx*sy*sz-sx*cz, cx*cy)}
    or  {vc(cz*cx+sz*sy*sx, -sz*cy, sz*sy*cx-cz*sx),
         vc(sz*cx-cz*sy*sx,  cz*cy, -cz*sy*cx-sz*sx),
         vc(sx*cy, sy, cx*cy)}
end
function ijk(...) return table.unpack(ijkraw(...)) end

local circles = {}
function onTick()
  -- 注意通道顺序：SW 的 GPS 是 (x=东, y=北, z=上)？本例按 ign(1),ign(3),ign(2) 重排
  mypos, targpos = vc(myX,myY,myZ), vc(coordX,coordY,coordZ)
  ivec, jvec, kvec = ijk(eulerX, eulerY, eulerZ)
  -- 🔑 一行完成「世界系相对位置 → 机体系」：先作差，再投影到三个基向量
  relpos = targpos:sbt(mypos):gtol(ivec, jvec, kvec)
  table.insert(circles, {relpos, remainingTicks = 15, symbol = symbol, ID = ID, Color = Color})
  for i = #circles, 1, -1 do                      -- 倒序删除，见 03 §18
    circles[i].remainingTicks = circles[i].remainingTicks - 1
    if circles[i].remainingTicks <= 0 then table.remove(circles, i) end
  end
end

function onDraw()
  local w2, h2 = screen.getWidth()/2, screen.getHeight()/2
  for _, circle in ipairs(circles) do
    -- 机体系 → 视角系（座椅还可以再转一次：ijk(seatX*2pi, seatY*2pi, 0, "aer")）
    local circ = circle[1]:gtol(ijk(seatX*math.pi*2, seatY*math.pi*2, 0, "aer"))
    if circ[3] > 0 then                            -- 🔑 剔除身后目标（z<=0 在相机背面）
      local px = ( circ[1]/circ[3]) * 173 + w2     -- 透视除法：除以深度
      local py = (-circ[2]/circ[3]) * 173 + h2     -- Y 取负：屏幕向下为正
      -- …按 circle.Color / circle.symbol 选色、选形状（X / 方块 / 三角）画符号
    end
  end
end
```

- 🔑 **`gtol` 是这套库的收口**：`04` §11 需要为每个「从哪系到哪系」各写一个函数；这里只要拿到三个基向量，`v:gtol(i,j,k)` 就能把任意向量拆成该系的三个分量，`v:ltog(i,j,k)` 是它的逆。**基向量本身也是 `vc` 对象**，所以视角再嵌一层（`ijk(...,"aer")`）也只是再调一次 `gtol`。
- **两套欧拉序必须分清**：`ijkraw` 的 `"aer"` 分支是航空序（先偏航再俯仰再滚转，YXZ），默认分支是另一套（ZYX 系）。**用错序时症状是「转头时画面斜着滑」**，不是完全乱掉，很难一眼看出来——调不出来时先换另一个分支试。
- **`dot` 的双语义省一半函数名**：传表做点积、传标量做数乘，靠 `type(b)=="table"` 分派。代价是**传错类型不报错**（传个数字进去静默变成缩放）。
- ⚠ **原脚本有两处残留**：`fovX, fovY = math.tan(1), math.tan(0.75)` 算完**没被使用**，投影用的是硬编码焦距 `someConstant = 173`。也就是说 FOV 与焦距已经脱钩，换屏幕尺寸只能手动重调 173。正确做法是 `f = (h/2)/math.tan(fovY/2)`，让焦距随 FOV 与屏高自动算。
- ⚠ **除零**：`circ[3]` 为 0（目标正好在相机平面内）时 `px/py` 变 `nan`。本例靠 `circ[3] > 0` 挡住了，若改成 `>= 0` 就会整屏乱画。
