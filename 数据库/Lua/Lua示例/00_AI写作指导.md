# 00 · AI 写作指导（动手前必读）

> **本文件是「指导书」，不是例题集。** 作用是让你在动笔前把方向、约束、通道规划定死，
> 避免写出「语法没错但接不进游戏」的脚本。例题在 `01`~`08`。
>
> 通用 Lua 语法（循环、表操作、字符串基础）本集一律不收——你自己会。
> 这里只讲 **Stormworks 特有的决策点**。

---

## §1 动手前必须回答的 5 个问题

### Q1. 脚本 Lua 还是附加 Lua？

| 判断依据 | 脚本 Lua | 附加 Lua |
| --- | --- | --- |
| 用户说「载具里 / 微控里 / 屏幕 / 方块」 | ✅ | |
| 用户说「附加 / Addon / 全局 / 任务 / 存档」 | | ✅ |
| 需要 `screen.*` 画图 | ✅ | ❌（附加无屏幕 API） |
| 需要 `server.*` 读写世界 | ❌ | ✅ |

**选错对象 = 全盘返工。** 拿不准就问用户。

### Q2. 这个状态要不要在多人下同步？

脚本级变量（`local` 或全局）在 **server 与 client 各跑一份且互不共享**。
因此：**凡是「状态记忆」类变量（toggle、计数器、积分项、状态机当前态）都必须考虑同步**。

| 需求 | 做法 |
| --- | --- |
| 单机 / 不同步也无所谓 | 直接用脚本变量（最简单） |
| 联机必须一致 | 状态经 `output` 写出 → 自身 `input` 读回；或用 Memory 方块；或整体挪到附加 Lua 用 `g_savedata` |

### Q3. 要不要画屏幕？

要 → `onDraw`；不要 → 只有 `onTick`。**两者严格分离**：
`onTick` 里调 screen API 无效，`onDraw` 里调 `input`/`output` 无效。
且 **onDraw 在接多个显示器时会被多次调用**，别在里面做有副作用的计算。

### Q4. 通道怎么分？

脚本方块有 **32 路数字输入 + 32 路布尔输入 + 32 路数字输出 + 32 路布尔输出**。
**先在纸上列一张表再写代码**——中途改通道号是最高频的返工原因。

模板：

| 通道 | 类型 | 接什么 | 单位 | 备注 |
| --- | --- | --- | --- | --- |
| N1 | 数字输入 | GPS X | m（东） | |
| N2 | 数字输入 | GPS Y | m（北） | |
| B1 | 布尔输入 | 主控开关 | — | |
| N31 | 数字输出 | 舵机角度 | 圈 | |

把这张表**写进代码顶部注释**（ASCII），后期维护成本降一个数量级。

### Q5. 角度单位是圈还是弧度？

**游戏内所有传感器 / 雷达 / 罗盘 / 舵机的角度输出都是「圈」（turn），1 圈 = 360°。**
Lua 的 `math.sin/cos/atan` 只认**弧度**。

- 进 `sin/cos` 前：`× 2π`
- 出 `atan` 后：`÷ 2π`
- 进 `math.rad()` 可用于「度数」输入（如手写刻度）

**这是最高频 bug 源，没有之一。** 详见 `03_传感器与雷达解算.md` §1。

## §2 标准骨架模板（可直接抄）

> 代码块保持 ASCII，可整段粘进游戏内 Lua 方块。

```lua
--[[ CHANNEL MAP
  N1 gps_x(m,E)   N2 gps_y(m,N)   N3 gps_alt(m)
  B1 master_on
  N31 out_throttle(0..1)   B31 out_alarm
]]
-- aliases (see 01 for the full compression scheme)
GN,GB,SN,SB = input.getNumber, input.getBool, output.setNumber, output.setBool
PN,PB,PT    = property.getNumber, property.getBool, property.getText
M,pi2       = math, math.pi*2
abs,fl,sqrt = M.abs, M.floor, M.sqrt
sin,cos,atan= M.sin, M.cos, M.atan

-- clamp + shortest angular difference (turns)
function cl(x,a,b) return x<a and a or (x>b and b or x) end
function angDiff(a,b) local d=(a-b+0.5)%1-0.5 return d end

-- state that MUST survive across ticks (remember: not synced in MP)
tickCount, prevBtn, state = 0, false, 0

function onTick()
  -- 1) read
  local gx,gy,ga = GN(1),GN(2),GN(3)
  local btn,on   = GB(1),GB(2)

  -- 2) edge detect (see 02 section 1)
  local pressed = btn and not prevBtn
  prevBtn = btn

  -- 3) main logic
  tickCount = tickCount + 1
  ...
  -- 4) write (ALWAYS write every output channel, even default values)
  SN(31, 0)
  SB(31, false)
end

function onDraw()
  local w,h = screen.getWidth(), screen.getHeight()
  screen.setColor(0,0,0)
  screen.drawClear()
  screen.setColor(255,255,255)
  screen.drawText(1,1,"OK")
end
```

**骨架里的每个设计都是有原因的**：

| 片段 | 为什么 |
| --- | --- |
| 顶部 `CHANNEL MAP` 注释 | 通道号改错是最频返工源；注释不占运行时，但省几小时 |
| 每 tick **无条件写满所有输出** | 未写的通道会保持上一次的值，产生「幽灵输出」 |
| `local` 修饰循环内临时量 | 局部变量访问更快，且避免污染全局（8192 上限下全局名也占字符） |
| `onDraw` 开头先 `drawClear` | 不 clear 会残留上一帧 |
| `prevBtn` 放在函数外 | 它必须跨 tick 存活；放函数内每次都是 false，边沿检测失效 |

## §3 调试手段（游戏内没有 `print`）

| 手段 | 用法 | 适用 |
| --- | --- | --- |
| **屏幕 dump** | 把变量塞进 `DEBUG` 表，用递归 `dump()` 打到屏幕上，能自动展开 table | 最常用，见 `04_数学·滤波·数据工具.md` §6 |
| **数值直通输出** | 可疑变量直接 `SN(31, x)`，用万用表/显示屏看 | 单变量追踪 |
| **PonyIDE / VSCode** | 离线编辑器里可 `print`，先离线跑通逻辑再粘进游戏 | 纯算法部分 |
| **语法检查按钮** | 编辑器左下角，压缩后必点（去空格易漏运算符） | 每次改完 |

快速 DEBUG 一行版（粘贴即用）：

```lua
function dump(b)if type(b)=='table'then local d='{ 'for e,f in pairs(b)do if type(e)~='number'then e='"'..e..'"'end;d=d..'['..e..'] = '..dump(f)..',\n'end;return d..'} 'else return tostring(b)end end
-- onDraw: screen.drawTextBox(0,0,screen.getWidth(),screen.getHeight(),dump(DEBUG),-1,-1)
```

## §4 常见错误速查（按报错/现象定位）

| 现象 | 大概率原因 | 修法 |
| --- | --- | --- |
| `attempt to perform arithmetic on a nil value` | 变量未初始化 / 通道号错 / 属性标签拼错 | 检查 `property.get*` 的标签**区分大小写**、且与方块标签完全一致 |
| `attempt to index a nil value` | 表未预填充就取 `t[i]` | 先 `for i=1,N do t[i]=0 end`（见 `03` §6） |
| 脚本一点反应没有 | ① 没接电；② 通道没接；③ 写在 `onTick` 的绘图无效 | 逐项排除 |
| 数值一直是 0 | 传感器未接电 / 复合线没连 / 通道偏移 1 位 | 用 dump 打印原始 `GN(i)` |
| 屏幕空白 | 显示器未接复合 / 脚本方块未连到显示器 | 检查复合线 |
| 屏幕有内容但错位 | `screen.getWidth()` 与预期不符；或用了硬编码尺寸 | 一律用 `getWidth/getHeight`，别硬编码 |
| 保存时报「too many characters」 | 超 8192 | 见 `01` §2/§3 |
| 中文字符相关报错 | 源码含非 ASCII | 见 `05` §6 |

## §5 交付自检清单（写完逐条打勾）

- [ ] **对象正确**：脚本 Lua，未出现 `server.*` / `g_savedata`。
- [ ] **纯 ASCII**：源码无中文、无全角标点（中文说明只能放在注释外或属性里）。
- [ ] **字符数 ≤ 8192**：已在编辑器里用语法检查确认。
- [ ] **单位正确**：传感器角度全部 ×2π / ÷2π 处理过；屏幕 Y 向下已考虑。
- [ ] **多返回值**：`f(g())` 形式已改成 `f((g()))`（`00_速查 §11`）。
- [ ] **表安全**：用到 `#` / `ipairs` 的表是从 1 起始的连续表（`00_速查 §6`）。
- [ ] **输出写满**：所有用到的输出通道每 tick 都有赋值（含默认值）。
- [ ] **状态同步**：跨 tick 状态若需联机一致，已走复合回环 / Memory。
- [ ] **术语查表**：中文专有名词已查 `汉化相关/` 对照表（部件名、UI、信号名）。
- [ ] **通道表**：代码顶部有通道映射注释，与实际接线一致。
