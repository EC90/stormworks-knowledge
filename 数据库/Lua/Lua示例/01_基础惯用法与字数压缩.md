## §2 字数压缩（8192 上限逼出来的惯用法）

### 2.1 起手别名化（**3 次以上使用的调用都值得压**）

```lua
-- IO（放 onTick 之前）
I,O=input,output
GN,GB=I.getNumber,I.getBool
SN,SB=O.setNumber,O.setBool

-- 属性
P=property
PN,PB,PT=P.getNumber,P.getBool,P.getText

-- 屏幕（BKN 版，一次压完）
S=screen
Text,TextBox,Color,Line,RectF,Rect,Circle,CircleF,Triangle,TriangleF
  =S.drawText,S.drawTextBox,S.setColor,S.drawLine,S.drawRectF,S.drawRect,
   S.drawCircle,S.drawCircleF,S.drawTriangle,S.drawTriangleF
w,h=S.getWidth(),S.getHeight()

-- 数学
m=math; sin,cos,abs,pi=m.sin,m.cos,m.abs,m.pi
```

> ⚠ `w,h=S.getWidth(),S.getHeight()` **必须在 `onDraw` 内部取**，写在文件顶层会拿到 0（屏幕尺寸在绘制时才确定）。
> BKN 原稿把它放在顶层别名区，若整段复制会出问题——**只抄函数别名，尺寸那行放进 `onDraw`**。

### 2.2 变量名压成单字母

按出现频率压成 `a,b,c…`。若想保留可读性，用「功能首字母 + 编号」如 `ER1,ER2`（Engine RPS 1/2）。

### 2.3 省字符的其他点

- 注释用 `--` 而非 `--[[ ]]`（后者合法但占字符）。
- 空格能省就省：`x=x+1` 而非 `x = x + 1`（交给压缩工具更稳）。
- `then/end` 单行块：`if x<0 then x=0 end`。

> **推荐流程**：开发期用全名 + 完整缩进 → 定稿后交给 PonyIDE 的 **Minify** 按钮压缩 → **点左下角语法检查**确认没压错（去空格后最易漏运算符/括号）→ 另存未压缩版备用。

## §3 🔥 最强手段：把大表搬进 `property.getText`

**这比变量名缩写有效得多**——字模表、配色表、航点表全部外置，脚本源码只留解析循环，
**8192 上限几乎不再是约束**。

```lua
-- 属性文本里存："0D0C0CFAF2F4B2D6F50C0..."
FONT=PT("FONT1")..PT("FONT2")
FONT_D={} FONT_S=0
for n in FONT:gmatch("....") do
  FONT_D[FONT_S+1]=tonumber(n,16) FONT_S=FONT_S+1
end
```

配色表同理（数字 +111 后三位切分，避免前导零被吞）：

```lua
-- 属性文本："111111366222111..."  ->  每 3 位一个通道，值 = num-111
for num in PT("MapColor1"):gmatch("%d%d%d") do M[#M+1]=num-111 end
```

**动态选择属性**（用一个数字属性当索引，切换整套预设）：

```lua
local idx = PN("Scheme")        -- 例如返回 2
local txt = PT(idx)             -- 读取标签为 "2" 的文本属性
```

> ⚠ `property.getText` 的标签参数**区分大小写**，必须与微控里属性方块的标签**完全一致**。
> 实测于 steam id 2774712393（Zizo Transponder Locator，2023-11-26）。

### 3.1 配色表：定宽切片 vs `#RRGGBB` 十六进制

两种都实测于工坊，配色**多组**用前者（一个属性存 N 组），**单组**用后者（用户可直接贴设计软件里的色值）。

```lua
-- ① 定宽切片：一个属性文本存 5 组配色，格式 "RRR GGG BBB"（每组各占 3 位、空格分隔）
--    属性标签按顺序命名 Color Code 1..5，用数字索引拼标签名批量读
function onTick()
  l = not input.getBool(31)
  _ = {{},{},{},{},{}}
  for f = 1, 5 do
    i = property.getText("Color Code " .. tostring(math.floor(f)))
    _[f].g, _[f].b, _[f].e = tonumber(k(i,1,3)), tonumber(k(i,5,7)), tonumber(k(i,9,11))
  end                                   -- k = string.sub，见 §2.1 别名化
end

-- ② #RRGGBB：tonumber 支持 "0x" 前缀，属性里直接填 #RRGGBB
function hex2rgb(hex)
  hex = hex:gsub("#", "")
  return {r = tonumber("0x"..hex:sub(1,2)),
          g = tonumber("0x"..hex:sub(3,4)),
          b = tonumber("0x"..hex:sub(5,6))}
end
C = hex2rgb(property.getText("Bars Color (Hex)"))
```

**要点**

- 定宽切片靠**位置**取值（1-3 / 5-7 / 9-11），所以每组必须**正好 3 位**，`016` 不能写成 `16`；
  作者在属性默认值里就写成 `255 000 128` 这种形式，改的时候别省前导零。
- 上面这段是 **LifeBoatAPI（VSCode 插件）Minify 后的产物**：`property`→`h`、`screen`→`j`、
  `string.sub`→`k`、局部变量全变单字母。头注释里保留了原作者写的
  `Minimized Size: 535 (885 with comment) chars`——**压缩后字符数是作者自觉记录的**，见 §4.1。
- 十六进制那条依赖 `tonumber("0x..")`，**只在标准 Lua 5.3+ 语法下成立**（SW 用它），
  写死的十以内数值别混进来。
- 与 `05` §6.3 的地图配色表对照：那里是把 8 组 24 通道塞进**数字**属性（每 3 位一组、+111 偏移防吞零），
  本例是把少量通道塞进**文本**属性——通道多到上百个时数字属性更省，几组配色用文本更直观。
- 完整脚本：`../../../AI相关/_提取暂存/_new/3792899963_vehicle_11.lua`（定宽切片）
  / `../../../AI相关/_提取暂存/_new/3793581819_vehicle_30.lua`（`#RRGGBB`，与已收录的
  `2623064051_vehicle_0.lua` 完全同源码，是同一模块的再分发）

## §4 读取被 Minify 压缩的代码（工坊下载物必备）

### 4.1 识别压缩态

| 特征 | 说明 |
| --- | --- |
| 单行 / 极少行，`;` 作语句分隔 | 结构被压平 |
| 几乎无空格、无注释 | 可读性被剥离 |
| 局部变量是 `a` `b` `c` | **原名已永久丢失** |
| `onTick` / `onDraw` / `httpReply` **一定保留原名** | PonyIDE 硬编码不改这三个回调名 —— **先靠它们定位入口** |

### 4.2 先反压缩再读（结构可 100% 恢复）

本工作区已备好反压缩脚本：

```bash
PY="<PY>"
"$PY" "<WS>/AI相关/_scripts/unminify.py" \
      "<WS>/AI相关/_提取暂存/<file>.lua" \
      -o "<WS>/AI相关/_提取暂存/_readable/<file>.lua"
```

做的事：`;` → 换行、在 `function/if/for/while/local/return/else/end` 等关键字边界断行、按 `then/do/function/end` 缩进。
**字符串字面量与注释受保护**，不会被误断行。

### 4.3 变量名有损 —— 只能按语义重命名

- **Conservative 模式不保存原名映射**，原名永久丢失；
- **Agressive 模式**可能在 `--yyy--` 后内嵌 `短名=原名;` 映射（作者若保留则可还原）；
- 因此 `a=GN(1)` 只能**读代码理解用途后自己改名**。

> `06` §2（自适应巡航）就是「反压缩 + 语义改名」的成品，可与 `AI相关/_提取暂存/3687286349_microcontroller_0.lua` 的原始单行 blob 对照看。

## §5 多人同步红线（哪些写法不能直接用）

来自日文例文集的明确警告 + `00_速查 §15`：

**凡是靠脚本级变量记忆状态的写法，在 server / client 各跑一份且互不共享 → 一定会分叉。**
典型案例：`toggle` 自锁、tick 累加计时器、PID 的积分项、状态机的当前态、滤波器的历史值。

**三种解法**

| 方案 | 做法 | 适用 |
| --- | --- | --- |
| ① 复合回环 | 状态经 `output` 写出，再由自身 `input` 读回 | 单机/联机都稳，最常用 |
| ② Memory 方块 | 状态存 Memory 寄存器 | 少量布尔/数值状态 |
| ③ 挪到附加 Lua | 用 `g_savedata` 持久化 | 关卡级、跨会话的状态 |

```lua
-- ① 复合回环示例：toggle 状态走 N31 写出、N32 读回
function onTick()
  local btn   = GB(1)
  local state = GN(32) > 0.5        -- 上一 tick 自己写出的状态
  if btn and not prev then state = not state end
  prev = btn
  SN(31, state and 1 or 0)          -- 写出，外部把 N31 接回 N32
end
```

> ⚠ 另外：**`math.random` 两端不一致**（`00_速查 §1`）。联机随机要用**基于 tick 的确定性伪随机**：
> ```lua
> function rnd(seed) local x=math.sin(seed*127.1+tickCount*311.7)*43758.5453 return x-math.floor(x) end
> ```

## §6 Bool 切数值（三項演算子もどき）

Lua 没有 `?:`，用 `and/or` 在单行里按 Bool 选值（比 `if` 省字符）：

```lua
A=true; n1,n2=100,200
B=A and n1 or n2        -- A=true -> n1 ; false -> n2
```

> ⚠ **仅当 `n1` 永不为 `false`/`nil` 时等价。** 若 `n1` 可能是假值（比如它是 `GN(1)` 返回的 0 之外的假值，或可能是 `nil`），
> 必须用完整 `if` 或显式判断，否则会静默取到 `n2`。
> **写布尔到数值时惯用** `SN(1, flag and 1 or 0)`。

---
- 变体注记（夜轨补）：来源：steam id **2039963097**（`_v0`：`round(n) = n%1>=0.5 and ceil or floor` 三元版 round——54 分）。

## §7 批量 32 通道 IO

脚本方块有 **32 数字 + 32 布尔**输入，以及同样数量的输出。一次性搬运后再处理：

```lua
B,N={},{}
function onTick()
  for c=1,32 do B[c]=GB(c); N[c]=GN(c) end
  -- 在此处理 N[1..32] / B[1..32]
  for c=1,32 do SB(c,B[c]); SN(c,N[c]) end
end
```

> ⚠ `#N` / `ipairs` 只对「从 1 起始的连续表」安全。这里 `N` 是预填充的连续数字表，可用。
> 稀疏表或字符串键表必须改用 `pairs` + 计数器（`00_速查 §6`）。
>
> ⚠ 若只用了前 8 路，**循环写成 `for c=1,8`**——刷满 32 路是纯浪费（onTick 有 16ms 预算）。

## §9 ⚠ 多重赋值多余的值会被**静默丢弃**（工坊实测隐蔽 bug）

- 来源：steam id 3794762394（雷达多目标 HUD，独立微控，2026-09-01）
- 亮点：一个不报错、不影响运行、只让配色悄悄变错的 Lua 语义陷阱

作者想把 7 种颜色写成 RGB 三元组，于是写下：

```lua
red=255,0,0
green=0,255,0
blue=0,0,255
purple=128,128,0
yellow=0,128,128
```

Lua 中 `a = 1,2,3` 是**合法**赋值：等号右侧是表达式列表，**多出来的值被丢弃**。
所以实际结果全是标量：

```lua
red=255    -- 后面的 0,0 直接扔掉
green=0    -- 后面的 255,0 扔掉，本该是纯绿，结果拿到 0
blue=0
purple=128
yellow=0
```

后续 `screen.setColor(red, green, blue)` 只有第一个分量有效，7 种"配色"退化成几个灰度值，
画面看不出明显异常（都是暗色），但**永远不会报错**。

**正确写法只有两种**

```lua
-- ① 表：可以整体传递、也能塞进配色方案表（推荐）
red = {255,0,0}
screen.setColor(red[1], red[2], red[3])

-- ② 平行变量：变量名会长，但省一次表索引
redR, redG, redB = 255, 0, 0
```

**自检判据**：看到 `x = a,b,c` 这种「单个变量接多个值」的写法，一定是写错了——
要么补上左侧的变量列表，要么改成表。

关联：`../lua总体设定/00_速查_SW_Lua与常规Lua差异.md` §13（语法与调试差异）

## §10 把大批量数值常量塞进属性文本：base64 → float32 流式解码

- 来源：steam id **2793934450** · 描述页 <https://steamcommunity.com/sharedfiles/filedetails/?id=2793934450> · **载具**（`_vehicle_2`，3D 渲染屏的数据加载段）
- 更新时间：未取到（本轮 Steam Web API 不可达，下轮补）
- 用到：属性文本（`b64` 基数表、`v1`…`vn` 顶点流、`t1`… 面索引流、`c1`… 颜色流）、显示器
- 亮点：**突破 8192 字符预算存大常量**——顶点坐标、三角面索引、面颜色全部编码成 base64 字符串放进若干个属性文本框，加载时一次性解码成 Lua 表。本例用它喂 `05` §40 的 3D 渲染器。

> 脚本方块的 8192 字符上限装不下几百个顶点坐标；属性文本**不计入脚本长度**。把常量编码成字符串存进属性，是「常量多到写不下」时的通用解法。

```lua
local B64 = property.getText("b64")          -- 64 字符的基数表，下标即 6 bit 值

-- ① 每 6 个 base64 字符解出 1 个 float32
local function b64ToFloat(s)
  local n = 0
  for i = 1, 6 do
    n = n | ((B64:find(s:sub(i, i), 1, true) - 1) * 2 ^ ((6 - i) * 6))
  end
  return (string.unpack("f", string.pack("I", n)))   -- 按 64 位整数打包，取低 32 位当 float32 读
end

-- ② 把 v1 / v2 / … 一串属性文本读成「每组 stride 个 float」的二维数组
local function readStream(prefix, stride)
  local out, row, col, idx = {}, 1, 1, 0
  repeat
    idx = idx + 1
    local txt = property.getText(prefix .. idx)
    for chunk in txt:gmatch("......") do             -- 每 6 字符一段
      out[row] = out[row] or {}
      out[row][col] = b64ToFloat(chunk)
      col = col + 1
      if col > stride then row, col = row + 1, 1 end
    end
  until txt == ""                                    -- 🔑 读到空属性即停，不用另存「共几条」
  return out
end

-- ③ 加载期一次性解码，不进 onTick / onDraw
local verts  = readStream("v", 3)      -- 顶点：x, y, z
local faces  = readStream("t", 3)      -- 三角面：三个顶点下标
local colors = readStream("c", 3)      -- 面颜色：r, g, b
-- 面表里带上颜色，绘制时直接 F[5], F[6], F[7] 取用（见 05 §40）
for i = 1, #faces do
  faces[i][4], faces[i][5], faces[i][6], faces[i][7] =
    0, colors[i][1], colors[i][2], colors[i][3]
end
```

**要点**

- **编码密度**：1 个 float32 = 6 个 base64 字符 = 6 字节文本。一条属性文本按 512 字符算能装约 85 个 float（约 28 个顶点）；本例用 `v1/v2/…` 多条属性串联，`repeat until txt == ""` 自动在遇到空属性时收尾。
- ⚠ **36 bit 打包只取低 32 bit**：6 字符 × 6 bit = 36 bit，但 `string.unpack("f", …)` 只读前 4 字节，最高 4 bit 被静默丢弃——**每个 float 白扔 2/3 个字符**。若要更省，可改成 6 字符装两个 18 bit 定点数（例如 `x*1000` 的定点，量程 ±145），密度翻倍。原脚本这里没优化。
- ⚠ **`string.find` 默认是模式匹配**：基数表里若含 `. % ( ) [ ] * + - ? ^ $` 会被当元字符，`.` 甚至会匹配任意字符导致解出错误的值。稳妥写法是 `B64:find(c, 1, true)`（第三个参数 `true` = 纯文本查找），上面的代码已改成这种写法。
- ⚠ **半角 `<` 红线**：源码里若写成 `n << 30`，在 `vehicle.xml` 里必须转义成 `&lt;&lt;`，否则 XML 解析直接崩。上面的代码改用 `* 2^k`，既绕开红线又不损失可读性（乘法在加载期只跑一次，性能无差别）。
- **解码只跑一次**：`readStream` 写在全局区（函数体外的顶层），只在 MC 加载/重置时执行一次，不占每帧预算。⚠ 若放在 `onTick` 里会每帧重解几千个字符串，必卡死。
- **终止符技巧**：用「遇到空属性文本就停」代替单独存一个「共 N 条」的常量，省字符也省一个属性槽；代价是属性编号必须连续，中间不能有空洞（否则提前收尾，后面的数据静默丢失）。
- **什么时候不该用**：常量少于 20~30 个时，直接写字面量更短也更易改（`local V = {1,0,0, 0,1,0, …}`）。编码流的收益来自规模——顶点上百、或者需要让用户在不改脚本的情况下换模型时，才值得上这套。
- 关联：`05` §40（本例数据的消费方：3D 渲染管线）、`03` §18 / `05` §35（同类思路：把 16 进制 ROM 字模存进属性文本）、`01` §5（属性文本的其它用法）。
- 完整脚本：`../../../AI相关/_提取暂存/2793934450_vehicle_2.lua`

## §12 属性**哨兵值**编码 + 一次性随机锁存（车牌生成器）

来源：steam id **3794954536** · <https://steamcommunity.com/sharedfiles/filedetails/?id=3794954536> · **载具**（FL ST500 FW）· 更新时间 **2026-09-04**

一个属性数值框通常只存一个数。本例让它**兼存「指令」**：约定 -1~-5 是哨兵值，分别表示「这一位留空」「这一位按区间随机」……于是玩家不用改脚本就能配置车牌格式。配套的另一个关键是**随机只做一次**——`math.random` 每 tick 都变，不锁存的话屏幕上七个数字会一直乱跳。

**用到**：属性数值 ×7（每位的取值或哨兵）、属性数值 ×2 ×7（随机区间上下界）、数字输出 7 路、屏幕

**亮点**：① **哨兵值把属性从「数据」升级成「指令」**；② `ticked` **一次性锁存**，只对 `math.random` 采一次样；③ 数值→字符映射 `10~35 → A~Z`；④ 文末附一块写坏了的同款脚本（锁存条件永假）当反面教材。

```lua
-- ① 哨兵值约定：-2 = 按该位的自定义区间随机，-3/-4/-5 = 三种预设区间，-1 = 空格，其余 = 定值
pm = {"-2", "-2", "-2", "-2", "-2", "-2", "-2"}    -- 属性文本取出来是字符串，要 tonumber
r1 = {10, 10, 0, 0, 10, 10, 10}                    -- 每位随机区间下界
r2 = {35, 35, 9, 9, 35, 35, 35}                    -- 上界

for i, pms in ipairs(pm) do
  local v = tonumber(pms)
  if     v == -2 then on[i] = math.random(r1[i], r2[i])   -- 用自定义区间
  elseif v == -3 then on[i] = math.random(0, 9)           -- 纯数字位
  elseif v == -4 then on[i] = math.random(10, 35)         -- 纯字母位
  elseif v == -5 then on[i] = math.random(0, 35)          -- 任意
  else                on[i] = v end                        -- 定值，照抄
end
```

```lua
-- ② 🔑 一次性锁存：math.random 每 tick 都不同，不锁的话车牌每帧都在变
ticked = false
function onTick()
  if not ticked then
    for i = 1, 7 do output.setNumber(i, on[i]) end
    nplate = Gen(on[1]) .. " " .. Gen(on[2]) .. " " .. Gen(on[3]) .. " " .. Gen(on[4])
             .. "   " .. Gen(on[5]) .. " " .. Gen(on[6]) .. " " .. Gen(on[7])
    ticked = true                       -- 🔑 只跑一次，之后 onTick 直接空转
  end
end
```

```lua
-- ③ 数值 → 字符：-1 空格 / 0~9 数字 / 10~35 字母
--    原脚本用 26 行 elseif 逐个写死（可读但占字符）；下面这行是等价压缩版
function Gen(s)
  if     s == -1            then return " "
  elseif s >= 10 and s <= 35 then return string.char(s + 55)   -- 10 → 65 → 'A'
  else                           return math.floor(s) end
end
```

- ⚠ **反面教材（同一辆车的另一块脚本）**：作者想先采样 100 拍再锁存，写成了

  ```lua
  if not ticked and count < 100 then     -- ❌ 外层把 count 卡在 100 以内
    count = count + 1
    ...
    if count > 1000 then ticked = true end   -- ❌ 内层却要 count 超过 1000 → 永假
  end
  ```

  两个条件分处内外层且互相矛盾，`ticked` 永远翻不了，车牌每 tick 重掷一次。**锁存条件必须和计数上限写在同一层判断里**，例如 `if not ticked then ... count = count + 1; if count >= 100 then ticked = true end end`。

- 🔑 **哨兵值的取值要避开合法数据域**。本例合法数据是 0~35，哨兵取 -1~-5 才安全；若某属性的合法域本身包含负数，就得改用「超出上界的怪值」（如 999）或另开一个布尔属性当模式开关。
- ⚠ `math.random` 在 SW 里**服务端与客户端各自独立**（`00_速查` 多人同步那条），所以这种随机车牌每人看到的都不一样——用在本车车牌上无所谓，用在「全服统一的随机事件」上就会不同步。
- 关联：`01` §3（把大表搬进属性文本）/ `01` §9（多重赋值多余值被静默丢弃）/ `05` §43（同样是「生成一次就不再变」的字符串）

## §13 「圈」时间 → `hh:mm:ss` 三级分解 + 命名键调色板表 + `#` 与 `pairs` 的口径差

- 来源：steam id **3793679025** · 描述页 <https://steamcommunity.com/sharedfiles/filedetails/?id=3793679025> · **载具**（`_vehicle_4` 视频切换 + 彩条测试图）
- 更新时间：未取到（本轮 Steam Web API 不可达）
- 用到：复合数值 1（一天中的时刻，**圈**，0..1）、复合布尔 1~6（摄像头选择）、属性（切换延迟、两行频道名）、屏幕
- 亮点：游戏给的 `input.getNumber` 时间是**一天的圈数**（0..1），作者用「逐级减掉已取出的大单位再乘 60」把它拆成时分秒，避免了大系数连乘的浮点误差。同一脚本里的 `Color()` / `presets` 调色板表也是一套值得抄的小骨架。

```lua
-- 🔑 输入是「一天的圈数」：0 = 0 点，0.5 = 正午
function onTick()
  clock  = input.getNumber(1)
  hour   = math.floor(clock*24) % 24
  minute = math.floor((clock*24 - hour)*60) % 60          -- 先减掉小时，再乘 60
  second = math.floor((clock*24*60 - minute)*60) % 60     -- 再减掉分钟
  clockString = leadingZeros(hour,2)..":"..leadingZeros(minute,2)..":"..leadingZeros(second,2)
end

function leadingZeros(number, totalLength)
  local s = tostring(number)
  local zeros = ""
  for i = 1, math.max(totalLength - #s, 0) do zeros = zeros.."0" end
  return zeros..s
end

-- 🔑 命名键表做调色板：一处定义、整表传参、一次解包
function Color(red, green, blue) return {red=red, green=green, blue=blue} end
presets = { black = Color(0,0,0), white = Color(255,255,255), light = Color(55,55,55),
            dark  = Color(25,25,25), red = Color(255,0,0), green = Color(0,255,0),
            blue  = Color(0,0,255), yellow = Color(255,255,0), cyan = Color(0,255,255) }

function lengthTable(theTable)
  local count = 0
  for _ in pairs(theTable) do count = count + 1 end      -- ⚠ 用 pairs，不用 #
  return count
end

function onDraw()
  function setColor(c) screen.setColor(c.red, c.green, c.blue) end
  -- 🔑 彩条：整表传进去，按元素个数均分宽度
  function drawBars(y, height, colors)
    local width = w / lengthTable(colors)
    for i, color in ipairs(colors) do
      setColor(color)
      screen.drawRectF(math.floor((i-1)*width), y, math.ceil(width), height)
    end
  end
  drawBars(0, h*2/3, {presets.light, presets.blue, presets.red, presets.magenta,
                      presets.green, presets.cyan, presets.yellow})
end
```

- 🔑 **逐级相减，别一次连乘**：`second` 直接写成 `floor(clock*86400) % 60` 会让 `clock` 的浮点误差放大 86400 倍（一天的圈数精度只有约 1e-7，乘完就是 ±0.0086 s，看着没事，但分钟进位边界上会闪）。先减掉已取整的大单位，误差就锁在当前这一级。
- 🔑 **命名键表做调色板**：`presets.red` 比 `setColor(255,0,0)` 好维护，且能整表传给 `drawBars` 之类的通用函数。配色改动只动一处。
- ⚠ **`#` 与 `pairs` 计数口径不同**：`#t` 只数**连续整数键**部分，对 `{black=…, white=…}` 这种命名键表返回 **0**；`pairs` 循环计数返回真实元素个数。本脚本的 `colors` 其实是数组（`#` 也能用），但作者统一用 `lengthTable` 是为了对 `presets` 同样有效。**别在同一个项目里混用两种口径**。
- ⚠ **手写 `leadingZeros` 通常不如 `string.format("%02d", n)`**：后者一行搞定、更短、也不会拼错。`leadingZeros` 的价值只在于处理「位数可能超过格式化宽度」或需要在非数字上下文补零的场景；常规补零直接用 `string.format`。
- ⚠ `drawBars` 里 `math.floor((i-1)*width)` + `math.ceil(width)` 是**防缝隙**的标准写法：直接用 `i*width` 会因取整在色块之间留 1 px 背景色。
- 关联：`01` §12（属性哨兵值编码，同样是把多个量塞进一个数的思路）/ `02` §11（同一脚本的摄像头切换栈）/ `05` §45（手写渐变调色板）/ `00_速查 §4`（圈 ↔ 秒的换算）

## §14 `2^k - 1` 位掩码：一条数字通道带 N 段指示 + 一行任意步长取整
- 来源：steam id 3793044670 · 描述页 https://steamcommunity.com/sharedfiles/filedetails/?id=3793044670 · 载具
- 更新时间：未取到（未被价值轨榜单收录，Steam Web API 未返回元数据）
- 用到：负载 / 电量 0~1 的百分比读数 + 一路数字输出
- 亮点：用 `2^k - 1` 把「百分比」编成「低 k 位全 1」，**一条通道就带走了 8 段 LED**；
  配套的 `round(x, y)` 是任意步长的四舍五入

```lua
-- ① 四舍五入到 y 的任意整数倍（round(x,1) 就是普通四舍五入）
function round(x, y)
    return y * math.floor((x + y/2) / y)
end

-- ② 0~1 的百分比 → N 段指示的位掩码（低 k 位全 1）
local N = 8
sn(5,  (2^round(N * gn(13), 1)) - 1)     -- 负载：0.5 → 2^4-1 = 15 = 0b00001111
sn(10, (2^round(N * gn(17), 1)) - 1)     -- 电量：同一套写法再抄一遍
-- 下游取第 i 段（0 起）：(mask >> i) & 1
```

- 🔑 **`2^k - 1` 一行生成「低 k 位全 1」**：k=1→`1`、k=3→`7`、k=8→`255`。
  下游只要 `(mask >> i) & 1` 就能点亮第 i 段，**比传 N 路 Bool 省下 N-1 条通道**。
  这是「一条数字通道当 N 路开关」最省事的编码。
- 🔑 **与 `07` §11 的十进制位打包分工不同**：那个能在一串数字里塞**不同含义**的位（频率 / 可见 / 方位），
  本例只传**连续 N 段**（进度条、环形指示、电量格）。语义是「从最低位往上涨」时用 `2^k-1` 就够了。
- 🔑 `round(x, y)` 写成 `y*floor((x+y/2)/y)` 而不是 `floor(x/y+0.5)*y`——两者等价，
  但前者在 `y` 是小数时更稳，且**改步长只改一个参数**：`y=2` 就是「只亮偶数段」。
- ⚠ `2^k` 在 Lua 5.3 里是浮点运算，`k` 超过 53 会丢精度。SW 场景 k 通常 ≤ 20，安全；
  真要 32 段就改用两次 16 位拼接。
- ⚠ **掩码方向要上下游约定一致**：`2^k-1` 是「最低位为第一段」。想让指示从高位往下降，
  要么下游反着取位，要么发 `mask ~ (2^N-1)`（Lua 5.3 的按位异或；**不是** `~mask` 取反）。
- ⚠ `round(N*load, 1)` 里的 `1` 是步长参数，等于 `floor(N*load + 0.5)`；
  直接写 `round(N*load)` 会拿到 `y = nil` 而报算术错——**这个函数没有默认参数**。
- 关联：`01` §12（属性哨兵值编码，同一个数值框兼存「指令」）/ `07` §11（十进制位打包布尔）/
  `05` §50（3×5 字模的 15 bit 单整数编码）/ `09` §29（分段圆环仪表，本节掩码的另一种消费方式）/
  `00_速查 §13`（8192 字符上限）

## §15 一个数值当两个用：**属性滑块拆宽高** + **基准值/单次偏移让按住只走一格**

- 来源：steam id 3796799293 · 描述页 https://steamcommunity.com/sharedfiles/filedetails/?id=3796799293 · 载具（Liffey Class SAR Vessel，`_vehicle_2` 面板 / `_vehicle_8` 电台）
- 更新时间：2026-09-06
- 用到：属性滑块 `Display`、触控屏、无线电（信道 1~88）
- 亮点：两个「省一个变量」的小手法——① 单个属性滑块的**整数段/小数段**分别当屏幕高与宽；② 频率 +/- 用**基准值 + 单次偏移**重算，按住不连发、必须松手再按。

```lua
-- ① 属性滑块 "Display"：整数段 = 高 h，小数段（定长三位）= 宽 w
h  = math.floor(property.getNumber("Display"))      -- 32.096 -> h = 32
w  = (property.getNumber("Display") - h) * 1000      --         -> w = 96
cx, cy = w/2, h/2
```

```lua
-- ② 频率 +/-：freq 是当前值，freqb 是「已经确认的基准」
freq, freqb = 16, 16
function onDraw()
  w, h = screen.getWidth(), screen.getHeight()
  p, x, y = input.getBool(1), input.getNumber(3), input.getNumber(4)
  if y > 24 then
    if x < 8 and p then                    -- 按左半（减）
      screen.drawRectF(0, 25, 8, 10)
      if freq > 1  then freq = freqb - 1 end
    elseif x > 8 and x < 16 and p then     -- 按右半（加）
      screen.drawRectF(9, 25, 8, 10)
      if freq < 88 then freq = freqb + 1 end
    else
      freqb = freq                         -- 🔑 松手（或点在别处）才把新值固定成基准
    end
  end
end
```

- 🔑 **为什么按住不连发**：触控屏的 `p` 是**按住**状态，一次触摸会持续几十帧（见 `02` 序）。直接 `freq = freq - 1` 会按住瞬间跳到底。作者的写法是**每帧都从同一个基准重算**，按住期间 `freq` 恒等于 `freqb ± 1`，必须松手再按才走第二格。与 `02` §8（点动 + 长按连发）、`05` §57（首触发延迟后连发）、`05` §49（按住连发）是**相反的选择**——读数精确但调整慢，适合频率这种必须落在整数信道上的量。
- 🔑 **零状态**是这套写法的第二个好处：不需要「上一帧是否按住」的边沿变量，`p` 直接参与重算。代价是 `freqb` 的更新必须放在能覆盖「没按」与「按在别的按钮上」两种情况的 `else` 里。
- 🔑 **属性拆宽高**的动机：屏幕只有 1×1 / 2×1 / 3×2 等固定比例，一个滑块（整数段高、小数段宽）让玩家**一次拖动换型号**，不必维护两个滑块、也不用怕两者组合出非法比例。
- ⚠ **小数段必须写成定长三位**：`0.096` 而不是 `0.96`。后者 `*1000` 得到 960，宽高直接离谱；而 `0.096` 与 `0.0960` 等价，属性框里补零无害。
- ⚠ `math.floor` 对负数不是「向下取整」的语义直觉（`-3.2 → -4`），属性值别设成负数。
- ⚠ **整段在 `onDraw` 里改状态**。`freq = freqb ± 1` 是**幂等**的（每帧算出同一个值），重复调用不会累积，所以放 `onDraw` 反而安全；但 `freqb = freq` 不幂等。真要搬进 `onTick`，务必保留「按钮分支幂等、`else` 分支只跑一次」的结构，否则一帧内 `else` 先执行会把还没生效的旧值固定住。
- ⚠ 上限写死 `88`（`if freq < 88`）：SW 无线电信道是 1~88 的整数，超了会被游戏钳位。
