## §1 Lua 键盘协议位解析（一个数字同时传坐标与字符）

- 来源：steam id **2659444728** · <https://steamcommunity.com/sharedfiles/filedetails/?id=2659444728> · **载具**（Lua Keyboard）
- 更新时间：**2022-04-29**
- 用到：键盘微控、显示器、复合通道 31/32
- 亮点：**键盘把「点击事件」和「字符」打包进同一个数字**，用位运算解出；作者给出了完整位布局注释，是协议级的可靠范例。

```lua
-- bit 1      = type (1 = 点击/触摸, 0 = 字符)
-- bit 2      = 键盘是否已弹出
-- type == true（点击）:
--   bits 3-13  = x (11 bit, 0..2047)
--   bits 14-24 = y (11 bit, 0..2047)
-- type == false（字符）:
--   bits 2-8   = charcode (7 bit ASCII)
function parseKeyboard(numb)
  local fl   = math.floor(numb)                       -- 必须先取整：位移对浮点不可靠
  local typ  = (numb & 1) == 1                        -- SW Lua 5.3：原生 & >> <<
  local shown= (numb & 2) == 2
  local ret  = {type=typ, keyboardShown=shown, click=false, x=0, y=0, key=0, char=""}

  if typ then
    ret.click = true
    ret.x = (fl >> 2)  & 2047                         -- >>2 跳过 type+shown，掩码 11 bit
    ret.y = (fl >> 13) & 2047
  else
    local charc = (fl >> 2) & 127                     -- 7 bit ASCII
    ret.key = charc
    if charc > 31 and charc < 127 then
      ret.char = string.char(charc)                   -- 可打印字符
    elseif charc == 4 then   ret.CONFIRM = true       -- 确认
    elseif charc == 127 then ret.DEL     = true end   -- 退格
  end
  return ret
end

message = ""
function onTick()
  local k = parseKeyboard(GN(31))
  SB(31,false) SB(32,false)                           -- 默认不请求（形成脉冲）

  if k.click and not k.keyboardShown then
    if inRect(k, buttonOpen)  then SB(31,true) end    -- 请求打开键盘
    if inRect(k, buttonClose) then SB(32,true) end    -- 请求关闭
  end
  if k.DEL then
    message = string.sub(message, 1, string.len(message)-1)
  elseif k.char then
    message = message .. k.char
  end
end
```

**要点**
- SW 的 Lua 是 **5.3+**，原生支持 `& | ~ << >>`，**不需要 bit32 库**——这是位打包的前提。
- `math.floor()` 必须先做：`>>` 对浮点数行为不可靠。
- 同一通道既传坐标又传字符，靠 **bit 1 区分**——复合通道数量有限，这是非常珍贵的做法。
- 「打开/关闭键盘」是**请求式**的：拉高后由键盘微控响应，脚本每 tick 默认拉低 → 形成脉冲。
- 该作品自带可直接复用的键盘微控，**把 `parseKeyboard` 抄进自己的脚本就获得全 ASCII 输入**。

## §2 无线电多目标跟踪（平行表 + 过期剔除）

- 来源：steam id **2046605849** · <https://steamcommunity.com/sharedfiles/filedetails/?id=2046605849> · **载具**（SR-71 Blackbird）
- 更新时间：**2021-03-12**
- 用到：无线电接收机、GPS 传感器、显示器
- 亮点：**8 张平行表同步维护多机档案**；前向轨迹预测；CLIMB/DESCEND 解脱建议；告警文字滚动闪烁。

### 2.1 档案维护

```lua
RATE=15 MAXD=600 Expiry=1500 MINALT=300
DC={} DX={} DY={} DA={} DD={} DS={} DV={} DE={}
-- 代号 / X / Y / 高度 / 航向 / 地速 / 升降率 / 存活 tick

function onTick()
  -- 本机状态（由「回波自身数据」通道周期性刷新）
  if GN(11)>0 and GB(30) then
    MY_DIR = math.atan(GN(13)-MY_Y, GN(12)-MY_X)                 -- atan(y=Δ北, x=Δ东)
    MY_GS  = math.sqrt((GN(13)-MY_Y)^2+(GN(12)-MY_X)^2)*60/MY_AGE
    MY_VS  = (GN(14)-MY_ALT)*60/MY_AGE
    MY_X,MY_Y,MY_ALT = GN(12),GN(13),GN(14)
    MY_AGE = 0
    MY_CODE= GN(11)
  end
  MY_AGE = MY_AGE + 1                                            -- 60 tick = 1 秒

  -- 他机：过期剔除（倒序遍历，安全）+ 命中更新
  for k=#DC,1,-1 do
    DE[k] = DE[k] + 1
    if DE[k] > Expiry then
      removeRecord(k)
    elseif DC[k] == GN(26) then                                  -- 同一代号 => 更新
      isEXIST = true
      DD[k] = math.atan(GN(23)-DY[k], GN(22)-DX[k])
      DS[k] = math.sqrt((GN(23)-DY[k])^2+(GN(22)-DX[k])^2)*60/DE[k]
      DV[k] = (GN(24)-DA[k])*60/DE[k]
      DX[k],DY[k],DA[k] = GN(22),GN(23),GN(24)
      DE[k] = 0
    end
  end

  -- 新目标：过滤地面目标（高度）与自己（代号）
  if not isEXIST and GN(26)>0 and GN(24)>MINALT and GN(26)~=MY_CODE then
    table.insert(DC, GN(26))
    table.insert(DX, GN(22)) table.insert(DY, GN(23)) table.insert(DA, GN(24))
    table.insert(DD,0) table.insert(DS,0) table.insert(DV,0) table.insert(DE,0)
  end
end

function removeRecord(k)
  table.remove(DC,k) table.remove(DX,k) table.remove(DY,k) table.remove(DA,k)
  table.remove(DD,k) table.remove(DS,k) table.remove(DV,k) table.remove(DE,k)
end
```

### 2.2 过期剔除的推荐写法：重建表（而不是 `table.remove`）

来源：steam id **3793328793**（Nordic VISION，2026 年）—— 雷达轨迹点老化。
这是 §2.1 里「`table.remove` 不安全」问题的**正面解法范例**：**遍历旧表，把存活元素拷进新表，最后整体替换**。

```lua
pointX, pointY, timeago = {}, {}, {}        -- 三张平行表：轨迹点坐标 + 存活 tick

function clean()
  local tempX, tempY, tempago = {}, {}, {}  -- 必须用 local，否则污染全局
  for i=1, #timeago do
    timeago[i] = timeago[i] + 1             -- 先老化
    if timeago[i] < 120 then                -- 存活阈值
      tempago[#tempago+1] = timeago[i]
      tempX  [#tempX+1]   = pointX[i]       -- 三表同步拷贝
      tempY  [#tempY+1]   = pointY[i]
    end
  end
  pointX, pointY, timeago = tempX, tempY, tempago   -- 整体替换
end
```

**为什么这样更好**
| 做法 | 评价 |
| --- | --- |
| `table.remove(t, k)` 在 `for/pairs` 里 | ❌ 下标前移，漏删或越界 |
| 倒序 `for k=#t,1,-1` | ✅ 正确，但只适合"删除"场景 |
| **重建表**（本例） | ✅ 最通用：过滤、变换、老化一次做完，且天然支持多表同步 |
| `pairs` 里置 `t[k]=nil` | ✅ 安全，但会留下空洞，`#t` 变得不可靠 |

> ⚠ **原稿有笔误**：`onDraw()` 里写的是 `timeago[#tempago+1] = 0`（用 `tempago` 的长度当 `timeago` 的索引），
> 应为 `timeago[#timeago+1] = 0`。抄的时候注意——这正是「重建表」写法最容易犯的错：
> **每张表的自增索引必须用自己表的长度**。
- 冲突检测用**时间步进 + 三维欧氏距离**。`RATE=15`（秒）是精度与算力的折中：600 秒 / 15 = 40 步 × 目标数。
- `MY_AGE` 记录距上次刷新的 tick 数，`*60/MY_AGE` 把「这段时间的位移」换算成 m/s。
- 过滤条件 `GN(24) > MINALT` 排除地面载具、`~= MY_CODE` 排除自己的回波 —— **做无线电共享时这两条缺一不可**。

### 2.3 TCAS 冲突预测（前向轨迹步进）

```lua
NEAREST = SENSE
for i = 0, MAXD, RATE do                        -- 未来 0..600 秒，步长 15 秒
  local X_CHK = MY_X + MY_GS*i*math.cos(MY_DIR)
  local Y_CHK = MY_Y + MY_GS*i*math.sin(MY_DIR)
  local A_CHK = MY_ALT + MY_VS*i
  for k=1,#DC do
    local TX = DX[k] + DS[k]*i*math.cos(DD[k])
    local TY = DY[k] + DS[k]*i*math.sin(DD[k])
    local TA = DA[k] + DV[k]*i
    local d  = math.sqrt((X_CHK-TX)^2 + (Y_CHK-TY)^2 + (A_CHK-TA)^2)
    if d < NEAREST then
      NEAREST = d; ALARM = true
      ADVICE = (MY_ALT>=DA[k] or A_CHK<=MINALT) and "CLIMB" or "DESCEND"
    end
  end
  if ALARM then break end                       -- 首个命中即停，省算力
end
```

**要点**
- 🔴 **原稿用 `table.remove` 写在 `pairs` 循环里，是风险做法**：删除会使后续 key 前移，导致跳过元素或越界。
  **安全写法是倒序 `for k=#DC,1,-1 do ... end`**（本例已改为倒序），或先收集待删下标再重建表。
  对比：`pairs` 里置 `t[k]=nil` 是**安全的**，`table.remove` 是**不安全的**（见 `02` §5）。
- **平行表（parallel arrays）** 是 SW 存多目标最常见的形态：8 张表下标对齐，插入/删除必须**八表同步**。
  更稳的写法是单表存 record（`{code=,x=,y=,...}`），但平行表在字符数紧张时更省。

## §3 UAV / 无人机群指挥数据链（ID 编码寻址 + 跳频 + 航点增删）

来源：steam id **3261800786** · <https://steamcommunity.com/sharedfiles/filedetails/?id=3261800786> · **载具**（ZTQ-15，脚本 `datalink3RcvRC&UAV`）——车长用数据链指挥无人机群：每架无人机靠**自身 ID 解码出是否在被指挥**，频率按 ID 偏移做**跳频**，航点/攻击/返航指令走复合通道的各位。

```lua
Rcv = {}                                            -- 收到的消息表
function onTick()
  if GN(1) ~= 0 then                                -- 收到一帧
    for i=1,#Rcv do if GN(1)==Rcv[i].id then j=i; break end end   -- 按消息自带 ID 查重/建档
    if j > #Rcv then Rcv[j] = {j={}, w={}} end
    Rcv[j].id = GN(1); Rcv[j].t = 0
    -- 自身 ID 编码在 GN(16) 的万位数字 → 命中说明「这帧是命令我的」
    if Mf(GN(16)/1e4) == selfID then
      slave = true; slavef = GN(1)
      if drone then                                  -- 无人机专属指令
        add = GB(29); del = GB(30); atk = GB(31); rtb = GB(7); cv = GB(8)
        wayx = GN(13); wayy = GN(14)
        wayz = Mf(GN(16)%1e2); wayr = Mf(GN(16)%1e4/1e2)   -- 航点坐标/半径藏在 GN(16) 各位
      end
    end
  end
  -- 跳频：被指挥时收听「指令方频率+其ID」，否则守自己频率
  if slave then rtf = freq + slavef
  elseif SLID~=0 and page==1 then rtf = freq + SLID
  else rtf = freq + selfID end
  vf = freq + selfID
end
```

**要点**
- **ID 编码寻址**：指挥方把 `selfID` 写进消息某几位（`Mf(GN(16)/1e4)`），接收方比对自身 ID 才知道「这帧是对我下的令」——比广播+过滤更省带宽。
- **跳频**：`rtf = freq + slavef`，每架无人机听不同偏移频率降低同频互扰；`vf`（发频）固定 `freq+selfID`。
- 航点坐标/半径**塞进一个复合数 GN(16) 的各位**（`%1e2`、`%1e4/1e2`）——又见「一个数字传多值」套路（`07` §1）。
- 指令用**边沿布尔**：`add/del/atk/rtb/cv` 各占一个通道位，接收端按需动作。
- 消息表 `Rcv` 按 `t>300` 过期剔除（重建表而非 `table.remove` 遍历中删，见 §2.2）。
- 完整脚本：`../../../AI相关/_提取暂存/3261800786_vehicle_10.lua`（配套 `..._vehicle_15.lua` 指挥地图 UI、`..._vehicle_6.lua` 目标类型符号）

## §4 移动单站三边交汇定位（静默信标）

- 来源：steam id **2774712393**（Zizo Transponder Locator）/ steam id **3664940456**（PYO's Transponder Locator，同功能新版）

只有一个测距通道（无方位）时，**自己边走边测**，把每个「站位+距离」记成一个圆，圆的交点就是信标：

```lua
-- 边走边采样：与上一站位拉开距离才记新圆（车速过快不采样，误差大）
if dist > 300 and valid and speed < max_speed then
  if not C[1] or length(C[#C].x, C[#C].y, gps_x, gps_y) > clamp(#C*5, 10, 200) then
    table.insert(C, {x=gps_x, y=gps_y, r=dist, e=speed+1})   -- e=误差权重
  end
end
-- 两个站位圆求交（三圆方程组代数解）
function findCircleIntersections(c1, c2, c3)
  local A = 2*(c2.x-c1.x)
  local B = 2*(c2.y-c1.y)
  local C = c1.r^2 - c2.r^2 - c1.x^2 + c2.x^2 - c1.y^2 + c2.y^2
  -- ... 联立求解交点
end
-- 多个交点按 1/误差 加权融合，再投影回最新一圈定唯一解
x, y = closestPointOnCircle(point.x/point.d, point.y/point.d, gps_x, gps_y, dist)
```

**要点**
- **采样间距自适应**：`clamp(#C*5,10,200)`——圆越多要求站位间隔越大，避免几何稀释精度（GDOP）恶化。
- 车速误差直接当权重（`e=speed+1`，慢=准），融合时 `1/e` 加权——**测得慢的样本更可信**。
- 两圆相交有两个解，加权融合后**投影回最新一圈**（`closestPointOnCircle`）消歧义，不用存历史假设。
- PYO 新版（3664940456）把同思路整理成 `solve_2_circles/solve_3_circles`，函数更通用，二选一即可。
- 完整脚本：`../../../AI相关/_提取暂存/2774712393_microcontroller_0.lua`、`.../3664940456_vehicle_0.lua`

## §7 数字通道**逐字符轮询**传字符串（定宽十进制拼接，不用位运算）

- 来源：steam id 3788946785 · 描述页 https://steamcommunity.com/sharedfiles/filedetails/?id=3788946785 · 载具（MV-24 倾转旋翼机※，`_vehicle_20`）
- 更新时间：2026-08-26
- 用到：属性文本（载具名）、属性滑块（武器参数）、2 个数字输出通道
- 亮点：SW 的复合信号**没有字符串类型**，本例用「**固定位宽十进制拼接**」把一串字符拆成每 tick 一个数字发出去，接收端按位数切回来——比 `07` §1 的位运算方案**更易调试**（数字肉眼可读）。

```lua
positionCharacter   = 1
positionWeaponData  = 1

function onTick()
  local name    = property.getText("Name")          -- 要广播的字符串（如载具呼号）
  local type    = property.getNumber("Type")
  local subtype = property.getNumber("Subtype")

  local weaponProperties = {
    property.getNumber("Radar FOV Launch Horizontal"),
    property.getNumber("Radar FOV Launch Vertical"),
    property.getNumber("Minimum Range (m)"),
    property.getNumber("Maximum Range (m)"),
  }

  -- ① 每 tick 只推进一个字符下标，循环播完整串
  positionCharacter = (positionCharacter % name:len()) + 1

  -- ② 字符 -> 3 位 ASCII 码；下标 -> 2 位（最多 99 字符）
  local asciiCharString = string.format("%03d", string.byte(name:sub(positionCharacter, positionCharacter)))
  local positionString  = string.format("%02d", positionCharacter)

  -- ③ 类型(1位) + 子类型(1位) + ASCII(3位) + 位置(2位) = 7 位定宽
  local typeString = tostring(math.floor(type)) .. tostring(math.floor(subtype))
  output.setNumber(32, tonumber(typeString .. asciiCharString .. positionString))

  -- ④ 武器参数同样轮询：1 位下标 + 值
  positionWeaponData = (positionWeaponData % 4) + 1
  output.setNumber(31, tonumber(positionWeaponData .. weaponProperties[positionWeaponData]))
end
```

**接收端怎么拆**（对称写法）

```lua
local v   = input.getNumber(32)
local pos = v % 100                       -- 末 2 位 = 字符位置
local asc = math.floor(v / 100) % 1000    -- 再往前 3 位 = ASCII
local sub = math.floor(v / 100000) % 10
local typ = math.floor(v / 1000000) % 10
buf[pos] = string.char(asc)               -- 攒够 name:len() 个就能拼回整串
```

**要点与坑**

- **位宽必须固定**：`%03d` / `%02d` 是这套协议成立的前提。值超宽（ASCII > 999、位置 > 99）会整体错位，宁可多留一位。
- **轮询代价**：N 字符的串要 N tick 才播完（60 tick/s）。适合呼号、航路点名这类**慢变量**，不适合实时数据。
- 与 `07` §1 对比：§1 是**位运算打包**（同一帧塞进一个数，快但不可读）；本例是**十进制拼接 + 多帧轮询**（慢但能用 `print`/遥测直接看值定位问题）。要实时选 §1，要调试友好选本例。
- 第二个通道用「下标 + 值」拼（`1` + 数值），接收端看首位就知道这是第几条参数——**同一通道轮播多参数**的通用套路。

## §8 应答机（XPDR）协议：**询问-应答握手 + 周期重发 + 字符表定宽编码机型名**

- 来源：steam id 3794618673 / vehicle.xml block#6（Military Pilatus，PenguinO 的 XPDR v2.2）
- 更新时间：2026-09-03
- 用到：显示器、触控屏、GPS、属性文本、无线电（数据链）
- 亮点：一整套可跑的空管应答协议 —— 用「消息类型码 + 应答码匹配」做寻址，用「周期重发」
  绕开多机同步，把机型名用一张**字符串当查表**编成两个定宽十进制数字通道传出去。
- ⚠ 这里的「应答机 / XPDR」是**玩家自建的无线电协议**，不是游戏部件「应急信标
  (Transponder Locator)」；游戏本身没有 XPDR 部件。

```lua
-- KEY: 前 10 个空格是占位对齐, 使 '0' 的 find 结果正好 = 11
PATT = "          0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZ"
TXT  = {"", "", "", "", "", ""}
Expiry, Expmax = 0, 300         -- 周期重发: 300 tick = 5 s
IDENT, IDENT_sus = 0, 5         -- KEY: 计"剩余发射次数", 不是剩余 tick
ACK, DispSQ = false, "1200"
InN, InB, ExB, ExN = input.getNumber, input.getBool, output.setBool, output.setNumber

function onTick()
  local tX, tY, T1 = InN(3), InN(4), InB(1)
  GPS_X, GPS_Y, ALT = InN(11), InN(12), InN(13)
  TYPE   = string.upper(property.getText("Aircraft Type"))
  SQUAWK = InN(27)                      -- 四位应答码, 如 1200

  PINGED = false
  if InN(21) == 6 and InN(26) == SQUAWK then   -- KEY: 类型码 6 = 询问, 且应答码对上自己
    PINGED = true
    if InN(7) > 0 then                  -- 转发询问方的呼号/坐标给本机显示
      ExB(16, true)
      ExN(16, InN(7)) ExN(17, InN(8)) ExN(18, InN(9)) ExN(19, InN(10))
    end
  else
    ExB(16, false)
    ACK = false                         -- KEY: 询问消失才解锁, 防同次询问被反复应答
  end

  if TXT[1] == "" then                  -- KEY: property 是常量, 只编码一次
    for i = 1, math.min(string.len(TYPE), 6) do
      local CHR = string.find(PATT, string.sub(TYPE, i, i)) or 0
      -- KEY: 奇偶字符交替塞进两个通道, 每字符固定 2 位十进制
      TXT[((i-1)%2)+1] = TXT[((i-1)%2)+1] .. string.format("%02.0f", CHR)
    end
  end

  if T0 and not T1 then                 -- KEY: 松手沿(下降沿)触发, 只用一个 T0 变量
    for i = 1, 4 do                     -- SQUAWK 四位数, 每位一对 上/下 按钮
      if isInRect(tX, tY, 30-(i*5), 13, 5, 7) then ExB((i*2)-1, true)
      elseif isInRect(tX, tY, 30-(i*5), 24, 5, 7) then ExB(i*2, true) end
    end
    ExB(27, true) ExN(27, SQUAWK)       -- KEY: 每次改码都重发一次, 修 desync
  else
    ExB(27, false)
    for i = 1, 8 do ExB(i, false) end
  end
  DispSQ = string.format("%04.0f", SQUAWK)

  if T1 and isInRect(tX, tY, 1, 8, 8, 17) then IDENT = IDENT_sus end

  if Expiry > Expmax or (PINGED and not ACK) then   -- KEY: 周期广播 OR 被询问
    local CODE = PINGED and 7 or 1                  -- 7 = 应答, 1 = 主动广播
    ExN(7, C1) ExN(8, C2) ExN(9, C3) ExN(10, C4)    -- 呼号四段
    ExN(21, CODE) ExN(22, GPS_X) ExN(23, GPS_Y) ExN(24, ALT)
    ExN(25, TXT[1]) ExN(29, TXT[2])                 -- 机型名两个通道
    ExN(26, SQUAWK)
    if IDENT > 0 then                               -- IDENT 专用通道, 管制端据此闪烁
      ExN(28, SQUAWK)
      IDENT = IDENT - 1
    else
      ExN(28, 0)
    end
    ACK, Expiry = true, 0
    ExB(30, true)                                   -- XMITTING 灯
  else
    ExB(30, false)
  end

  Expiry = Expiry + 1
  T0 = T1                                           -- 存上一帧触摸态
end

function isInRect(x,y, rx,ry,rw,rh)
  return x > rx and y > ry and x < rx+rw and y < ry+rh
end
```

**要点与坑**

- 🔑 **字符串当查表：`string.find(PATT, ch)` 直接返回字符序号**。不用建 `{A=1,B=2,...}` 表，
  一行字符串就是编码表；**开头补 10 个空格是刻意的对齐**，让 `'0'` 落在下标 11、`'A'` 落在 21，
  于是所有序号都是**两位数**，`%02.0f` 恒定 2 字符宽。⚠ 因此 `PATT` 长度**不能超过 99**
  （现为 45），超了就变 3 位、接收端解码会整体错位。
- 🔑 **奇偶交替分通道**：`TXT[((i-1)%2)+1]` 把第 1/3/5 个字符塞进 `TXT[1]`、第 2/4/6 塞进 `TXT[2]`。
  6 字符机型名 → 两个通道各 6 位十进制（`格式为 3 组 2 位`），双精度浮点完全装得下。
  比按顺序切成「前 3 后 3」的好处是：**任一通道丢包时，剩下的通道仍能还原出交错的可读残片**。
  与 `07` §7 的「逐字符轮询」相比：本例一帧发完（快），§7 要 N 帧（慢但通道数少）。
- 🔑 **`if TXT[1] == "" then` 是 SW 的「伪 onInit」**。MC 没有初始化回调，`property.getText`
  又是编译期常量，所以用哨兵值判断「是否已算过」，第一帧算完永久缓存。
  比每帧重算省掉 6 次 `string.find` + 6 次 `format`。
- 🔑 **同步靠周期重发，不靠一次性写入**。原作注释写着 `Stupid-Desync Fixed by PenguinO on v2.2`，
  修法就是把 `ExB(27,true) ExN(27,SQUAWK)` 塞进「每次松手」分支 —— 多个 MC / 多个客户端之间
  逻辑通道的写入可能错帧，**任何"状态型"数据都要能被重复播报**，不能假设写一次就到位。
  这是 SW 多 MC 协作最重要的一条工程纪律。
- 🔑 **发射条件是「周期到了 **或** 被询问且未应答」**：`Expiry > Expmax or (PINGED and not ACK)`。
  `ACK` 只在「不再收到询问」时清零，所以一次询问只会换来一次应答，
  不会因为询问方连发 60 帧而被应答 60 次挤爆信道。
- 🔑 **`IDENT` 计的是「剩余发射次数」而不是剩余 tick**（`IDENT_sus = 5`，只在发射分支里 `-1`）。
  因为发射是稀疏事件（5 s 一次），用 tick 计时的话按一下 IDENT 可能一次都没赶上发射；
  计次数能保证**至少被管制端看到 5 次**。稀疏事件的计时器都该这么写。
- **消息类型码分流**：`CODE = 1` 主动广播、`6` 询问、`7` 应答询问。接收端先看 21 号通道再决定怎么解，
  等价于给数据链加了一个「协议头」。与 `07` §3 的 ID 编码寻址是两种互补的寻址方式：
  §3 按目标 ID 寻址，本例按 SQUAWK 应答码寻址（同码可群响应，天然支持编队）。
- ⚠ `SQUAWK == nil` 的兜底分支（原作有，此处省略）**实际上永不触发**：SW 数字通道读不到时返回 `0`，
  不是 `nil`。想给默认值应该判 `if SQUAWK == 0 or SQUAWK < 1000 then SQUAWK = 1200 end`。
- **按钮坐标 `30-(i*5)` 是「从右往左第 i 位」**：i=1 在 x=25、i=4 在 x=10，正好对应
  `%04.0f` 的个/十/百/千位从右到左，编号与视觉位置一致，省掉一次 `5-i` 换算。
- 完整脚本：`../../../AI相关/_提取暂存/_new/3794618673_vehicle_6.lua`


## §9 弹药标识总线：**一路数字通道既传字符串又传数值**（序号 + 值定宽拼接）

- 来源：steam id 3794316877（武器挂点标识系统，载具，2026-08-31）
- 用到：属性文本 `Name` / `Custom name`、4 路武器参数属性、32 路复合输出
- 亮点：发送端把「类型码 + 字符 ASCII + 字符位置」和「参数序号 + 参数值」各自拼成
  **一个**十进制整数；接收端按位拆回来。一路通道当总线用，极度省通道
- 区别于 `07` §7（逐字符轮询传字符串）：§7 只传字符串；本节同一根通道还要传
  **数值型参数**，并额外演示接收端 `string.byte` → `string.char` 的还原链路

### 发送端：定宽拼接

```lua
name   = property.getText("Name")
type   = property.getNumber("Type")
subtype= property.getNumber("Subtype")

-- ① 字符游标：每 tick 前进一格，循环
positionCharacter = (positionCharacter % name:len()) + 1

-- ② 字符 → 3 位定宽 ASCII（%03d 保证 0..255 都是 3 位）
asciiCharString = string.format("%03d", string.byte(string.sub(name, positionCharacter, positionCharacter)))

-- ③ 位置 → 2 位定宽（%02d → 最多 99 个字符）
positionString  = string.format("%02d", positionCharacter)

-- ④ 类型 + 子类型 → 2 位（各取整数部分，均须 ≤ 9）
typeString      = tostring(math.floor(type)) .. tostring(math.floor(subtype))

-- ⑤ 拼成一个整数：MainType SubType | ASCII | 位置
--    例：类型 3、子类型 1、第 7 个字符 'A'(065) → "31" "065" "07" → 3106507
output.setNumber(32, tonumber(typeString .. asciiCharString .. positionString))
```

**帧格式（7 位十进制）**

| 位 | 含义 | 宽度 |
| --- | --- | --- |
| 第 1 位 | 主类型 `Type` | 1 |
| 第 2 位 | 子类型 `Subtype` | 1 |
| 第 3–5 位 | 当前字符的 ASCII 码 | 3（`%03d`） |
| 第 6–7 位 | 字符在串中的位置 | 2（`%02d`） |

定宽是这套协议的**唯一命门**：任何一段宽度不固定，接收端就无法切分。
所以 ASCII 必须用 `%03d`（`65` 要写成 `065`），位置必须用 `%02d`。

> ⚠ `type`/`subtype` 各占 1 位，意味着**只能有 10 种主类型、10 种子类型**；
> 需要更多就扩宽并同步改接收端切片。这是定宽协议的固有代价
> （对照 `07` §8 的应答机用**字符表**当查表，容量换复杂度）。

### 同一根总线上再塞数值参数

```lua
weaponProperties = {
  property.getNumber("Radar FOV Launch Horizontal"),
  property.getNumber("Radar FOV Launch Vertical"),
  property.getNumber("Minimum Range (m)"),
  property.getNumber("Maximum Range (m)")
}

positionWeaponData = (positionWeaponData % 4) + 1                  -- 4 项轮询
output.setNumber(31, tonumber(positionWeaponData .. weaponProperties[positionWeaponData]) + 0)
```

格式：`序号(1 位) + 值(其余位)`。接收端看首位就知道这是第几项。

⚠ **三个实测陷阱**
1. **值必须是非负整数**。`tonumber(1 .. -30)` = `1-30` → `tonumber` 得到 `nil`
   （Lua 不会把它当 `-130`）；`tonumber(2 .. 1.5)` = `21.5`，小数点是额外字符，
   接收端按整数协议解析就会错位。**浮点数先 `math.floor` 并钳到 ≥ 0**。
2. **值不能以 0 开头**。`序号 3 + 值 012` = `3012`，接收端无法区分「值 12」与「值 012」。
   距离、角度这类可能出现前导零的量，改用固定宽度 + `string.format`。
3. `+ 0` 是无操作（Lua 里数字加 0 还是数字），写在这里大概是作者想强制转数字；
   `tonumber` 已经做了这件事，可以删。

### 接收端：拆回来

```lua
types = {"R80D","R30D","RM95","nTGP","PJ2k","RPOD","CANO","FUEL","Misc","Bast",
         "R80E","GBU","ASM","AAM","AShM","Ltrp","LM4+","R80X","RKT","65","9","7",
         "120","L131","IRIS","Mete","Torp","Bomb"}
guidetypes = {"RADAR","LASER","DUMB","OTHER"}

function onTick()
  local t = input.getNumber(1)                     -- 类型下标
  local gt = input.getNumber(2)
  guide = guidetypes[gt] or ""                     -- 🔑 查表 + or "" 兜底（越界不报错）
  minr = math.floor(input.getNumber(3))
  maxr = math.floor(input.getNumber(4))

  local left = input.getNumber(32)
  local custom = property.getText("Custom name (override default text output)")
  if custom ~= "" and custom then
    typ = custom .. math.floor(left)               -- 自定义名时把余弹数拼在后面
  else
    typ = types[t]
  end

  -- 4 个字符拆成 4 路数字输出，再现场拼回字符串
  for i = 1, 4 do
    local b = string.byte(typ or "", i)
    output.setNumber(4 + i, b)
  end
  text = string.char(string.byte(typ or "",1) or 0) ..
         string.char(string.byte(typ or "",2) or 0) ..
         string.char(string.byte(typ or "",3) or 0) ..
         string.char(string.byte(typ or "",4) or 0)
end
```

- `guidetypes[gt] or ""` 是**下标越界的标配兜底**：`gt` 为 0 或 > 4 时返回空串，
  不会让 `screen.drawText` 收到 `nil` 而整块屏黑掉。
- 🔴 `output.setNumber(4+i, b)` 里 `b` 在字符串短于 4 个字符时是 **`nil`**，
  而 `setNumber` 收到 `nil` 会报错。本例只在上一步 `string.char(... or 0)` 兜了底，
  **输出通道没兜**。正确写法：`output.setNumber(4+i, b or 0)`。
  这是"兜底写了一半"的典型（关联 `09` §14「外部通道非零兜底」）。

### 何时用这套协议

| 需求 | 方案 |
| --- | --- |
| 只传一个短字符串，通道有余 | `07` §7 逐字符轮询（更简单） |
| 字符串 + 若干数值，通道紧张 | **本例**：定宽拼成一个整数 |
| 要传任意字符集（含大小写 + 符号） | `07` §8 字符表 `string.find` 定宽编码 |
| 数据量大（> 几十项） | `08` §5 流式广播 + 状态位 |

## §10 自回中通道怎么还原成「按键」：**减掉自然衰减量**再判方向

来源：steam id **3794758874** · <https://steamcommunity.com/sharedfiles/filedetails/?id=3794758874> · **载具**（Heavy Recovery Truck）· 更新时间 **2026-09-03**

SW 的遥控器 / 操纵杆通道是**自回中**的：松手后读数会自己往 0 走。这带来一个麻烦——你拿到的是一个 0~±1 的模拟量，却想知道「玩家**现在**按的是 A 还是 D」。直接看正负号不行（松手后它要衰减好几秒才回到 0），看这一拍的增量也不行（增量里混着回中量）。

**用到**：数字输入（遥控四轴 AD / WS / LR / UD）、属性（每轴的模式与灵敏度）、数字输出四路

**亮点**：① **先算出「如果没按键，本拍增量应该是多少」**，再用实测增量减去它，剩下的就是按键；② 容差 0.0099 吸收量化误差；③ 两种积分语义（Sticky 累加 / Reset 一阶趋近）用属性切换；④ 灵敏度 `sens^2/10000` 二次映射，低灵敏区更细腻；⑤ 原脚本四轴复制四遍，文末给出表驱动压到 1/5 字符的改法。

```lua
-- 遥控器轴在 SW 里松手后会自己回中；作者实测的回中速率约为「每 tick 往 0 走当前值的 1%」
ad2      = input.getNumber(1)          -- 本拍读数
addelta  = ad2 - ad1                   -- 本拍增量
ad1      = ad2                         -- 存给下一拍
adrdelta = -ad2 * 0.01                 -- 🔑 自然回中量：如果没按键，增量就该正好等于它

if     math.abs(addelta - adrdelta) < 0.0099 then adtgt = 0    -- 增量 == 回中量 → 没按
elseif addelta > adrdelta              then adtgt = 1          -- 增量更大 → 按了正向键
else                                        adtgt = -1 end    -- 更小 → 按了反向键
```

```lua
-- 两种积分语义：Sticky = 按住一直加、松手停住；Reset = 松手自己走回 0
adrate = (adsens ^ 2) / 10000          -- 灵敏度 1..100 → 每 tick 步长 0.0001..1（二次曲线）
if admode == 1 then
  adnew = clamp(adnew + adtgt * adrate, -1, 1)              -- Sticky：纯累加
elseif admode == 2 then
  adnew = clamp(adnew + (adtgt - adnew) * adrate, -1, 1)    -- Reset：一阶趋近
end
output.setNumber(1, adnew)
```

```lua
-- ✅ 表驱动改写：原脚本把上面两段给四根轴复制了四遍（约 60 行），压成 12 行
AX = {}
for i = 1, 4 do
  AX[i] = {v = 0, prev = 0,
           mode = property.getNumber("Mode " .. i),
           rate = (property.getNumber("Sens " .. i) ^ 2) / 10000}
end

function onTick()
  for i = 1, 4 do
    local a, cur = AX[i], input.getNumber(i)
    local d, rd = cur - a.prev, -cur * 0.01
    a.prev = cur
    local tgt = 0
    if     d - rd >  0.0099 then tgt =  1
    elseif d - rd < -0.0099 then tgt = -1 end
    if a.mode == 1 then a.v = clamp(a.v + tgt * a.rate, -1, 1)
    else                a.v = clamp(a.v + (tgt - a.v) * a.rate, -1, 1) end
    output.setNumber(i, a.v)
  end
end
```

- ⚠ **回中速率 `-v * 0.01` 必须先实测**。不同输入源（遥控、操纵杆、方向盘、触控虚拟摇杆）的回中曲线不一样；若中间还夹了缩放、取整、死区，这个式子就不成立，判据会整体偏移（表现为「松手后还在缓慢加/减」）。测法：松手不动，打印若干拍的 `v`，看它是否按固定比例收敛。
- ⚠ 容差 `0.0099` 要**大于一拍的量化误差**，否则会把「松手」误判成「轻推」。通道经过 `math.floor` 之类处理时要把容差调大。
- 🔑 **这条思路的通用形式**：任何「读数自带一个可预测的趋势项」的通道，都可以用「实测增量 − 趋势项」还原出外部输入。回中摇杆是最典型的一种，弹簧复位的踏板、自动归位的舵机同理。

## §11 **把整张清单存进复合通道**：脚本每 tick 无状态重建 + 十进制位当布尔打包 + 脏标记回写

- 来源：steam id **3793892285** · 描述页 <https://steamcommunity.com/sharedfiles/filedetails/?id=3793892285> · **载具**（`_vehicle_14` 无线电台频率清单管理器）

  for i = 1, 20 do

    end

                                        table.remove(ds, o) upd = true end

        end
      end
    end

                                  + (ds[i9][3] and 10 or 0) + (ds[i9][4] and 1 or 0)) or 0)
    end
  end
  ds = {}                                -- ⚠ 结尾再清空，本 tick 彻底无状态
  upd = false

function prs(lx, ux, ly, uy)

end

- 🔑 **十进制位当布尔打包**：`freq*1000 + 可见*100 + 方位*10 + 航路点`——一个整数装下「一个数值 + 三个布尔」，拆包只用 `/` 和 `%`。比位运算（`<<` / `&`）可读性差一点，但**在复合通道里肉眼可直接读出含义**（`2475110` = 频率 2475、可见、方位开、航点关），调试时极其方便，也不用担心 SW Lua 位运算对负数的行为。
- 🔑 **「读到 0 就 break」让清单保持紧凑**：删除时 `table.remove` 会把后面前移，末尾自然补 0。序列化只需 20 次固定循环，不必先数长度。
- 🔑 **脏标记 `upd` 是这类写回的必需品**：20 路数值 + 目标频率每 tick 全写一遍，会淹没总线、也会让下游微控每 tick 都触发一次处理。只有真的改过才回写。
- 🔑 **长按清空用 `c1` 计数而非另起状态**：`prs(...) and c1+1 or tp and 0 or c1`——按住累加、松手归零，`c1 > 1` 即「按住了不止一 tick」。一次误触不会清表。
- ⚠ **`ds` 在 `onTick` 末尾清空，`onDraw` 里读不到它**。本脚本的 `onDraw` 只画静态框架所以没事；若绘制也要用清单数据，必须另设一个全局快照变量在 `onTick` 里赋值——**「状态存通道」与「onTick→onDraw 传参」是两件事，别混为一谈**。
- ⚠ `upd = #ds > 0` 作为初值意味着「上电时若通道里已有旧清单就回写一次、若为空则不写」。想要「上电即清空全部输出」应显式置 `true`。

## §13 无线电**扫频接收机**：步进扫频 + 命中驻留 + 定时续扫 + 整频跳过

- 来源：steam id **3796718728** · 描述页 <https://steamcommunity.com/sharedfiles/filedetails/?id=3796718728> · **载具**（LRV "Jamper"，`_vehicle_2`）
- 更新时间：2026-09-06
- 用到：属性（驻留秒数 `Timer`）、数值输入（信号强度 / 起始频率 / 终止频率）、布尔输入（电源 / 跳过 / 允许发射）、2 路数值输出（主频 / 副台频偏）、3 路布尔输出
- 亮点：`07` §3 讲「跳频躲干扰」、`07` §12 讲「多路电台共享态势图」，都是**主动**那一侧；这一节补**被动监听**——接收机怎么自动扫过一段频率、扫到台就驻留、停够时间再继续。

```lua
i=property.getNumber
ign=input.getNumber
igb=input.getBool
osn=output.setNumber
osb=output.setBool
timer=0
tx=0                        -- 当前频率，一路数值通道直接喂电台模块
timerx=false
wait=i("Timer")*60          -- 属性里填「秒」，乘 60 换 tick；⚠ 顶层只执行一次
output3=0
function onTick()
  trans=igb(3)              -- 允许发射 / 本频点可用
  qp=ign(1)                 -- 当前频点信号强度，>0 视为有台
  power=igb(1)
  skip=igb(2)
  strt=ign(2) stp=ign(3)
  osb(3,(strt~=0 and stp~=0) and power)   -- and 链当布尔输出，省一个 if

  if not power then tx=strt timer=0 timerx=false intercept=false end
  if power then
    -- ① 已锁定但信号消失 -> 开始数驻留时间
    if intercept and not ((qp>0) and trans) then
      timerx=true timer=timer+1
    else
      timer=0 timerx=false
    end
    -- ② 驻留时间到 -> 解除锁定（下一 tick 起继续扫）
    if timer>wait then intercept=true timerx=false timer=0 end
    -- ③ 手动跳过：跳到下一个整数频点
    if skip then tx=math.floor(tx)+1 intercept=false timerx=false timer=wait+1 end
    -- ④ 有信号（或还在驻留）就保持锁定，否则步进
    if ((qp>0) or timerx) and (trans or timerx) then
      intercept=true
      output3=tx-0.2        -- 副电台跟台，留 0.2 固定频偏
    else
      intercept=false
      output3=0
      frq()
    end
  end
  osn(1,tx) osn(2,output3)
  osb(1,intercept) osb(2,timerx)
end
function frq()                -- 步进 0.1，到顶回绕到起始频率
  tx=tx+0.1
  if tx>stp then tx=strt end
end
```

- 🔑 **频率本身就是一路数值通道**：`osn(1,tx)` 直接接到电台模块的频率输入，扫频 = 每 tick 给这路通道加一个步长。第二路 `tx-0.2` 用**固定频偏**让副电台跟台，不必再算一次频率。
- 🔑 **三态机只用两个布尔表达**：`intercept`（停扫）/ `timerx`（驻留计时中），两种都不是就 `frq()` 步进。比 `state=1/2/3` 的枚举状态变量省字符，也不用一个大 `if/elseif` 树。
- 🔑 **整频跳过用 `math.floor(tx)+1`**：电台频道常按整 MHz 划分，`floor+1` 一下跳到下一个整数频点，比继续 0.1 步进快十倍。
- ⚠ **原脚本 `skip` 分支里的 `timer=wait+1` 是死代码**：它把 `intercept` 置成 false，下一 tick 开头 `if intercept and ...` 不成立，会先走 `else` 把 `timer` 归 0，`wait+1` 根本轮不到和 `wait` 比较。想「跳过后立刻续扫」不写这行效果完全一样。
- ⚠ **`wait = i("Timer")*60` 写在顶层，改属性要重启脚本才生效**（与 `09` §25 的 `mod` 同一个坑）。想在线可调就把它挪进 `onTick`；代价是每 tick 多一次属性读。
- ⚠ **断电分支没清 `output3`**：`if not power` 只重置了 `tx` 与计时器，副电台频率仍停在断电前的值。稳妥写法是在这个分支里补 `output3=0`。

## §14 一条 Bool 通道 = 一个比特：**LSB-first 位编码器** + **3+2 位分层量化**做向后兼容

- 来源：steam id 3792099957 · 描述页 https://steamcommunity.com/sharedfiles/filedetails/?id=3792099957 · 载具（DB BR 622 / I 620 B 动车组，`_vehicle_3` 门控与灯色编码器）
- 更新时间：2026-08-29
- 用到：复合布尔输出 32 路、复合数值输入、`property` 无
- 亮点：① `enc(c,b,n)` 把任意整数拆成 b 个**连续** Bool 通道，且**起始通道是最低有效位**；② 颜色先传 3 bit 粗值、再补 2 bit 残差修正，**老接收端不改线也能用，新接收端精度翻倍**。

```lua
gN = input.getNumber; gB = input.getBool
sN = output.setNumber; sB = output.setBool

-- ① 把整数 n 用 b 条 Bool 通道输出，从通道 c 开始；c 号是最低有效位 (LSB)
function enc(c, b, n)
  for i = 0, b-1 do
    n = math.floor(n)
    sB(c + i, n % 2 == 1)
    n = n / 2
  end
end

function clamp(v, x, y) return math.min(math.max(v, x), y) end

function onTick()
  sB(1, gB(4))                            -- 左门
  sB(2, gB(5))                            -- 右门
  sB(3, gB(6))                            -- 开门
  enc(4,  6, clamp(gN(4), 0, 63))         -- 首车厢号：6 bit（占通道 4~9）
  enc(10, 6, clamp(gN(5), 0, 63))         -- 末车厢号：6 bit（占通道 10~15）

  -- ② 颜色：0~1 浮点先放大到 5 bit 精度 (0..31)
  high_r = clamp(gN(6), 0, 1) * 31
  high_g = clamp(gN(7), 0, 1) * 31
  high_b = clamp(gN(8), 0, 1) * 31

  -- ③ 粗量化成 3 bit (0..7) —— 老接收端只读这三根线
  low_r = math.floor(high_r * 7 / 31)
  low_g = math.floor(high_g * 7 / 31)
  low_b = math.floor(high_b * 7 / 31)

  -- ④ 把「粗量化丢掉的残差」再量化成 2 bit，并排发出去
  error_r = high_r - (low_r * 31 / 7)                  -- 恒为非负（见下方说明）
  corr_r  = math.floor((error_r / (31 / 7)) * 3 + 0.5) -- 0..3

  enc(16, 3, low_r)                       -- 红：粗 3 bit（老设备）
  enc(19, 3, low_g)
  enc(22, 3, low_b)
  enc(26, 2, corr_r)                      -- 红：残差修正 2 bit（新设备）
  enc(28, 2, corr_g)
  enc(30, 2, corr_b)
end
```

```lua
-- 解码端（新设备）：粗值 + 修正 → 恢复 0~1
r = (low_r*31/7 + corr_r*(31/7)/3) / 31
-- 解码端（老设备）：只读前 3 根线
r_old = low_r / 7
```

- 🔑 **`enc` 是「N 条 Bool 通道 = 一个数值」的通用序列化器**。SW 的复合**布尔**输出有 32 路而**数值**输出同样紧张、且常被引擎/传感器占满，于是用小整数换布尔通道是标准的省通道办法（反过来：`01` §14 用 `2^k-1` 让**一条数值通道当 N 路开关**）。
- 🔑 **LSB-first 的取舍**：低位放在起始通道，**扩位不用改老接线**——3 bit 扩到 5 bit 时原来那 3 根线的权重不变，只是在后面多接 2 根。若反过来 MSB-first，扩位会把所有位的权重整体移位，老设备全废。**凡是协议可能升级的通道，一律 LSB 打头。**
- 🔑 **分层量化是这份代码最值钱的地方**：老接收端只读 `enc(16,3)` 那三根线就能拿到 0~7 的粗颜色（能用，只是色阶明显）；新接收端再读 `enc(26,2)` 的修正量，把量化误差补回约 3/4，等效精度接近 5 bit。**协议升级不破坏旧设备**，比「直接把 3 bit 换成 5 bit」高明得多——后者会让所有老车瞬间显示错色。
- 🔑 **残差再量化是通用套路**：`error = 原值 - 反量化(粗值)`，再除以一个量化步长 `(31/7)/3` 后四舍五入。任何渐进/分层传输（缩略图 → 原图、粗角度 → 精角度、粗坐标 → 精坐标）都是这三行。
- ⚠ **残差恒为非负是有前提的**：`low_r = math.floor(high_r*7/31)` 向下取整，所以残差 ∈ `[0, 31/7)`，2 bit 无符号刚好够。若把粗量化改成四舍五入，残差会有负的，就必须留符号位（或把零点平移到中点）。
- ⚠ `enc` 里 `n = n/2` 是浮点除法，靠循环开头的 `math.floor(n)` 逐位取整。Lua 5.3 有原生整数运算，写成 `sB(c+i, n & 1 == 1); n = n >> 1` 更快更好读；但 `n%2` / `n/2` 在**负数**上也成立（`-3 % 2 == 1`），而位运算对负数是补码语义——**同一份代码里不要两种混用**。
- ⚠ **通道号必须手工排布且不重叠**：`enc(4,6,·)` 占 4~9、`enc(10,6,·)` 占 10~15。起始号写错一位就会静默覆盖别人的数据，而且没有任何报错。建议每段都在注释里标出占用区间（本例已标）。
- 🔑 门控那几行 `sB(1, gB(4))` 是纯直通——**直通与编码混排**时，把直通放前面、编码段按块往后排，接线时最容易核对。
