## §1 Lua 键盘协议位解析（一个数字同时传坐标与字符）

- 来源：steam id **2659444728** · <https://steamcommunity.com/sharedfiles/filedetails/?id=2659444728> · **载具**（Lua Keyboard）
- 更新时间：**2022-04-29**
- 用到：键盘微控、显示器、复合通道 31/32
- 亮点：**键盘把「点击事件」和「字符」打包进同一个数字**，用位运算解出；作者给出了完整位布局注释，是协议级的可靠范例。

```lua
-- bit 1      = type (1 = 点击/触摸, 0 = 字符)
-- bit 2      = 键盘是否已弹出
-- type == true（点击）:
--   bits 3-13  = x (11 bit, 0..2047)
--   bits 14-24 = y (11 bit, 0..2047)
-- type == false（字符）:
--   bits 2-8   = charcode (7 bit ASCII)
function parseKeyboard(numb)
  local fl   = math.floor(numb)                       -- 必须先取整：位移对浮点不可靠
  local typ  = (numb & 1) == 1                        -- SW Lua 5.3：原生 & >> <<
  local shown= (numb & 2) == 2
  local ret  = {type=typ, keyboardShown=shown, click=false, x=0, y=0, key=0, char=""}

  if typ then
    ret.click = true
    ret.x = (fl >> 2)  & 2047                         -- >>2 跳过 type+shown，掩码 11 bit
    ret.y = (fl >> 13) & 2047
  else
    local charc = (fl >> 2) & 127                     -- 7 bit ASCII
    ret.key = charc
    if charc > 31 and charc < 127 then
      ret.char = string.char(charc)                   -- 可打印字符
    elseif charc == 4 then   ret.CONFIRM = true       -- 确认
    elseif charc == 127 then ret.DEL     = true end   -- 退格
  end
  return ret
end

message = ""
function onTick()
  local k = parseKeyboard(GN(31))
  SB(31,false) SB(32,false)                           -- 默认不请求（形成脉冲）

  if k.click and not k.keyboardShown then
    if inRect(k, buttonOpen)  then SB(31,true) end    -- 请求打开键盘
    if inRect(k, buttonClose) then SB(32,true) end    -- 请求关闭
  end
  if k.DEL then
    message = string.sub(message, 1, string.len(message)-1)
  elseif k.char then
    message = message .. k.char
  end
end
```

**要点**
- SW 的 Lua 是 **5.3+**，原生支持 `& | ~ << >>`，**不需要 bit32 库**——这是位打包的前提。
- `math.floor()` 必须先做：`>>` 对浮点数行为不可靠。
- 同一通道既传坐标又传字符，靠 **bit 1 区分**——复合通道数量有限，这是非常珍贵的做法。
- 「打开/关闭键盘」是**请求式**的：拉高后由键盘微控响应，脚本每 tick 默认拉低 → 形成脉冲。
- 该作品自带可直接复用的键盘微控，**把 `parseKeyboard` 抄进自己的脚本就获得全 ASCII 输入**。

## §2 无线电多目标跟踪（平行表 + 过期剔除）

- 来源：steam id **2046605849** · <https://steamcommunity.com/sharedfiles/filedetails/?id=2046605849> · **载具**（SR-71 Blackbird）
- 更新时间：**2021-03-12**
- 用到：无线电接收机、GPS 传感器、显示器
- 亮点：**8 张平行表同步维护多机档案**；前向轨迹预测；CLIMB/DESCEND 解脱建议；告警文字滚动闪烁。

### 2.1 档案维护

```lua
RATE=15 MAXD=600 Expiry=1500 MINALT=300
DC={} DX={} DY={} DA={} DD={} DS={} DV={} DE={}
-- 代号 / X / Y / 高度 / 航向 / 地速 / 升降率 / 存活 tick

function onTick()
  -- 本机状态（由「回波自身数据」通道周期性刷新）
  if GN(11)>0 and GB(30) then
    MY_DIR = math.atan(GN(13)-MY_Y, GN(12)-MY_X)                 -- atan(y=Δ北, x=Δ东)
    MY_GS  = math.sqrt((GN(13)-MY_Y)^2+(GN(12)-MY_X)^2)*60/MY_AGE
    MY_VS  = (GN(14)-MY_ALT)*60/MY_AGE
    MY_X,MY_Y,MY_ALT = GN(12),GN(13),GN(14)
    MY_AGE = 0
    MY_CODE= GN(11)
  end
  MY_AGE = MY_AGE + 1                                            -- 60 tick = 1 秒

  -- 他机：过期剔除（倒序遍历，安全）+ 命中更新
  for k=#DC,1,-1 do
    DE[k] = DE[k] + 1
    if DE[k] > Expiry then
      removeRecord(k)
    elseif DC[k] == GN(26) then                                  -- 同一代号 => 更新
      isEXIST = true
      DD[k] = math.atan(GN(23)-DY[k], GN(22)-DX[k])
      DS[k] = math.sqrt((GN(23)-DY[k])^2+(GN(22)-DX[k])^2)*60/DE[k]
      DV[k] = (GN(24)-DA[k])*60/DE[k]
      DX[k],DY[k],DA[k] = GN(22),GN(23),GN(24)
      DE[k] = 0
    end
  end

  -- 新目标：过滤地面目标（高度）与自己（代号）
  if not isEXIST and GN(26)>0 and GN(24)>MINALT and GN(26)~=MY_CODE then
    table.insert(DC, GN(26))
    table.insert(DX, GN(22)) table.insert(DY, GN(23)) table.insert(DA, GN(24))
    table.insert(DD,0) table.insert(DS,0) table.insert(DV,0) table.insert(DE,0)
  end
end

function removeRecord(k)
  table.remove(DC,k) table.remove(DX,k) table.remove(DY,k) table.remove(DA,k)
  table.remove(DD,k) table.remove(DS,k) table.remove(DV,k) table.remove(DE,k)
end
```

### 2.2 过期剔除的推荐写法：重建表（而不是 `table.remove`）

来源：steam id **3793328793**（Nordic VISION，2026 年）—— 雷达轨迹点老化。
这是 §2.1 里「`table.remove` 不安全」问题的**正面解法范例**：**遍历旧表，把存活元素拷进新表，最后整体替换**。

```lua
pointX, pointY, timeago = {}, {}, {}        -- 三张平行表：轨迹点坐标 + 存活 tick

function clean()
  local tempX, tempY, tempago = {}, {}, {}  -- 必须用 local，否则污染全局
  for i=1, #timeago do
    timeago[i] = timeago[i] + 1             -- 先老化
    if timeago[i] < 120 then                -- 存活阈值
      tempago[#tempago+1] = timeago[i]
      tempX  [#tempX+1]   = pointX[i]       -- 三表同步拷贝
      tempY  [#tempY+1]   = pointY[i]
    end
  end
  pointX, pointY, timeago = tempX, tempY, tempago   -- 整体替换
end
```

**为什么这样更好**
| 做法 | 评价 |
| --- | --- |
| `table.remove(t, k)` 在 `for/pairs` 里 | ❌ 下标前移，漏删或越界 |
| 倒序 `for k=#t,1,-1` | ✅ 正确，但只适合"删除"场景 |
| **重建表**（本例） | ✅ 最通用：过滤、变换、老化一次做完，且天然支持多表同步 |
| `pairs` 里置 `t[k]=nil` | ✅ 安全，但会留下空洞，`#t` 变得不可靠 |

> ⚠ **原稿有笔误**：`onDraw()` 里写的是 `timeago[#tempago+1] = 0`（用 `tempago` 的长度当 `timeago` 的索引），
> 应为 `timeago[#timeago+1] = 0`。抄的时候注意——这正是「重建表」写法最容易犯的错：
> **每张表的自增索引必须用自己表的长度**。
- 冲突检测用**时间步进 + 三维欧氏距离**。`RATE=15`（秒）是精度与算力的折中：600 秒 / 15 = 40 步 × 目标数。
- `MY_AGE` 记录距上次刷新的 tick 数，`*60/MY_AGE` 把「这段时间的位移」换算成 m/s。
- 过滤条件 `GN(24) > MINALT` 排除地面载具、`~= MY_CODE` 排除自己的回波 —— **做无线电共享时这两条缺一不可**。

### 2.3 TCAS 冲突预测（前向轨迹步进）

```lua
NEAREST = SENSE
for i = 0, MAXD, RATE do                        -- 未来 0..600 秒，步长 15 秒
  local X_CHK = MY_X + MY_GS*i*math.cos(MY_DIR)
  local Y_CHK = MY_Y + MY_GS*i*math.sin(MY_DIR)
  local A_CHK = MY_ALT + MY_VS*i
  for k=1,#DC do
    local TX = DX[k] + DS[k]*i*math.cos(DD[k])
    local TY = DY[k] + DS[k]*i*math.sin(DD[k])
    local TA = DA[k] + DV[k]*i
    local d  = math.sqrt((X_CHK-TX)^2 + (Y_CHK-TY)^2 + (A_CHK-TA)^2)
    if d < NEAREST then
      NEAREST = d; ALARM = true
      ADVICE = (MY_ALT>=DA[k] or A_CHK<=MINALT) and "CLIMB" or "DESCEND"
    end
  end
  if ALARM then break end                       -- 首个命中即停，省算力
end
```

**要点**
- 🔴 **原稿用 `table.remove` 写在 `pairs` 循环里，是风险做法**：删除会使后续 key 前移，导致跳过元素或越界。
  **安全写法是倒序 `for k=#DC,1,-1 do ... end`**（本例已改为倒序），或先收集待删下标再重建表。
  对比：`pairs` 里置 `t[k]=nil` 是**安全的**，`table.remove` 是**不安全的**（见 `02` §5）。
- **平行表（parallel arrays）** 是 SW 存多目标最常见的形态：8 张表下标对齐，插入/删除必须**八表同步**。
  更稳的写法是单表存 record（`{code=,x=,y=,...}`），但平行表在字符数紧张时更省。

## §3 UAV / 无人机群指挥数据链（ID 编码寻址 + 跳频 + 航点增删）

来源：steam id **3261800786** · <https://steamcommunity.com/sharedfiles/filedetails/?id=3261800786> · **载具**（ZTQ-15，脚本 `datalink3RcvRC&UAV`）——车长用数据链指挥无人机群：每架无人机靠**自身 ID 解码出是否在被指挥**，频率按 ID 偏移做**跳频**，航点/攻击/返航指令走复合通道的各位。

```lua
Rcv = {}                                            -- 收到的消息表
function onTick()
  if GN(1) ~= 0 then                                -- 收到一帧
    for i=1,#Rcv do if GN(1)==Rcv[i].id then j=i; break end end   -- 按消息自带 ID 查重/建档
    if j > #Rcv then Rcv[j] = {j={}, w={}} end
    Rcv[j].id = GN(1); Rcv[j].t = 0
    -- 自身 ID 编码在 GN(16) 的万位数字 → 命中说明「这帧是命令我的」
    if Mf(GN(16)/1e4) == selfID then
      slave = true; slavef = GN(1)
      if drone then                                  -- 无人机专属指令
        add = GB(29); del = GB(30); atk = GB(31); rtb = GB(7); cv = GB(8)
        wayx = GN(13); wayy = GN(14)
        wayz = Mf(GN(16)%1e2); wayr = Mf(GN(16)%1e4/1e2)   -- 航点坐标/半径藏在 GN(16) 各位
      end
    end
  end
  -- 跳频：被指挥时收听「指令方频率+其ID」，否则守自己频率
  if slave then rtf = freq + slavef
  elseif SLID~=0 and page==1 then rtf = freq + SLID
  else rtf = freq + selfID end
  vf = freq + selfID
end
```

**要点**
- **ID 编码寻址**：指挥方把 `selfID` 写进消息某几位（`Mf(GN(16)/1e4)`），接收方比对自身 ID 才知道「这帧是对我下的令」——比广播+过滤更省带宽。
- **跳频**：`rtf = freq + slavef`，每架无人机听不同偏移频率降低同频互扰；`vf`（发频）固定 `freq+selfID`。
- 航点坐标/半径**塞进一个复合数 GN(16) 的各位**（`%1e2`、`%1e4/1e2`）——又见「一个数字传多值」套路（`07` §1）。
- 指令用**边沿布尔**：`add/del/atk/rtb/cv` 各占一个通道位，接收端按需动作。
- 消息表 `Rcv` 按 `t>300` 过期剔除（重建表而非 `table.remove` 遍历中删，见 §2.2）。
- 完整脚本：`../../../AI相关/_提取暂存/3261800786_vehicle_10.lua`（配套 `..._vehicle_15.lua` 指挥地图 UI、`..._vehicle_6.lua` 目标类型符号）

## §4 移动单站三边交汇定位（静默信标）

- 来源：steam id **2774712393**（Zizo Transponder Locator）/ steam id **3664940456**（PYO's Transponder Locator，同功能新版）

只有一个测距通道（无方位）时，**自己边走边测**，把每个「站位+距离」记成一个圆，圆的交点就是信标：

```lua
-- 边走边采样：与上一站位拉开距离才记新圆（车速过快不采样，误差大）
if dist > 300 and valid and speed < max_speed then
  if not C[1] or length(C[#C].x, C[#C].y, gps_x, gps_y) > clamp(#C*5, 10, 200) then
    table.insert(C, {x=gps_x, y=gps_y, r=dist, e=speed+1})   -- e=误差权重
  end
end
-- 两个站位圆求交（三圆方程组代数解）
function findCircleIntersections(c1, c2, c3)
  local A = 2*(c2.x-c1.x)
  local B = 2*(c2.y-c1.y)
  local C = c1.r^2 - c2.r^2 - c1.x^2 + c2.x^2 - c1.y^2 + c2.y^2
  -- ... 联立求解交点
end
-- 多个交点按 1/误差 加权融合，再投影回最新一圈定唯一解
x, y = closestPointOnCircle(point.x/point.d, point.y/point.d, gps_x, gps_y, dist)
```

**要点**
- **采样间距自适应**：`clamp(#C*5,10,200)`——圆越多要求站位间隔越大，避免几何稀释精度（GDOP）恶化。
- 车速误差直接当权重（`e=speed+1`，慢=准），融合时 `1/e` 加权——**测得慢的样本更可信**。
- 两圆相交有两个解，加权融合后**投影回最新一圈**（`closestPointOnCircle`）消歧义，不用存历史假设。
- PYO 新版（3664940456）把同思路整理成 `solve_2_circles/solve_3_circles`，函数更通用，二选一即可。
- 完整脚本：`../../../AI相关/_提取暂存/2774712393_microcontroller_0.lua`、`.../3664940456_vehicle_0.lua`

## §7 数字通道**逐字符轮询**传字符串（定宽十进制拼接，不用位运算）

- 来源：steam id 3788946785 · 描述页 https://steamcommunity.com/sharedfiles/filedetails/?id=3788946785 · 载具（MV-24 倾转旋翼机※，`_vehicle_20`）
- 更新时间：2026-08-26
- 用到：属性文本（载具名）、属性滑块（武器参数）、2 个数字输出通道
- 亮点：SW 的复合信号**没有字符串类型**，本例用「**固定位宽十进制拼接**」把一串字符拆成每 tick 一个数字发出去，接收端按位数切回来——比 `07` §1 的位运算方案**更易调试**（数字肉眼可读）。

```lua
positionCharacter   = 1
positionWeaponData  = 1

function onTick()
  local name    = property.getText("Name")          -- 要广播的字符串（如载具呼号）
  local type    = property.getNumber("Type")
  local subtype = property.getNumber("Subtype")

  local weaponProperties = {
    property.getNumber("Radar FOV Launch Horizontal"),
    property.getNumber("Radar FOV Launch Vertical"),
    property.getNumber("Minimum Range (m)"),
    property.getNumber("Maximum Range (m)"),
  }

  -- ① 每 tick 只推进一个字符下标，循环播完整串
  positionCharacter = (positionCharacter % name:len()) + 1

  -- ② 字符 -> 3 位 ASCII 码；下标 -> 2 位（最多 99 字符）
  local asciiCharString = string.format("%03d", string.byte(name:sub(positionCharacter, positionCharacter)))
  local positionString  = string.format("%02d", positionCharacter)

  -- ③ 类型(1位) + 子类型(1位) + ASCII(3位) + 位置(2位) = 7 位定宽
  local typeString = tostring(math.floor(type)) .. tostring(math.floor(subtype))
  output.setNumber(32, tonumber(typeString .. asciiCharString .. positionString))

  -- ④ 武器参数同样轮询：1 位下标 + 值
  positionWeaponData = (positionWeaponData % 4) + 1
  output.setNumber(31, tonumber(positionWeaponData .. weaponProperties[positionWeaponData]))
end
```

**接收端怎么拆**（对称写法）

```lua
local v   = input.getNumber(32)
local pos = v % 100                       -- 末 2 位 = 字符位置
local asc = math.floor(v / 100) % 1000    -- 再往前 3 位 = ASCII
local sub = math.floor(v / 100000) % 10
local typ = math.floor(v / 1000000) % 10
buf[pos] = string.char(asc)               -- 攒够 name:len() 个就能拼回整串
```

**要点与坑**

- **位宽必须固定**：`%03d` / `%02d` 是这套协议成立的前提。值超宽（ASCII > 999、位置 > 99）会整体错位，宁可多留一位。
- **轮询代价**：N 字符的串要 N tick 才播完（60 tick/s）。适合呼号、航路点名这类**慢变量**，不适合实时数据。
- 与 `07` §1 对比：§1 是**位运算打包**（同一帧塞进一个数，快但不可读）；本例是**十进制拼接 + 多帧轮询**（慢但能用 `print`/遥测直接看值定位问题）。要实时选 §1，要调试友好选本例。
- 第二个通道用「下标 + 值」拼（`1` + 数值），接收端看首位就知道这是第几条参数——**同一通道轮播多参数**的通用套路。
- 完整脚本：`../../../AI相关/_提取暂存/_new/3788946785_vehicle_20.lua`

## §8 应答机（XPDR）协议：**询问-应答握手 + 周期重发 + 字符表定宽编码机型名**

- 来源：steam id 3794618673 / vehicle.xml block#6（Military Pilatus，PenguinO 的 XPDR v2.2）
- 更新时间：2026-09-03
- 用到：显示器、触控屏、GPS、属性文本、无线电（数据链）
- 亮点：一整套可跑的空管应答协议 —— 用「消息类型码 + 应答码匹配」做寻址，用「周期重发」
  绕开多机同步，把机型名用一张**字符串当查表**编成两个定宽十进制数字通道传出去。
- ⚠ 这里的「应答机 / XPDR」是**玩家自建的无线电协议**，不是游戏部件「应急信标
  (Transponder Locator)」；游戏本身没有 XPDR 部件。

```lua
-- KEY: 前 10 个空格是占位对齐, 使 '0' 的 find 结果正好 = 11
PATT = "          0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZ"
TXT  = {"", "", "", "", "", ""}
Expiry, Expmax = 0, 300         -- 周期重发: 300 tick = 5 s
IDENT, IDENT_sus = 0, 5         -- KEY: 计"剩余发射次数", 不是剩余 tick
ACK, DispSQ = false, "1200"
InN, InB, ExB, ExN = input.getNumber, input.getBool, output.setBool, output.setNumber

function onTick()
  local tX, tY, T1 = InN(3), InN(4), InB(1)
  GPS_X, GPS_Y, ALT = InN(11), InN(12), InN(13)
  TYPE   = string.upper(property.getText("Aircraft Type"))
  SQUAWK = InN(27)                      -- 四位应答码, 如 1200

  PINGED = false
  if InN(21) == 6 and InN(26) == SQUAWK then   -- KEY: 类型码 6 = 询问, 且应答码对上自己
    PINGED = true
    if InN(7) > 0 then                  -- 转发询问方的呼号/坐标给本机显示
      ExB(16, true)
      ExN(16, InN(7)) ExN(17, InN(8)) ExN(18, InN(9)) ExN(19, InN(10))
    end
  else
    ExB(16, false)
    ACK = false                         -- KEY: 询问消失才解锁, 防同次询问被反复应答
  end

  if TXT[1] == "" then                  -- KEY: property 是常量, 只编码一次
    for i = 1, math.min(string.len(TYPE), 6) do
      local CHR = string.find(PATT, string.sub(TYPE, i, i)) or 0
      -- KEY: 奇偶字符交替塞进两个通道, 每字符固定 2 位十进制
      TXT[((i-1)%2)+1] = TXT[((i-1)%2)+1] .. string.format("%02.0f", CHR)
    end
  end

  if T0 and not T1 then                 -- KEY: 松手沿(下降沿)触发, 只用一个 T0 变量
    for i = 1, 4 do                     -- SQUAWK 四位数, 每位一对 上/下 按钮
      if isInRect(tX, tY, 30-(i*5), 13, 5, 7) then ExB((i*2)-1, true)
      elseif isInRect(tX, tY, 30-(i*5), 24, 5, 7) then ExB(i*2, true) end
    end
    ExB(27, true) ExN(27, SQUAWK)       -- KEY: 每次改码都重发一次, 修 desync
  else
    ExB(27, false)
    for i = 1, 8 do ExB(i, false) end
  end
  DispSQ = string.format("%04.0f", SQUAWK)

  if T1 and isInRect(tX, tY, 1, 8, 8, 17) then IDENT = IDENT_sus end

  if Expiry > Expmax or (PINGED and not ACK) then   -- KEY: 周期广播 OR 被询问
    local CODE = PINGED and 7 or 1                  -- 7 = 应答, 1 = 主动广播
    ExN(7, C1) ExN(8, C2) ExN(9, C3) ExN(10, C4)    -- 呼号四段
    ExN(21, CODE) ExN(22, GPS_X) ExN(23, GPS_Y) ExN(24, ALT)
    ExN(25, TXT[1]) ExN(29, TXT[2])                 -- 机型名两个通道
    ExN(26, SQUAWK)
    if IDENT > 0 then                               -- IDENT 专用通道, 管制端据此闪烁
      ExN(28, SQUAWK)
      IDENT = IDENT - 1
    else
      ExN(28, 0)
    end
    ACK, Expiry = true, 0
    ExB(30, true)                                   -- XMITTING 灯
  else
    ExB(30, false)
  end

  Expiry = Expiry + 1
  T0 = T1                                           -- 存上一帧触摸态
end

function isInRect(x,y, rx,ry,rw,rh)
  return x > rx and y > ry and x < rx+rw and y < ry+rh
end
```

**要点与坑**

- 🔑 **字符串当查表：`string.find(PATT, ch)` 直接返回字符序号**。不用建 `{A=1,B=2,...}` 表，
  一行字符串就是编码表；**开头补 10 个空格是刻意的对齐**，让 `'0'` 落在下标 11、`'A'` 落在 21，
  于是所有序号都是**两位数**，`%02.0f` 恒定 2 字符宽。⚠ 因此 `PATT` 长度**不能超过 99**
  （现为 45），超了就变 3 位、接收端解码会整体错位。
- 🔑 **奇偶交替分通道**：`TXT[((i-1)%2)+1]` 把第 1/3/5 个字符塞进 `TXT[1]`、第 2/4/6 塞进 `TXT[2]`。
  6 字符机型名 → 两个通道各 6 位十进制（`格式为 3 组 2 位`），双精度浮点完全装得下。
  比按顺序切成「前 3 后 3」的好处是：**任一通道丢包时，剩下的通道仍能还原出交错的可读残片**。
  与 `07` §7 的「逐字符轮询」相比：本例一帧发完（快），§7 要 N 帧（慢但通道数少）。
- 🔑 **`if TXT[1] == "" then` 是 SW 的「伪 onInit」**。MC 没有初始化回调，`property.getText`
  又是编译期常量，所以用哨兵值判断「是否已算过」，第一帧算完永久缓存。
  比每帧重算省掉 6 次 `string.find` + 6 次 `format`。
- 🔑 **同步靠周期重发，不靠一次性写入**。原作注释写着 `Stupid-Desync Fixed by PenguinO on v2.2`，
  修法就是把 `ExB(27,true) ExN(27,SQUAWK)` 塞进「每次松手」分支 —— 多个 MC / 多个客户端之间
  逻辑通道的写入可能错帧，**任何"状态型"数据都要能被重复播报**，不能假设写一次就到位。
  这是 SW 多 MC 协作最重要的一条工程纪律。
- 🔑 **发射条件是「周期到了 **或** 被询问且未应答」**：`Expiry > Expmax or (PINGED and not ACK)`。
  `ACK` 只在「不再收到询问」时清零，所以一次询问只会换来一次应答，
  不会因为询问方连发 60 帧而被应答 60 次挤爆信道。
- 🔑 **`IDENT` 计的是「剩余发射次数」而不是剩余 tick**（`IDENT_sus = 5`，只在发射分支里 `-1`）。
  因为发射是稀疏事件（5 s 一次），用 tick 计时的话按一下 IDENT 可能一次都没赶上发射；
  计次数能保证**至少被管制端看到 5 次**。稀疏事件的计时器都该这么写。
- **消息类型码分流**：`CODE = 1` 主动广播、`6` 询问、`7` 应答询问。接收端先看 21 号通道再决定怎么解，
  等价于给数据链加了一个「协议头」。与 `07` §3 的 ID 编码寻址是两种互补的寻址方式：
  §3 按目标 ID 寻址，本例按 SQUAWK 应答码寻址（同码可群响应，天然支持编队）。
- ⚠ `SQUAWK == nil` 的兜底分支（原作有，此处省略）**实际上永不触发**：SW 数字通道读不到时返回 `0`，
  不是 `nil`。想给默认值应该判 `if SQUAWK == 0 or SQUAWK < 1000 then SQUAWK = 1200 end`。
- **按钮坐标 `30-(i*5)` 是「从右往左第 i 位」**：i=1 在 x=25、i=4 在 x=10，正好对应
  `%04.0f` 的个/十/百/千位从右到左，编号与视觉位置一致，省掉一次 `5-i` 换算。
