# 07 · 字数压缩与工程手法

> 游戏内单个 Lua 脚本方块**上限 8192 字符**（`00_速查 §14`），这是 SW 编程的**第一约束**。
> 工坊作者普遍用 PonyIDE 的 **Minify** 按钮压缩（`00_速查 §14.1`），所以你从工坊提取到的脚本**很可能是压缩态**。
> 本章三件事：**怎么读压缩代码 → 怎么自己写省字符 → 哪些坑别踩**。

---

## 1. 反压缩（reformat）流程

### 1.1 识别压缩态

| 特征 | 说明 |
| --- | --- |
| 单行或极少行、`;` 作语句分隔 | 结构被压平 |
| 几乎无空格、无注释 | 可读性被剥离 |
| 局部变量是 `a` `b` `c` 单字母 | **原名已丢失** |
| `onTick` / `onDraw` / `httpReply` **一定保留原名** | PonyIDE 硬编码不改这三个回调名 —— **先靠它们定位入口** |

### 1.2 先反压缩再读（结构可 100% 恢复）

本工作区已备好反压缩脚本（`AI相关/_scripts/unminify.py`，纯标准库）：

```bash
PY="C:/Users/EC90/.workbuddy-ai/binaries/python/versions/3.13.12/python.exe"
"$PY" "D:/STORMWORKS/AI相关/_scripts/unminify.py" \
      "D:/STORMWORKS/AI相关/_提取暂存/<file>.lua" \
      -o "D:/STORMWORKS/AI相关/_提取暂存/_readable/<file>.lua"
```

做的事：`;` → 换行、在 `function/if/for/while/local/return/else/end` 等关键字边界断行、按 `then/do/function/end` 做缩进。
**字符串字面量与注释受保护**，不会被误断行。

### 1.3 变量名有损 —— 只能按语义重命名

- **Conservative 模式不保存原名映射**，原名永久丢失；
- **Agressive 模式**可能在开头 `--yyy--` 标记后内嵌 `短名=原名;` 映射表（作者若保留则可还原）；
- 因此 `a=input.getNumber(1)` 这类只能**靠读代码理解用途后自己改名**。

> 本示例集 `01 例 2`、`02 例 3` 都是「反压缩 + 语义改名」后的产物——**对比 `_提取暂存/` 里的原始单行 blob 与文档里的可读版，能直观看到这套流程的效果。**

## 2. 自己写时的省字符手法（来自 steam id 3687286349，更新 2026-06-13）

### 2.1 顶部一次性建别名

```lua
igN=input.getNumber igB=input.getBool
osN=output.setNumber osB=output.setBool
pgN=property.getNumber
ab=math.abs mx=math.max mn=math.min
Mc=math.cos Ms=math.sin Ma=math.atan Mr=math.sqrt
```

**收益**：`input.getNumber` 出现 40 次即省下约 400 字符。
**代价**：可读性下降。**建议开发期用全名、定稿后压缩**，并保留未压缩版另存。

> 注意：`math.xxx` 的别名要用 `Mc=math.cos`（**值拷贝**），不是 `M=math` 后再 `M.cos`——后者每次多 2 字符。两者都有人用，前者更省。

### 2.2 常量集中在顶部，同时充当「调参面板」

```lua
ra=0.22 hz=60 tgp=2.0 lw=3.0
sw=14 swn=10 slt=22 mst=6
maxD=800 stc=46 aW=3.0 eW=2.0 tW=8.0
```

好处不只是省字符：**所有可调项一眼可见**，配合 `property.getNumber` 外置后，用户无需改代码。

### 2.3 单行 `if`（压缩期写法，慎用于开发期）

```lua
if lw<=0 then lw=3.0 end
if v<0 then v=0 end
```

PonyIDE 压缩后 `then/end` 会被保留但换行消失，形成 `if x then y end` 单行块。
**自己写时不要刻意单行**——可读性优先，交给工具压。

### 2.4 最大的省字符手段：把大表搬进属性文本

见 `03_显示HUD与触控屏.md` 例 2——字模表、配色表、航点表全部存进 `property.getText`，
**脚本源码只留解析循环**。这是绕过 8192 上限最有效的办法，远比变量名缩写有效。

## 3. 必踩坑清单（按出现频率排序）

| # | 坑 | 表现 | 正确做法 |
| --- | --- | --- | --- |
| 1 | **角度单位混淆**（`00_速查 §4`） | 姿态乱跳、罗盘反着转 | 传感器输出是**圈**；进 `sin/cos` 前 ×2π，出 `atan` 后 ÷2π |
| 2 | **`pairs` 循环内 `table.remove`** | 漏删元素、下标越界 | 倒序 `for k=#t,1,-1 do`，或先收集待删下标再重建 |
| 3 | **多返回值不加括号**（`§11`） | 函数收到多余实参 | `f((g()))` 只取第一个；`a,b=g()` 赋值安全 |
| 4 | **`#` 与 `ipairs` 遇 `nil` 提前停**（`§6`） | 列表「少一半」 | 预填充固定尺寸数组，或改用 `pairs` + 计数器 |
| 5 | **onTick 里调 screen API** | 无效、静默失败 | 绘图只放 `onDraw`，读数只放 `onTick`（`§9`） |
| 6 | **onDraw 里调 input/output** | 无效 | 同 `§9`；onDraw 可能被**多次**调用（接多屏时） |
| 7 | **触控原始信号当触发器** | 一次触摸翻 N 页 | 外部造一个 tick 脉冲，或用 `not lp` 闩锁（见 `03 例 4`、`02 例 3`） |
| 8 | **源码含非 ASCII**（`§13`） | 脚本报错/乱码 | 代码全 ASCII；中文只放 `property.getText` 与注释外 |
| 9 | **超 8192 字符**（`§14`） | 无法保存 | 拆多脚本方块，或大表搬进属性文本 |
| 10 | **联机变量不同步**（`§15`） | 主机正常、客机错乱 | 脚本级变量每人一份，跨人状态必须走复合信号/无线电同步 |
| 11 | **逐像素渲染失控**（本集 `02 例 3`） | 帧率暴跌 | 96×96 网格 = 9216 次绘制；大屏必须降分辨率 |
| 12 | **死代码残留**（本集 `01 例 1`） | 抄了用不上的函数 | 引用工坊代码前先 `grep` 确认函数真的被调用 |

---

## 4. 引用工坊代码的三步自检

1. **确认单位**：涉及角度的，先查是圈还是弧度（对照 `17_传感器与雷达.md`）。
2. **确认被调用**：`grep` 目标函数名，排除作者留下的死代码。
3. **确认时效性**：比对本工作区 `_meta/items.json` 里的 `updated`，同功能优先用新作。
