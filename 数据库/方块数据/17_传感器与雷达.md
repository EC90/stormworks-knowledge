### 1.2 ⚠ 两套坐标系（最高频 bug 来源）

游戏里存在两套**轴向定义不同**的坐标系，混用必然算错：

| | GPS 坐标系（右手系） | 物理传感器坐标系（左手系） |
|---|---|---|
| X 轴正方向 | 东 | 东 |
| Y 轴正方向 | **北** | **铅直向上** |
| Z 轴正方向 | **高度**（海平面为 0） | **北** |
| 使用者 | 地图右下角坐标、GPS传感器 | 物理传感器、自稳定云台摄像机 |

**换算公式**（记住这一行就够）：

```
GPS_X = PS_通道1        （东，两边一致）
GPS_Y = PS_通道3        （北 ← 物理传感器的 Z）
GPS_Z = PS_通道2        （高度 ← 物理传感器的 Y）
```

> 日文 wiki 原话：「古いY座標を新しいZ座標に、Z座標をY座標にそれぞれ読み替えればよい」。

### 1.3 欧拉角：Z-Y-X 顺序

物理传感器输出的欧拉角，是「先把局部坐标系与世界坐标系对齐，再按 **Z 轴 → Y 轴 → X 轴** 顺序旋转」
得到的姿态角（左旋为正）。即所谓的 **Z-Y-X 系欧拉角**。

换算到 GPS 坐标系视角，等价于 **(-Y)-(-Z)-(-X) 系**（负号表示旋转方向相反）。

⚠ **要换成其它旋转顺序的欧拉角，不能只做数值置换**，必须经由四元数等中间表示重新计算。

> 日文 wiki 建议：看文字搞不清时，把物理传感器装在三个正交的枢轴上实际转一遍，
> 对比枢轴角度与传感器输出——能同时吻合的安装顺序只有一种。

| 要点 | 说明 |
|---|---|
| 供电 | ✅ **不接电就没有坐标输出**（GPS 功能依赖电力） |
| 朝向基准 | ✅ 以自身 Y 轴（绿箭头）为准；顶部水色大箭头 = 局部 Z 正，小箭头 = 局部 X 正 |

### 2.4 误差与滤波

✅ **雷达误差**：距离 **±1%**，角度 **±0.001 圈**。

⚠ **这说明误差极大**：真值 1000 m 的目标，水平面误差约 251 m²、三维约 3158 m³。
而求速度要做时间微分，**通常会放大误差**。因此用于火控时必须滤波。

> ✅ **滤波要加在「算完的坐标」上，不要加在雷达原始数据（距离/角度）上**。

#### LPF（低通滤波器）—— 简单但有延迟

```lua
k = 0.02          -- 滤波系数：越小越平滑，但延迟越大；一般取 0~0.5
x = 0
function onTick()
    y = input.getNumber(1)          -- 雷达原始数据或算出的坐标
    x = x * (1 - k) + y * k
    output.setNumber(1, x)          -- 滤波后输出
end
```

> ⚠ LPF 的问题是**相位滞后（位相ずれ）**：目标机动时输出会系统性落后于真值。
> k 越小越平滑，落后越明显。

#### ABF（α-β 滤波器）—— 推荐，用速度补偿消除延迟

```lua
a = 0.02          -- α：位置修正增益
b = 0.002         -- β：速度修正增益，一般取 β ≈ α/10
target_pred = 0
target_est  = 0
target_ddt  = 0
function onTick()
    target_current = input.getNumber(1)
    target_pred = target_est + target_ddt          -- 用上一拍速度外推
    residual    = target_current - target_pred     -- 残差
    target_est  = target_pred + a * residual       -- 修正位置
    target_ddt  = target_ddt  + b * residual       -- 修正速度
    output.setNumber(1, target_est)
    output.setNumber(2, target_ddt * 60)           -- 顺便输出速度（每秒）
end
```

**LPF vs ABF 选型**：

| 场景 | 建议 |
|---|---|
| 目标近似匀速直线（导弹中段、飞机巡航） | **ABF**，几乎完美跟踪 |
| 目标做非线性机动（正弦般转弯） | 两者都会失真，需**非线性卡尔曼滤波** |
| 只要求平滑、不在乎延迟 | LPF 足够 |

> ⚠ ABF 调参：β 过大（例中 β=0.02）会**振荡**。固定 α=0.02 时，β=0.002 表现良好。
> 记住经验值 **β ≈ α/10**。

#### 实测基准（本册离线跑的，非 wiki 抄的）

条件：目标匀速直线 0.5 m/tick，观测噪声 σ=2.0 m，跑 600 tick，取后 40% 统计。

| 滤波器 | 参数 | 收敛后最大误差 | 末期误差 | 速度估计（真值 0.5） |
|---|---|---|---|---|
| **ABF** | α=0.02 β=0.002 | **0.97 m** | 0.26 m | **0.524** ✅ |
| ABF | α=0.05 β=0.005 | 1.29 m | 0.16 m | 0.470 |
| ABF | α=0.01 β=0.001 | 3.85 m | 0.04 m | 0.455 |
| ABF ⚠ | α=0.02 **β=0.02** | 1.43 m | 1.43 m | **0.334** ❌ 崩了 |
| **LPF** | k=0.02 | **24.88 m** ❌ 纯滞后 | — | 无输出 |

> ✅ 结论：**ABF 比 LPF 好 25 倍**（0.97 m vs 24.88 m）。
> ✅ β=α/10 的经验值成立；**β=α 时速度估计会崩到真值的 2/3**，务必别把 β 调大。
> 想更快收敛就同时放大 α 和 β（保持 10:1），例如 α=0.05 / β=0.005。

### 2.5 ⚠ Stormworks 的坐标转换约定（与教科书不同）

**极坐标（2D）**：教科书写 `(x, y) = (r·cosθ, r·sinθ)`。
但 Stormworks 的角度**以 Y 轴（北/前方）为基线、顺时针为正**，所以：

```
x = r · sin(θ)
y = r · cos(θ)
```

**球面坐标（3D）**：教科书 `(x,y,z) = (r·sinθ·cosφ, r·sinθ·sinφ, r·cosθ)`。
Stormworks 中 **θ（仰角）以水平面为基准、φ（方位角）以 Y 轴为基线顺时针为正**，所以：

```
x = r · cos(仰角) · sin(方位角)     -- 东
y = r · cos(仰角) · cos(方位角)     -- 北
z = r · sin(仰角)                   -- 上
```

> 一句话记忆：**距离投到水平面用 cos(仰角)，再按「sin 给 X、cos 给 Y」拆方位角。**

### 2.6 目标绝对坐标解算（可直接用的 Lua）

把「雷达的相对距离/方位角/仰角」+「本机的物理传感器位姿」合成目标的**世界绝对坐标**。

```lua
pi2 = math.pi * 2
s = math.sin
c = math.cos

--[[ 数值输入约定
  1,2,3 = 物理传感器 X / Y / Z    （注意：Y 是高度，Z 是北）
  4,5,6 = 物理传感器 欧拉 X / Y / Z（单位：弧度，实测确认）
  7     = 雷达目标距离 (m)
  8     = 雷达目标方位角（圈）
  9     = 雷达目标仰角（圈）
  数值输出 1,2,3 = 目标绝对 X(东) / Y(北) / Z(高度)
]]
function onTick()
    -- ① 物理传感器坐标 → GPS 坐标：Y 与 Z 互换
    self_X = input.getNumber(1)
    self_Y = input.getNumber(3)          -- 北
    self_Z = input.getNumber(2)          -- 高度

    -- ② 单位：欧拉角(4-6)已是弧度；雷达角(8-9)是圈，须 ×2π
    al  = input.getNumber(4)        -- 欧拉角单位已是弧度，勿再 ×2π
    ga  = input.getNumber(5)
    be  = input.getNumber(6)
    dst = input.getNumber(7)
    azi = input.getNumber(8) * pi2
    ele = input.getNumber(9) * pi2

    -- ③ 本机姿态旋转矩阵（Z-Y-X 欧拉序）
    m = {
        { c(be)*c(ga),                       -s(ga),       s(be)*c(ga)                      },
        { c(al)*c(be)*s(ga) + s(al)*s(be),   c(al)*c(ga),  c(al)*s(be)*s(ga) - s(al)*c(be) },
        { s(al)*c(be)*s(ga) - c(al)*s(be),   s(al)*c(ga),  s(al)*s(be)*s(ga) + c(al)*c(be) }
    }

    -- ④ 相对偏移（Stormworks 球面坐标约定）
    local_X = dst * s(azi) * c(ele)
    local_Y = dst * c(azi) * c(ele)
    local_Z = dst * s(ele)

    -- ⑤ 旋转 + 平移（注意是 mᵀ·local）
    output.setNumber(1, m[3][1]*local_Z + m[2][1]*local_Y + m[1][1]*local_X + self_X)
    output.setNumber(2, m[3][2]*local_Z + m[2][2]*local_Y + m[1][2]*local_X + self_Y)
    output.setNumber(3, m[3][3]*local_Z + m[2][3]*local_Y + m[1][3]*local_X + self_Z)
end
```

> ⚠ **日文 wiki 原版代码有两处单位错误**：① 漏了雷达角（方位/仰角）的圈→弧度转换；② 把欧拉角（本就是弧度）也乘了 2π。
> 上面是修正版：雷达角 ×2π，欧拉角直接使用（实测：物理传感器欧拉角输出值域为 -π~+π，即弧度）。
> 若沿用原版，欧拉角会被放大 2π 倍，在 ±π 附近 sin/cos 符号翻转，解算结果呈多态跳变。
>
> ⚠ 输出 1/2/3 是 **GPS 坐标系**（X=东、Y=北、Z=高度），可直接喂给 GPS 航法的目标坐标。

✅ **本册已对上面这段做过数值验证**（离线跑 300 组随机姿态角）：

| 检查项 | 结果 |
|---|---|
| 零姿态时应为恒等变换 | ✅ 输入 (1,2,3) → 输出 (1,2,3) |
| 正交性 R·Rᵀ = I | ✅ 最大误差 4.4e-16 |
| 行列式 = +1（是旋转不是镜像） | ✅ 200 组全为 1.000000 |
| 保长性（旋转不改变向量长度） | ✅ 0/300 超差 |

> 即：**矩阵本身和「取转置后再乘」的下标写法都是对的**，可以直接用。
> 真正容易错的只剩第 ② 步的单位和第 ① 步的 Y/Z 互换。

### 2.7 制导电路的失探保护（实战技巧）

从日文 wiki `誘導兵器` 页提炼：导弹末制导启动时若雷达**立刻丢失目标**，会瞬间切回 GPS 导航而脱靶。
解决办法是在切换路径上串一个**电容**：

| 环节 | 接法 |
|---|---|
| 电容 | charge = 0 s，discharge ≈ **0.5 s** |
| 复合开关盒 | off 端接 GPS 制导信号，on 端接雷达的「导弹输出」 |
| 触发源 | 雷达 Radar Data 的**开关通道 1**（发现目标） |

这样失探后仍有约 0.5 s 的雷达制导余量，避免瞬间跳变。

## §6 激光与光学

### 6.1 激光三件套与编码配对

> ✅ 关键术语：游戏里 **Wavelength 译为「激光编码」**，不是「波长」。
> 配对规则：**发射端与接收端必须设为相同整数编码**才能互相识别。

| 中文 | 英文名 | 角色 | 编码节点 |
|---|---|---|---|
| 激光距离传感器 | Laser Distance Sensor | 发射 + 测距 | Wavelength（激光编码）= 要发射的编码 |
| 激光点传感器 | Laser Point Sensor | 接收 + 测向 | Wavelength（激光编码）= 要捕获的编码 |
| 激光信标 | Laser Beacon | 自身即为一个激光光点 | — |
| 自稳定云台摄像机 | Camera Stabilized | 可自行照射激光，也可追踪光点 | Laser Wavelength（激光编码） |

**激光距离传感器**节点（✅）：距离(米) / 电 / 打开（Active，控制是否发射）/ 激光编码 / **轴（Pivot）**。
> ✅ 「轴 Pivot」是新发现的节点：输出激光传感器的 X/Y 轴数值（数值1=X轴，数值2=Y轴）。

**激光点传感器**节点（✅）：电 / 数据输出 / 激光编码。
- 数据输出：开关通道1 = 检测到激光；数值通道 1、2 = 光点在传感器 **120° 视场内**的 X、Y 位置。
- 多光点时**取靠近视场中心**的那个。
- 数值范围 -1~1，对应视场角 **-cos(0.5) ~ cos(0.5)**（约 ±0.8776 rad，双向一致）。

**红外选项**：发射端与接收端都有 `Infrared`（红外）勾选框——
勾选后激光束与光点**肉眼不可见，只有红外模式的摄像机能看到**。

⚠ **日文 wiki 标注「波长设置需调查」**；游戏内文本已明确为「相同编码才能识别」，可以结案。

### 6.2 摄像机家族

### 7.2 液位测量仪（⚠ 常见误译点）

✅ 游戏内英文名是 **Liquid Meter**，中文 **液位测量仪**。

| 节点 | 中文 | 说明 |
|---|---|---|

| 通道 | 1 | 2 | 3 | 6 | 7 | 9 | 10 |
|---|---|---|---|---|---|---|---|

> 液位测量仪测的是**受风浪实时起伏的海面**，**向下（水下）为正**。两者符号相反。

### 7.3 风力传感器的相对风向换算

✅ 输出的是**相对**风：风速相对传感器自身速度，且**只测量传感器所在平面内的风**。
传感器移动时测到的是「移动速度矢量 + 自然风」的合成风。

**求绝对风向**：把罗盘传感器（与风力传感器同向安装）的读数，**减去**风力传感器的风向输出。

⚠ **符号陷阱**：罗盘输出的是「**为朝向正北所需转动的角度**」，风力传感器输出的是「**转到当前风向所需转动的角度**」——
两者同为顺时针为正，但**正负号相反**。

换算到 -0.5~0.5 区间（超出时折回），日文 wiki 给的函数式：

```
-(1 - abs(x)) * sgn(x)
```

> 例：460° 折算成 100°。也可用 LESS-THAN / GREATER-THAN + 两个开关盒，或用取余实现。

### 7.6 线性速度传感器的 4 种模式（✅ 游戏内中文）

| `sonar_noise` | **0.001** | 声纳角度误差范围（±），单位「圈」 |

> ⚠ **角度误差的单位是「圈」不是弧度也不是度**：0.001 圈 = 0.36°，

> **Stormworks 里凡是传感器输出的角度，默认单位都是「圈」**。

> 📌 **重力常量澄清**：`gravity="10.0"` 是**载具/世界**重力。

`lift_force=0.25`、`air_drag_factor=0.2`、浮力 `buoyancy_mass_multiplier=10.0` 等），
