## §1 三个关键事实（先看这个，能省半天）

### 1.1 摄像头(中型) 支持 Pivot —— Fandom 漏记

Fandom/wiki 未记载 `camera_med` 的 Pivot 输入，**游戏定义文件才是权威**：

```xml
<!-- rom/data/definitions/camera_med.xml -->
<logic_node label="Pivot" type="5"
  description="Inputs for camera X/Y pivot. (Value 1 : Pivot X) (Value 2 : Pivot Y)">
```
tooltip：**「Can be pivoted up to 0.125 turns using composite input」**

→ **Pivot X/Y 复合输入存在，范围 ±0.125 圈（±45°）**。此前代码里的 ±0.125 钳制是正确的。

### 1.2 摄像头 Pivot 轴是「非物理」的 —— 控制架构的第一原理

**这是整个调试过程中最关键的认知**：

| | 座圈（云台） | 摄像头 Pivot |
|---|---|---|
| 性质 | **物理执行机构**：有电机、质量、转速上限 | **逻辑轴**：无惯性、无转速限制 |
| 响应 | 有真实滞后，需低增益/阻尼 | 逻辑给角度 → **瞬间指向** |
| 正确控制 | 比例控制 + 抗饱和，增益受稳定边界限制 K≈5~10 | **纯传感器残差转换 + 轻滤波** |

→ **给无惯性逻辑轴做控制，不要套用物理执行机构的重滤波**。
摄像头应「纯雷达 az/el 残差 → Pivot」，**与座圈（物理、有滞后）解耦**，二者不共用同一套滤波。

### 1.3 单位：物理传感器欧拉角是「弧度」，雷达角度是「圈」

| 量 | 单位 | 值域 | 喂 `sin/cos` 前 |
|---|---|---|---|
| 物理传感器 ch4-6（欧拉角 X/Y/Z） | **弧度 rad** | −π ~ +π | **直接用，勿 ×2π** |
| 雷达方位/仰角（Radar Data） | **圈** | — | **必须 ×2π** |

> ⚠ 17 册 §2.6 旧示例对欧拉角也 ×2π（照抄会三态跳变），**已修正**。

## §2 雷达噪声表征（静对静，777 m）

- **距离**：777.54 ± 4.44 m（**0.57 %**），与手册 ±1 % 同量级。
- **角度**：az/el ±0.0006 圈；**量化 21 档、步长 0.0001 圈 = 0.036°**（即雷达角度分辨率）。
- **噪声不是白的**：dist/el 自相关 滞后4 ≈ 0.70、滞后8 ≈ 0.66 → **「4-tick 周期节拍 + 真随机」混合**。
- **伪随机判定（决定性）**：三轮 dist 均值/std 一致，但**逐 tick 序列 corr ≈ −0.2（完全无关）**
  → 噪声**不可复现** → **火炮反因果修正表法不适用**（该法要求纯确定性序列）。
- **滤波结论**：
  - 静态目标 → 累积平均（829 样本 ≈ 207 独立样本 → 0.31 m）。
  - 动态目标 → **4-tick 均值 + ABF(α=0.05, β=0.005)**，滤波加在**解算后的坐标**。
  - 实测效果（rt_6）：未滤波 |e| 5.74 ± 1.88 → 滤波后 **1.83 ± 0.82（压制 2.5×）**。

## §3 座圈（物理云台）调参历程与结论

雷达/PS/摄像头同轴装于 `turret_large` 座圈子网格。目标：让座圈把雷达指向目标。

| 轮次 | 方案 | 结果 |
|---|---|---|
| 7 | 比例 K=2 | 跟不上 |
| — | K=8 | 低频振荡（az std 0.018，扫满 FOV） |
| — | K=15 / 20 | 严重振荡 |
| 9 | K=8 + Ki=4（条件积分） | 摆动放大 11× |
| 10 | Kp=15 | 又振荡；**积分 windup 过冲**（转向后冲过头转开） |
| 11 | anti-windup（误差<0.01 圈才积分，钳位 ±0.1） | 改善但积分仍弊大于利 |
| **12** | **纯比例 K=5 + 死区 0.001（bknsw 原版建议）** | ✅ **调通** |

**最终参数**：`K=5`、`DEAD=0.001`、`DIR=-1`（正转速=左转，az 右正故取负）、限幅 ±10、**无积分**。

- 静态 az std **0.00058**；动对静 **0.0006**，静差 < 0.24°。
- **稳定边界 ≈ K=10**（座圈+雷达+PS 惯性 + 速度输入延迟共同决定）。
- 🔑 **教训**：雷达 az 噪声下**积分项极易发散/饱和**（Ki=30 直接满速空转）。追踪类控制**优先纯比例 + 死区**；
  要消静差必须**条件积分 + 抗饱和 + 小 Ki**。
- 参考：bknsw 手册 `Utils/speed-pivot`（速度枢轴控制，增益 5，不用积分）是权威参考。

## §4 摄像头随动稳定：从滞后到零滞后（核心成果）

### 4.1 问题演进

| 阶段 | 方案 | 症状 | 根因 |
|---|---|---|---|
| 初版 | 解算世界坐标 → Pivot/FOV | 画面抖 | 用**未滤波**解算，雷达噪声直通 |
| 改1 | 解算 + ABF(α=0.05) | 抖改善但**滞后** | ABF 滞后 ~30 tick |
| 改2 | ABF α=0.1 | 好一些 | 仍有 ~10 tick 滞后 |
| 改3 | 直接 az/el 残差，滤波 0.6 | **抖** | 原始 az 噪声直通 |
| ✅ **终版** | **直接 az/el 残差 + EMA α=0.3** | **零滞后、平滑** | — |

🔑 **「动起来滞后 / 没追上滤波锁定点」的真正根因**：
座圈用**原始 az（0 滞后）**，摄像头却用**解算+ABF（~10 tick 滞后）** → 响应不同步，摄像头落后座圈半拍。
**不是**滤波器没调好，而是**架构错误地给无惯性轴强加了滞后**。

### 4.2 终版方案：残差轻滤波

前提：摄像头与雷达**同轴装于同一座圈子网格**，座圈锁定后目标就在雷达轴正前方，
因此 **az/el 本身就是「目标相对雷达轴的残差」**，直接补偿即可，**无需解算世界坐标**。

```lua
-- 输入: B1=发现; N29=雷达方位(圈,右正); N30=仰角(圈,上正); N28=距离
-- 输出: N1=Pivot X(圈); N2=Pivot Y(圈); N32=FOV
at=math.atan
AZF,ELF=0,0
SPAN=10
FW,FN=2.2,0.025        -- camera_med FOV: 0→2.2 rad 最宽, 1→0.025 rad 最窄, 中间线性
function onTick()
    found=input.getBool(1)
    pvx,pvy,fov=0,0,0
    dst=input.getNumber(28)
    if found and dst>0 then
        az=input.getNumber(29)
        el=input.getNumber(30)
        AZF=AZF+0.3*(az-AZF)          -- EMA α=0.3, 延迟约 3 tick (~55 ms)
        ELF=ELF+0.3*(el-ELF)
        pvx=-AZF                       -- 符号: 水平取负
        pvy=ELF                        --        垂直取正
        pvx=math.max(-0.125,math.min(0.125,pvx))   -- ±0.125 圈硬钳
        pvy=math.max(-0.125,math.min(0.125,pvy))
        fd=math.max(dst,1)
        fov=math.max(0,math.min(1,(FW-2*at(SPAN/2/fd))/(FW-FN)))
    else
        AZF,ELF=0,0                    -- 失探清零, 防下次捕获时甩头
    end
    output.setNumber(1,pvx)
    output.setNumber(2,pvy)
    output.setNumber(32,fov)
end
```

**唯一调参旋钮 = α**（大 → 同步更紧但略抖；小 → 更平滑但略滞后）。
α=0.3 是「同步紧度 ↔ 平滑度」的**最优折中**。动对静若微抖 → α 调到 0.2；若仍滞后 → 调到 0.4。

### 4.3 实测验证（rt_15 / rt_16，动对静）

| 指标 | rt_15 | rt_16 |
|---|---|---|
| 雷达 az std | 0.00131 | 0.00078 |
| **Pivot X std** | 0.00039（az 的 **1/3.4**） | 0.00024（**1/3.3**） |
| **Pivot Y std** | 0.00056（el 的 **1/3.4**） | 0.00033（**1/3.4**） |
| **互相关滞后** | **0 tick** | **0 tick** |
| 相机净指向残差 | 0.329° | **0.196°** |

- 平台 778→659 m / 777→703 m 全程机动，pivot std 稳定 ≤ 0.0006 → **抗扰强**。
- 唯一极微特征：CPY 均值 +0.00032（≈ **+0.11° 垂直偏置**），源于雷达 el 残差自身均值，
  非相机逻辑问题；0.1° 在画面上不可分辨，可忽略（想消除可调 CAMOFF.y 或给 CPY 加固定零偏）。

### 4.4 ⚠ 速率前馈（lead）对本架构不适用

参考工坊作品 **Radar Targeting System**（steam id 3168029480）的 `radar fcs` 块：

```lua
SN(1,(aimx+(aimx-aimxo))/P2*8)   -- aim + (aim - aim_old) = 位置 + 速率前馈
```

在 rt_16 上离线仿真对比「EMA α=0.3」vs「EMA + 速率前馈」：

| | EMA α=0.3 | + 速率前馈 |
|---|---|---|
| 水平净残差 | 0.169° | **0.096°（改善）** |
| **抖动** | 0.072°/tick | **0.173°/tick（恶化 2.4×）** |
| 垂直净残差 | 0.701° | **0.739°（反而变差）** |

🔑 **根因**：作者的前馈建立在**先经 `radar denoise` 块降噪的目标位置**上（速率干净）；
我们的输入是**含噪雷达 az/el 残差**，对其取差分 = **放大噪声** → 抖动。
→ **结论：速率前馈对该架构不适用，保持 EMA α=0.3**。
若未来要追「零滞后紧跟移动目标」，应走作者完整管线（**位置先降噪 → 再 pos+rate**），
而不是对原始残差直接加前馈。

### 4.5 FOV 公式（与工坊互证一致）

```
fov = ( FW − 2·atan(SPAN/2 / dist) ) / ( FW − FN )
      FW = 2.2 rad（最宽）, FN = 0.025 rad（最窄）, SPAN = 视野覆盖尺度(m)
```
工坊 3168029480 写作 `cfov=(2.2-angT*P2)/(2.2-0.025)`，**常数 2.2 / 0.025、SPAN=10 完全一致**
→ 本标定是「业界事实标准」，可放心复用。改视野尺度**只需改 SPAN**。

## §5 工程陷阱清单（踩过的坑，务必避开）

| # | 陷阱 | 现象 / 后果 | 对策 |
|---|---|---|---|
| 1 | **`httpGet` URL 超长** | 游戏**崩溃**（无报错） | SW示波器 DataRecord 每批拼 `/send?value=...`，长度=通道数×精度×批量。**上限 ~4096 字符**：9 通道×30 tick×`%.6f` ≈ 3910（临界），12 通道 ≈ 5170（必崩）。修复：**批量 30→15、精度 `%.6f`→`%.4f`**（12 通道 ≈ 2230） |
| 2 | **CSV 列是 0 基** | 看错通道、得出错误结论 | `output.setNumber(N)` → CSV **第 N−1 列**。例：num19=CPX→col18、num20=CPY→col19、col20=fov |
| 3 | **欧拉角单位** | 解算三态跳变、偏离 1000 m | PS 欧拉角 = **弧度**（不 ×2π）；雷达角 = **圈**（×2π）。见 §1.3 |
| 4 | **`m_sweep_mode` 枚举** | 雷达不扫描 | 以**游戏 UI 下拉顺序**为准：**0 Static / 1 Clockwise / 2 Anticlockwise / 3 Sweep / 4 Manual**。Fandom 行文顺序是错的 |
| 5 | **Lua 里的半角 `<`** | **破坏 XML**，ET 解析失败 | 写进 XML 属性时**绝对禁止 `<`**（**注释里也不行！**）。改用 `>` 方向比较（`if -10>spd then`）或 `math.min/max` |
| 6 | **Edit 静默未生效** | 以为改了其实没落盘 | 编辑载具 XML 后**必须重新 grep 复核**，并 `ET.parse` 验 well-formed |
| 7 | **多 lua 块同名符号** | 误删活代码 | 同一载具的 object 82 与 96 **可有同名 `rotm/wld/CAMOFF` 但语义不同**——96 里是死代码，82 里是活的（用于解算世界坐标）。**清理必须按 `object id` 精确限定范围** |
| 8 | 雷达 `Effective Range` | 目标探不到 | 属性面板该项 = **当前 FOV 下实际探测距离上限**，目标须在此距离内（dish FOV 0.1×0.1 → 8000 m） |
