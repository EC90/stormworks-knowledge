## §0 PID控制器：接口与固有性质

🎮 `gate_pid_controller.xml`：mass 1 · $100 · 尺寸 2x1x2 · 逻辑节点 4 个

| 节点 | 方向 | 类型 | 说明 |
|---|---|---|---|
| Setpoint | 输入 | 数值 | **目标值** |
| Process Variable | 输入 | 数值 | **控制量**（系统当前实测值） |
| Control Output | 输出 | 数值 | **操作量**（计算结果） |
| Active | 输入 | 开关 | 是否启用 |

> 🎮 **关键性质**：定义文件原文 `When inactive, stored values are reset.`
> 即 **Active 失活时内部累积值被清零**（含积分项）。这是防积分暴走的正解，见 §6。

### 三个量的命名

| 中文 | 英文 | 含义 |
|---|---|---|
| 控制量 | Process Variable | 被控对象当前的实际值（高度、RPS、方位…） |
| 目标值 | Setpoint | 希望控制量达到的值 |
| 操作量 | Control Output | PID 算出来、用来驱动执行器的值 |

**接线铁律**：操作量为正时，控制量必须朝正方向变化。若接反了，**不要给 K 加负号**，
应在控制对象侧（执行机构或接线）取反 —— 见 §3。

### 三个增益

| 汉化译名 | 游戏内英文 | 惯用符号 |
|---|---|---|
| 比例增益(Proportional Gain) | Proportional Gain | Kp |
| 积分增益(Integral Gain) | Integral Gain | Ki |
| 导数增益(Derivative Gain) | Derivative Gain | Kd |

> **术语辨析**：游戏内与汉化补丁作「导数增益」，工学术语通行为「微分增益」。
> wiki 亦指出：PID 部件与逻辑门上写作 Derivative，但工程上一般用 **Differential**，
> 语源是"差分"，在数学与工程中的定译是"微分"。**两者同义**，本册按官方译名写"导数增益"。

## §1 P / I / D 各自的作用与失效模式

### P（比例）
- **作用**：误差越大，把控制量推回目标的力越大。Kp 越大，越快地接近目标值。
- **失效**：P 只看"当前误差"，会冲过目标 → **过冲（overshoot）**。
  冲过头后误差反向，P 输出也反向 → 上下往复 → **振荡（hunting）**。
- **致命场景**：直升机自动着陆，目标值 = 离地高度 0 m，过冲就是砸地。
- 结论：**P 是振荡的主要来源**。

### I（积分）
- **作用**：消除 **稳态偏差（offset / 定常偏差）**。
  典型：直升机因自重，纯 PD 会稳定在略低于目标高度的位置。
- **失效 1**：误差持续越久，补偿越强。若执行机构长期推不动（重物、未通电、无速度），
  一旦阻力消失就会**暴走**。
- **失效 2**：Ki 过大会助长振荡（比 Kp 弱，但确实会）。
- 〔经验〕**Ki 取 0.0001 量级**；若小误差无所谓，**直接置 0 也是合理选择**。

### D（导数/微分）
- **作用**：控制量接近目标时给 P 踩刹车，主动抑制过冲与振荡。
- **失效**：Kd 过大 → 到达目标所需时间明显变长。

## §2 ZN 极限灵敏度法 —— 定 K 的起点

载具输出与重量千差万别，K 必须逐机调整。**极限灵敏度法（Ziegler-Nichols，简称 ZN 法）**
是控制工程里唯一能给出接近最优 K 的系统方法，Stormworks 里同样可用。

**步骤**
1. 把 Ki、Kd 均置 0。
2. 逐步增大 Kp，直到系统出现**等幅振荡**。
3. 记下此时的 Kp（临界增益，**Kp1**）与振荡周期。
4. 按 ZN 公式由 Kp1 与周期算出 Kp / Ki / Kd。

**参考**：niconico `sm36286214`
「【Stormworks】PIDの調整がちょっと楽に出来る(かもしれない)方法」

> 〔经验〕作者立场：ZN 法确实并非对所有 PID 控制都适用，但**除此之外没有任何定 K 的依据**，
> 所以一律先用 ZN 法打底，再按 §3 微调。
> 若 ZN 法定出的 Kd 下仍然振荡，就把 **Kp1 本身改小后重算三个 K**，而不是只改结果。

## §3 调参纪律（四条）

1. **一次只改一个 K。** 同时改多个，就无法判断是哪个值的改动起了多大作用。
   必须改一个、测一次、对比结果。
2. **步进 10%。** 先改 10%；变化过大就回退 5%；没变化就再改 10%；
   **再改 3 次仍无变化**，就该换下一个调整项了。
3. **K 永不为负。** 需要反相输出时，在控制对象侧取反，不要给 K 加负号。
4. **振荡时的调整顺序：Kp↓ → Kd↑ → Ki↓。**
   - P 是振荡主因，先减 Kp
   - D 抑制振荡，再增 Kd
   - 前两步都做了仍有小幅残余振荡，最后才减 Ki

## §4 控制量量程放大

🎮 **倾斜传感器**输出范围 **-0.25 ~ 0.25 圈**（定义文件：`-0.25 to 0.25 turns`，0.25 = 90°）。

**问题**：船在波浪中的摇摆幅度可能只有 ±0.02 量级，PID 几乎不产生有效输出。

**解法**〔经验〕：把输入 PID 的控制量**乘 10 / 20 / 100**。
判据：控制量最大波动幅度 < 0.25，或风浪等小扰动引起的波动 < 0.05 时值得考虑。

> ⚠ **三个连带后果（容易漏）**
> 1. **目标值非 0 时，目标值必须乘同一个系数。**
> 2. 乘得过大本身会引发振荡 → 振荡排不掉时把倍数**减半到 1/5**。
> 3. **改了倍数，ZN 法必须从头重算 K。**

## §5 振动源诊断：问题可能不在 PID 侧

🎮 绝大多数 Stormworks 装置只接受 **-1 ~ 1** 的操作量。
若**操作量以远超 ±1 的振幅振荡**，原因是下列之一：

- **Kp 过大** → 按 §3 减小
- **控制对象上另有振动源**〔经验〕

### 已知的两个外部振源

| 振源 | 机理 | 正解 |
|---|---|---|
| **重型旋翼总距** | 用陀螺仪 Up/Down 控总距时，过度的桨距变化会产生 1 秒以下的上下抖动。直接 PID 控 Up/Down 会被它顶住；即便不直接控 Up/Down，只要 PID 在控滚转/俯仰/引擎油门也会受明显影响 | **不要调 PID**，改调陀螺仪的**最大节流阀 Max Throttle** 来限制 Stabilised Up/Down 输出。注意别调太小导致无法起飞 —— 先看 Stabilised Up/Down 的实际输出值再定 |
| **柴油机驱动的旋翼** | 发动机触及断油限速时转速振荡，被转换成推力振荡（旋翼则表现为上下抖动） | 避免让发动机运行到转速上限 |

## §6 门控：什么时候必须关掉 PID

**核心风险**：执行机构不起作用时，误差会持续存在，I 项不断累积 → 阻力一消失就**暴走**。

**必须加门控的场景**
- 引擎停机时控油门
- 船停泊/微速时控方向舵（无速度则舵无效）
- 无速度时控航向
- 控制对象未通电

### 两种门控方式

| 方式 | 行为 | 适用 |
|---|---|---|
| 🎮 **断 Active 端** | 内部累积值被重置（积分清零） | 重新投入时无冲击，但状态丢失 |
| 〔经验〕**PID 常开 + 目标值跟随控制量** | Setpoint 接到等于 Process Variable 的值，同时切断操作量输出 | 积分不丢失，切入切出**无跳变** |

> 后者是评论区针对"PID 启动瞬间输入下冲、速度掉一下"给出的推荐解法。

## §7 四个实战案例

### 7.1 直升机高度保持
| 项 | 接法 |
|---|---|
| 目标值 | 键盘(大)输入；或用**存储寄存器**锁存"停止上下操纵那一刻的高度" |
| 控制量 | 高度计 |
| 控制对象 | 主旋翼总距 ← **陀螺仪**的 Up/Down |

- 4 个轴都建议在**座椅 → 陀螺仪**这一级介入，比完全不用陀螺仪简单得多。
- 介入方式：**座椅有上下输入时直送操作值；上下无输入时才启动 PID** 保持高度。
  做到水平机动时也能维持高度，就像现实中的多旋翼无人机一样好用。
- 用"松手瞬间的高度"作目标值时，必然过冲一次（松手瞬间垂直速度不为零）。
  改用**线性速度传感器**的垂直速度作控制量，可得到平滑停止的效果（垂直方向仍会有过冲）。
- 〔经验〕锁存实现：用脉冲（Pulse）把高度值写入寄存器，再送进 Setpoint。

### 7.2 固定翼滚转稳定
| 项 | 接法 |
|---|---|
| 目标值 | 0 |
| 控制量 | 倾斜传感器 —— **必须朝左舷方向安装**（此朝向下右滚输出正值） |
| 控制对象 | 控制面，接成正操作值 = 右滚 |

- 只在座椅**滚转无输入**时启用 PID。
- 控制量也可改用**角速度传感器**：行为会变成"松手后保持当前倾角"，
  甚至能用 PID 维持固定翼的倒飞状态。
- 上下的正负很直观，**左右极性最容易搞反** —— 调试时始终假设自己可能接反了。

### 7.3 引擎怠速
| 项 | 接法 |
|---|---|
| 目标值 | 固定值，例如 2.5（可加电路按电池余量抬高目标值 → 自动提速） |
| 控制量 | 引擎 RPS |
| 控制对象 | 引擎油门 |

- ⚠ 引擎停机时 PID 必须同时停止，否则 I 项暴走 → **需要专门的停机开关**。
- 直升机若用旋翼总距（而非油门）做垂直控制，也可让 PID 维持足够输出的转速。

### 7.4 自动舵（auto rudder）
| 项 | 接法 |
|---|---|
| 目标值 | 由目标航点（键盘(大)输入）与当前位置（GPS传感器）算出目标方位 |
| 控制量 | 罗盘传感器 |
| 控制对象 | 方向舵 |

- ⚠ **罗盘跨界问题**：罗盘输出在**正南处 0.5 与 -0.5 交界**。
  例：目标 -0.47（南稍偏东），当前 +0.43（南稍偏西）——
  必须"向左拧一点"，而不是向右绕一大圈。
  **解法**：分别算出右转量与左转量，**取绝对值较小者（带符号）**。
- 低速/停船时方向舵无效 → 关掉 PID 防 I 暴走。
- 若要更完善，可加"倒车时退出控制"的逻辑。

## §8 陀螺仪接口（高度保持案例的必需前置）

🎮 `gyro.xml`：mass 10 · $500 · 尺寸 5x1x3 · 逻辑节点 10 个

| 节点 | 方向 | 范围 | 说明 |
|---|---|---|---|
| Roll / Pitch / Yaw / Up-Down | 输入 | -1 ~ 1 | 目标的滚转/俯仰/偏航/垂直**速度** |
| Stabilised Roll / Pitch / Yaw | 输出 | -1 ~ 1 | 稳定后的对应速度值 |
| **Stabilised Up/Down** | 输出 | **0 ~ 1** | 稳定后的**上升推力**（注意不是 -1~1） |
| Auto-hover | 输入 | 开关 | 收到接通信号时启用内部自动悬停电路 |
| Electric | 输入 | 电力 | 供电 |

**SELECT 可调属性**

| 属性 | 范围 | 作用 |
|---|---|---|
| 最小节流阀 Min Throttle | 1~100% | 油门下限 |
| **最大节流阀 Max Throttle** | 1~100% | 油门上限 ← §5 抑制重旋翼抖动的调整点 |
| Roll / Pitch / Yaw | 1~100% | 各轴修正强度 |

> 注意：陀螺仪 Stabilised Up/Down 输出 **0~1**，与另外三个轴的 -1~1 **不同**。
> 直接把它当对称信号处理会出错。

## §9 评论区典型故障速查

| 症状 | 回答 |
|---|---|
| 固定翼自动调速，**PID 启动瞬间输入下冲**，速度暂时掉下来 | PID 常开；不用时把 Setpoint 接到等于 Process Variable 的值，同时切断操作量输出 |
| 喷气机用 PID 控俯仰保持高度，**超过目标后一直往上爬不下来** | 大概率 **Ki 过大**或长时间偏离导致的**积分饱和（windup）**。先把 Ki 置 0 验证是否由此引起 |
| 同上（另一说法） | 自建 PID 时检查输出**下限是否被设成 0**（应为 -1）；仍不稳则试 -0.5 |
| 「停止上下操纵瞬间的高度」怎么锁存 | 用脉冲（Pulse）把高度值写入寄存器，再送进 Setpoint |
| 「オートラダー」英文叫什么 | 自动航行 / 自律航行 的一部分，英文对应 auto navigation 或 auto pilot |
