> 仿照夜间定时任务 `automation-9bf331d6`（每晚 23:00 起滚动至次日 09:00）的 Goal 结构化改造，
> 闲时任务与之**日夜双轨并行**：日间直写主库，夜间走暂存轨，晨间核查合并，闲时结果优先度更高。

## 一、如何使用

- **粘贴位置**：ZCode 客户端 → 自动化 → 闲时任务 → 点开已有任务（工坊学习）→ 将下方「二、指令全文」整体粘贴覆盖「指令」框 → 保存。
- **任务标题建议**：`工坊实例学习·闲时滚动补学（学完为止）`
- **项目**：`D:\STORMWORKS`（闲时任务创建后项目锁定，已有任务不用动）。
- **权限/模型**：与夜间定时任务保持一致即可。
- 闲时任务是一次性提交：运行不会自己结束（唯一结束点=全部学完）；若被外力中断（客户端退出等），账本已落盘，重新提交即可续跑。

```
【工坊实例学习 · 闲时滚动补学】你是 ZCode「闲时任务」派发的学习运行，与夜间定时任务（automation-9bf331d6，工作窗 [23:00,09:00)）共用同一套规程与主账本，日夜双轨并行接力学习创意工坊作品，直到学完为止。第一步必须 Read 全文 D:\STORMWORKS\AI相关\Steam创意工坊Lua提取与示例编写规程.md（附录 A-4 为执行方式权威说明）与 D:\STORMWORKS\AI相关\_scripts\本地学习任务规格说明.md；本提示补充/覆盖以下条款，与规程冲突时以本提示为准。所有时间判断用 `date +%H:%M`（北京时间）。

🎯 目标（Goal）
- 终极目标：按规程确认学完 Stormworks 创意工坊全部作品——主账本 completeness.done=true 且 `ws_rank.py --top` 输出为空。
- 本次运行目标：日夜不停连续滚动微批学习（夜间自动转暂存轨，见 ⚠0），直至终极目标达成。除完成标准外不存在任何结束点，没有时间停工线。

✅ 完成标准（Done when）
- 唯一合法结束点：选题步判定全部学完 → 输出「【停机条件已触发】创意工坊全部作品已学完，闲时任务结束」后结束。判定前移到选题步，学完即判，不要拖到收尾。判定依据必须是主账本+主索引（直写模式随时可判；夜轨影子判定学完后，须先用主账本只读复核再输出停机标记）。
- 以下均不是结束点，运行必须继续：
  · 上下文压缩——一批完成 → 账本落盘 → 立即开下一批，压缩后无缝续跑；
  · 夜窗暂存轨 / 晨间核查 / 静默复查——属于模式切换与等待，不是停止；
  · 模型限流 / 单步失败——落盘后按 ⚠4 等待重试；
  · 被外力中断（客户端退出、进程被杀）——账本已落盘，用户重新提交闲时任务即从账本续跑。

📖 上下文（Context）
- 平台：ZCode 闲时任务（一次性提交、项目 D:\STORMWORKS）。兄弟任务：夜间定时任务 automation-9bf331d6 在 [23:00,09:00) 直写主库；本任务其余时段直写、夜窗转暂存轨。
- 主账本：AI相关\_meta\ws_scan_progress.json（进度唯一事实源）；影子账本：_work\idle\ws_scan_progress.idle.json（仅夜轨使用）。
- 开场（整个运行只做一次，压缩续跑后不重复）：`date +%H:%M` 判模式 → `sw_paths.py` 解析路径 → `ws_progress.py --fast` 记基线 → 若主账本 mtime <15 分钟且非本会话所写，按 ⚠0.5 静默复查后再动主库。

⚠ 约束（Constraints）
0. 双模时段守卫（最优先；每个新批次开批前复查 `date +%H:%M`）：
   (a) 日间直写模式 [09:20, 22:30)：本会话是主库唯一写者，按规程 A-4 流水线直写主账本/例题库/README，每选题轮（3 微批）收尾推送一次 git。
   (b) 22:30–22:45：不再开新批，完成当前批收尾落盘，准备切换。
   (c) 夜间暂存模式 [22:45, 次日 09:20)：定时任务在主库工作，本任务转暂存轨，铁律=不碰主账本/例题库/README/_meta，不跑任何 git 写操作：
       ① 入夜第一步：复制主账本 → _work\idle\ws_scan_progress.idle.json，此后只写影子账本（主账本正在被写导致 JSON 解析失败时，等 10 秒重读，至多 2 次）；
       ② 选题只用只读命令：`ws_rank.py --top 48` 取后 24 个（与定时任务的前 24 错开，减少撞车）；完整性轨 `--browse` 只读推进，游标只记影子；禁止 `--crawl/--refresh/--no-lua`（写主榜单，晨间补做）；
       ③ 批次目录用 AI相关\_提取暂存\_idle_bN；不跑 `--purge-check`（防删定时任务在用的 content 项，晨间补）；
       ④ 例题全部写入 _work\idle\Lua示例增量\（该目录被 .gitignore 排除，不污染定时任务的 git add -A）；
       ⑤ SteamCMD 下载撞锁：重试 ≤2 次仍败则跳过该 id，晨间再补下载。
   (d) 派发时即落在 [22:45, 次日 09:20)：直接以暂存模式开工，不等待、不结束。
0.5. 双写者静默保险（WorkBuddy 侧旧任务停用前的过渡保险）：日间开场或晨间发现主账本 mtime <15 分钟且非本会话所写 → 不结束运行，每 10 分钟复查一次，静默 ≥15 分钟后再动主库。
1. 晨间核查合并（≥09:20 且主账本静默后、暂存轨切回直写前必须完成）：
   ① 逐 id 核查夜间暂存例题：主库已学 → 先把原例题备份到 _work\idle\replaced_backup\，再用闲时版本覆盖，README 索引表/需求表/坑表按来源 id 定位替换行；主库未学 → 按规程分册归属装入例题库、README 加行、记入主账本（查漏补缺）；
   ② 账本合并：ids_learned / ids_downloaded 取并集，pending 重算，cursor_page 取 max，id 状态冲突以闲时结果为准；
   ③ 补做夜间欠账：--no-lua 标记、--purge-check 清理、`ws_reference --rebuild` → `ws_progress.py` 终值 → `ws_gitpush.py` 推送；
   ④ 输出【核查报告】：覆盖 N 项（已备份）/ 补缺 M 项 / 冲突与跳过明细，随后切回日间直写继续滚动。
2. 共存纪律：夜窗 [23:00,09:00) 主库唯一写者是夜间定时任务，暂存轨绝不跨写；不启动/关闭/监控任何进程（WorkBuddy 9:30 启动、22:50 关闭的自动化与本任务无关）；不停用/不修改任何其他自动化；无自动化自管理工具，禁止尝试自暂停/自删除。
3. git：日间每选题轮收尾、晨间核查后各推送一次 `ws_gitpush.py`（无变更自动跳过；non-fast-forward → `git pull --rebase origin main` 一次后重试一次；其余失败打印错误不阻塞）；夜间暂存轨零 git 操作。
4. 中断与重试：单步工具失败重试 ≤2 次，仍败跳过该项继续（steamcommunity 403 同规不重试）；模型限流 → 当前批落盘，每 10 分钟重试等待，恢复后续跑；任何等待环都不是结束点。
5. 微批流水线：完全按规程附录 A-4（① 批次隔离提取 → ② 差分三清单 → ③ 普查/去重 → ④ 装箱 → ⑤ 精读 → ⑥ 写例题并入主库（夜轨写 _work\idle\ 暂存区）→ ⑦ 完整性轨兜底 → ⑧ 收尾）；①③ 同空 → 整批记「重复跳过」直接并入。每微批精读预算 22000 字符、单文件上限 4000（--maxc 截断）；上下文压力 → 先落盘再开新批。
6. 收尾 (a)–(e)（每个选题轮结束、每次切模前执行）：(a) `ws_reference --rebuild`（夜轨跳过，晨间补）→ (b) `--purge-check` 清暂存（夜轨跳过）→ (c) 写账本（夜轨写影子）→ (d) `ws_progress.py` 终值（夜轨报影子自算值）→ (e) `ws_gitpush.py` 只看 RESULT 行（夜轨跳过）。
7. 报告：每批完成、每次模式切换、每次核查后输出【闲时补学报告】，沿用规程报告口径，另加三行：「模式：直写/暂存」「时段：HH:MM–HH:MM」「核查：未到 / 覆盖 N 补缺 M」。
```

## 三、双轨并行架构速览

| | 日间直写模式 | 夜间暂存模式 |
| --- | --- | --- |
| 时段 | [09:20, 22:30) 开批，22:45 前收尾 | [22:45, 次日 09:20)（定时任务窗 [23:00,09:00)） |
| 主账本 | 直写（唯一写者） | 只读复制 → 只写影子 `_work\idle\ws_scan_progress.idle.json` |
| 例题/README | 直写 `数据库\Lua\Lua示例` | 写 `_work\idle\Lua示例增量\`（git 忽略） |
| 选题 | 规程 A-4（--top 24） | 只读 `--top 48` 取后 24（错位避让） |
| git | 每选题轮推送一次 | 零 git 操作 |
| 晨间 | — | ≥09:20 且主账本静默后核查合并：重复→闲时覆盖（夜间版本备份到 replaced_backup\）、缺漏→双向互补、账本并集+cursor 取 max、补做 --no-lua/--purge-check/--rebuild 后推送 |

- 冲突契约：夜窗主库唯一写者=定时任务；闲时任务全时段运行、唯一结束点=全部学完；时间边界只触发「切模式/等待」，不触发结束。
- 过渡期保险：WorkBuddy 侧旧任务停用前，日间开场遇主账本 15 分钟内被他端写入 → 静默复查后再动主库。
