## 2. 收尾同步脚本 `ws_gitpush.py`

纯标准库 + 系统 git，无第三方依赖。放在 `AI相关\_scripts\`。

```bash
PY="<PY>"
S="<WS>/AI相关/_scripts/ws_gitpush.py"

# 预览：本轮将提交/推送哪些变更（不碰网络）
"$PY" "$S" --dry

# 真实执行：检测变更 → add -A → 中文提交说明 → commit → push origin main
"$PY" "$S"

# 指定分支（默认 main）
"$PY" "$S" --branch main
```

行为：
- `git status --porcelain` 无输出 → 打印「无变更，跳过」，exit 0（不提交、不推送）。
- 有变更 → `git add -A`（`.gitignore` 已排除 `_tools/`、`pony IDE/`、`.workbuddy/`、`_work/` 等，不会误入）→
  按区域归类生成中文提交说明 → `commit` → `git push origin <branch>`。
- 任何一步失败 → 打印错误并 exit 1；自动化以 `|| true` 吞掉，**不阻塞主流程、不重试**。

## 3. 认证前提（非交互推送可用）

`git push` 走 HTTPS 远端 `https://github.com/EC90/stormworks-knowledge.git`，需要凭据：

- 推荐：`gh auth setup-git` 把 gh 配置为 git 凭据助手（gh 已设备码授权后即时生效）。
- 或：环境内已有可用的 git 凭据存储 / SSH。
- 若推送报 `Authentication failed` / `could not read Username`：先确认 gh 已登录
  （`gh auth status`），再 `gh auth setup-git`，然后手动跑一次 `ws_gitpush.py` 验证。

## 4. 排障

| 现象 | 处理 |
| --- | --- |
| 每轮都提交、只有账本时间戳变 | 正常：进度账本 `ws_scan_progress.json` 每轮更新即视为「有更新」。若想减少噪声，可在 `ws_gitpush.py` 增加「仅 volatile 字段变更则跳过」的判断（当前未做，以「有更新就上传」为准） |
| push 报认证失败 | 见 §3：配 `gh auth setup-git` 或登录 gh |
| push 报非快进（non-fast-forward） | 本机与远端出现分叉（如协作者刚推了同分支）；先 `git pull --rebase origin main` 再手动 `ws_gitpush.py` |
| 工作区无变更却仍想推送 | 不需要；`ws_gitpush.py` 会自动跳过 |
| 误提交了大文件 | 远端已拒绝（`_tools/` 等被 `.gitignore` 排除）；若仍误入，用 `git rm --cached` 撤出并重提 |
