## 适用场景

- 用户跑完一轮模块化引擎测试，给出 `数据库\SW示波器v0.1.3\*.csv` 之类的数据文件
- 需要把「测试条件 + 数据」整理成一份文档，供后续轮次横向对比
- 提到换曲轴/气缸尺寸、追加新轮次、对比不同尺寸引擎

## 领域约定（硬规则，不要自行发挥）

1. **熄火判据：`RPS < 3` 记为熄火**。理由：模块化发动机起动器（起动机）全程开启，低转速由起动器维持，发动机不自持。有效工作区 = RPS ≥ 3 的区间。
2. **空转（仅带一个 3x3轮、无制动）启动曲线是每轮必采基线**，不是可选项。加载段起点完全由空转稳态决定，缺了它无法区分「发动机能力」与「负载水平」。每轮须先跑 60 s 以上空转再加载。
3. **斜坡速率与空转时长必须跨轮统一**：推荐斜坡 **0.001/s**、空转 **≥60 s**。斜坡快 15 倍会让熄火点带上转动惯量滞后而偏高，跨轮直接比制动输入会得出错误倍数（02 轮就是 0.015/s，熄火点属上限估计）。
4. **接口匹配（用户已确认的口径）**：**离合器一律使用与曲轴同尺寸的模块化引擎分类部件**——1x1 用 模块化发动机离合器(1x1)，3x3 用 模块化发动机离合器(3x3)，5x5 用 5x5。不要用通用 离合器。气缸口同理（`cylinder_3` 只接 3x3 气缸）。
5. **斜坡速率公式**：测试用油门杆（`button_throttle_lever`）加载，**输出斜坡速率 = 灵敏度 × 区间上限**。已记录：01 轮 1%×0.1 = 0.001/s，02 轮 3%×0.5 = 0.015/s，03 轮 3%×1.0 = 0.03/s（均与实测吻合）。跨轮对比时不要只看速率倍数——有效区间也同比放大，应比较**有效工作区内的采样时长**（建议 ≈40 s，即 `速率 ≈ 预期熄火点 / 40`）。
6. **轮数变了必须归一化**：制动输入是**每个轮子**的输入值，N 个轮子由同一信号驱动时总制动扭矩约为 N 倍。跨轮比较负载能力要用 **归一化负载 = 制动输入 × 轮数**。三轮记录：01 单轮 0.0391、02 单轮 0.4635、03 双轮 ≥1.0（→ ≥2.0）。
7. **一次只改一个变量**：03 轮同时换了引擎尺寸和轮数，导致负载类指标无法与 02 轮直接比。换尺寸时负载要保持不变，换负载时要固定尺寸。
8. **扫描变量本身也可能换**：01–03 轮扫「制动输入」，**04 轮改扫「离合器接合压」**（负载换成刹车锁死的 5x5轮）。**横轴量纲不同则熄火点不可互比**；跨轮只能比空转类指标（RPS、油耗、压力、每冲程油量、起动时间）。生成文档时用 `--ch1label/--ch1unit/--ch1key` 改通道 1 的称呼与附录列名。
9. 🗂 **数据留档（血泪）**：用户会清理 `SW示波器v0.1.3\` 下的旧 CSV，**归档文档 §6 附录是 01–03 轮数据的唯一副本**；`eng_test.xml` 也只有一份，每次换台架都会覆盖上一轮。每轮结束先提醒另存 CSV 与载具副本。
10. **术语必须先查表**：跑 `sw_check.py --auto` 后用 `sw_batch.py` 核对部件译名，禁止凭语感意译（详见 `<WS>\术语对照指南.md`）。常用译名：3x3轮、可变制动（Variable Brake）、模块化发动机曲轴/气缸、气体歧管、燃油歧管、离合器、模块化发动机起动器（Starter）。
11. **部件规格用 🎮 权威源**：`sw_defs.py get "<游戏内英文名>"`，不要抄 wiki。注意 3x3 气缸的定义文件叫 `modular_engine_piston_3x3.xml`（不是 cylinder_3x3）。
12. **扭矩计（07 轮起）——机制已由日文 wiki 考证清楚**：
    - 📖 权威出处：`https://wikiwiki.jp/sbarjp/PROPULSION` 的 `TORQUE METER` 条目（它在 PROPULSION 页，不在 SENSORS 页）。
    - **测的是「接続されている動力配管 = 所连接的整个动力网络」的扭矩与 RPS**，不是某一点传递扭矩；且「管路のどこで測定しても違いはありません」（**安装位置不影响读数**）。
    - **读数 = 该网络上所有连接件的动力需求之总和**。⚠ 要测**引擎输出扭矩**，扭矩计须装在**发动机侧网络**（曲轴/传动带 ↔ 离合器之间）；装在离合器负载侧，测到的是**负载网络的需求**。
    - **单位存疑**：日文 wiki「単位はＮ・ｍ。但しトルクメーターから得られるトルクは慣性モーメントであると推測されています。(要検証)」；Fandom 又称 "force"。**别当 N·m 用**，只作相对比较。
    - **已实证的两个坑（07/08 轮）**：
      - 锁死负载引入**与接合压无关的常数项 ≈20.0**（1x1 + 锁死 5x5轮实测），会主导读数、掩盖引擎自身扭矩变化（1.0→3.9）。→ 跨工况比扭矩前必须确认网络里挂了什么；定零点用"空载"配置（底值 1.0）。
      - 扭矩计还有一路 **RPS 输出**（网络转速），建议一并记录（第 6 通道）——能区分"引擎侧/负载侧"转速（锁死时应 ≈0 而引擎 60 RPS）。
    - 跨排量比扭矩：3x3/5x5 各跑「空载 + 锁死轮」两轮，用 **净扭矩 = 读数 − 空载底值** 计算。
13. **通道定义会变，用 `--roles` 映射**（11 轮起必备）：通道顺序不再固定，脚本已支持
    `--cols 1,2,3,4 --roles rps,press,flow,aux` 这类映射，可用角色：`scan / rps / press / flow / torque / aux / skip`。
    - **不写 `scan` 角色 = 无扫描变量**（如纯起动/储能测试），此时自动跳过负载扫描与熄火点章节。
    - 例：11 轮 `--cols 1,2,3,4 --roles rps,press,flow,aux`（num1=曲轴RPS、num2=压力、num3=流量、num4=飞轮RPS）。
    - 布尔通道也已可记录（如起动机信号），CSV 列数随之变化。
14. **飞轮（11 轮）**：模块化发动机飞轮(1x1) mass **100** / $450（远重于引擎本体），
    官方描述「acts as a momentum (energy) store …, but also **makes the engine harder to start**」已实测印证：
    同款双缸达 60 RPS 由 **1.9 s → 41.0 s（慢 20 倍）**；但**稳态 RPS 与压力基本不变**（60.45→59.95、0.5202→0.5214）。
    → **飞轮只改动态、不改稳态**；飞轮 RPS 与曲轴 RPS **逐点相同（零滑差）**，打滑只发生在离合器。

## 数据格式（SW示波器 v0.1.3）

- 每行 = 1 tick，**60 tick/s**；无表头。
- **9 列**（常规）：`,(num1),(num2),(num3),(num4),(bool1),(bool2),(bool3),(bool4)`；
  **10 列**（07 轮起加扭矩计）：`,num1..num5,bool1..4`。
  首列为空（上传格式遗留），末 4 列为布尔通道（通常未用、全 0）。
- 生成脚本已支持第 5 通道：`--cols 1,2,3,4,5` + `--ch5label/--ch5unit/--ch5key`。
- 采集链路：`DataRecord.xml` 微控每 tick 采样 → 每 30 tick `async.httpGet` 发到本机 **5588** 端口 → `main.exe` 落盘 `data.csv`。

## 标准流程

1. **新鲜度检查 + 术语核对**
   ```bash
   PY="<PY>"
   "$PY" "<WS>/汉化相关/脚本/sw_check.py" --auto
   "$PY" "<WS>/汉化相关/脚本/sw_batch.py" --terms "Modular Engine Crankshaft 1x1, Modular Engine Cylinder 1x1, ..."
   ```
2. **确认通道定义**（问用户或查上一轮文档）：哪个通道是制动输入、RPS、进气压力、柴油流量。
   > 每轮通道顺序必须保持一致，否则跨轮对比会错。
3. **拉权威部件规格**
   ```bash
   "$PY" "<WS>/数据库/方块数据/脚本/sw_defs.py" get "Modular Engine Crankshaft 1x1"
   ```
4. **生成文档**（脚本自动完成全部统计）：
   ```bash
   "$PY" "<WS>/技能库/sw-modular-engine-bench/scripts/make_record.py" \
     --csv "<WS>/数据库/SW示波器v0.1.3/1X1 data.csv" \
     --out "<WS>/数据库/方块数据/原始抓取_游戏定义/模块化引擎实测_01_1x1曲轴_1x1单缸.md" \
     --round 01 --config "1x1曲轴_1x1单缸" --stall 3.0
   ```
   通道列号可用 `--cols 1,2,3,4` 调整（= CSV 第 2~5 列，对应 num1~4）。
5. **人工补写**：部件清单、参数设定（歧管节气门/离合器值）、观察记录——脚本只算数，不替你下结论。
6. **写工作区记忆**：`<WS>\.workbuddy\memory\YYYY-MM-DD.md` 追加一轮摘要。

## 分析要点（别漏）

- **启动瞬态流量异常**：开头约 60 tick 柴油流量会出现 **281.97 L/s** 的数（两轮完全相同，确认是流量计初始化的系统性假读数），统计时必须剔除并标注。
- **进气压力随冲程振荡**，且**与转速基本无关**——反映歧管/冲程状态，不是转速的函数；做表时用窗口均值（±30 tick）。空转压力随排量增大而降低：1x1 为 0.678 atm，3x3 为 0.519 atm。
- **上升非一阶**：1x1 单缸 t₉₀/t₅₀ = 1.89（远小于一阶的 4.79），后段拖尾长；3x3 则 3.7 s 就进稳态带。用 6 个时间节点做跨轮对比。
- **加载段形状随排量变化**：1x1 是一加载就陡降（几乎无扭矩储备）；3x3 有 **0–0.15 平台区**（RPS 不掉），之后近线性下降约 −190 RPS/单位制动输入。
- 🔑 **每冲程油量（流量 ÷ (RPS/2)）是关键的归一化指标**：1x1 全程恒定（0.0013–0.0015），3x3 在加载后由 0.008 跳升到 **0.036–0.037**（约 4 倍）并保持——这解释了 3x3 加载初期总油耗不降反升。该跳变**尚未验证为稳态特性**（02 轮斜坡快 15 倍），建议补定点稳态测试。
- **熄火后**：制动保持 0.5 时 RPS 稳定在 0.49（起动器拖动转速），油耗趋近 0。

## 测试台架（`eng_test.xml`）

- 路径：`<SW_SAVE>\data\vehicles\eng_test.xml`（载具与微控存档目录同为该 `data` 目录）。**只读，不要改**。
- 用 Python `xml.etree` 解析即可，部件名在 `<c d="定义名">` 的 `d` 属性里；油门杆参数在 `button_throttle_lever` 的 `<o>` 属性：`sensitivity` / `min_lever_value` / `max_lever_value`。
- 台架固定套路（换尺寸时照此搭）：
  - 曲轴 → 传动带（同尺寸，挂起动器）→ 离合器（同尺寸）→ 轮；起动器由**布尔常量门**常开驱动。
  - **负载两种模式**（04 轮起切换）：
    - *制动扫描*：轮自由转动，油门杆 → 轮 Variable Brake（01–03 轮口径）
    - *离合器扫描*：轮 **Brake 布尔输入恒 1（锁死）**，油门杆 → 离合器 Clutch Pressure（04 轮口径）
    - 离合器扫描时**起动特别快**（1.4 s 进稳态带），因为接合压 0 时发动机与锁死轮完全脱开——起动段耗时由"要带动多少惯量"决定。
  - 🔑 **09 轮起的"扭矩计前置"标准接法**（测引擎输出扭矩，推荐沿用）：
    `曲轴 → 模块化引擎离合器(同尺寸，恒定 1 取力) → 扭矩计 → 通用离合器(Clutch，=扫描变量) → 锁死轮`
    - 用户经验：**模块化引擎必须经同尺寸的模块化引擎离合器才能取力**，不能省；所以变量改用后面串的**通用离合器**（需供电）。
    - 扭矩计因此落在**引擎侧网络**，读到的是引擎输出扭矩（07 轮置于负载侧时读到的是负载需求，二者差 17+ 个单位）。
  - 歧管：气体歧管节门 1、燃油歧管节门 0.5（各用**浮点常量门**给值）。
  - 供油：大型流体罐 → **液体泄压阀**（借其 `Flow Rate` 读柴油流量，台架里没有专用流量计）→ 管道 → 燃油歧管。
  - 进气：流体口（water_inlet）→ 三通 → **流体压力传感器**（读进气压力）+ 气体歧管。
  - 信号：微控B 把 `BREAK / RPS / A P / F F` 打包成 4 通道复合信号 → Data Recorder（属性 `1,2,3,4`）。
  - 大量配重块（01_block_weight）固定台架。
